# CMU 15-445/645 · Database Systems（数据库系统）课程总览

> **一句话定位**：这门课教你自己动手写一个数据库。不是「怎么用 MySQL」，而是「MySQL 内部那 20 个核心模块各自怎么实现、为什么这样实现」。你会用 C++ 从零实现一个能跑 SQL 的存储引擎（BusTub），并在这个过程中理解 50 年来数据库系统的设计权衡。

## 二、⚠️ C++ 先修要求（重要）

这是本课**最容易低估的门槛**。它不是一门「讲理论、写伪代码」的课——**每个 Project 都要写几千行 C++**。

### 2.1 语言标准

| 项目 | 要求 |
|---|---|
| **语言** | **C++17 及以上** |
| **依据** | 项目页原文说明项目以 **C++17** 编写；掌握 **C++11** 亦够用（C++11 的核心特性是理解代码库的最低要求） |
| **代码风格** | **必须遵守 Google C++ Style Guide** |
| **格式化工具** | 必须使用 **clang-format**（项目自带 `.clang-format`，提交前跑 `make format`） |
| **静态检查** | 提交前跑 `make check-clang-tidy-p1`（各 Project 对应后缀） |
| **文档注释** | 要求 **Doxygen** 风格的 Javadoc 注释 |
| **构建系统** | **CMake** |

> 待核实：slides 第 1 讲第 6 页写「we will not teach you how to write/debug C++20」，与本库采用的「C++17」口径存在表述差异。**以项目页的 C++17 要求为准**；若你已熟悉 C++20，写 C++17 代码不会有障碍（只是不能用 C++20 新特性）。

### 2.2 必须掌握的 C++ 特性

| 特性 | 在本课哪里用到 | 最低要求 |
|---|---|---|
| **智能指针**（`unique_ptr` / `shared_ptr` / `weak_ptr`） | 缓冲池的页管理、B+ 树节点所有权、迭代器 | 能说清所有权语义，知道何时用 `unique_ptr` 而非裸指针 |
| **RAII**（Resource Acquisition Is Initialization） | latch 的自动释放（`std::lock_guard` / `std::scoped_lock`）、Page Guard | 能写出异常安全的资源管理 |
| **move 语义**（`std::move` / 右值引用 / `&&`） | 元组的零拷贝传递、`std::promise` 传递 I/O 结果 | 理解「移动而非复制」何时发生 |
| **模板**（template / 模板特化） | 泛型 Value、泛型 Key、比较器特化 | 能读懂 `template <typename T> class X` 并写简单特化 |
| **`std::atomic` 与内存序** | latch 实现（TAS）、无锁结构 | 知道 `compare_exchange` 的语义 |
| **`std::mutex` / `shared_mutex` / 条件变量** | latch、读写锁 | 能写正确的临界区 |
| **`std::optional` / `std::variant`** | 可空值、多类型 Value | 会用即可 |
| **STL 容器**（`vector` / `unordered_map` / `list` / `deque`） | 几乎所有数据结构 | 知道各容器的复杂度与迭代器失效规则 |
| **`std::promise` / `std::future`** | Project #1 的 Disk Scheduler 异步 I/O | 理解 future 的阻塞语义 |

### 2.3 建议的准备顺序

```
第 1 步（1 周）：把 15-213 的 malloc lab 重做一遍
                → 理解指针、内存布局、隐式/显式空闲链表
第 2 步（3 天）：读一遍 Google C++ Style Guide 的「Naming」「Comments」「Classes」三节
第 3 步（2 天）：装好 clang-format 与 clang-tidy，跑通一个 hello world 的 CMake 项目
第 4 步（1 周）：用 C++ 手写一个哈希表 + 一个 B+ 树（不用模板，就 int→int）
                → 这是 Project #2 的最小预演
第 5 步（3 天）：写一个生产者-消费者队列，用 mutex + condition_variable
                → 这是 Project #1 缓冲池的最小预演
```

**如果你只会 Python/Java**：先花 2–3 周补 C++，否则 Project #1 会直接卡死。这门课的 C++ 要求不是「会用语法」，而是「能管理手动内存 + 能写正确的并发代码」。

## 三、课程定位与知识地图

### 3.1 这门课在 CMU 课程体系中的位置

```
15-122 命令式计算原理（C0 → C，契约、数据结构）
   ↓
15-213 计算机系统导论（C + 汇编 + 内存层次 + 并发）  ← 本课先修
   ↓
15-445 数据库系统（存储引擎 + 查询执行 + 事务）
   ↓
15-721 高级数据库系统（研究型，Andy Pavlo）
15-799 专题（查询优化、列式存储等）
```

**先修 15-213 的三个具体用处**：

1. **存储层次**（第 3 讲）：L1/L2/DRAM/SSD/HDD 的延迟差异是「为什么需要缓冲池」的全部理由。
2. **虚拟内存与 mmap**（第 4 讲）：DBMS 为什么不该把内存管理交给 OS，需要理解页表、TLB、缺页。
3. **并发与原子操作**（第 10、18–21 讲）：latch、CAS、内存序直接来自 15-213 的并发章节。

### 3.2 课程的五大模块

| 模块 | 讲次 | 核心问题 | 对应 Project |
|---|---|---|---|
| **① 关系模型与 SQL** | 01–02 | 数据怎么用关系表达？SQL 到底在算什么？ | — |
| **② 存储与缓冲池** | 03–06 | 数据怎么落到磁盘？怎么在内存里管？怎么压得更小？ | **Project #1**（Buffer Pool） |
| **③ 索引与哈希** | 07–10 | 怎么快速找到一条记录？并发下怎么保证索引不被写坏？ | **Project #2**（B+ Tree） |
| **④ 查询执行与优化** | 11, 13–17 | SQL 怎么变成算子树？每个算子怎么实现？哪个计划最快？ | **Project #3**（Query Execution） |
| **⑤ 事务、并发与恢复** | 18–24 | 多个事务同时跑怎么不出错？崩了怎么恢复？跨机器怎么办？ | **Project #4**（Concurrency Control） |

**模块之间的依赖**：

```
① 关系模型 ──→ ④ 查询执行（要懂 SQL 语义才能实现算子）
     │
     └──→ ② 存储（元组怎么放）──→ ③ 索引（怎么找）──→ ④（索引用在扫描/连接）
                                          │
                                          └──→ ⑤ 并发（索引的 latch）
② 缓冲池 ──→ ④ 外部排序/哈希连接（都要缓冲页）
② 缓冲池 ──→ ⑤ 日志与恢复（WAL 要刷盘）
```

### 3.3 一句话概括每一讲

| # | 主题 | 一句话 |
|---|---|---|
| 01 | Relational Model & Algebra | 数据库是「关系的集合」，SQL 是关系代数的语法糖 |
| 02 | Modern SQL | SQL 不是关系代数——它是**包（bag）** 语义，还带窗口函数和 CTE |
| 03 | Database Storage I | 磁盘比内存慢 10 万倍，所以要把数据组织成「页」 |
| 04 | Memory Management | 缓冲池是 DBMS 的「L1 缓存」，替换策略决定命中率 |
| 05 | Database Storage II | 日志结构存储（LSM）用「追加写」换掉「原地改」 |
| 06 | Storage Models & Compression | 行存适合 OLTP、列存适合 OLAP；列存能压 10 倍是因为同质性 |
| 07 | Hash Tables | 哈希表 O(1) 但无序，所以只做内部结构、不做表索引 |
| 08 | Indexes & Filters I | B+ 树是「有史以来最伟大的数据结构」 |
| 09 | Indexes & Filters II | 布隆过滤器、Trie、倒排索引、向量索引——B+ 树不是万能的 |
| 10 | Index Concurrency Control | 用 crabbing 协议让 B+ 树支持并发，且不死锁 |
| 11 | Sorting & Aggregation | 数据装不进内存时，排序与聚合都靠「分治 + 落盘」 |
| 12 | — | **DRC（无课）** |
| 13 | Joins Algorithms | 连接是规范化的代价；哈希连接几乎总是最快 |
| 14 | Query Execution I | 火山模型 / 物化模型 / 向量化模型：算子之间怎么传数据 |
| 15 | Query Execution II | 并行执行、进程模型、调度 |
| 16 | Query Optimization I | 把 SQL 变成「最便宜的」算子树 |
| 17 | Query Optimization II | 代价估算、连接顺序搜索、遗传算法 |
| 18 | Concurrency Control Theory | 可串行化、冲突可串行化、视图可串行化 |
| 19 | Two-Phase Locking | 2PL 及其变体（strict / rigorous / SSI） |
| 20 | Timestamp Ordering | 不用锁，用时间戳定序 |
| 21 | MVCC | 多版本：读不阻塞写、写不阻塞读 |
| 22 | Database Logging | WAL：先写日志再写数据 |
| 23 | Database Recovery | 崩溃后怎么用日志重放/回滚 |
| 24 | Distributed Databases | 跨机器的事务：2PC、Paxos/Raft |

## 四、BusTub：你要动手写的数据库

### 4.1 什么是 BusTub

**BusTub** 是 CMU 数据库组自研的**教学用关系型数据库**，用 C++17 编写。它不是一个「玩具」——它有完整的 SQL 解析器、优化器、执行引擎、存储引擎、事务管理器，只是每个模块都留了「待实现」的骨架，等你填。

**它已经有的**（不用你写）：

- SQL 解析（用 PostgreSQL 的 parser）
- 部分执行算子（seq scan、projection、filter 的框架）
- 目录（catalog）与系统表
- 测试框架（GTest + SQLLogicTest）

**你要写的**（按 Project）：

- Project #1：缓冲池管理器、ARC 替换策略、磁盘调度器
- Project #2：B+ 树索引（含并发版本）
- Project #3：查询执行算子（聚合、连接、排序、窗口函数）
- Project #4：并发控制（锁管理器、MVCC、事务）

### 4.2 为什么用 BusTub 而不是「读源码」

| 读 MySQL/PostgreSQL 源码 | 写 BusTub |
|---|---|
| 几百万行，模块耦合深 | 几万行，模块清晰 |
| 大量历史包袱与兼容代码 | 每个决策都是「教科书式」的 |
| 你只能「看懂」，不能「验证」 | 有测试告诉你对不对 |
| 抽象层次混乱 | 每一层都是课上讲过的模型 |

**关键价值**：**你必须做取舍**。写 B+ 树时你会真切体会到「节点大小选多大」「什么时候分裂」「latch 持多久」——这些在讲义上只是一行字，在代码里是几十个决策。

### 4.3 Project 概览

| Project | 主题 | 核心任务 | 难度 |
|---|---|---|---|
| **#0** | C++ 入门（Primer） | 热身：实现一个简单的矩阵/字符串处理，熟悉 CMU 的构建与提交流程 | ★★☆☆☆ |
| **#1** | **Buffer Pool Manager** | ① **ARC 替换策略**（自适应替换缓存）② **Disk Scheduler**（单请求队列、`std::promise` 模拟异步 I/O）③ **Buffer Pool Manager**（page table、page guard、pin/unpin 顺序） | ★★★★☆ |
| **#2** | **B+ Tree Index** | ① Page Layouts（叶子含 tombstone、延迟 merge）② Operations（点查、分裂插入、兄弟偷取 + 合并）③ Index Iterator（STL 风格、仅升序）④ **Concurrent Index**（crabbing 协议） | ★★★★★ |
| **#3** | **Query Execution** | 实现执行算子：聚合（sort/hash）、连接（nested loop / sort-merge / hash）、排序（external merge sort）、窗口函数、Top-N | ★★★★☆ |
| **#4** | **Concurrency Control** | 锁管理器（2PL）、死锁检测、MVCC（事务可见性、垃圾回收） | ★★★★★ |

**Project 之间的依赖**：

```
#0（热身）
 ↓
#1 缓冲池 ←────────────┐
 ↓                     │
#2 B+ 树（用缓冲池）    │
 ↓                     │
#3 查询执行（用 B+ 树做索引扫描、用缓冲池做外部排序）
 ↓
#4 并发控制（给 #1/#2/#3 加事务语义）
```

**每个 Project 的通用要求**：

- **代码质量**：Google C++ Style + Doxygen 注释
- **提交前检查**：`make format`（clang-format）+ `make check-clang-tidy-pN`（静态分析）+ `make check-lint`
- **禁止使用生成式 AI 工具**（讲义明确列出）
- **Extra Credit**：内存版 BusTub 的排行榜（leaderboard），通常 #1 加 50%、#2–10 加 25%、#11–20 加 10%

## 九、常见问题

**Q：没有 15-213 基础能学吗？**
A：能「读」，不能「做 Project」。存储层次与并发这两块必须先补。建议先看 15-213 的 malloc lab 与并发章节。

**Q：只会 Python，能学吗？**
A：理论部分（01–02、11、13、16–24）能学；Project 部分必须先补 2–3 周 C++。本课的 C++ 要求是「能管理手动内存 + 能写正确的并发代码」，不是「会语法」。

**Q：Fall 2026 的视频在哪看？**
A：**看不到**（仅 CMU 学生）。用 Fall 2025 的公开视频，按 `01-课程目录.md` 的映射表对应讲次。注意 2026 #13 对应 2025 #12（因为 2026 #12 是 DRC 无课）。

**Q：notes 缺了两讲怎么办？**
A：`15-optimization1`（#16）与 `18-twophaselocking`（#19）的官方 notes 未发布/未获取。这两讲用 slides + Fall 2025 视频（2025 #15 与 #18）。slides 页数分别是 156 与 158，信息量足够。

**Q：需要买教材吗？**
A：*Database System Concepts* 第 7 版是**参考书**，不是必读。讲义自包含度很高。若要看，重点章节是：第 12–14 章（存储与索引）、第 15–16 章（查询处理与优化）、第 17–19 章（事务）。**不要从第一页读起。**

**Q：Project 能参考开源实现吗？**
A：讲义明确**禁止使用生成式 AI 工具**。参考往届学生的公开实现处于灰色地带（很多学校明确禁止），且 DRC 会当面问你实现细节——**照抄必挂**。建议只看讲义与 BusTub 的测试。
