### 2.2 单讲学时怎么估

一个粗糙但好用的公式：

```
单讲学时 ≈ slides 页数 / 25 + notes 页数 × 0.5 + 复习 1h
```

例：

| 讲次 | slides 页 | notes 页 | 估算 |
|---|---|---|---|
| #04 缓冲池 | 245 | 6 | 245/25 + 3 + 1 ≈ **14h** |
| #11 排序聚合 | 39 | 4 | 39/25 + 2 + 1 ≈ **4.5h** |
| #18 并发理论 | 49 | 5 | 49/25 + 2.5 + 1 ≈ **5.5h** |
| #13 连接 | 135 | 5 | 135/25 + 2.5 + 1 ≈ **9h** |

**页数多的讲不一定是难点**（#04 页多是因为动画帧多、示例多），**页数少的讲不一定简单**（#18 只有 49 页但全是理论证明）。

## 三、五个模块的阶段目标

### 模块 ① 关系模型与 SQL

**要能回答的问题**：

1. 关系（relation）与表（table）的区别是什么？（答案：关系是**集合**，表在 SQL 里是**包**）
2. 关系代数的六个基本算子是什么？（σ 选择、π 投影、∪ 并、− 差、× 笛卡尔积、ρ 重命名）
3. 为什么 `JOIN` 在关系代数里就是「笛卡尔积 + 选择」？
4. `NULL` 在三值逻辑里怎么传播？`NULL = NULL` 是什么？
5. 窗口函数的 `ROW_NUMBER()` 与 `RANK()` 为什么结果不同？（答案：计算时机相对于排序）

### 模块 ② 存储与缓冲池

**要能回答的问题**：

1. 为什么数据库页大小通常是 4–16 KB，而不是 4 KB（OS 页）或 1 MB？
2. slotted page 的 slot array 为什么从前往后长、tuple 数据为什么从后往前长？
3. LRU、CLOCK、LRU-K、ARC 各自解决什么问题？ARC 的四个列表（T1/T2/B1/B2）分别存什么？
4. 为什么 mmap 不适合做缓冲池？（四个原因：事务安全、I/O 停顿、错误处理、性能）
5. LSM 树的写放大与读放大分别来自哪里？leveled 与 universal compaction 怎么权衡？
6. 列存的六种编码（RLE、位打包、mostly、位图、delta、字典）各自适用什么数据分布？

### 模块 ③ 索引与哈希

**要能回答的问题**：

1. B+ 树的三个不变量是什么？（完美平衡、除根外至少半满、k 个键对应 k+1 个子指针）
2. 叶子分裂时中间键是 copy up 还是 push up？内部节点分裂呢？
3. 为什么 B+ 树的平均占用率是 69% 而不是 100%？
4. 布隆过滤器为什么允许假阳性但不允许假阴性？位数组大小 m 与元素数 n 怎么定？
5. 可扩展哈希的 global bit count 与 local bit count 是什么关系？
6. 线性哈希的 split pointer 为什么能让查找只需要两次哈希中的一次？
7. crabbing 协议里「safe」的判据是什么？为什么读操作不需要 safe？

### 模块 ④ 查询执行与优化

**要能回答的问题**：

1. 火山模型（Volcano）与向量化模型（Vectorized）在 CPU 效率上的差别来自哪里？
2. 外部归并排序的趟数公式是什么？为什么 k 路归并要用 B−1 路而不是 B 路？
3. 五种连接算法的 I/O 代价公式分别是什么？什么时候索引嵌套循环最优？
4. 哈希连接为什么只能用于等值连接？
5. GRACE hash join 的两个阶段分别做什么？为什么要用两个不同的哈希函数？
6. 优化器的代价模型基于什么统计信息？为什么连接顺序搜索要用动态规划而不是穷举？

### 模块 ⑤ 事务、并发与恢复

**要能回答的问题**：

1. 冲突可串行化与视图可串行化的区别？哪个更严格？
2. 2PL 为什么能保证可串行化？为什么还会有死锁？
3. 时间戳定序（TO）怎么处理「过晚的读」和「过晚的写」？
4. MVCC 的可重复读是怎么实现的？为什么需要垃圾回收？
5. WAL 的两条规则是什么？（先写日志再写数据；事务提交前日志必须落盘）
6. ARIES 的三个阶段分别做什么？为什么 Redo 要「重复历史」而不是「只重做已提交的」？
7. 2PC 的阻塞问题来自哪里？Paxos/Raft 怎么解决协调者单点？

## 四、C++ 准备清单

这门课的 Project 全部用 C++17 写，且要求 **Google C++ Style + clang-format + clang-tidy**。以下清单按「必须先会」到「会用更好」排序。

### 4.1 必须先会（不会就做不了 Project）

- [ ] **指针与手动内存**：能说清栈/堆、`new`/`delete`、悬垂指针、内存泄漏
- [ ] **`unique_ptr` 与所有权**：知道「一个对象只能有一个 `unique_ptr` 拥有」，会用 `std::move` 转移所有权
- [ ] **`shared_ptr` 与引用计数**：知道它解决什么、代价是什么（原子引用计数）、什么时候会循环引用
- [ ] **RAII**：能写一个「构造时加锁、析构时解锁」的类；会用 `std::lock_guard` / `std::scoped_lock`
- [ ] **`std::mutex` 与临界区**：能写出正确的生产者-消费者
- [ ] **`std::atomic`**：知道 `load` / `store` / `compare_exchange_strong` 的语义
- [ ] **STL 容器**：`vector`（连续、随机访问）、`unordered_map`（哈希）、`list`（链表）、`deque`；知道迭代器何时失效
- [ ] **模板基础**：能读懂 `template <typename KeyType, typename ValueType, typename KeyComparator> class BPlusTree`，能写简单的函数模板

### 4.2 应该会（影响 Project 质量与速度）

- [ ] **move 语义**：右值引用 `T&&`、`std::move`、移动构造/移动赋值；知道「移动后源对象处于有效但未指定状态」
- [ ] **`std::optional`**：表示「可能没有值」，替代返回指针或哨兵值
- [ ] **`std::variant`**：表示「多种类型之一」，BusTub 的 `Value` 用它
- [ ] **`std::function` 与 lambda**：用于比较器、回调、迭代器的谓词
- [ ] **`std::promise` / `std::future`**：Project #1 的 Disk Scheduler 用它模拟异步 I/O
- [ ] **`std::shared_mutex`**：读写锁，Project #1/#2 的 latch 可能用到
- [ ] **条件变量 `std::condition_variable`**：等待/通知，实现阻塞式 latch
- [ ] **`const` 正确性**：知道哪些成员函数该标 `const`，为什么 Google Style 要求它
- [ ] **异常安全**：知道 basic guarantee 与 strong guarantee 的区别

- [ ] **CMake**：能读懂 `CMakeLists.txt`，会用 `cmake -B build && cmake --build build`

- [ ] **Google C++ Style**：至少读一遍 Naming（文件名、类型名、变量名、常量名）、Comments（Doxygen 风格）、Classes（访问控制、构造/析构顺序）三节

### 5.4 五个高频误区（提前打预防针）

| 误区 | 正解 |
|---|---|
| 「B+ 树就是二叉树」 | B+ 树是 **m 路**的，一个节点存几百个键，目的是**降低树高以减少 I/O** |
| 「哈希索引比 B+ 树快，所以更好」 | 哈希**不支持范围查询与排序**，所以数据库默认索引用 B+ 树 |
| 「列存一定比行存快」 | 列存只在**扫描少量列的聚合查询**上快；点查、单行更新反而慢 |
| 「MVCC 不用锁」 | MVCC 解决**读写冲突**，但**写写冲突**仍需要锁或其他机制 |
| 「有 WAL 就不会丢数据」 | WAL 只保证**已提交**的事务不丢；未提交的靠 Undo 回滚；还要考虑 `fsync` 的真实语义 |
