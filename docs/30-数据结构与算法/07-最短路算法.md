# 最短路算法：Dijkstra、Bellman-Ford 与 Floyd-Warshall

> 覆盖 `01-知识点目录.md` 中的「Dijkstra / Bellman-Ford / Floyd」。
> 本篇为原创笔记，不逐页翻译任何讲义；课程与教材见 [02-权威课程与资料](02-权威课程与资料.md)。

## 一句话总结

三种最短路算法共用同一个原子操作——**松弛（relaxation）**，区别只在「按什么顺序松弛」。Dijkstra 用优先队列每次取当前最近的未确定点，靠**非负权**保证这个点一旦取出就是最终值；Bellman-Ford 放弃贪心，对所有边老老实实扫 V-1 轮，换来吃负权与检测负环的能力；Floyd-Warshall 把「允许哪些点当中转站」当成 DP 的阶段，一次算出全源最短路。**选算法的顺序是：有负权吗 → 是全源吗 → 图稠密吗。**

## 核心概念

### 松弛（Relaxation）：三种算法共用的原子操作

对一条边 `(u, v, w)`，若 `dist[u] + w < dist[v]`，就把 `dist[v]` 更新为 `dist[u] + w`，并记 `pred[v] = u`。这一次操作叫松弛。

为什么是它：最短路有最优子结构——若 `s → … → u → v` 是最短路，则它的前缀 `s → … → u` 也必须是到 `u` 的最短路。所以「用已知的 `u` 去改进 `v`」是唯一有效的改进手段，不存在别的信息源。

代价：单次松弛是 O(1)。于是**任何最短路算法的总代价 = 松弛次数 + 决定「下一个松弛谁」的代价**。这句话是理解三者的钥匙：Dijkstra 花 log 因子去挑点，Bellman-Ford 完全不挑（所以要多扫很多轮），Floyd 用 DP 顺序代替挑选。

有一个必须先立住的不变式：只要图中没有从源点可达的负环，任何时刻都有 `dist[v] ≥ δ(v)`（`δ` 表示真实最短距离）。这叫**上界不变式**（upper-bound invariant），因为初始 `dist = ∞` 成立，每次松弛只会把值改成某条真实路径的长度。所有正确性论证都从这里出发。

### Dijkstra's algorithm（迪杰斯特拉算法）：贪心 + 优先队列

维护一个「已确定」集合 `S`。每轮从 `V \ S` 中取出 `dist` 最小的顶点 `u`，把 `u` 并入 `S`，然后松弛 `u` 的所有出边。初始 `dist[s] = 0`，其余为 `∞`。

它的正确性依赖一条引理：**`u` 被取出时，`dist[u]` 已经是 `δ(u)`。**

证明（反证 + 路径上的分界点，这是 CLRS 第 24 章的骨架）：

1. 假设 `u` 被取出时 `dist[u] > δ(u)`，取一条真实最短路 `P: s → … → u`。
2. 让 `y` 是 `P` 上**第一个不在 `S` 中**的顶点（`s ∈ S`，所以 `y` 一定存在；`u ∉ S`，所以 `y` 不晚于 `u`）。
3. `y` 的前驱 `pred(y)` 在 `S` 中。当 `pred(y)` 被加入 `S` 时，边 `(pred(y), y)` 被松弛过，之后 `dist[y]` 只会更小，所以此刻 **`dist[y] = δ(y)`**（等号，不是 `≤`——这是「上界不变式」加上「已被松弛到最短路」两头夹出来的）。
4. `u` 是堆中键最小的，所以 `dist[u] ≤ dist[y]`。
5. 由 `P` 的最短性，`δ(y) ≤ δ(u)`（从 `y` 沿 `P` 走到 `u` 的剩余段长度 ≥ 0）。
6. 串起来：`dist[u] ≤ dist[y] = δ(y) ≤ δ(u) < dist[u]`，矛盾。

第 5 步是唯一用到「非负」的地方。负权一出现，`δ(y) ≤ δ(u)` 就可能反过来，第 6 步的矛盾不成立，整个证明失效。

代价：正确性是用「不能处理负权」换来的。这是它唯一的、也是致命的假设。

### 懒惰删除（Lazy Deletion）：堆里为什么允许有过期条目

标准二叉堆只支持 push / pop-min，**不支持把堆中某个已有元素的值改小**（decrease-key）。要支持就得维护「元素 → 堆中下标」的反向索引，实现复杂、常数大。

懒惰删除的做法：发现 `dist[v]` 可以变小时，不去找堆里的旧条目，而是直接 push 一个新的 `(新dist, v)`。弹出时检查 `弹出的键 == dist[v]`；不等就说明这是**过期条目**（stale entry），直接丢弃，继续弹。

代价：堆里最多同时存在 `E + 1` 个条目（源点 1 个 + 每次成功松弛 1 个），空间从 O(V) 涨到 O(E)。换来的是实现极简、不需要索引堆，而且在绝大多数图上常数比索引堆更小。

对照：用索引堆可以做到 O(V) 条目、每次 decrease-key O(log V)；用 Fibonacci heap（斐波那契堆）把 decrease-key 摊还到 O(1)，总代价降到 O(E + V log V)。这个改进只在稠密图上才有意义，工程里很少真用。

### Bellman-Ford（贝尔曼-福特算法）：按边数分层的 DP

不再挑选顺序，直接对**所有边**做 V-1 轮松弛，每轮内边的顺序任意。第 k 轮结束后，`dist[v]` 已经覆盖了「从源点出发、至多 k 条边」的所有路径中的最小值。

为什么是 V-1 而不是 V：在没有负环的图里，任何最短路都可以取成**简单路径**（不重复顶点）——重复顶点意味着中间有个环，环的权重非负，去掉它不会变长。简单路径最多经过 V 个顶点、V-1 条边。所以 V-1 轮之后不可能还有能改进的东西。

第 V 轮的作用反过来用：如果第 V 轮**仍然**有边能松弛成功，说明存在一条 V 条边的路径比所有 ≤ V-1 条边的路径都短，这只能来自一个**负环**（negative cycle）。这就是负环检测。

代价：O(VE)，比 Dijkstra 慢一个数量级，但它是唯一能处理负权单源最短路的常规算法（除非用 Johnson 重赋权再套 Dijkstra）。

### Floyd-Warshall（弗洛伊德-沃舍尔算法）：把三维 DP 压成二维

定义状态 `dp[k][i][j]` = 只允许顶点集合 `{1, …, k}` 作为**中间点**时，`i` 到 `j` 的最短距离。转移只有两种选择：不用 `k` 当中转，或者用。

- 不用：`dp[k-1][i][j]`
- 用：`dp[k-1][i][k] + dp[k-1][k][j]`

边界是 `dp[0][i][j] = w(i,j)`（无边则 `∞`），`dp[0][i][i] = 0`。答案在 `dp[V][i][j]`。

代价：O(V³) 时间、O(V²) 空间，不需要堆也不需要邻接表——**邻接矩阵是它最自然的输入形式**。它同时给出全源答案，所以在稠密图上往往比跑 V 次 Dijkstra 划算（后者是 O(V·E log V)，稠密时 O(V³ log V)）。

一个免费的副产品：`dp[i][i] < 0` 说明存在经过 `i` 的负环；而且 Floyd 检测的是**全图**的负环，不限于某个源点可达的部分。

### 0-1 BFS 与 A*：两个「窄化」的变体

**0-1 BFS（双端队列 BFS）**：当边权只有 0 和 1 时，用双端队列（deque）代替堆。松弛成功且权为 0，把 `v` 压到**队首**；权为 1 压到**队尾**。这样队列里的 `dist` 值天然保持非降序（任意时刻队内值相差不超过 1），于是「取最小」变成 O(1) 的 pop-front。

**A\*（A-star）**：把优先队列的键从 `dist[u]` 换成 `dist[u] + h(u)`，`h(u)` 是对「`u` 到目标还剩多远」的估计。`h` 可采纳（admissible，不高估）时结果仍最优；`h` 一致（consistent，满足 `h(u) ≤ w(u,v) + h(v)`）时每个点最多展开一次。`h ≡ 0` 时它就退化成 Dijkstra。

共同点：两者都**没有改动「松弛」这个原子操作**，只改了「下一个弹谁」。这正是本节开头那句话的具体体现。

## 推导 / 例子

### 例子一：Dijkstra 完整手算，以及懒惰删除的代价计数

有向图，6 个顶点 A–F，9 条边：

```text
A → B (4)    A → C (2)
C → B (1)    C → D (8)    C → E (10)
B → D (5)
D → E (2)    D → F (6)
E → F (3)
```

（非官方，仅用于说明概念）

伪代码（懒惰删除版本）：

```text
dijkstra(G, s):
    dist[s] = 0;  其余 dist = ∞
    S = 空集                                 # 已确定的顶点
    H = 空的最小堆;  push(H, (0, s))
    while H 非空:
        (d, u) = pop_min(H)
        if u in S: continue                  # 已经确定过，跳过
        if d != dist[u]: continue            # 过期条目，丢弃
        S = S ∪ {u}                          # 此刻 dist[u] = δ(u)
        for (v, w) in adj[u]:
            if v not in S and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                push(H, (dist[v], v))        # 不删旧条目
```

（非官方，仅用于说明概念）

两个 `continue` 的职责要分清，因为它们**不是**「一个管正确性、一个管效率」的关系：

- `u in S`：保证每个顶点只被处理一次。一旦 `u` 进 `S`，它的 `dist` 被视为终局。
- `d != dist[u]`：丢掉同一顶点在堆里的旧副本。

在**非负权**的纯 Dijkstra 里，这两个检查**任留其一**都足以同时保证正确性与 `O((V+E) log V)`（因为 `dist` 只减不增，堆里键最小的那份必然先弹；第一份弹完进 `S`，后面更大的键全是废物）。但**两个都删掉**就不行了：过期条目会把邻接表重扫一遍，总扫描量从 E 涨到远超 E。

一个可复现的小实验（60 顶点、690 条边、非负随机权，随机种子 20261111）：三个版本（`S+stale`、只有 `S`、只有 `stale`）的 push 数、pop 数、边扫描数完全相同（135 / 135 / 690），而**两个检查都删掉**时扫描数变成 1580——多扫了 129%。这个数字说明两件事：① 冗余的检查不改变结果；② 少了全部检查，代价立刻可见，而且图越大、改进次数越多，膨胀越严重。

真正让 `u in S` 变得**不可省**的是负权（见例子二）：去掉它，代码会退化成一个低效但可能给出正确答案的松弛算法；留着它，答案直接错。所以写代码时保留 `u in S`，理由是「它定义了算法」，不是「它防了一个 bug」。

逐步推演（`E = 9`；「丢弃」列写明是被哪个 `continue` 拦下的）：

| 步 | 弹出 | 是否处理 | 松弛动作 | 堆（按弹出顺序排列） |
| --- | --- | --- | --- | --- |
| 1 | (0,A) | 是，`S={A}` | B←4, C←2 | (2,C) (4,B) |
| 2 | (2,C) | 是，`S={A,C}` | B←3（覆盖 4）, D←10, E←12 | (3,B) (4,B) (10,D) (12,E) |
| 3 | (3,B) | 是，`S={A,C,B}` | D←8（覆盖 10） | (4,B) (8,D) (10,D) (12,E) |
| 4 | (4,B) | **否：`B ∈ S`** | 不扫边 | (8,D) (10,D) (12,E) |
| 5 | (8,D) | 是，`S` 加 D | E←10（覆盖 12）, F←14 | (10,D) (10,E) (12,E) (14,F) |
| 6 | (10,D) | **否：`D ∈ S`** | 不扫边 | (10,E) (12,E) (14,F) |
| 7 | (10,E) | 是，`S` 加 E | F←13（覆盖 14） | (12,E) (13,F) (14,F) |
| 8 | (12,E) | **否：`E ∈ S`** | 不扫边 | (13,F) (14,F) |
| 9 | (13,F) | 是，`S` 加 F | 无出边 | (14,F) |
| 10 | (14,F) | **否：`F ∈ S`** | 不扫边 | 空 |

10 次 push、10 次 pop，其中 4 次被 `u in S` 拦下（这些条目其实也都是过期条目，两个 `continue` 在这里重叠，顺序无关）。

最终 `dist = {A:0, B:3, C:2, D:8, E:10, F:13}`。

验算一条路径：A→C→B→D→E→F = 2+1+5+2+3 = 13，与答案一致；换 A→C→B→D→F = 14，更差，说明 13 确实是最优。

**复杂度推导（这是重点，不是背结论）**：

1. 每条有向边 `(u,v)` 只在 `u` 被**处理**（加入 `S`）时被扫描一次；`S` 保证每个顶点最多加入一次，所以总扫描次数 = E。
2. 每次扫描最多产生一次成功松弛，成功松弛才 push；加上源点的 1 次，总 push ≤ E + 1。本例正好 9 + 1 = 10 次，与上表数出来的一致。
3. pop 次数 = push 次数（每条都要弹出来，被拦下的也弹），所以 pop ≤ E + 1。
4. 堆操作总数 = push + pop ≤ 2(E + 1) = O(E)。堆大小 ≤ E + 1 ≤ V² + 1，所以单次 O(log E) = O(log V)。
5. 初始化 `dist` 是 O(V)；外层循环本身没有额外开销。

合计 `O(V) + O(E) · O(log V) = O((V + E) log V)`。注意**不能**简化成 O(E log V) 就丢掉 V 项——稀疏图（E ≈ V）时 V 项是同阶的。也可以写成 `O(E log V)` 并补一句「忽略 O(V) 的初始化」，两种写法都常见，但要知道差在哪。

**如果省掉 `u in S` 那一行会怎样**（保持「只有 `d != dist[u]`」）：`dist` 只减不增，堆里同一个顶点的键单调递减，所以第一份（最小的）必然先弹、`u` 的邻接表被扫一遍；之后该顶点更大的旧键被 `d != dist[u]` 拦下。因此**每条边仍然只扫一次，复杂度结论不变**——这一点和很多人的直觉相反。

真正的代价出现在「两个检查都删掉」时：每个过期条目都会让邻接表**重扫一遍**，第 1 步的前提作废，上面的推导整体失效。所以严格来说，**`u in S` 不是复杂度所必需的，它是「算法定义」所必需的**（见例子二：负权下它决定了答案是错还是碰巧对）。

补充：如果图用邻接矩阵存，则「取最小值」用线性扫描 O(V)、每轮扫一整行 O(V)，总代价 `O(V² + E)`；稠密图 `E ≈ V²` 时就是 O(V²)，**比堆版本更快**。所以「Dijkstra 是 O((V+E)logV)」只在邻接表 + 二叉堆下成立。

### 例子二：负权如何杀死 Dijkstra

图：`A → B (1)`、`A → C (2)`、`C → B (-2)`。求 A 到 B。

Dijkstra 的执行：弹出 (0,A)，松弛得 `dist[B]=1`、`dist[C]=2`；堆里有 (1,B) 和 (2,C)；弹出 (1,B)，`B` 被**确定为 1**；弹出 (2,C)，松弛 `C→B`：`2 + (-2) = 0 < 1`，但 `B` 已在 `S` 中，按算法定义不再更新。

Dijkstra 返回 1，正确答案是 0（A→C→B = 2 + (-2) = 0）。

**这里有一个必须说清的陷阱。** 把这张负权图喂给「只有 `d != dist[u]` 检查、没有 `S`」的懒惰删除代码，输出的 `dist[B]` 是 **0**——答案碰巧对了。原因很直接：`B` 先以 1 被弹出并扫过边，之后 `C` 被弹出时把 `B` 改成 0，新条目 `(0,B)` 进堆、再弹出来又扫一遍边。代码里没有任何东西**阻止**一个点被重新处理，所以它悄悄退化成了一种低效的松弛算法。

所以更准确的说法是：

- 代码里有 `S`（或 `visited`，即每个点只处理一次）：负权 → **答案错误**（本例返回 1）。
- 代码里只有 `d != dist[u]`：负权 → 小图上**可能**给出正确答案，但没有复杂度保证；**一旦存在负环，必然死循环**（`dist` 无限下降，每次改进都产生新条目，堆永不为空）。

第二点可以用一个 5 顶点、含负环的小图验证：`0→1 (1)`、`1→2 (1)`、`2→3 (1)`、`3→4 (1)`、`4→0 (-9)`，环总权 `1+1+1+1-9 = -5`。无 `S` 的版本迭代到 5000 次上限仍不终止，`dist[0]` 已降到 **-5000**。所以「它碰巧能算对负权」是个危险的错觉——它不是算法，是一个在特定输入上偶然收敛的循环。

**结论**：Dijkstra 的「不能处理负权」不是伪代码层面的限制，而是「每个点只处理一次」这个不变式的限制。真正的实现必须带 `S`；带了 `S` 就绝不能喂负权。

**贪心选择性质为什么失效**：回看核心概念里那条引理，矛盾的支点是第 4、5 步：

```text
dist[u] ≤ dist[y] = δ(y) ≤ δ(u)
```

（非官方，仅用于说明概念）

最后一个不等号 `δ(y) ≤ δ(u)` 的论证是「从 `y` 沿最短路走到 `u` 的剩余段长度 ≥ 0」。本例中 `y = C`、`u = B`，剩余段是 `C→B`，权重 `-2`，于是 `δ(C) = 2 > δ(B) = 0`——`C` 明明比 `B` 更「远」，却被判定为更近。堆中最小 ≠ 距离最小，整个贪心就塌了。

**复杂度推导（如果硬要「修好」它）**：最直接的想法是「允许已确定的点被再次更新」，即去掉 `S` 的终局性。那么一次更新可能引发连锁更新，最坏情况下要退化成反复迭代到不动点——这正是 Bellman-Ford 的形态，代价 O(VE)。更糟的是，如果存在从源点可达的**负环**，`dist` 会无限下降，程序**根本不终止**（实践中表现为死循环或整数下溢）。这说明：负权不是「多跑几轮就能修」的小问题，它改变了问题的结构。

### 例子三：Bellman-Ford 的 V-1 轮是紧的

取一条链 `s → v1 → v2 → v3 → v4`，每边权 1，共 5 个顶点、4 条边。**边的处理顺序故意写成反序**：`(v3,v4), (v2,v3), (v1,v2), (s,v1)`。

伪代码：

```text
bellman_ford(G, s):
    dist[s] = 0;  其余 dist = ∞
    repeat V-1 times:
        for each edge (u, v, w) in G:        # 顺序任意
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    # 第 V 轮：检测负环
    for each edge (u, v, w) in G:
        if dist[u] + w < dist[v]:
            return "存在从 s 可达的负环"
    return dist
```

（非官方，仅用于说明概念）

逐步推演：

| 轮次 | (v3,v4) | (v2,v3) | (v1,v2) | (s,v1) | 本轮结束后的 dist |
| --- | --- | --- | --- | --- | --- |
| 初始 | — | — | — | — | s=0, 其余 ∞ |
| 1 | ∞ | ∞ | ∞ | v1←1 | v1=1 |
| 2 | ∞ | ∞ | v2←2 | 无变化 | v1=1, v2=2 |
| 3 | ∞ | v3←3 | 无变化 | 无变化 | v1=1, v2=2, v3=3 |
| 4 | v4←4 | 无变化 | 无变化 | 无变化 | 全部确定 |
| 5（检测轮） | 无变化 | 无变化 | 无变化 | 无变化 | 无负环 |

每轮只能把「已知区域」向前推一条边，所以恰好需要 V-1 = 4 轮。这证明 V-1 这个界是**紧的**，不能改成更小的常数。反过来说，如果边的顺序是正序，1 轮就够了——但算法不能假设输入顺序，必须按最坏情况设计。

**为什么 V-1 轮就够（归纳证明）**：设 `d_k[v]` 为第 k 轮结束后的 `dist[v]`。断言 `d_k[v] ≤` 「从 s 到 v、至多 k 条边的所有路径」的最小长度。

- 基础：`d_0[s] = 0`，其余 `∞`，对应「至多 0 条边」。
- 归纳：一条至多 k 条边的路径，要么至多 k-1 条边（由归纳假设已被 `d_{k-1}` 覆盖，且松弛只会让值变小），要么是「至多 k-1 条边到 u」+ 一条边 `(u,v)`。后者在第 k 轮处理 `(u,v)` 时，`dist[u]` 已经 ≤ `d_{k-1}[u]`，所以会被松弛到不超过该路径长度。
- 收尾：无负环时最短路可取简单路径，边数 ≤ V-1，故 `d_{V-1} = δ`。

**负环检测的具体演示**：在上面加一条 `v4 → v1` 权 `-5`。环 `v1→v2→v3→v4→v1` 的总权是 `1+1+1-5 = -2 < 0`。四轮之后的 `dist` 是 `[s=0, v1=-1, v2=2, v3=3, v4=4]`——`v1` 已经从 1 降到 -1。

注意**不能**把「第 V-1 轮还在改进」当作负环的信号：例子三那条正常链在第 4 轮（也就是 V-1 轮）同样在改进。**唯一可靠的判据是「V-1 轮之后再跑一轮，是否仍有边能改进」**。

进入检测轮，逐条边检查：

| 边 | 计算 | 是否改进 |
| --- | --- | --- |
| (v3,v4) | 3 + 1 = 4，vs 4 | 否 |
| (v2,v3) | 2 + 1 = 3，vs 3 | 否 |
| **(v1,v2)** | **-1 + 1 = 0，vs 2** | **是** |
| (s,v1) | 0 + 1 = 1，vs -1 | 否 |
| (v4,v1) | 4 - 5 = -1，vs -1 | 否 |

检测在 `(v1,v2)` 上触发。这一点值得注意：**触发的边不一定是你直觉上「属于环的那条负权边」**。`(v4,v1)` 之所以没触发，是因为前四轮已经把它带来的改进吃进去了（`dist[v1]` 已经是 -1，等于 `dist[v4] + (-5)`）；而 `(v1,v2)` 因为 `dist[v1]` 又降了一次，重新产生了改进空间。**只要有负环，检测轮必然至少有一条边触发**，具体是哪条取决于边序与轮数，不该依赖它来定位负环位置。

若没有负环，第 V 轮所有边都不会改进，因为 `d_{V-1}` 已经是真值。

**复杂度推导**：V-1 轮 × 每轮扫 E 条边 × 每条 O(1) = `O(VE)`；检测轮再加 O(E)，同阶。空间 O(V)。在邻接矩阵实现下仍是 O(VE)（每轮扫 V² 个位置），所以 Bellman-Ford 通常用**边表**（edge list）实现，这样每轮只碰真实存在的边。

### 例子四：Floyd-Warshall 的 DP 与「k 必须最外层」

伪代码：

```text
floyd_warshall(W):                       # W 是 V×V 权重矩阵
    dp = W 的副本;  对 i: dp[i][i] = 0
    for k in 1..V:                       # 阶段：允许 {1..k} 当中转
        for i in 1..V:
            for j in 1..V:
                dp[i][j] = min(dp[i][j], dp[i][k] + dp[k][j])
    return dp
```

（非官方，仅用于说明概念）

逐步推演。顶点 1,2,3,4，边 `1→2 (1)`、`2→4 (1)`、`4→3 (1)`，其余不可达。初值：

| dp | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 1 | ∞ | ∞ |
| 2 | ∞ | 0 | ∞ | 1 |
| 3 | ∞ | ∞ | 0 | ∞ |
| 4 | ∞ | ∞ | 1 | 0 |

- k=1：以 1 为中间点。`dp[i][1]` 除 `dp[1][1]=0` 外全是 `∞`，所以任何 `dp[i][1] + dp[1][j]` 都是 `∞`。矩阵不变。
- k=2：以 2 为中间点。`dp[1][4] = min(∞, dp[1][2] + dp[2][4]) = 1 + 1 = 2`。其余项的 `dp[i][2]` 或 `dp[2][j]` 至少一边是 `∞`（例如 `dp[1][3] = 1 + ∞ = ∞`），不变。
- k=3：以 3 为中间点。`dp[3][j]` 除 `dp[3][3]=0` 外全是 `∞`，所以每个候选 `dp[i][3] + dp[3][j]` 都是 `∞`。矩阵**不变**。（`dp[4][3]=1` 是初始就有的直接边，与阶段 3 无关；`dp[1][3]`、`dp[2][3]` 此刻仍为 `∞`，因为到 3 必须先经过 4，而 4 还没被允许当中转。）
- k=4：以 4 为中间点。`dp[2][3] = min(∞, dp[2][4] + dp[4][3]) = 1 + 1 = 2`；`dp[1][3] = min(∞, dp[1][4] + dp[4][3]) = 2 + 1 = 3`。这里用到的 `dp[1][4] = 2` 是阶段 k=2 就存进表里的值，**这正是 DP 复用前一层结果的意义**：Floyd 不需要重新搜索路径，只需要组合已有答案。

最终 `dp[1][3] = 3`，路径 1→2→4→3，正确。整张 4×4 表一共只被改动了 3 个格子（`(1,4)` 在 k=2；`(2,3)`、`(1,3)` 在 k=4），却覆盖了全部 16 个顶点对的答案——这就是用 O(V³) 次「候选计算」换来的东西：绝大多数计算的结果是「不改进」，而正是这些白算的 min 保证了不需要搜索。

**为什么能压成二维（原地更新）**：三维转移需要 `dp[k-1][i][k]` 和 `dp[k-1][k][j]`，看起来必须保留上一层。但注意

```text
dp[k][i][k] = min(dp[k-1][i][k], dp[k-1][i][k] + dp[k-1][k][k])
            = min(dp[k-1][i][k], dp[k-1][i][k] + 0)
            = dp[k-1][i][k]
```

（非官方，仅用于说明概念）

即「第 k 列」和「第 k 行」在阶段 k 里**根本不会变**（用 k 当中间点去改进「到 k 的距离」是白费力气）。所以原地写入 `dp[i][j]` 时，被读到的 `dp[i][k]` 和 `dp[k][j]` 恰好等于上一层的值，覆盖它们不会污染结果。空间从 O(V³) 降到 O(V²)。

**为什么 k 必须在最外层（反例）**：把循环写成 `for i: for j: for k`，用同一张图跑一遍。

- 处理 `(i,j) = (1,3)` 时依次试 k=1,2,3,4：
  - k=2 需要 `dp[1][2] + dp[2][3]`。`dp[1][2] = 1` 已算好，但 `dp[2][3]` 此刻仍是 **∞**——第 2 行还没轮到。
  - k=4 需要 `dp[1][4] + dp[4][3]`。`dp[1][4]` 此刻也是 **∞**——`(1,4)` 排在 `(1,3)` 之后。
  - 结果 `dp[1][3]` 保持 **∞**。
- 之后第 2 行算出 `dp[2][3] = 2`、第 1 行后面的 `(1,4)` 算出 `dp[1][4] = 2`，但 `dp[1][3]` 已经错过，不会再被访问。

最终 `dp[1][3] = ∞`，而正确答案是 3。**错误的根源**：DP 要求「算 `(i,j)` 时，`(i,k)` 和 `(k,j)` 都已经完成阶段 k-1」。`for k` 在最外层时这个前提由阶段本身保证；一旦 k 被挤到内层，就变成了「碰运气看行列顺序」，对某些输入正确、对另一些错误——这种「有时对」的 bug 最难查。

**一个可复现实验**（2 万个随机 4 顶点图，随机种子 7，基准是 `k` 在最外层的标准 Floyd）：只有 **`k` 在最外层**的两种（`for k: for i: for j` 与 `for k: for j: for i`）**零错误**；`for i: for j: for k` 与 `for j: for i: for k` 错 2313 次（11.6%），`for i: for k: for j` 与 `for j: for k: for i` 错 3108 / 3098 次（15.5%）。

两个结论值得记住：

1. **只有 k 必须在最外层，内两层怎么排都行。** 因为转移 `dp[i][j] = min(dp[i][j], dp[i][k] + dp[k][j])` 只依赖第 k 行和第 k 列，而它们在阶段 k 内不变；`i` 和 `j` 之间没有任何依赖关系。
2. **k 放中间也会错**（15.5%），而且错得比 `ijk` 更多。这张实验表比任何单点反例更有说服力——不是「某个图上会错」，而是「换一下顶点编号就换一个答案」。

**复杂度推导**：三层循环，每层 V 次，循环体是常数次比较与加法，合计 `V · V · V · O(1) = O(V³)`。空间 O(V²)（原地）。没有堆、没有邻接表，常数极小；在稠密图上，这个常数优势通常让它在 V 不太大时比「V 次 Dijkstra」更省实际时间。

**与矩阵乘法的关系**：定义 min-plus（也叫 tropical）乘法

```text
(A ⊗ B)[i][j] = min over k of ( A[i][k] + B[k][j] )
```

（非官方，仅用于说明概念）

它与普通矩阵乘法形状完全一样，只是把「乘」换成「加」、「加」换成「min」。在这个半环里，`W ⊗ W` 的第 `(i,j)` 项就是「至多 2 条边」的最短路，`W` 的 `t` 次 min-plus 幂给出「至多 t 条边」的最短路，重复平方可以 O(V³ log V) 算出全源最短路。

必须说清楚的是：**Floyd-Warshall 和 min-plus 幂算的是同一个量（最短路闭包），但不是同一个递推。** Floyd 的 `dp[k]` 不是 `W` 的 k 次幂，而是「中间点集合受限」的版本；它之所以只要 O(V³)，是因为复用了一整层的表，而不是靠快速幂。把两者混为一谈是常见的理解错误。

### 例子五：0-1 BFS 与 A\* 的代价对比

**0-1 BFS** 的伪代码只比 Dijkstra 少一个堆：

```text
zero_one_bfs(G, s):
    dist[s] = 0;  其余 dist = ∞
    D = 双端队列;  push_back(D, (0, s))
    while D 非空:
        (d, u) = pop_front(D)
        if u in S: continue                     # 已确定，跳过
        if d != dist[u]: continue               # 过期条目
        S = S ∪ {u}
        for (v, w) in adj[u]:                   # w ∈ {0, 1}
            if v not in S and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if w == 0: push_front(D, (dist[v], v))
                else:      push_back(D, (dist[v], v))
```

（非官方，仅用于说明概念）

推演一小段：`s → a (0)`、`s → b (1)`、`a → b (0)`。

1. `dist[s]=0`，队列 `[(0,s)]`。
2. 弹出 `(0,s)`：松弛 `a`（权 0 → 压队首），松弛 `b`（权 1 → 压队尾）。队列 `[(0,a), (1,b)]`。
3. 弹出 `(0,a)`：松弛 `b`，`0 + 0 = 0 < 1`，`dist[b] = 0`，压**队首**。队列 `[(0,b), (1,b)]`。
4. 弹出队首的 `(0,b)`：键与 `dist[b] = 0` 一致，确定，`S` 加 b。
5. 弹出 `(1,b)`：`b ∈ S`，丢弃。

`dist[b] = 0`。而普通 BFS（把 0 权和 1 权一视同仁）会在第 2 步就把 `b` 定为 1，因为它是「第一层」——**这就是 0 权边必须能「插队」的原因**。`a` 到 `b` 是一条不增加距离的边，`b` 应该和 `a` 同层，而不是下一层。

**复杂度推导**：成功松弛才 push，每条边最多被扫描一次（`u` 被加入 `S` 时，而 `S` 保证每个顶点只进一次），故 push ≤ E + 1，pop ≤ push，deque 每次操作 O(1)，加上 O(V) 初始化，总计 `O(V + E)`。对比 Dijkstra 的 `O((V+E) log V)`，省掉的正是那个 `log V`。这就是「权重只有两档」这个额外信息的价格。

**为什么队列天然有序**（直觉，不展开证明）：设当前弹出的是距离 `d` 的顶点，它松弛出的新距离只能是 `d` 或 `d+1`；由归纳假设，队列中其余元素的距离不超过 `d+1`，所以把 `d` 压队首、`d+1` 压队尾后，队列仍按距离非降排列。

注意这条论证的**前提**是「弹出的总是当前最小」——一旦队里混着过期条目，陈述就要改成「队列中所有**未被丢弃**的条目」有序，这需要把 `d != dist[u]` 的检查纳入不变式。一个可复现实验（2 万个随机 8 顶点 0/1 权图，随机种子 11）显示：带 `S` 和不带 `S` 的版本都与 Dijkstra 结果完全一致（0 个错误），所以**在这个变体里 `S` 不是正确性所必需的**，它只是让复杂度分析更干净。这与 Dijkstra 的情况不同——那里 `S` 是语义的一部分。这类「哪个检查是本质的」问题，光靠读代码判断容易出错，小规模穷举更可靠。

**A\*** 的代价：`h ≡ 0` 时与 Dijkstra 完全相同。`h` 一致时每个顶点只展开一次，界仍是 `O((V+E) log V)`，但**实际展开数**通常远小于 V——它的收益体现在常数和实际访问量上，不在渐近界上。`h` 只是可采纳而不一致时，顶点可能被反复展开，渐近界退化到与启发式质量相关，没有比 Dijkstra 更好的通用上界。所以「A\* 一定比 Dijkstra 快」是错的：`h` 取得不好时它反而更慢。

## 容易混淆的概念

| 对比 | Dijkstra | Bellman-Ford | Floyd-Warshall |
| --- | --- | --- | --- |
| 适用图 | 非负权，单源 | 可含负权，单源 | 可含负权，全源 |
| 复杂度 | O((V+E) log V)（邻接表+二叉堆） | O(VE) | O(V³) |
| 能否处理负权 | **否** | 能（无负环时） | 能（无负环时） |
| 能否检测负环 | 不能 | 能（第 V 轮） | 能（`dp[i][i] < 0`） |
| 空间 | O(V + E) | O(V + E) | O(V²) |

| 对比 | 懒惰删除 | 索引堆 decrease-key |
| --- | --- | --- |
| 堆中条目数 | 最多 E+1 | 恰好 V |
| 单次操作代价 | push/pop O(log V) | decrease-key O(log V) |
| 总代价 | O((V+E) log V) | O((V+E) log V)（Fibonacci 堆为 O(E + V log V)） |
| 实现难度 | 低，普通堆即可 | 高，需维护元素→下标的反向索引 |

| 对比 | 已发现（discovered） | 已确定（finalized） |
| --- | --- | --- |
| 含义 | `dist[v] < ∞`，有某条路径到达 | `dist[v] = δ(v)`，不可能再变小 |
| Dijkstra 中的标志 | 被松弛过至少一次 | 被加入 `S` 一次，此后不再更新 |
| Bellman-Ford 中有吗 | 有 | **没有**——它从不宣称任何点已确定 |

| 对比 | 0-1 BFS | Dijkstra | A\* |
| --- | --- | --- | --- |
| 取最小的手段 | deque 队首，无需堆 | 二叉堆 | 二叉堆，键含 `h(u)` |
| 复杂度 | O(V+E) | O((V+E) log V) | 一致启发式下同 Dijkstra，展开数更少 |
| 前提 | 边权 ∈ {0,1} | 边权 ≥ 0 | `h` 可采纳（最优性）/ 一致（不重展开） |

**三个高频错误**（都真实发生过，不是凑数）：

1. **Dijkstra 把两个检查都省了，或误以为 `u in S` 可以换成 `d != dist[u]` 就万事大吉。** 分清三件事：
   - 只留 `d != dist[u]`：非负权下答案对、复杂度也对（第一份键必然最小，先弹；其余被拦）。**但语义丢了**——代码里没有「这个点已经定案」，一旦换到 A\*（键含 `h`，不再单调）或允许负权，答案就真的错。A\* 里 `h` 不一致时，同一个顶点可能先以劣质 `g` 被弹出并「关闭」，之后更优的路径再也进不来。
   - 只留 `u in S`：同样正确（`dist` 只减不增，第一份即最终值），这是最常见的紧凑写法。
   - **两个都删**：每个过期条目都会重扫邻接表。实测 60 顶点、690 条边的随机图上，扫描量从 690 涨到 1250（+81%），且改进次数越多膨胀越严重。
   一句话：`u in S` 定义算法，`d != dist[u]` 是防御性冗余；**省掉哪个都不该省掉 `u in S`**。
2. **Bellman-Ford 轮数写错。** 两种错法：① 只写 V-1 轮、**不做**第 V 轮检测——负环被静默吞掉，返回一个看起来正常的有限值；② 把检测塞进 V-1 轮循环内部——第 k 轮的改进本来就可能发生（见例子三的链，第 1 轮到第 4 轮每轮都在改），于是**正常图被误报成有负环**。正确写法只有一种：**先** V-1 轮松弛，**再**单独一轮检测，两件事在代码上分开。
3. **Floyd 的 k 循环不在最外层。** 见例子四的反例。这个错误的特点是**依赖顶点编号**：把同样的图重新编号，可能就「碰巧对了」。所以「我的测试全过了」完全不能作为证据——必须知道 k 在最外层是 DP 阶段的一部分，而不是一个可以随意调换的循环。

## 和已有知识的连接

- [[15-122-25-Priority-Queues]]：Dijkstra 的「取最小」直接复用最小堆的 `sift_down`。那篇讲的「有序不变式 + 形状不变式」正是这里 `pop_min` 为 O(log V) 的依据；懒惰删除则是「不改堆内元素、只追加」的工程妥协，与堆的 ADT 接口限制直接相关。
- [[15-122-22-Graph-Search]]：BFS 的层序性质就是「无权图最短路」——每条边权为 1 时 `dist` 恰好是层号。0-1 BFS 是把这个性质推广到「边权 0 或 1」：权 0 不增加层数，所以压回队首。理解了 BFS 为什么正确，就理解了 0-1 BFS 为什么不需要堆。
- [[15-122-21-Graph-Representation]]：表示法直接决定复杂度。Dijkstra 的 O((V+E) log V) 依赖邻接表；Floyd 的 O(V³) 依赖邻接矩阵（用邻接表反而要额外 O(V²) 空间存结果）。「算法复杂度」从来不是脱离表示法独立存在的。
- [[15-122-23-Spanning-Trees]]：Prim 与 Dijkstra 的代码骨架几乎同构，区别只在堆里存什么。那篇的 Prim 是「边中心」版本——把跨界边按权重入堆，复杂度 O(v + e log e)；换成「顶点中心」版本、堆键为「该点到已选集合的最小边权」，就与 Dijkstra 逐行对应，只是 Dijkstra 的键是「到源点的累计距离」。把两个版本并排写一遍，能看清「贪心 + 优先队列」这个骨架是可复用的，而**键的定义决定了它解的是哪个问题**。
- [[15-122-24-Union-Find]]：并查集能 O(α) 判断无向图是否有环（加边时两端已连通即成环），但它**只能判断环的存在，不能判断环的权重和是否为负**——因为并查集没有「路径长度」的概念。这解释了为什么负环检测必须靠松弛而不能靠并查集。
- [[15-122-05-Big-O]]：`log V` 的来源是堆高，`O(VE)` 与 `O(V³)` 的比较要用到「稀疏图 E ≈ V、稠密图 E ≈ V²」这个前提。脱离图密度谈「哪个算法更快」是没有意义的。
- [[15-122-09-Stacks-and-Queues]]：0-1 BFS 用的双端队列就是那篇讲的 deque 的两个操作（push_front / push_back）同时用上；普通队列只有一个入口，所以只能处理等权。
- [[15-122-11-Unbounded-Arrays]]：那篇用「代币 + 不变式」证明扩容的摊还代价，本质是「不去界名单次操作，而是界住一串操作的总代价」。这里 Dijkstra 的「总 push ≤ E+1」是同类的**计数论证**：不关心某次松弛推了几次堆，只数「每条边最多贡献一次成功松弛」，于是总数被结构限死。两种思路都值得刻意练：看到「最坏单次很贵、但总账可控」就该想到它们。
- [[15-445-17-Query-Optimization-II]]：这里有一个容易接错的地方。真正与 Floyd 同构的 DP 是查询优化里的**连接顺序枚举**（System R 三步法，按「表子集」从小到大做 DP），它讲在同课程的第 16 讲；17 讲讲的是这个 DP 的**输入**——基数估计与代价模型。连接点是：两者都是「用一个逐渐扩大的允许集合当阶段，复用上一层整张表」，而 17 讲提醒的是同一个风险——**DP 的正确性依赖每一层的状态值准确**。Floyd 里状态是精确的边权和，所以只要没有负环就一定对；查询优化里状态是估计值，估错了 DP 再正确也会选出坏计划。
- [06-拓扑排序](06-拓扑排序.md)：DAG 上没有环，按拓扑序做**一轮**松弛就能得到最短路，代价 O(V+E)——比 Dijkstra 还快，因为没有「取最小」这一步。这说明「图的特殊结构」比「更强的算法」更值钱。
- [04-算法设计范式](04-算法设计范式.md)：Dijkstra 是贪心（且需要交换论证式的正确性证明），Bellman-Ford 是按边数分层的 DP，Floyd 是标准的三维 DP 压成二维。三种范式在同一组问题上各占一角，是那篇笔记最好的实例补充。

## 没懂的地方

- **A\* 在「可采纳但不一致」时的重展开次数紧界。** 我知道它可能重复展开，也知道一致性能避免，但最坏情况下重展开多少次、有没有一个只依赖 V 和 E 的界，我没查到确定的结论。待核实：CLRS 与 Russell & Norvig 对这一点的表述是否一致。
- **Johnson 算法的重赋权（reweighting）为什么保序。** 它先跑一次 Bellman-Ford 得到势函数 `h`，再把每条边改成 `w + h(u) - h(v)` 使全部非负，然后跑 V 次 Dijkstra。我能验证「新权非负」，但「新权下最短路与原图最短路是同一组路径」这一步（望远镜求和）没有自己完整推过。
- **Floyd 检测到负环之后，如何判定「哪些顶点对的距离被这个负环污染」。** 只知道看 `dp[i][i] < 0`，但要把「经过负环的顶点对」标成 `-∞`，需要再做一次可达性组合；具体怎么写我还没实测过。
- **0-1 BFS 的「队内值差不超过 1」这条不变式，我没有写出严格归纳。** 直觉上权 0 压队首、权 1 压队尾能维持有序，但过期条目混在队列里时，不变式该怎么陈述才准确（是「所有条目」还是「所有未丢弃条目」），我还在想。实测带/不带 `S` 都不出错，但「实测不出错」和「证明正确」是两件事。

2. `A→B (1)`、`A→C (2)`、`C→B (-2)`（3 条边，不是 2 条——2 条边的图里 Dijkstra 不会错，因为唯一的候选路径就是直达边）。Dijkstra 返回 1，正确是 0。失效的是正确性证明第 5 步的 `δ(y) ≤ δ(u)`：这里 `y=C`、`u=B`，`δ(C)=2 > δ(B)=0`，因为剩余段 `C→B` 的权为负，路径会「倒着变短」。若允许更新已确定的点（去掉 `S`），`B` 会被改成 0，但若存在负环（比如再加 `B→C (-5)`），`dist` 会无限下降，循环不终止。
3. 归纳。基础：`d_0[s]=0`、其余 `∞`，覆盖「至多 0 条边」。归纳步：一条至多 k 条边的路径 `P`，若边数 ≤ k-1，由归纳假设 `d_{k-1}[v] ≤ |P|`，而松弛只会让值变小，故 `d_k[v] ≤ d_{k-1}[v] ≤ |P|`；若恰有 k 条边，设最后一条是 `(u,v)`，前缀是至多 k-1 条边到 `u` 的路径，归纳假设给 `d_{k-1}[u] ≤ |P| - w(u,v)`，第 k 轮处理 `(u,v)` 时会把 `dist[v]` 压到 `≤ d_{k-1}[u] + w(u,v) ≤ |P|`。前提：①松弛只会减小不会增大；②每轮**所有**边都被处理一次（顺序任意）。若某轮跳过某条边，归纳就断。
4. 因为无负环时最短路可取**简单路径**，最多 V-1 条边；V-1 轮足以覆盖所有简单路径。紧的例子：链 `s→v1→v2→…→v_{V-1}`，边权全 1，且**边表顺序与路径方向相反**（先处理最远的边）。这样每轮只能把已知区域推进一条边，恰好需要 V-1 轮。特点是「依赖关系与处理顺序完全逆向」。
5. `dp[1][3] = ∞`。处理 `(1,3)` 时，k=2 需要 `dp[2][3]`，但第 2 行还没算（仍是 `∞`）；k=4 需要 `dp[1][4]`，而 `(1,4)` 排在 `(1,3)` 之后（仍是 `∞`）。之后 `dp[2][3]` 与 `dp[1][4]` 都算出了 2，但 `dp[1][3]` 已经错过，不会回头。正确值是 3（1→2→4→3）。
6. `dp[k][i][k] = min(dp[k-1][i][k], dp[k-1][i][k] + dp[k-1][k][k])`。而 `dp[k-1][k][k] = 0`（自己到自己的距离恒为 0，且只允许 `{1..k-1}` 当中转时仍成立），所以 `dp[k][i][k] = min(dp[k-1][i][k], dp[k-1][i][k] + 0) = dp[k-1][i][k]`。对称地 `dp[k][k][j] = dp[k-1][k][j]`。于是阶段 k 中第 k 行与第 k 列不变，读到的 `dp[i][k]`、`dp[k][j]` 都还是上一层值，原地覆盖安全。
7. Dijkstra：约 `(V+E) log V ≈ (10⁶ + 5×10⁶) × 20 ≈ 1.2×10⁸` 次堆相关的基本操作，实际常数还要乘以堆的比较与交换。0-1 BFS：约 `V + E = 6×10⁶` 次 deque 操作，每次是常数条指令。差约 20 倍，且 Dijkstra 的堆操作会带来随机内存访问（cache miss 严重），实际差距往往比 20 倍更大。在 10⁶ 量级上，这决定了是「几秒跑完」还是「几分钟」。
