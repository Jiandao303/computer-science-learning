# 拓扑排序

> 覆盖 `01-知识点目录.md` 中「图」组的「拓扑排序」。
> 本篇为原创笔记，不逐页翻译任何讲义；课程与教材见 [02-权威课程与资料](02-权威课程与资料.md)。

## 一句话总结

拓扑排序（topological sort）把有向无环图（DAG）的顶点排成一条线，使每条边都从线的左边指向右边。它解决的是「一堆带先后约束的任务，按什么顺序做才不违反约束」。如果图里有环，这样的顺序根本不存在，所以拓扑排序同时也是**有向图的环检测器**。

## 核心概念

### DAG 与偏序（partial order）

有向无环图（directed acyclic graph, DAG）就是没有有向环的有向图。把「存在一条从 `u` 到 `v` 的路径」记作 `u ≺ v`，这个关系满足：

- **非自反**：不存在 `u ≺ u`（否则就是环）；
- **传递**：`u ≺ v` 且 `v ≺ w` 推出 `u ≺ w`；
- **非对称**：`u ≺ v` 时不可能同时 `v ≺ u`（否则两条路径拼成环）。

这正是**严格偏序**（strict partial order）的三条公理。所以「DAG」和「有限集合上的严格偏序」是同一件事的两种说法：图是关系的显式存储，偏序是关系的代数性质。

偏序和全序（total order）的差别是这一节的关键：全序要求**任意两个元素都能比较**，偏序允许两个元素互不可达，称为**不可比**（incomparable）。拓扑排序做的事就是给不可比的元素人为规定一个先后，把一个偏序**扩展**成全序，术语叫**线性扩展**（linear extension）。线性扩展通常不唯一——这就是同一个 DAG 能有很多个合法拓扑序的原因。

### 为什么有环就没有拓扑序

假设图里有一个环 `v1 → v2 → … → vk → v1`。任何拓扑序都必须把每条边都摆成「左端点在前」，于是必须同时满足 `v1` 在 `v2` 前、`v2` 在 `v3` 前、……、`vk` 在 `v1` 前。把这些不等式串起来得到 `v1` 在 `v1` 前，矛盾。

换个说法：拓扑序要求「排在前面」这个关系是严格偏序，而环让它变成 `v1 ≺ v1`，违反非自反性。**有环 ⇔ 不存在拓扑序**，这不是算法实现的问题，而是定义层面的不可能。自环（self-loop）是最小的环，同样直接破坏。

代价是：任何拓扑排序算法都必须顺带做环检测，不能假设输入一定是 DAG。生产代码里这一点比排序本身更重要——构建系统报「circular dependency」、电子表格报「循环引用」，靠的都是这一步。

### 入度与「不断删掉源点」的不变式

**入度**（in-degree）是指向某顶点的边数。入度为 0 的顶点叫**源点**（source），它没有前置约束，可以立刻输出。

Kahn 算法（Kahn's algorithm，卡恩算法）的核心不变式是：**当前入度为 0 的顶点，其所有前驱都已经输出。** 因为每输出一个顶点 `u`，就把 `u` 的所有出边删掉（等价于把邻居的入度减 1）；邻居的入度降到 0，说明它的全部前驱都已被删掉，也就是都已输出。

这个不变式保证输出的前缀永远是一个合法的拓扑序前缀，因此算法不需要回溯，也不会反悔。代价是必须额外维护一张入度表（`Θ(V)` 空间），并且会**破坏性地修改**它；想再跑一次就得先复制。另外，删边只是逻辑上的，邻接表本身不变，所以边仍然只被扫描一次。

### DFS 后序与它的逆序

对图做深度优先搜索（depth-first search, DFS），每个顶点有一个**完成时间**（finishing time）：它的所有后代都被访问完之后才轮到它。把顶点按完成时间从小到大排，再整体反转，就得到一个拓扑序。

直觉是：如果存在边 `u → v`，那么 DFS 从 `u` 出发时，`v` 要么还没访问（会被 `u` 的递归访问到，于是 `v` 先完成）、要么正在栈上（灰色，那就是环）、要么已经完成（`v` 先完成）。在 DAG 里灰色不可能出现，所以**边的起点总比终点完成得晚**。反转之后，起点就排在终点前面。

这个方法的优雅之处是不需要入度表，复用一次 DFS 的框架就能同时得到后序、完成时间、以及环检测所需的颜色。代价是递归深度最坏等于 `V`（一条长链），十万个顶点就可能爆栈；而且它给出的是「一个」拓扑序，没有任何「按层」的结构信息。

### 环检测的两种视角

Kahn 的判据是**计数**：如果算法结束时输出的顶点数 `< n`，说明还有顶点入度永远降不到 0，它们必然被某个环「锁住」，因此有环。注意剩下的集合**不等于**环上的顶点集合：环的下游顶点也会被锁住（它们的某个前驱在环上），所以剩下的是「所有能被环到达的顶点」，要找精确的环需要强连通分量（strongly connected components, SCC）。

DFS 的判据是**颜色**：白色（未访问）、灰色（在当前递归栈上）、黑色（已完成）。如果从 `u` 出发遇到一条指向**灰色**顶点的边，这条边就是**回边**（back edge），它和 DFS 树上的路径拼成一个环。在 DAG 中不存在回边；反之有环必有回边。这个方法能直接给出环上的一个具体片段，比 Kahn 的「计数不足」信息更多，但也更容易写错（颜色恢复、递归栈）。

### 唯一性与「队列里只有一个元素」

Kahn 的队列在某一时刻若有两个或更多顶点，它们的入度都为 0。此时任取其中两个 `u`、`v`：不可能有边 `u → v`，否则 `v` 的入度至少是 1（来自尚未输出的 `u`）；同理不可能有 `v → u`。所以 `u` 与 `v` **不可比**，先输出谁都不违反约束，至少存在两个不同的拓扑序。

反过来，如果每一步队列里恰好只有一个顶点，那么每一步的选择都被迫唯一，整个序列唯一。于是判据是：**拓扑序唯一 ⇔ 执行 Kahn 时队列长度始终为 1**。这个判据只多花一个 `O(1)` 的判断，非常便宜。

有一个等价的图论刻画：拓扑序唯一 ⇔ DAG 中存在一条经过所有顶点的有向路径（Hamiltonian path，哈密顿路径）。因为唯一意味着相邻两项之间必须有边，否则就能交换它们。注意「唯一」并不要求图是一条简单的链：`1→2, 1→3, 2→3, 3→4` 有 4 个顶点 4 条边，但拓扑序仍然是唯一的 `1,2,3,4`。

## 推导 / 例子

以下所有伪代码均为**非官方，仅用于说明概念**。

### 例子一：Kahn 算法的完整伪代码与逐步执行

```text
# 非官方，仅用于说明概念
Kahn(G = (V, E)):
    indeg[v] = 0 for all v in V
    for each edge (u, v) in E:
        indeg[v] += 1                 # 建入度表，O(V + E)

    Q = empty FIFO queue
    for v in V:
        if indeg[v] == 0: enqueue(Q, v)

    order = empty list
    while Q not empty:
        u = dequeue(Q)
        append(order, u)
        for each v in Adj[u]:         # 每条出边恰好被看一次
            indeg[v] -= 1
            if indeg[v] == 0: enqueue(Q, v)

    if length(order) < |V|: return "有环"
    return order
```

取图 `G1`：`V = {1,2,3,4,5,6,7,8}`，边为
`(1,2), (1,3), (2,4), (2,5), (3,5), (4,6), (5,6), (6,7), (5,8)`，共 `V = 8`、`E = 9`。

初始入度：`1:0, 2:1, 3:1, 4:1, 5:2, 6:2, 7:1, 8:1`。初始 `Q = [1]`。

| 步骤 | 出队 | 输出序列 | 入度变化 | 队列 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 2:1→0 入队；3:1→0 入队 | [2,3] |
| 2 | 2 | 1,2 | 4:1→0 入队；5:2→1 | [3,4] |
| 3 | 3 | 1,2,3 | 5:1→0 入队 | [4,5] |
| 4 | 4 | 1,2,3,4 | 6:2→1 | [5] |
| 5 | 5 | 1,2,3,4,5 | 6:1→0 入队；8:1→0 入队 | [6,8] |
| 6 | 6 | 1,2,3,4,5,6 | 7:1→0 入队 | [8,7] |
| 7 | 8 | 1,2,3,4,5,6,8 | 8 无出边 | [7] |
| 8 | 7 | 1,2,3,4,5,6,8,7 | 7 无出边 | [] |

输出 8 个顶点，等于 `|V|`，所以无环。第 1 步结束时队列长度是 2，所以拓扑序**不唯一**。例如 `1,3,2,4,5,6,8,7` 同样合法：检查每条边，`(3,5)` 中 3 在 5 前，`(2,4)` 中 2 在 4 前，全部满足。

复杂度推导（不是背结论）：

1. 建入度表要扫一遍所有边，`Θ(E)`；初始化数组 `Θ(V)`。
2. 每个顶点最多入队一次——入度只减不增，降到 0 时入队，之后不会再次降到 0。所以出队与入队总计 `Θ(V)` 次，每次 `O(1)`。
3. 顶点 `u` 出队时扫描 `Adj[u]`，所有顶点加起来恰好扫描每条边一次，总计 `Θ(E)`。
4. 求和 `Θ(V) + Θ(E) = Θ(V+E)`。下界也是 `Ω(V+E)`：任何正确算法都必须至少读一遍图。所以是**紧界** `Θ(V+E)`。
5. 额外空间：入度表 `Θ(V)`、队列 `Θ(V)`、输出 `Θ(V)`，合计 `Θ(V)`，不含图本身的存储。

### 例子二：DFS 后序逆序法，同一张图

```text
# 非官方，仅用于说明概念
color[v] = WHITE for all v
post = empty list

DFS(u):
    color[u] = GRAY
    for each v in Adj[u]:
        if color[v] == GRAY: report "有环"      # 回边
        if color[v] == WHITE: DFS(v)
    color[u] = BLACK
    append(post, u)                              # 完成时入后序

for v in V:                                      # 外层必须覆盖所有点
    if color[v] == WHITE: DFS(v)

topo = reverse(post)
```

对 `G1`，邻接表按升序排列：`1:[2,3]`、`2:[4,5]`、`3:[5]`、`4:[6]`、`5:[6,8]`、`6:[7]`、`7:[]`、`8:[]`。从 1 开始：

1. `DFS(1)` → `DFS(2)` → `DFS(4)` → `DFS(6)` → `DFS(7)`。7 无出边，完成，`post = [7]`；6 完成，`post = [7,6]`；4 完成，`post = [7,6,4]`。
2. 回到 2，下一个邻居 5：`DFS(5)`。5 的邻居 6 已是黑色（跳过），接着 `DFS(8)`，8 完成，`post = [7,6,4,8]`；5 完成，`post = [7,6,4,8,5]`；2 完成，`post = [7,6,4,8,5,2]`。
3. 回到 1，下一个邻居 3：`DFS(3)`，邻居 5 已是黑色，3 完成，`post = [7,6,4,8,5,2,3]`；1 完成，`post = [7,6,4,8,5,2,3,1]`。

反转得到 `1,2,3,5,8,4,6,7`。逐边验证：`(1,2)` 1 在 2 前；`(1,3)` 1 在 3 前；`(2,4)` 2 在 4 前；`(2,5)` 2 在 5 前；`(3,5)` 3 在 5 前；`(4,6)` 4 在 6 前；`(5,6)` 5 在 6 前；`(6,7)` 6 在 7 前；`(5,8)` 5 在 8 前。全部成立。

注意它和 Kahn 的结果 `1,2,3,4,5,6,8,7` **不一样**，但两者都合法——这正好演示了线性扩展不唯一。这也提醒一件事：拿 DFS 的拓扑序去和 Kahn 的拓扑序逐个比较来「验证正确性」是错的，只能逐边验证。

复杂度：每个顶点进入一次、每条邻接表条目被看一次，`Θ(V+E)`。空间：颜色表 `Θ(V)`、后序数组 `Θ(V)`、递归栈最坏 `Θ(V)`。

### 例子三：环检测的两种结果对比

取 `G2`：`V = {a,b,c,d}`，边 `a→b, b→c, c→a, d→a`。入度：`a:2, b:1, c:1, d:0`。

Kahn：`Q = [d]`，出队 d，`a` 的入度 2→1，队列空。输出 1 个顶点 `< 4`，判有环。剩下的集合是 `{a,b,c}`，恰好是环 `a→b→c→a` 的全部顶点。

再看 `G2'`：在 `G2` 基础上加边 `c→e`（`e` 无出边）。此时 `e` 的入度为 1。Kahn 输出仍然只有 `{d}`，剩下的集合是 `{a,b,c,e}`。但 `e` **不在任何环上**，它只是环的下游受害者：`e` 的入度永远等不到 `c` 被输出。这就是为什么 Kahn 只能回答「有没有环」，不能回答「哪些顶点在环上」。要精确判定，需要对剩余子图（或整图）跑 SCC：`|SCC| > 1` 的分量、以及带自环的单点分量，才是环上的顶点。

DFS 三色法在 `G2` 上：`DFS(d)`，d 变灰，邻居 a，a 变灰，邻居 b，b 变灰，邻居 c，c 变灰，c 的邻居 a 是**灰色**，报回边。这条回边 `c→a` 与 DFS 树上的 `a→b→c` 拼成环 `a→b→c→a`，直接给出环的具体成员。这比 Kahn 的「少了 3 个点」信息量更大，代价是需要维护三色和递归栈。

### 例子四：唯一性判定

对 `G1`，第 1 步后队列为 `[2,3]`，长度 2，所以不唯一，我们确实构造出了两个序。现在把 `G1` 改成 `G3`：删掉边 `(2,4)`、`(3,5)`、`(5,8)`，加边 `(3,4)`，得到边集 `(1,2), (1,3), (2,5), (3,4), (4,6), (5,6), (6,7)`。

入度：`1:0, 2:1, 3:1, 4:1, 5:1, 6:2, 7:1`。

- 第 1 步：`Q=[1]`，出队 1，2 和 3 同时降为 0，`Q=[2,3]`，长度 2。

还是有两个源点，所以不唯一——`1,2,3,5,4,6,7` 和 `1,3,2,4,5,6,7` 都合法。想让队列恒为 1，必须让每个顶点的入度在它「该出场」之前恰好为 0，也就是相邻两项之间都有边。改成链 `1→2→3→4`：入度 `1:0, 2:1, 3:1, 4:1`。第 1 步 `Q=[1]`；出队 1，2 入队，`Q=[2]`；出队 2，3 入队；出队 3，4 入队。每步长度都是 1，唯一序 `1,2,3,4`。

再看前面提过的 `1→2, 1→3, 2→3, 3→4`：入度 `1:0, 2:1, 3:2, 4:1`。第 1 步 `Q=[1]`；出队 1，2 入队而 3 的入度只降到 1，`Q=[2]`；出队 2，3 降到 0 入队，`Q=[3]`；出队 3，4 入队。每步长度 1，唯一。它有 4 个顶点 4 条边，不是链，但存在哈密顿路径 `1→2→3→4`，所以唯一。

### 例子五：DAG 上的单源最短路（按拓扑序松弛）

给 `G1` 的边加权重：`(1,2)=3, (1,3)=2, (2,4)=4, (2,5)=1, (3,5)=2, (4,6)=2, (5,6)=3, (6,7)=1, (5,8)=5`。

```text
# 非官方，仅用于说明概念
DAG-Shortest-Paths(G, w, s):
    topo = TopologicalSort(G)          # 先线性化
    d[v] = INF for all v; d[s] = 0
    for u in topo:                     # 严格按拓扑序
        for each (u, v) in Adj[u]:
            if d[u] + w(u,v) < d[v]:
                d[v] = d[u] + w(u,v)
    return d
```

用 Kahn 得到的序 `1,2,3,4,5,6,8,7`，源点 `s = 1`：

| 处理 | `d[2]` | `d[3]` | `d[4]` | `d[5]` | `d[6]` | `d[7]` | `d[8]` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 初始 | ∞ | ∞ | ∞ | ∞ | ∞ | ∞ | ∞ |
| 1 | 3 | 2 | ∞ | ∞ | ∞ | ∞ | ∞ |
| 2 | 3 | 2 | 7 | 4 | ∞ | ∞ | ∞ |
| 3 | 3 | 2 | 7 | 4（2+2=4，不更小） | ∞ | ∞ | ∞ |
| 4 | 3 | 2 | 7 | 4 | 9 | ∞ | ∞ |
| 5 | 3 | 2 | 7 | 4 | 7（4+3=7 < 9） | ∞ | 9 |
| 6 | 3 | 2 | 7 | 4 | 7 | 8 | 9 |
| 8 | 3 | 2 | 7 | 4 | 7 | 8 | 9 |
| 7 | 3 | 2 | 7 | 4 | 7 | 8 | 9 |

结果 `d = [0,3,2,7,4,7,8,9]`。两处值得注意：

1. 处理 3 时 `2+2=4` 与现有的 4 相等，**不更新**。严格小于才更新，这保证了相等路径不会来回抖动。
2. 处理 5 时把 `d[6]` 从 9 改成 7，说明**后出现的松弛可以修正先前的估计**。这不是 bug，而是为什么必须先拓扑排序：`6` 排在 `5` 后面，所以 `5` 的修正一定发生在 `6` 被处理之前，`6` 不需要被重新处理。

正确性证明用归纳法：设 `u` 被处理时 `d[u]` 已是最终值。基础是源点 `d[s]=0`。归纳步：`u` 的任一前驱 `p` 在拓扑序中都在 `u` 之前，按归纳假设 `d[p]` 已最终，且 `p` 处理时已经用边 `(p,u)` 松弛过，所以 `d[u] ≤ d[p] + w(p,u)`；而最短路必然经过某个前驱，取最优的那个前驱即得等号。**关键前提是「所有前驱都已处理完」，这正是拓扑序的定义。**

复杂度：拓扑排序 `Θ(V+E)`，松弛每条边一次 `Θ(E)`，总 `Θ(V+E)`，比 Dijkstra 的 `O((V+E) log V)` 少一个对数因子，而且**允许负权**（只要没有负环，而 DAG 本来就没有环）。作为交换，它要求图必须是 DAG；一般图只能退回 Bellman-Ford 的 `O(VE)` 或 Dijkstra 的 `O((V+E) log V)`。

同一套框架还能顺手算别的：

- **最长路**（关键路径）：把 `min` 换成 `max`。按上面的权重，`l[2]=3, l[3]=2, l[4]=7, l[5]=max(3+1, 2+2)=4, l[6]=max(7+2, 4+3)=9, l[8]=4+5=9, l[7]=9+1=10`，关键路径 `1→2→4→6→7` 长度 10（校验 `3+4+2+1=10`）。一般图上的最长路是 NP-hard，DAG 上却是线性的——「无环」这个限制消掉了全部难度。
- **路径计数**：`cnt[s]=1`，按拓扑序把 `cnt` 沿出边累加。`cnt[2]=1, cnt[3]=1, cnt[4]=1, cnt[5]=cnt[2]+cnt[3]=2, cnt[6]=cnt[4]+cnt[5]=3`，所以从 1 到 6 有 3 条路径：`1-2-4-6`、`1-2-5-6`、`1-3-5-6`。

## 容易混淆的概念

| 对比 | 拓扑排序 | 比较排序（如 quicksort） |
| --- | --- | --- |
| 输入 | DAG（偏序关系） | 一个全序集合上的元素 |
| 输出 | 一个线性扩展，可能不唯一 | 唯一的非降序列（元素可重复时也唯一） |
| 比较次数 | 不需要两两比较，只看边 | 下界 `Ω(n log n)` |
| 判失败 | 有环 ⇒ 无解 | 不会失败 |

| 对比 | Kahn（入度 + 队列） | DFS 后序逆序 |
| --- | --- | --- |
| 环检测判据 | 输出数 `< n` | 遇到灰色顶点（回边） |
| 环的信息量 | 只知道有环，剩下一堆顶点 | 能指出环上的具体一段 |
| 实现方式 | 迭代，无递归 | 递归（或显式栈） |
| 空间风险 | 队列 `Θ(V)`，无爆栈风险 | 递归深度可达 `V` |
| 附加能力 | 天然分层、可判唯一、可换优先队列 | 同时得到完成时间，是 SCC 算法的基础 |
| 对入度的依赖 | 需要入度表且会破坏它 | 不需要入度 |

| 对比 | 偏序（partial order） | 全序（total order） |
| --- | --- | --- |
| 可比性 | 允许两个元素不可比 | 任意两个元素可比 |
| 图论对应 | DAG 的可达关系 | 一条有向路径（链） |
| 拓扑序 | 把偏序扩展成全序，通常多解 | 自身就是唯一的「序」 |
| 例子 | 课程先修关系 | 整数上的 `≤` |

| 对比 | 拓扑序 | BFS/DFS 遍历序 |
| --- | --- | --- |
| 保证 | 每条边 `u→v` 满足 `u` 在 `v` 前 | 无此保证 |
| 依赖 | 需要无环 | 任意图 |
| 用途 | 调度、依赖求值 | 连通性、可达性、最短路（无权） |

## 和已有知识的连接

- [[15-122-22-Graph-Search]] 提供 DFS/BFS 的骨架与「访问标记」这套写法。拓扑排序的 DFS 版本几乎就是在这套骨架上加一个 `post` 数组和颜色判断；差别在于**完成的时机**才是信息所在，而普通遍历只关心「访问过没有」。
- [[15-122-21-Graph-Representation]] 决定了复杂度里的 `E` 是什么。邻接表下每条边只被扫一次，得到 `Θ(V+E)`；若用邻接矩阵，出队一个顶点要扫整行 `V` 个格子，总时间退化成 `Θ(V²)`，在稀疏图上差距是数量级的。同时，建入度表时邻接矩阵也要 `Θ(V²)`。
- [[15-122-09-Stacks-and-Queues]] 是 Kahn 的容器来源。把 FIFO 队列换成栈，得到的仍是合法拓扑序，只是顺序不同（更像 DFS 的风格）；换成最小堆，就得到**字典序最小**的拓扑序，代价升到 `O((V+E) log V)`。容器选择直接改变了输出的性质。
- [[15-122-11-Unbounded-Arrays]] 的摊还分析解释了为什么队列操作可以按 `O(1)` 计入：用可增长数组实现队列，扩容是偶发的 `Θ(n)`，摊还到每次入队仍是 `O(1)`。Kahn 总共有 `V` 次入队，所以容器部分总共 `Θ(V)`。
- [[15-122-24-Union-Find]] 也做环检测，但**只适用于无向图**：无向图有环 ⇔ 某条边的两个端点已属于同一连通分量。有向图不行——`a→b` 和 `a→b` 的两条不同路径方向不同，并查集会把它误判成环，或者漏掉真正的有向环。这是最常被搞混的一处，判断依据是「环是否有方向」。
- [[15-122-05-Big-O]] 提供 `Θ(V+E)` 的写法与紧界概念。这里值得强调：`Θ(V+E)` 不是「两个复杂度相加」的凑数，而是因为**顶点和边是两类独立的输入规模**，必须同时出现在界里。
- [[15-122-25-Priority-Queues]] 连接两处：Dijkstra 用堆在一般图上做最短路，而 DAG 上按拓扑序松弛可以完全不用堆；反过来，把 Kahn 的队列换成堆，就用堆换到了字典序最小的拓扑序。同一个数据结构在两种算法里扮演的角色不同。
- [[15-122-07-Quicksort]] 是对照组：比较排序把「全序」当作输入前提，拓扑排序恰恰是在**缺少全序**时造一个出来。两者的输出都叫「排好序」，但一个受 `Ω(n log n)` 下界约束，一个只受 `Ω(V+E)` 约束，因为拓扑排序不要求比较任意两个元素。
- [[15-445-11-Sorting-and-Aggregation]] 里的外部排序同样在「建立顺序」，但它的约束是 I/O 次数和内存，顺序来自键值比较；拓扑排序的约束来自依赖关系。两者可以组合：聚合前需要按 group key 排序，而查询计划的算子本身要先按依赖拓扑排序才能执行。
- [[15-445-17-Query-Optimization-II]] 的连接点是「算子 DAG」。查询计划是一棵（或一张）算子图，执行顺序必须满足数据依赖；连接顺序的枚举用 DP，而一旦计划确定，物理执行就是按拓扑序推进。这就是「先线性化、再逐个求值」的同一套思路。
- [[15-122-13-Hash-Dictionaries]] 用得上：当顶点标签是稀疏的字符串（如包名、单元格坐标）而不是 `0..n-1` 的整数时，入度表就得用哈希字典，`Θ(1)` 期望查询，但常数和内存都变大。这也是「图必须先做一次编号映射」的原因。
- [[15-122-10-Linked-Lists]] 解释了邻接表的形状：数组套链表，`Adj[u]` 的遍历代价与 `u` 的出度成正比，这正是「每条边扫一次」的结构基础。

   与 FIFO 结果 `1,2,3,4,5,6,8,7` 的差异来自「同层顶点」的弹出次序：3 比 2 先出，导致 5 被提前处理、4 被压到 5 之后。关键观察是 6 **始终排在 4 和 5 之后**，因为 6 的入度必须等 4、5 都处理完才降到 0——容器只改变同层元素的相对顺序，不改变「入度归零才可输出」这个必要条件。所以两个序列都合法，但都不唯一。
2. 设边 `u→v`。DFS 从 `u` 开始时，`v` 有三种状态：白色——`v` 会在 `u` 的递归里被访问，作为 `u` 的后代先完成，故 `finish(v) < finish(u)`；灰色——`v` 在栈上，说明存在 `v ⇝ u` 的路径，加上 `u→v` 构成环，DAG 中不可能；黑色——`v` 早已完成，`finish(v) < finish(u)`。所以 DAG 中必有 `finish(u) > finish(v)`。按完成时间升序排列时 `v` 在前、`u` 在后；反转后 `u` 在前，正是拓扑序要求。有环时「灰色」这一情形会出现，此时 `finish` 尚未赋值，`finish(u) > finish(v)` 不成立，论证断裂。
3. 入度：`a:2（来自 c,d）, b:1, c:1, d:0, e:1`。`Q=[d]`；出队 d，`a` 的入度 2→1，队列空。输出 1 个顶点 `< 5`，判有环。剩下的集合是 `{a,b,c,e}`。其中 `a,b,c` 在环 `a→b→c→a` 上；`e` 不在环上，它只是被 `c` 卡住（`c` 永远不会被输出，所以 `e` 的入度永远降不到 0）。精确判定用 SCC：对整图（或剩余子图）求强连通分量，`|SCC| > 1` 的分量是环；单点分量若有自环也算环。这里 `{a,b,c}` 是一个大小 3 的 SCC，`{d}`、`{e}` 是大小 1 且无自环，所以只有 `a,b,c` 在环上。
4. 正向：队列长度恒为 1 意味着每一步只有一个入度为 0 的顶点可选，选择被完全确定，序列唯一。反向：设某步队列里有 `u ≠ v`。两者入度均为 0，若存在边 `u→v`，则 `v` 的入度至少为 1（来自尚未输出的 `u`），矛盾；`v→u` 同理。所以 `u`、`v` 之间没有边，也没有任何路径（否则路径上的第一条边就构成上述矛盾），二者不可比。先输出 `u` 再输出 `v`、与先输出 `v` 再输出 `u`，得到的两个序列都满足所有约束，故至少两个拓扑序。哈密顿路径的等价性：若唯一，相邻两项之间必须有边（否则可交换），这些边依次串起来就是哈密顿路径；若存在哈密顿路径 `v1→v2→…→vn`，则 `vi` 必须先于 `v(i+1)`，归纳得唯一。
5. 邻接矩阵下，初始化入度表要扫描整个矩阵 `Θ(V²)`；出队每个顶点时扫描一整行 `Θ(V)`，共 `V` 个顶点，`Θ(V²)`；总计 `Θ(V²)`。这与邻接表的 `Θ(V+E)` 在稀疏图（`E = O(V)`）上差一个 `V` 的因子。用最小堆维护「当前入度为 0 的顶点集合」：每次取最小是 `O(log V)`，每次入度归零时插入是 `O(log V)`，共 `V` 次，所以堆操作总计 `O(V log V)`；加上扫边的 `Θ(E)`，总计 `O(V log V + E)`。它比 `Θ(V+E)` 多一个对数，换来的是「字典序最小」这一额外性质——普通 Kahn 只保证合法，不保证最小。
6. `l[1]=0`；处理 1：`l[2]=3`，`l[3]=2`；处理 2：`l[4]=3+4=7`，`l[5]=3+1=4`；处理 3：`l[5]=max(4, 2+2)=4`（相等，不变）；处理 4：`l[6]=7+2=9`；处理 5：`l[6]=max(9, 4+3)=7`→仍取 9，`l[8]=4+5=9`；处理 6：`l[7]=9+1=10`；处理 8、7：无出边。最长路长度 10，关键路径 `1→2→4→6→7`，校验 `3+4+2+1=10`。一般图上的最长路等价于「是否存在长度 ≥ k 的简单路径」，含哈密顿路径作为特例，是 NP-hard；DAG 上不存在「走回头路」的可能，按拓扑序做一次 DP 就覆盖了所有路径，所以是 `Θ(V+E)`。
