# 软件工程 · 领域总览

> **一句话**：多人长期维护的代码，如何不腐化。

## 这个领域回答的问题

- 如何设计一个三个月后还看得懂的结构？
- 测试要写到什么程度才够？
- 如何安全地改一段不熟悉的代码？

## 边界：它不负责什么

不教具体语言语法；不替代项目管理与组织行为学。

## 前置与后继

| | |
| --- | --- |
| **学之前最好已掌握** | 20 编程基础、至少一个完整项目的经验 |
| **学完之后支撑** | 100 前端开发、110 后端开发、150 系统架构 |

## 学完应该能做到

1. 用本领域的术语准确描述一个具体问题，而不是用「感觉慢」「好像有问题」。
2. 拿到一个陌生系统，能判断它在本领域的哪一层、瓶颈可能在哪里。
3. 读得懂本领域的经典教材章节与官方文档，不需要先看二手解读。
