## 一、先决条件表

| 想学 | 必须先会 | 否则会出现的问题 |

| 数据结构与算法 | 编程基础（函数、递归、指针/引用） | 看得懂伪代码，写不出能编译的代码 |

| 前端开发 | 编程基础 + 计算机网络（HTTP） | 只会调框架 API，不会排查白屏 |
| 后端开发 | 操作系统 + 网络 + 数据库 | 写出的接口在并发下静默出错 |
| 软件安全 | 组成 + 操作系统 + 网络 | 只能照着靶场步骤复现，不能自己发现 |

| 分布式系统 | 操作系统 + 网络 + 数据库 | 把 CAP 当口号 |
| 系统架构 | 前面 12 个领域各至少一门课 | 用名词替代权衡 |

## 三、每门课的标准动作

学一门课不要只看视频。固定五步：

1. **读课程页**：拿到 syllabus、lecture 列表、作业列表，先看作业——作业决定这门课真正教什么。
2. **看讲义而非视频**：视频慢，讲义可跳读；视频只在卡住时回看某一段。
3. **做作业，不做"看作业"**：至少完成官方作业的前 60%。不做作业的课等于没上。
4. **写一篇中文笔记**：按 [note-template-spec](../99-学习记录/维护脚本/note-template-spec.md) 的结构，重点是「我原来错在哪」。
5. **回填知识点清单**：把 `01-知识点目录.md` 里对应条目打勾，未打勾的写一行「为什么还没懂」。

## 四、常见误区

| 误区 | 后果 | 纠正 |
| --- | --- | --- |
| 先学"架构"再学系统课 | 只会画框图，答不出"为什么选它" | 架构放最后，用项目倒逼 |
| 收集 200 门课再开始 | 资料收集替代了学习 | 每个领域只认 1 门主课 + 1 门备选 |
| 只看视频不做作业 | 产生"我会了"的错觉 | 作业完成率 < 50% 不算学完 |
| 跳过数学直接学 ML | 只能调包，读不懂论文 | 线代 + 概率必须先过 |
| 同时开 4 门课 | 每门都停在第二章 | 同一时间最多 2 门（1 门主 + 1 门轻） |
| 笔记抄讲义 | 复习时等于重读讲义 | 笔记只写「推导过程 + 我的错误」 |

## 五、每周节奏建议

| 时段 | 内容 |
| --- | --- |
| 工作日 2×1.5h | 主课：看讲义 + 做作业 |
| 工作日 3×0.5h | 轻任务：背术语、读一篇文档、整理笔记 |
| 周末 1×3h | 项目 / 实验（必须产出可运行的东西） |
| 周末 1×1h | 复盘：更新知识点清单与 `99-学习记录/00-学习日志.md` |

> 连续两周没有产出可运行的东西，说明当前阶段选错了——要么课太难，要么在逃避作业。
