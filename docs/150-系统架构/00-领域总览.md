# 系统架构 · 领域总览

> **一句话**：在约束下做技术选型与权衡——它不引入新知识，只做取舍。

## 这个领域回答的问题

- 这个设计牺牲了什么换来了什么？
- 流量涨十倍，哪一层先断？
- 什么时候不该上微服务？

## 边界：它不负责什么

不提供「正确答案」；不替代具体领域的实现能力。没有 50/60/70/110/140 的基础，本领域只会剩下名词。

## 前置与后继

| | |
| --- | --- |
| **学之前最好已掌握** | 50 操作系统、60 计算机网络、70 数据库、110 后端开发、140 分布式系统 |
| **学完之后支撑** | （汇聚层，无后继） |

## 学完应该能做到

1. 用本领域的术语准确描述一个具体问题，而不是用「感觉慢」「好像有问题」。
2. 拿到一个陌生系统，能判断它在本领域的哪一层、瓶颈可能在哪里。
3. 读得懂本领域的经典教材章节与官方文档，不需要先看二手解读。
