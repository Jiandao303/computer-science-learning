# 08 编译与链接

> 对应模块 08。**「能编译」和「理解编译过程」是两件事。** 前者按回车就行；后者决定了你能不能读懂 `undefined reference`、重复定义、头文件循环包含这类报错。

## 学习目标

1. 说清从 `.c` 到可执行文件经过的四个阶段，以及每个阶段的产物。
2. 正确使用头文件：声明放头文件、定义放源文件、加包含保护。
3. 用 `gcc` 分步编译，理解 `-c`、`-o`、`-I`、`-L`、`-l`。
4. 读懂并修复 `undefined reference` 与 `multiple definition`。
5. 写一个可用的 `Makefile`。

## 前置知识

- [01-基础语法](01-基础语法.md)：声明与定义。
- 能在命令行运行 `gcc`。

## 核心概念

### 1. 四个阶段

```text
hello.c
  │  预处理（preprocessing）  gcc -E
  ▼
hello.i   展开 #include、#define、条件编译
  │  编译（compilation）       gcc -S
  ▼
hello.s   汇编代码（文本）
  │  汇编（assembly）          gcc -c
  ▼
hello.o   目标文件（机器码 + 符号表）
  │  链接（linking）           gcc
  ▼
hello     可执行文件
```

| 阶段 | 命令 | 输入 | 输出 | 做什么 |
| --- | --- | --- | --- | --- |
| 预处理 | `gcc -E` | `.c` | `.i` | 展开宏、插入头文件、删注释 |
| 编译 | `gcc -S` | `.i` | `.s` | 生成汇编 |
| 汇编 | `gcc -c` | `.s` | `.o` | 汇编成机器码，生成符号表 |
| 链接 | `gcc` | `.o` + 库 | 可执行文件 | 解析符号、重定位 |

### 2. 预处理

```c
#include <stdio.h>        /* 系统头文件，从系统目录找 */
#include "myheader.h"     /* 本地头文件，先从当前目录找 */
#define MAX(a, b) ((a) > (b) ? (a) : (b))
#ifdef DEBUG
  printf("debug\n");
#endif
```

**宏的陷阱**：

```c
#define SQUARE(x) x * x
SQUARE(1 + 2)      /* 展开为 1 + 2 * 1 + 2 = 5，不是 9 */
#define SQUARE(x) ((x) * (x))   /* 正确：每个参数和整体都加括号 */
```

### 3. 声明与定义

| | 放哪里 | 例子 |
| --- | --- | --- |
| 函数声明 | 头文件 | `int add(int, int);` |
| 函数定义 | `.c` 文件 | `int add(int a, int b) { return a + b; }` |
| 类型定义 | 头文件 | `typedef struct {...} Node;` |
| 全局变量声明 | 头文件（加 `extern`） | `extern int counter;` |
| 全局变量定义 | 一个 `.c` 文件 | `int counter = 0;` |

**规则**：头文件里只放**声明**（`extern`、函数原型、类型、宏）；定义放 `.c`。头文件被多个 `.c` 包含时，定义会导致重复定义。

### 4. 头文件包含保护

```c
#ifndef MYHEADER_H
#define MYHEADER_H

/* 内容 */

#endif /* MYHEADER_H */
```

或（所有主流编译器都支持）：

```c
#pragma once
```

**为什么需要**：同一个头文件被间接包含两次时，类型定义会重复，编译器报错。

### 5. 链接：解析符号

链接器把所有 `.o` 的**符号表**合在一起：

| 符号 | 含义 |
| --- | --- |
| 已定义（defined） | 这个 `.o` 里有函数体或变量 |
| 未定义（undefined） | 这个 `.o` 用了，但没定义，需要别的 `.o` 或库提供 |

**两类典型错误**：

```text
undefined reference to `add'
  → 声明了、调用了，但没有把定义所在的 .o 或库传给链接器

multiple definition of `counter'
  → 在头文件里定义了变量，被多个 .c 包含
```

### 6. 静态库与动态库

| 类型 | 扩展名 | 链接时机 | 特点 |
| --- | --- | --- | --- |
| 静态库 | `.a` | 编译时复制进可执行文件 | 体积大、部署简单 |
| 动态库 | `.so` | 运行时加载 | 体积小、需带库文件 |

```bash
# 静态库
gcc -c util.c -o util.o
ar rcs libutil.a util.o
gcc main.c -L. -lutil -o main

# 动态库
gcc -shared -fPIC util.c -o libutil.so
gcc main.c -L. -lutil -o main
```

`-L` 指定库目录，`-l` 指定库名（`libutil.a` → `-lutil`）。

### 7. `gcc` 常用参数

| 参数 | 作用 |
| --- | --- |
| `-std=c11` | 指定标准 |
| `-Wall -Wextra -Wpedantic` | 打开常用警告 |
| `-Werror` | 警告当错误 |
| `-g` | 生成调试信息（GDB 需要） |
| `-O0` / `-O2` | 优化级别 |
| `-I dir` | 头文件搜索路径 |
| `-L dir` | 库搜索路径 |
| `-l name` | 链接库 |
| `-c` | 只编译不链接 |
| `-o file` | 输出文件名 |
| `-DNAME=value` | 定义宏 |
| `-fsanitize=address` | 启用 AddressSanitizer |

**本库固定使用**：

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0 file.c -o file
```

### 8. Makefile

```makefile
CC      = gcc
CFLAGS  = -std=c11 -Wall -Wextra -Wpedantic -g -O0
TARGET  = app
OBJS    = main.o util.o

$(TARGET): $(OBJS)
	$(CC) $(CFLAGS) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) $(TARGET)

.PHONY: clean
```

**注意**：命令行缩进必须是 **Tab**，不是空格。

## 英文术语与中文解释

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| preprocessing | 预处理 | 展开宏与头文件 |
| compilation | 编译 | 源码 → 汇编 |
| assembly | 汇编 | 汇编 → 机器码 |
| linking | 链接 | 合并目标文件、解析符号 |
| translation unit | 编译单元 | 一个 `.c` 预处理后的全部内容 |
| include guard | 包含保护 | 防止头文件重复包含 |
| symbol table | 符号表 | 记录定义与未定义符号 |
| static library | 静态库 | `.a`，编译时复制 |
| shared library | 动态库 | `.so`，运行时加载 |

## 通俗类比

- **编译** = 把每个章节分别翻译成另一种语言（每个 `.c` 独立翻译）。
- **链接** = 把各章拼成一本书，并把「见第 3 页」这类交叉引用全部填上。链接器报 `undefined reference`，就是「书里引用了第 3 页，但根本没印第 3 页」。

## 原理讲解

### `undefined reference` 的完整排查顺序

1. **函数声明了吗？** 没有声明，编译阶段就报错（不是链接错误）。
2. **函数定义在哪个 `.o`？** 用 `nm` 查看：

```bash
nm -C main.o | grep add      # U add 表示未定义
nm -C util.o | grep add      # T add 表示已定义
```

3. **那个 `.o` 传进链接命令了吗？**
4. **如果是库**：`-l` 的顺序对吗？（链接器从左到右扫描，库要放在使用它的 `.o` 之后。）

### 为什么头文件里不能定义变量

```c
/* bad.h */
int counter = 0;      /* 定义 */
```

被 `a.c` 和 `b.c` 同时包含时，两个 `.o` 里都有 `counter` 的定义，链接器报 `multiple definition`。

正确写法：

```c
/* good.h */
extern int counter;   /* 声明 */

/* counter.c */
int counter = 0;      /* 定义，只有一处 */
```

### `-O2` 与未定义行为

优化器会**利用 UB 做假设**。例如有符号溢出是 UB，`-O2` 可能假设它不发生，把 `if (x + 1 < x)` 优化成 `false`。这就是「UB 的代码在 `-O0` 能跑、`-O2` 崩溃」的原因。

**调试用 `-O0`，发布用 `-O2`，并且保证代码无 UB。**

## 内存示意图

```text
链接前：
main.o:  [ main (T) ] [ add (U) ] [ printf (U) ]
util.o:  [ add  (T) ]

链接后（可执行文件）：
+-------------------+
| .text             |
|   main            |
|   add             |   <- 从 util.o 合并
+-------------------+
| .data / .bss      |
+-------------------+
| 动态链接信息       |   <- printf 来自 libc.so
+-------------------+
```

`T` = 已定义（text），`U` = 未定义（undefined）。

## 代码示例

```c
/* ---- util.h ---- */
#ifndef UTIL_H
#define UTIL_H

#include <stddef.h>

int add(int a, int b);
int sum_array(const int *arr, size_t n);

#endif /* UTIL_H */
```

```c
/* ---- util.c ---- */
#include "util.h"

int add(int a, int b) { return a + b; }

int sum_array(const int *arr, size_t n) {
    int s = 0;
    for (size_t i = 0; i < n; i++) s += arr[i];
    return s;
}
```

```c
/* ---- main.c ---- */
#include <stdio.h>
#include "util.h"

int main(void) {
    int a[] = {1, 2, 3, 4};
    printf("add(2,3) = %d\n", add(2, 3));
    printf("sum = %d\n", sum_array(a, 4));
    return 0;
}
```

```makefile
CC      = gcc
CFLAGS  = -std=c11 -Wall -Wextra -Wpedantic -g -O0
TARGET  = app
OBJS    = main.o util.o

$(TARGET): $(OBJS)
	$(CC) $(CFLAGS) -o $@ $^

%.o: %.c util.h
	$(CC) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) $(TARGET)

.PHONY: clean
```

## 逐行代码解释

| 行 | 说明 |
| --- | --- |
| `#ifndef UTIL_H` | 包含保护：第一次包含时 `UTIL_H` 未定义，进入 |
| `#define UTIL_H` | 定义标记，第二次包含时直接跳过 |
| `#include "util.h"` | 本地头文件用双引号 |
| `-o $@ $^` | `$@` 是目标名，`$^` 是所有依赖 |
| `%.o: %.c util.h` | 头文件变化时重新编译所有 `.o` |
| `.PHONY: clean` | `clean` 不是真实文件，避免同名文件干扰 |

## 常见错误

| 错误 | 报错 | 修复 |
| --- | --- | --- |
| 头文件里定义变量 | `multiple definition of 'x'` | 改 `extern`，定义移到 `.c` |
| 忘记包含保护 | `redefinition of 'struct x'` | 加 `#ifndef` 或 `#pragma once` |
| 忘记把 `.o` 传给链接器 | `undefined reference to 'f'` | 补上 `util.o` |
| `-l` 顺序错误 | `undefined reference` | 库放在使用它的 `.o` 之后 |
| Makefile 用空格缩进 | `missing separator` | 改用 Tab |
| 宏参数不加括号 | 运算优先级错误 | `((x) * (x))` |
| `#include` 写成 `<myheader.h>` | 找不到本地头文件 | 本地用 `"..."` |

## 边界情况

- **同一函数声明多次**：合法；定义多次：链接错误。
- **`static` 函数**：内部链接，每个 `.c` 可以有同名 `static` 函数。
- **`inline`**：C99 语义复杂，头文件里用 `static inline` 最安全。
- **`-O2` 下调试**：变量可能被优化掉，调试用 `-O0`。
- **`nm` 的输出**：`T` 已定义、`U` 未定义、`t` 局部、`D` 已初始化数据、`B` 未初始化数据。

## 本节总结

- 四阶段：预处理 → 编译 → 汇编 → 链接。
- 头文件放声明，`.c` 放定义；头文件必须加包含保护。
- `undefined reference` 是「符号没找到」，`multiple definition` 是「定义重复」。
- `gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0` 是本库固定参数。
