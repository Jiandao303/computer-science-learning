# 05 内存管理

> **本模块是最高优先级。** 15-213 的 `malloclab` 就是让你自己写一个 `malloc`。不把「栈 / 堆 / 生命周期」想清楚，后面所有系统课内容都只能背。

## 学习目标

1. 画出进程的完整内存布局，并指出任意变量落在哪一段。
2. 说清栈帧的建立与销毁，解释为什么不能返回局部变量的地址。
3. 正确使用 `malloc` / `calloc` / `realloc` / `free`，包括失败处理。
4. 识别并修复：内存泄漏、重复释放（double free）、释放后使用（use-after-free）、越界写。
5. 说清「谁负责释放」这一所有权问题。

## 核心概念

### 1. 进程内存布局

```text
高地址
+---------------------------+
| 环境变量 / 命令行参数        |  env, argv
+---------------------------+
| 栈 stack                   |  局部变量、返回地址，向低地址增长
|   ↓                        |
+---------------------------+
|                            |
|   （未映射的空隙）           |
|                            |
+---------------------------+
|   ↑                        |
| 堆 heap                    |  malloc 出来的内存，向高地址增长
+---------------------------+
| .bss                       |  未初始化的全局/静态变量（运行时清零）
+---------------------------+
| .data                      |  已初始化的全局/静态变量
+---------------------------+
| .rodata                    |  只读数据：字符串字面量、const 全局
+---------------------------+
| .text                      |  机器码
+---------------------------+
低地址
```

| 段 | 内容 | 生命周期 | 谁释放 |
| --- | --- | --- | --- |
| `.text` | 机器码 | 进程全程 | 不需要 |
| `.rodata` | 字符串字面量 | 进程全程 | 不需要 |
| `.data` / `.bss` | 全局、静态变量 | 进程全程 | 不需要 |
| 栈 | 局部变量、参数 | 函数调用期间 | 函数返回自动回收 |
| 堆 | `malloc` 分配 | 从 `malloc` 到 `free` | **程序员** |

### 2. 栈：自动管理的代价

每次函数调用压入一个**栈帧**（stack frame），包含参数、返回地址、保存的寄存器、局部变量。函数返回时整帧弹出。

```c
int *bad(void) {
    int x = 42;
    return &x;      /* 返回后 x 所在的栈帧已失效 */
}
```

**这就是「不能返回局部变量地址」的全部原因**：不是语法禁止，而是那块内存已经不属于你。

栈的大小有限（Linux 默认约 8 MB），递归太深会**栈溢出**（stack overflow）。

### 3. 堆：手动管理的代价

`malloc` 向堆申请一块**未初始化**的内存；`free` 归还。堆由 `malloc` 实现自己管理（空闲链表、边界标记等），这正是 `malloclab` 的内容。

```c
int *p = malloc(10 * sizeof *p);
if (p == NULL) { /* 处理失败 */ }
/* 使用 p[0..9] */
free(p);
p = NULL;
```

### 4. 四个分配函数

| 函数 | 原型 | 初始化 | 用途 |
| --- | --- | --- | --- |
| `malloc` | `void *malloc(size_t n)` | ❌ 不初始化 | 通用 |
| `calloc` | `void *calloc(size_t n, size_t size)` | ✅ 清零 | 数组、需要零值 |
| `realloc` | `void *realloc(void *p, size_t n)` | 保留旧内容 | 扩容/缩容 |
| `free` | `void free(void *p)` | — | 归还 |

**`realloc` 的三个陷阱**：

1. 可能返回**新地址**，旧指针失效。
2. 失败返回 `NULL`，**原内存仍然有效**——不要直接覆盖原指针。
3. `realloc(p, 0)` 行为由实现定义（C23 起明确为释放）。

```c
int *tmp = realloc(p, new_n * sizeof *p);
if (tmp == NULL) {
    /* p 仍然有效，保留它并处理失败 */
} else {
    p = tmp;
}
```

### 5. `sizeof` 与 `size_t`

- `sizeof` 返回 `size_t`（无符号整数类型，`<stddef.h>`）。
- 分配时用 `n * sizeof *p` 而不是 `n * sizeof(int)`，改类型时不用改这里。
- **`n * sizeof *p` 可能溢出**：`n` 极大时乘积回绕，分配出过小的块。安全写法是先检查 `n > SIZE_MAX / sizeof *p`。

### 6. 四类内存错误

| 错误 | 英文 | 现象 | 检测 |
| --- | --- | --- | --- |
| 内存泄漏 | memory leak | 程序占用持续增长 | Valgrind `definitely lost` |
| 重复释放 | double free | 堆结构损坏、崩溃 | Valgrind / ASan |
| 释放后使用 | use-after-free | 随机崩溃或数据错乱 | ASan / Valgrind |
| 越界写 | buffer overflow | 破坏相邻内存 | ASan / Valgrind |

```c
/* 四类错误的完整示例 */
int *leak(void) { return malloc(10 * sizeof(int)); }        /* 泄漏：没人 free */

void double_free(void) {
    int *p = malloc(sizeof *p);
    free(p);
    free(p);                    /* 重复释放 */
}

void uaf(void) {
    int *p = malloc(sizeof *p);
    free(p);
    *p = 1;                     /* 释放后使用 */
}

void overflow(void) {
    int *p = malloc(4 * sizeof *p);
    p[4] = 1;                   /* 越界写（合法下标是 0..3） */
    free(p);
}
```

### 7. 所有权（ownership）

**核心问题：这块内存归谁释放？**

| 模式 | 规则 | 例子 |
| --- | --- | --- |
| 调用者分配，调用者释放 | 最常见 | `char buf[64]; f(buf, sizeof buf);` |
| 函数分配，返回给调用者 | 文档必须写明「调用者负责 `free`」 | `char *s = make_copy(...)` |
| 函数接管所有权 | 文档必须写明「传入后不得再使用」 | `void list_push(Node *n)` |

**没有所有权约定的代码，必然泄漏或重复释放。** 写函数时第一件事就是确定这条。

## 英文术语与中文解释

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| memory layout | 内存布局 | 进程地址空间的各段划分 |
| stack frame | 栈帧 | 一次函数调用的栈上空间 |
| heap | 堆 | `malloc` 管理的内存区 |
| memory leak | 内存泄漏 | 分配后未释放，且已失去引用 |
| double free | 重复释放 | 对同一指针 `free` 两次 |
| use-after-free | 释放后使用 | 访问已 `free` 的内存 |
| buffer overflow | 缓冲区溢出 | 写入超出分配大小 |
| ownership | 所有权 | 谁负责释放这块内存 |
| alignment | 对齐 | `malloc` 返回的地址满足最大对齐要求 |

## 通俗类比

- **栈** = 餐厅的托盘架：进来放一个托盘，走时拿走，自动管理。
- **堆** = 仓库：你去申请一个储物格（`malloc`），用完必须自己去退（`free`）；不退就一直占着（泄漏），退两次就乱套（double free）。

## 原理讲解

### `malloc` 做了什么（简化）

1. 在堆的空闲链表里找一块**足够大**的空闲块。
2. 如果太大，切分成「分配块 + 剩余空闲块」。
3. 返回指向**数据区**的指针（块头在前面，存大小等信息）。
4. 返回的地址满足 16 字节对齐（x86-64）。

```text
malloc 返回的块：
+----------+---------------------------+
| 块头      | 数据区（返回给用户的指针）  |
| size/flags|                           |
+----------+---------------------------+
            ^
            malloc 的返回值
```

`free` 只知道数据区地址，通过**块头**反推整块的大小与位置。

### 为什么 `free` 后要置 `NULL`

```c
free(p);
p = NULL;
```

`free` 不会改 `p` 的值（C 是值传递），`p` 变成**悬空指针**。置 `NULL` 后，再解引用会立刻崩溃（易发现），而不是静默破坏内存（难发现）。

### `realloc` 可能搬家

```text
realloc 前：
[ 旧块 4 字节 ]

realloc 到 8 字节：
情况 A（原地扩容）：[ 旧块 4 | 新 4 ]          返回旧地址
情况 B（搬家）：     [ 旧块 4 ] ... [ 新块 8 ]  返回新地址，旧块被 free
```

**所以不能写 `p = realloc(p, n)`**：失败时 `p` 被覆盖成 `NULL`，原内存就泄漏了。

## 内存示意图

### 栈与堆的对比

```c
void f(void) {
    int local = 1;              /* 栈 */
    int *heap = malloc(4);      /* 堆 */
    *heap = 2;
    free(heap);
}
```

```text
高地址
+-----------------------+
| 栈帧 f                |
|   local = 1           |
|   heap = 0x55a0...    |----+
+-----------------------+    |
|         ...           |    |
+-----------------------+    |
| 堆：0x55a0... [ 2 ]   |<---+
+-----------------------+
低地址
```

`local` 随函数返回消失；堆上的块要等 `free` 才归还。

### 链表的所有权

```c
Node *head = NULL;
push_front(&head, 1);   /* 节点由 push_front 分配 */
/* ... */
free_list(head);        /* 由调用者统一释放整条链 */
```

**约定**：`push_front` 分配并移交所有权给链表；`free_list` 负责释放所有节点。只要所有代码遵守这条，就不会泄漏。

## 代码示例

```c
/* day05_dynamic_array.c —— 一个可增长的动态数组 */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

typedef struct {
    int *data;
    size_t len;
    size_t cap;
} IntVec;

static int vec_push(IntVec *v, int value) {
    if (v->len == v->cap) {
        size_t new_cap = (v->cap == 0) ? 4 : v->cap * 2;
        if (new_cap > SIZE_MAX / sizeof *v->data) return 0;   /* 溢出检查 */
        int *tmp = realloc(v->data, new_cap * sizeof *v->data);
        if (tmp == NULL) return 0;                            /* 保留旧指针 */
        v->data = tmp;
        v->cap = new_cap;
    }
    v->data[v->len++] = value;
    return 1;
}

static void vec_free(IntVec *v) {
    free(v->data);
    v->data = NULL;
    v->len = v->cap = 0;
}

int main(void) {
    IntVec v = {0};
    for (int i = 0; i < 10; i++) {
        if (!vec_push(&v, i * i)) {
            fprintf(stderr, "push failed\n");
            vec_free(&v);
            return 1;
        }
    }
    for (size_t i = 0; i < v.len; i++) printf("%d ", v.data[i]);
    printf("\nlen=%zu cap=%zu\n", v.len, v.cap);
    vec_free(&v);
    return 0;
}
```

## 逐行代码解释

| 行 | 说明 |
| --- | --- |
| `size_t len, cap` | 当前长度与容量，容量不够才扩容 |
| `new_cap > SIZE_MAX / sizeof *v->data` | 防止 `new_cap * sizeof` 溢出 |
| `realloc` 结果先存 `tmp` | 失败时不能丢掉原指针 |
| `v->data = tmp` | 成功后才替换 |
| `vec_free` 里置 `NULL` | 避免重复释放 |
| `fprintf(stderr, ...)` | 错误信息写 stderr，不混进正常输出 |

## 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| `p = realloc(p, n)` | 失败时原内存泄漏 | 先存 `tmp` |
| 不检查 `malloc` 返回 | 空指针解引用 | 每个分配都检查 |
| `free` 后继续用 | use-after-free | 置 `NULL`，重构逻辑 |
| 忘记 `free` | 内存泄漏 | 每个 `malloc` 配一个 `free` |
| `malloc(n * sizeof(int))` 溢出 | 分配过小，越界写 | 检查 `n > SIZE_MAX / sizeof *p` |
| 返回局部数组地址 | 栈帧失效 | 用堆分配或让调用者传缓冲区 |
| 释放后不置 `NULL` | 误用悬空指针 | `free(p); p = NULL;` |

## 边界情况

- **`malloc(0)`**：允许，返回 `NULL` 或一个可 `free` 的指针，**行为由实现定义**。
- **`free(NULL)`**：合法，什么也不做。
- **重复 `free(NULL)`**：也合法。
- **`realloc(NULL, n)`**：等价于 `malloc(n)`。
- **`realloc(p, 0)`**：实现定义（C23 明确释放）。
- **对齐**：`malloc` 返回的地址满足 `max_align_t` 对齐要求。

## 本节总结

- 栈自动管理，堆手动管理；**堆的所有权必须明确**。
- `malloc` 不初始化，`calloc` 清零，`realloc` 可能搬家。
- 四类内存错误：泄漏、double free、use-after-free、越界。
- `realloc` 必须用临时变量接收；分配必须检查失败与溢出。
