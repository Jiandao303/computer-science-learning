## 一、复盘目标

L01 是整门课的方法论底座。它的四道习题不是「练习题」，而是**四个必须内化的动作**：

| 习题 | 训练的能力 | 一句话概括 |
|---|---|---|
| Ex1 | **反驳** | 给定一个不变式，找出让它在初始化或保持时失败的具体输入 |
| Ex2 | **构造** | 给定一段没有契约的代码，反推它算什么，并写出能证明它的契约 |
| Ex3 | **完整证明** | 对一个简单算法走完 INIT / PRES / EXIT / TERM 四步 |
| Ex4 | **证明含函数调用的代码** | 额外多一步「调用安全性」，并处理规格函数（specification function） |

四道题合起来，就是「读代码 → 写规格 → 证正确」的完整闭环。**这个闭环在后面 25 讲里会重复出现几十次**，只是被证明的对象从「整数幂」换成了「BST 插入」「AVL 旋转」「堆的 sift down」。

## 二、先记住这个模板

后面所有证明题都用同一套骨架。**把这张表背下来**，比记住任何具体证明都有用。

| 步骤 | 要证什么 | 已知什么 |
|---|---|---|
| **SAFE** | 每次函数调用都满足被调函数的前置条件 | 当前已建立的断言 + 不变式 |
| **INIT** | 不变式在**第一次**检查循环条件之前成立 | 前置条件 + 进入循环前的赋值 |
| **PRES** | 假设不变式在本次迭代开始时成立，证明它在本次迭代结束时仍成立 | 不变式 + 循环条件为真 + 循环体赋值 |
| **EXIT** | 不变式 + 循环条件为假 ⇒ 后置条件 | 不变式 + `!(guard)` |
| **TERM** | 存在一个表达式，每轮严格单调、有下界（或上界），且触界时循环条件为假 | 循环条件为真 |

### 2.1 证明的书写格式

讲义用的是一种**逐行编号的推导格式**，每行是「结论 + 依据」：

```
A. a > 0 && b > 0          by line 2 (precondition)
B. a >= 1 && b >= 1        by math on A
C. d == min(a,b)           by line 6
D. min(a,b) >= 1           by math on B and C
```

**规则**：

- 每行只写一个事实，右边必须注明来源。
- 来源只有四类：`by line N`（代码行的赋值或判断）、`by line N (precondition)`、`by assumption`（本次迭代开始时的不变式）、`by math on X and Y`（前几行的逻辑/算术推论）。
- **不允许**写「显然」「易得」。如果一行推不出来，说明你缺一个不变式或一个中间结论。

### 2.2 带撇号（prime）的约定

`x'` 表示「本次迭代**结束后** x 的值」。这条约定解决了「数学里没有赋值」的问题：

- 要证 `x*y` 是不变式，不能写 `x*y = x*y`（恒真，无意义）。
- 要写 `x^y = x'^y'`，其中 `x' = x*x`、`y' = y/2` 由循环体给出。

**这是 L01 最重要的技术细节**。后面所有 PRES 步骤都靠它。

## 三、Ex1：找一个反例

### 3.1 题目（p33）

L01 §3 讨论了函数 `f` 的循环不变式。第一版猜测是：

```c0
//@loop_invariant POW(b,e) == POW(x,y);
```

请找出一个输入 `f(x, y)`，使这个不变式在**初始化**时就不成立。

（注：讲义在 §3 讨论时用的是 `x`、`y` 直接作为循环变量；后来因为后置条件引用了 `x`、`y`，才引入辅助变量 `b`、`e`。这里的不变式写的是 `b`、`e` 版本。）

### 3.2 思路

INIT 要证的是：**进入循环前**，`POW(b, e) == POW(x, y)` 成立。而进入循环前的赋值是：

```c0
int r = 1;
int b = x;
int e = y;
```

所以 INIT 要求的是：

```
POW(x, y) == POW(x, y)
```

这看起来恒真——**除非 `POW` 本身在某些输入上不终止或违反自己的前置条件**。

回到 `POW` 的定义（p13）：

```c0
int POW(int x, int y)
//@requires y >= 0;
{
  if (y == 0) return 1;
  else return x * POW(x, y-1);
}
```

它的前置条件是 `y >= 0`。如果 `y < 0`，`POW(x, y)` 会无限递归（`y` 每次减 1，永远不等于 0），或者更准确地说，**这个调用本身就是不安全的（unsafe）**。

### 3.3 答案

**`f(2, 7)` 不会失败**——这是讲义 sample solution 给的答案，但要注意它失败的原因和我们上面说的不完全一样。

让我把讲义 §3 的原始版本和 §7 的「反例」小节对齐来看。讲义 p36 的答案是一句话：

> **Solution of exercise 1**: A call that causes this loop invariant to fail is `f(2,7)`.

为什么是 `f(2, 7)`？因为 `POW(b, e) == POW(x, y)` 这条不变式**在 `y` 不是 2 的幂时根本不成立**——但更关键的是：这条不变式在**保持（PRES）**时会失败，而 `f(2, 7)` 是最小的奇数指数例子。

让我们逐步验算 `f(2, 7)`：

| 迭代 | b | e | r | `POW(b,e)` | `POW(x,y)` = `POW(2,7)` |
|---|---|---|---|---|---|
| 0（进入前） | 2 | 7 | 1 | 128 | 128 |
| 1 | 4 | 3 | 2 | `POW(4,3)` = 64 | 128 |
| 2 | 16 | 1 | 8 | `POW(16,1)` = 16 | 128 |
| 退出 | 16 | 1 | 8 | 16 | 128 |

**迭代 1 结束时，`POW(b,e) = 64 ≠ 128`**，不变式被破坏。

### 3.4 为什么这条不变式错了

正确的第二版不变式是（p22）：

```c0
//@loop_invariant r * POW(b,e) == POW(x,y);
```

对比一下：

| 版本 | 不变式 | 为什么 |
|---|---|---|
| 错 | `POW(b,e) == POW(x,y)` | 忽略了 `r`。当 `e` 为奇数时，`r` 会乘上 `b`，而 `b` 同时被平方、`e` 被减半——**`b^e` 的「亏空」被记在 `r` 里**，所以必须把 `r` 乘回来 |
| 对 | `r * POW(b,e) == POW(x,y)` | 完整记录了「已经提出来的因子」 |

**验算正确版在 `f(2,7)` 上**：

| 迭代 | b | e | r | `r * POW(b,e)` | `POW(2,7)` |
|---|---|---|---|---|---|
| 0 | 2 | 7 | 1 | 1 × 128 = 128 | 128 |
| 1 | 4 | 3 | 2 | 2 × 64 = 128 | 128 |
| 2 | 16 | 1 | 8 | 8 × 16 = 128 | 128 |
| 退出 | 16 | 1 | 8 | 8 × 16 = 128 | 128 |

### 3.5 这道题的真正教训

**不变式必须是「循环变量的完整函数」**。写不变式时问自己：

> 「循环体改了哪些变量？这些变量的旧值信息，我全都保存下来了吗？」

`f` 的循环体改了 `b`、`e`、`r` 三个变量。只写 `b`、`e` 而漏掉 `r`，就是漏掉了三分之一的旧值信息。

**这个错误在后面反复出现**：

- L15：BST 的 `is_ordered` 只比较父子，漏掉了「整棵子树 vs 祖先」的信息 ⇒ p11 那个 `/* THIS CODE IS BUGGY */`。
- L26：`is_heap_except_up` 只写「除 x 外父子有序」，漏掉了「x 的孩子 vs x 的父」的信息 ⇒ 需要 `grandparent_check`。

**三处错误同构**：局部信息不足以重建全局性质。

## 四、Ex2：补全契约与不变式

### 4.1 题目（p33）

```c0
int foo(int x)
//@requires ___________;
//@ensures  ____________;
{
  int p = 0;
  for (int i = 0; i < x; i++)
  //@loop_invariant ____________;
  //@loop_invariant ____________;
  {
    p += POW(2, i);
  }
  return p;
}
```

要求：先跑几个输入猜出它算什么，然后填前置条件、后置条件、两条循环不变式。

### 4.2 思路第一步：猜它算什么

`p` 从 0 开始，每轮加上 `2^i`，`i` 从 0 到 `x-1`。所以：

```
p = 2^0 + 2^1 + ... + 2^(x-1)
```

这是等比数列求和。公式：

```
Σ_{i=0}^{x-1} 2^i = 2^x - 1
```

**验证**：

| x | 累加过程 | p | `2^x - 1` |
|---|---|---|---|
| 0 | 循环不进 | 0 | `2^0 - 1 = 0` ✓ |
| 1 | `p += 2^0` = 1 | 1 | `2^1 - 1 = 1` ✓ |
| 2 | `p += 1, 2` | 3 | `2^2 - 1 = 3` ✓ |
| 3 | `p += 1, 2, 4` | 7 | `2^3 - 1 = 7` ✓ |
| 4 | `p += 1, 2, 4, 8` | 15 | `2^4 - 1 = 15` ✓ |

所以 `foo(x) = 2^x - 1`。

### 4.3 思路第二步：前置条件

`x` 能取什么值？

- `x < 0`：`for` 循环条件 `i < x` 一开始就是假，直接返回 `p = 0`。但 `2^0 - 1 = 0`，**恰好也对**。不过这是巧合，而且 `POW(2, x)` 在 `x < 0` 时**不安全**（前置条件是 `y >= 0`）——后置条件里如果写 `POW(2,x)`，那么 `x < 0` 时后置条件本身就违反了 `POW` 的契约。
- `x = 0`：返回 0，正确。
- `x > 0`：正常。

所以前置条件是 **`x >= 0`**。这既保证了 `POW(2, x)` 安全，也覆盖了所有有意义的情形。

> **注意**：讲义答案写的是 `//@requires x >= 0;`。这是**必需的**，不是因为 `x < 0` 时结果错（结果其实对），而是因为**后置条件里用到了 `POW(2, x)`，而 `POW` 要求第二个参数非负**。这是一个很重要的细节：**前置条件的必要性可能来自后置条件的书写方式，而不只是来自函数体的行为**。

### 4.4 思路第三步：后置条件

```c0
//@ensures \result == POW(2, x) - 1;
```

### 4.5 思路第四步：两条循环不变式

第一条：**`i` 的取值范围**。这是「控制变量」的不变式，几乎所有 `for` 循环都有。

```c0
//@loop_invariant 0 <= i && i <= x;
```

为什么需要 `i <= x` 而不只是 `i < x`？因为**不变式在检查循环条件之前被断言**，而在最后一次迭代后、退出检查时 `i == x`。如果只写 `i < x`，那么退出时不变式就假了，EXIT 步骤没法用。

> **这是初学者最常犯的错误**：把不变式写成循环条件的加强版（`i < x`），导致退出时不变式不成立。正确做法是写 `i <= x`，让退出时 `i == x` 成为 EXIT 步骤的起点。

第二条：**`p` 与 `i` 的关系**，即「已经累加到哪了」。

```c0
//@loop_invariant p == POW(2, i) - 1;
```

### 4.6 验证两条不变式

**INIT**（第一次检查循环条件前：`p = 0`，`i = 0`）：

- `0 <= 0 && 0 <= x`：由 `x >= 0` 得 ✓
- `p == POW(2, i) - 1`：`0 == POW(2,0) - 1 = 1 - 1 = 0` ✓

**PRES**（假设 `0 <= i && i <= x` 且 `p == POW(2,i) - 1`，且 `i < x`，证明迭代后仍成立）：

循环体是 `p += POW(2, i);`，然后 `i++`。所以：

- `p' = p + POW(2, i) = (POW(2,i) - 1) + POW(2,i) = 2·POW(2,i) - 1 = POW(2, i+1) - 1`
- `i' = i + 1`

于是：

- `0 <= i' && i' <= x`：由 `0 <= i` 得 `0 <= i+1`；由 `i < x`（循环条件）得 `i+1 <= x` ✓
- `p' == POW(2, i') - 1`：即 `POW(2,i+1) - 1 == POW(2, i+1) - 1` ✓

**EXIT**（`0 <= i && i <= x` 且 `p == POW(2,i) - 1` 且 `!(i < x)`，即 `i >= x`）：

- 由 `i <= x` 与 `i >= x` 得 `i == x`
- 所以 `p == POW(2, x) - 1`
- 返回 `p`，故 `\result == POW(2,x) - 1` ✓

**TERM**：`x - i` 每轮严格减少 1，下界 0，当它到 0 时 `i == x`，循环条件假。✓

### 4.7 完整答案

```c0
int foo(int x)
//@requires x >= 0;
//@ensures \result == POW(2, x) - 1;
{
  int p = 0;
  for (int i = 0; i < x; i++)
  //@loop_invariant 0 <= i && i <= x;
  //@loop_invariant p == POW(2, i) - 1;
  {
    p += POW(2, i);
  }
  return p;
}
```

### 4.8 这道题的教训

**两条不变式的分工**：

| 不变式 | 类型 | 作用 |
|---|---|---|
| `0 <= i && i <= x` | **范围不变式**（range invariant） | 保证索引安全（`POW(2, i)` 的 `i >= 0`）、保证 EXIT 时能推出 `i == x` |
| `p == POW(2, i) - 1` | **语义不变式**（semantic invariant） | 描述「部分结果」与「进度」的关系，是 EXIT 推出后置条件的关键 |

**几乎所有循环都需要这两类**。后面看到任何循环，先问「范围不变式是什么」「语义不变式是什么」。

## 五、Ex3：GCD 暴力版的五步证明

### 5.1 题目（p33–34）

```c0
1  int GCD(int a, int b)
2  //@requires a > 0 && b > 0;
3  //@ensures \result >= 1;
4  //@ensures a % \result == 0 && b % \result == 0;
5  {
6    int d = min(a, b);
7
8    while (d > 1)
9    //@loop_invariant d >= 1;
10   {
11     if (a % d == 0 && b % d == 0)
12       return d;
13     d = d - 1;
14   }
15   return d;
16 }
```

要求五步：(a) INIT、(b) PRES、(c) EXIT、(d) TERM、(e) 处理第 12 行的提前返回。

### 5.2 先读懂后置条件

**关键观察**：后置条件**没有**说返回值是「最大」公约数，只说它是「一个」公约数：

- `\result >= 1`
- `a % \result == 0 && b % \result == 0`

所以这个函数的**规格比它的名字弱**。`GCD` 这个名字有误导性——它算的是「a 和 b 的某个公约数」。这在后面 Ex4 里很重要：Ex4 用 `GCD` 作为**规格函数**，而后置条件写的是 `\result == GCD(a,b)`，这里的 `GCD` 指的是「这个函数算出来的值」，不是数学上的最大公约数。

> **这是一个极好的例子，说明「函数名不等于规格」**。规格只由契约决定。讲义 p34 明确说：
>
> > Note that the postconditions say nothing about the returned value being the greatest common divisor of the inputs, only that it is one of their divisors.

### 5.3 (a) INIT

**要证**：第一次检查循环条件前（第 8 行），`d >= 1` 成立。

| 行 | 结论 | 依据 |
|---|---|---|
| A | `a > 0 && b > 0` | by line 2 (precondition) |
| B | `a >= 1 && b >= 1` | by math on A（整数且 > 0） |
| C | `d == min(a,b)` | by line 6 |
| D | `min(a,b) >= 1` | by math on B and C |
| E | `d >= 1` | by C, D |

✓

### 5.4 (b) PRES

**假设**：`d >= 1`，且循环条件 `d > 1` 为真。
**要证**：迭代后 `d' >= 1`。

| 行 | 结论 | 依据 |
|---|---|---|
| A | `d > 1` | by line 8 (loop guard) |
| B | `d' == d - 1` | by line 13 |
| C | `d' >= 1` | by math on A and B（`d > 1` ⇒ `d >= 2` ⇒ `d-1 >= 1`） |

✓

> **讲义的一个有趣评论**（p37）：
>
> > In this proof, we did not make use of the assumption that `d >= 1`. This is not typical as most proofs of preservation rely critically on their assumption.
>
> 也就是说，这次 PRES 的证明**没有用到不变式假设**，只用了循环条件。这种情况很少见——大多数 PRES 证明必须依赖不变式。**如果你发现自己的 PRES 证明完全没用上不变式，要么是这段代码确实特殊，要么是你漏掉了某条不变式。**

### 5.5 (c) EXIT

**假设**：`d >= 1`，且 `!(d > 1)`，即 `d <= 1`。
**要证**：第 15 行（`return d;`）处，后置条件成立。

| 行 | 结论 | 依据 |
|---|---|---|
| A | `d >= 1` | by line 9 (loop invariant) |
| B | `d <= 1` | by line 8（`!(d > 1)`） |
| C | `d == 1` | by math on A and B |
| D | `n % 1 == 0` 对任意 `n > 0` | by math |
| E | `a % 1 == 0 && b % 1 == 0` | by D, A（`a,b > 0`） |
| F | `\result == d == 1 >= 1` | by C, line 15 |
| G | 后置条件成立 | by E, F |

✓

> **讲义的一个洞察**（p37）：
>
> > This proof suggests simplifying line 15 into `return 1`, since this is the only possible value that `d` can assume.
>
> 因为退出循环时 `d` 必然是 1，所以 `return d;` 可以直接写成 `return 1;`。**这是证明反过来改进代码的例子**——证明过程中发现的「必然成立的事实」，往往能简化代码。

### 5.6 (d) TERM

**要证**：存在严格单调递减、有下界的表达式。

**取 `d`**：

- **严格递减**：循环体第 13 行 `d = d - 1`，故 `d' = d - 1 < d` ✓
- **有下界**：由不变式 `d >= 1` ✓
- **触界时循环条件为假**：下界是 1，而循环条件是 `d > 1`。当 `d` 降到 1 时，`d > 1` 为假 ✓

所以循环至多执行 `min(a,b) - 1` 次。✓

### 5.7 (e) 提前返回（第 12 行）

这是最容易漏的一步。`return` 语句有**两个**出口：第 12 行和第 15 行。EXIT 步骤只覆盖了第 15 行。

**要证**：在第 12 行返回时，后置条件也成立。

**已知**：第 11 行的条件为真，即 `a % d == 0 && b % d == 0`。同时不变式 `d >= 1` 成立。

| 行 | 结论 | 依据 |
|---|---|---|
| A | `d >= 1` | by line 9 (loop invariant) |
| B | `a % d == 0 && b % d == 0` | by line 11（if 条件为真） |
| C | `\result == d` | by line 12 |
| D | `\result >= 1` | by A, C |
| E | `a % \result == 0 && b % \result == 0` | by B, C |

✓

### 5.8 这道题的完整教训

**1. 每个 `return` 都要单独证。** 一个函数有几个出口，EXIT 就要做几次。后面写递归函数时（L15 的 `bst_insert`、L22 的 `dfs_helper`），出口更多，更容易漏。

**2. 提前返回的证明依赖「进入 if 的条件」。** 这是 `if` 内部的 `return` 特有的：条件为真本身就是一个可用的断言。

**3. 规格弱于函数名是常态。** 读任何代码时，**只看契约，不看名字**。L15 的 `bst_insert` 后置条件、L22 的 `dfs` 后置条件，都有类似的「名字比规格强」的情况。

**4. 证明能反过来简化代码。** 上面 (c) 发现的 `d == 1` 就是一个例子。

## 六、Ex4：Euclid 算法

### 6.1 题目（p34–35）

```c0
1  int euclid(int a, int b)
2  //@requires a > 0 && b > 0;
3  //@ensures \result == GCD(a, b);
4  {
5    int x = a;
6    int y = b;
7
8    while (x != y)
9    //@loop_invariant x > 0 && y > 0;
10   //@loop_invariant GCD(x, y) == GCD(a, b);
11   {
12     if (x > y)
13       x = x - y;
14     else
15       y = y - x;
16   }
17   //@assert x == y;
18   return x;
19 }
```

要求五步：(a) 调用安全性、(b) INIT、(c) PRES、(d) EXIT、(e) TERM。

### 6.2 (a) SAFE：调用安全性

这是 Ex4 比 Ex3 多出来的一步。第 10 行的不变式里调用了 `GCD(x, y)` 和 `GCD(a, b)`，必须证明这两个调用满足 `GCD` 的前置条件 `a > 0 && b > 0`。

| 行 | 结论 | 依据 |
|---|---|---|
| A | `x > 0 && y > 0` | by line 9 (loop invariant) |
| B | `a > 0 && b > 0` | by line 2 (precondition) |
| C | `GCD(x,y)` 安全 | by A, `GCD` 的前置条件 |
| D | `GCD(a,b)` 安全 | by B, `GCD` 的前置条件 |

✓

> **这是「契约式推理」的核心机制**：每次调用都要检查前置条件。在 C0 里，`-d` 标志会在运行时自动检查（讲义 p15）；在标准 C 里（L17 起），需要手动 `#include "lib/contracts.h"` 并写 `REQUIRES(...)`。
>
> **注意循环不变式里也可以有函数调用**，此时不变式的「求值」本身就需要安全性。这就是为什么 SAFE 要放在 INIT 之前——不变式在每次检查循环条件时都会被求值。

### 6.3 (b) INIT

**要证**：第一次检查 `x != y` 前（第 8 行），两条不变式都成立。

**目标 1：`x > 0 && y > 0`**

| 行 | 结论 | 依据 |
|---|---|---|
| A | `x == a` | by line 5 |
| B | `y == b` | by line 6 |
| C | `a > 0 && b > 0` | by line 2 |
| D | `x > 0 && y > 0` | by A, B, C |

**目标 2：`GCD(x,y) == GCD(a,b)`**

| 行 | 结论 | 依据 |
|---|---|---|
| A | `x == a` | by line 5 |
| B | `y == b` | by line 6 |
| C | `GCD(a,b) == GCD(a,b)` | by math（自反性） |
| D | `GCD(x,y) == GCD(a,b)` | by A, B, C |

✓

> 讲义 p38 把这两个目标合在一起证，写的是 `D. GCD(a,b) == GCD(a,b) by math on A–B`。注意这里**用了等式的自反性**——这是 INIT 步骤里唯一能用的「数学事实」。

### 6.4 (c) PRES

**假设**：`x > 0 && y > 0` 且 `GCD(x,y) == GCD(a,b)`，且循环条件 `x != y` 为真。
**要证**：迭代后 `x' > 0 && y' > 0` 且 `GCD(x',y') == GCD(a,b)`。

需要分两种情形。

#### 情形一：`x > y`

循环体执行 `x = x - y`，`y` 不变。故 `x' = x - y`、`y' = y`。

**目标 1：`x' > 0 && y' > 0`**

| 行 | 结论 | 依据 |
|---|---|---|
| A | `x' == x - y` | by line 13 |
| B | `y' == y` | by line 14 未执行 |
| C | `x > y` | by line 12（if 条件为真） |
| D | `x - y > 0` | by math on C（整数，`x > y` ⇒ `x - y >= 1`） |
| E | `x' > 0` | by A, D |
| F | `y > 0` | by line 9 (loop invariant) |
| G | `y' > 0` | by B, F |

**目标 2：`GCD(x',y') == GCD(a,b)`**

关键数学事实：

```
GCD(n, m) == GCD(n - m, m)    对任意 n > m > 0
```

这是欧几里得算法的全部数学内容：**减去较小数不改变公约数集合**。直观理由：`d` 整除 `n` 且 `d` 整除 `m` ⟺ `d` 整除 `n-m` 且 `d` 整除 `m`。

| 行 | 结论 | 依据 |
|---|---|---|
| A | `x' == x - y` | by line 13 |
| B | `y' == y` | by line 14 未执行 |
| C | `GCD(x,y) == GCD(a,b)` | by line 10 (loop invariant) |
| D | `GCD(n,m) == GCD(n-m,m)` 对 `n > m > 0` | by math |
| E | `GCD(x-y, y) == GCD(x,y)` | by D, C（`x > y > 0`） |
| F | `GCD(x',y') == GCD(a,b)` | by A, B, E, C |

✓

#### 情形二：`x < y`

由循环条件 `x != y` 与 `x > y` 为假，得 `x < y`。循环体执行 `y = y - x`，`x` 不变。

证明完全对称：

- `y' = y - x > 0`（因为 `y > x`）
- `x' = x > 0`（不变式）
- `GCD(x, y-x) == GCD(x,y)`（由 `GCD(n,m) == GCD(n, m-n)`）

✓

> 讲义 p38 只写了「Assume that `x < y`: the proof is similar.」，把对称情形留给读者。**但考试时要写出来**——「similar」在笔试里不算分。

### 6.5 (d) EXIT

**假设**：`x > 0 && y > 0` 且 `GCD(x,y) == GCD(a,b)`，且 `!(x != y)`，即 `x == y`。
**要证**：`\result == GCD(a,b)`。

| 行 | 结论 | 依据 |
|---|---|---|
| A | `x == y` | by line 8（`!(x != y)`） |
| B | `GCD(x,y) == GCD(a,b)` | by line 10 (loop invariant) |
| C | `GCD(n,n) == n` 对任意 `n > 0` | by math（n 的最大公约数是 n） |
| D | `GCD(x,x) == x` | by C, line 9（`x > 0`） |
| E | `x == GCD(a,b)` | by A, B, D |
| F | `\result == x` | by line 18 |
| G | `\result == GCD(a,b)` | by E, F |

✓

> 注意这里用到 `GCD(n,n) == n`。**这依赖 `GCD` 确实是「最大公约数」**，而 Ex3 的代码只保证了「某个公约数」。所以严格来说，Ex4 的证明**建立在一个假设上**：`GCD` 返回的是最大公约数。
>
> 讲义把 `GCD` 当作「规格函数」（specification function）使用——它的作用不是被执行，而是**在契约里描述期望的行为**。这是编程语言理论里的标准做法：用简单但可能低效的函数作为规格，用复杂但高效的函数作为实现。L01 p13 说得很清楚：
>
> > The idea in this and many other examples is to capture a specification in the simplest possible form, even if it may not be computationally efficient.

### 6.6 (e) TERM

**取表达式 `x + y`**：

- **严格递减**：每轮要么 `x' = x - y`（`x + y` 变成 `x`），要么 `y' = y - x`（`x + y` 变成 `y`）。两种情况下 `x' + y' < x + y`（因为减去的那个数 `> 0`）✓
- **有下界**：由不变式 `x > 0 && y > 0`，得 `x + y >= 2` ✓
- **触界时循环条件为假**：下界是 2，达到 2 时只能 `x == y == 1`，循环条件 `x != y` 为假 ✓

> 也可以取 `max(x,y)`，同样严格递减、下界 1。**`x + y` 更简单，因为不用分情形讨论哪个更大。**

### 6.7 第 17 行的 `//@assert`

```c0
//@assert x == y;
```

这条断言其实是**冗余的**——它就是循环条件取反。但它有教学意义：

- **它让 EXIT 步骤的起点显式化**。读者看到 `assert` 就知道「这里 x 必然等于 y」。
- **它在 `-d` 模式下会被运行时检查**，如果循环逻辑写错，这里会立刻报错。

> **写断言的习惯**：在循环结束后、返回之前，把 EXIT 步骤依赖的关键事实写成 `assert`。这既是文档，也是运行时检查点。

| 维度 | Ex1 | Ex2 | Ex3 | Ex4 |
|---|---|---|---|---|
| **题型** | 反驳 | 构造 | 完整证明 | 完整证明 + 调用安全 |
| **难点** | 找最小反例 | 猜语义 + 补两条不变式 | 处理提前返回 | 处理规格函数 + 分情形 |
| **关键教训** | 不变式必须覆盖所有被改的变量 | 范围不变式 + 语义不变式缺一不可 | 每个 return 都要证 | 每次调用都要证前置条件 |
| **对应的后续讲次** | L15 `is_ordered`、L26 `grandparent_check` | L04 线性搜索、L06 二分 | L15 `bst_insert`、L22 `dfs_helper` | L16 `avl_insert`、L26 `pq_add` |

### 7.1 三个反复出现的模式

**模式一：局部信息不足**

- Ex1：`POW(b,e)` 漏了 `r`
- L15 p11：`is_ordered` 只比父子，漏了祖先
- L26：`is_heap_except_up` 漏了祖父母

**统一诊断方法**：问「我的不变式提到的变量/节点，覆盖了循环体/递归调用可能改变的全部对象吗？」

**模式二：范围不变式 + 语义不变式**

- Ex2：`0 <= i && i <= x` + `p == POW(2,i) - 1`
- L06 二分：`0 <= lo && lo <= hi && hi <= n` + 「目标在 `[lo,hi)` 内或不存在」
- L26 sift：`1 <= i && i < H->next` + `is_heap_except_down(H,i)`

**统一模板**：

```
//@loop_invariant <索引/指针的合法范围>;
//@loop_invariant <部分结果与进度的关系>;
```

**模式三：每个出口都要证**

- Ex3：第 12 行 + 第 15 行
- L15 `bst_insert`：`T == NULL` 分支 + 末尾 `return T`
- L22 `dfs_helper`：找到目标 + 遍历完所有邻居

**统一诊断方法**：数一数函数里有几个 `return`，EXIT 就要做几次。

## 八、自测：三个变式题

### 题 1

下面这段代码的循环不变式写成了 `//@loop_invariant p == POW(2, i);`。找出一个让它失败的输入。

```c0
int bar(int x)
//@requires x >= 0;
{
  int p = 0;
  for (int i = 0; i < x; i++)
  //@loop_invariant p == POW(2, i);
  {
    p += POW(2, i);
  }
  return p;
}
```

<details><summary>参考答案</summary>

**`x = 1`**。

- INIT：`i = 0`，`p = 0`，要求 `0 == POW(2,0) = 1`——**已经失败**。

如果放宽到「只要求 PRES 成立」，那么任何 `x >= 1` 都会在第一次迭代后失败：

- 迭代 1 后：`i = 1`，`p = 1`，要求 `1 == POW(2,1) = 2`——失败。

**正确的语义不变式是 `p == POW(2,i) - 1`**（见 Ex2）。

**教训**：`p` 是「前 i 项之和」，不是「第 i 项」。写不变式时要想清「p 代表的是累积量还是当前项」。

</details>

### 题 2

把 Ex3 的 `GCD` 改成下面的版本（`d` 从 `min(a,b)` 开始，但循环条件是 `d >= 1`）。写出它的 INIT / PRES / EXIT / TERM，并指出哪个步骤会失败。

```c0
int GCD2(int a, int b)
//@requires a > 0 && b > 0;
//@ensures \result >= 1;
{
  int d = min(a, b);
  while (d >= 1)
  //@loop_invariant d >= 0;
  {
    if (a % d == 0 && b % d == 0)
      return d;
    d = d - 1;
  }
  return d;
}
```

<details><summary>参考答案</summary>

**PRES 会失败。**

- **INIT**：`d = min(a,b) >= 1 >= 0` ✓
- **PRES**：假设 `d >= 0`，循环条件 `d >= 1`。迭代后 `d' = d - 1`。要证 `d' >= 0`，即 `d >= 1`。由循环条件 `d >= 1` 可得 ✓——**这条其实成立**。
- **EXIT**：假设 `d >= 0`，且 `!(d >= 1)`，即 `d <= 0`。得 `d == 0`。返回 0，但后置条件要求 `\result >= 1`——**失败**。
- **TERM**：`d` 严格递减、下界 0、触界时 `d >= 1` 为假 ✓

**所以失败的是 EXIT，不是 PRES。**

**根本原因**：循环条件写成 `d >= 1` 时，退出时 `d` 可以是 0，而 `0` 不是合法的公约数（后置条件要求 `>= 1`）。

**另一个更严重的问题**：如果 `a`、`b` 互质（如 `a=3, b=5`），那么 `d` 会一路减到 1，此时 `a % 1 == 0 && b % 1 == 0` 成立，在第 8 行返回 1。**所以实际上永远不会走到 `d == 0`**——但这需要额外论证，而不变式 `d >= 0` 太弱，推不出来。

**修复方式**：把不变式加强为 `d >= 1`，循环条件保持 `d >= 1`。这样退出时 `d == 0` 与不变式矛盾，说明这个出口不可达（可以用 `assert(false)` 或直接删掉 `return d;`）。

</details>

### 题 3

下面这段代码计算 `n` 的阶乘。补全两条循环不变式。

```c0
int fact(int n)
//@requires n >= 0;
//@ensures \result == FACT(n);
{
  int p = 1;
  for (int i = 0; i < n; i++)
  //@loop_invariant ____________;
  //@loop_invariant ____________;
  {
    p = p * (i + 1);
  }
  return p;
}
```

其中 `FACT(0) = 1`，`FACT(n) = n * FACT(n-1)`。

<details><summary>参考答案</summary>

```c0
//@loop_invariant 0 <= i && i <= n;
//@loop_invariant p == FACT(i);
```

**INIT**：`i = 0`，`p = 1`。`0 <= 0 && 0 <= n` ✓；`1 == FACT(0) = 1` ✓

**PRES**：假设 `0 <= i && i <= n`、`p == FACT(i)`，且 `i < n`。迭代后 `p' = p * (i+1) = FACT(i) * (i+1)`，`i' = i + 1`。

- `0 <= i+1 && i+1 <= n`：由 `0 <= i` 与 `i < n` ✓
- `p' == FACT(i+1)`：`FACT(i+1) = (i+1) * FACT(i) = (i+1) * p = p'` ✓

**EXIT**：`i <= n` 且 `!(i < n)` ⇒ `i == n` ⇒ `p == FACT(n)` ✓

**TERM**：`n - i` 严格递减，下界 0 ✓

**注意**：`p == FACT(i)` 而不是 `p == FACT(i+1)`，因为 `p` 累乘到 `i` 为止（`1 * 2 * ... * i`）。这是「累积量对应到当前索引」的又一个例子，和 Ex2 的 `p == POW(2,i) - 1` 是同一个模式。

</details>
