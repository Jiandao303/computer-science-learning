# CMU 15-122 · 复杂度与算法复盘

> 覆盖 L05（Big-O 与选择排序）、L06（二分搜索）、L07（快速排序）、L11（无界数组与摊还分析）、L12（哈希表）。
> 各讲原始笔记见 [[15-122-05-Big-O]]、[[15-122-06-Binary-Search]]、[[15-122-07-Quicksort]]。

## 一、复盘目标

复杂度分析在本课程里的目的不是性能优化，而是**选型判断**：给定两个方案，判断哪一个在输入变大后还能用。

复盘要解决三个问题：

1. **定义**：Big-O 到底在说什么？为什么常数因子可以丢？为什么只有最大项重要？
2. **推导**：给定一段代码，怎么从循环结构推出它的复杂度？
3. **判断**：凭什么说一个方案比另一个好？好在哪一项？

## 二、Big-O 的严格定义（L05 p2–p4）

### 2.1 定义

```
f ∈ O(g)  当且仅当  存在实数 c > 0 和自然数 n0，
                    使得对所有 n >= n0 都有 f(n) <= c * g(n)
```

用集合写：

```
O(g) = { f | 存在 c > 0 和 n0，使得对所有 n >= n0，f(n) <= c * g(n) }
```

### 2.2 讲义为什么这样定义：两步演化（p2–p3）

理解演化过程比背定义重要。

**第一步：从「所有 n」放宽到「足够大的 n」**

最初的想法是：

```
f <=0 g  当且仅当  对所有 n >= 0，f(n) <= g(n)
```

这违反了一条原则：**我们只关心大输入**。算法之间的差距只在大输入时才显著。于是放宽为：

```
f <=1 g  当且仅当  存在 n0，使得对所有 n >= n0，f(n) <= g(n)
```

**第二步：允许常数倍**

但按上一条定义，`3n <=1 5n` 而 `5n <=1 3n` 不成立——两者实际是一回事（只差常数因子），却被判为不同。而常数因子受编译器、运行时系统、机器型号、可用内存影响太大，讲义说「在抽象的数学层面精确分析既不合适也不可行」。于是再放宽：

```
f <=2 g  当且仅当  存在 c > 0 和 n0，使得对所有 n >= n0，f(n) <= c * g(n)
```

这就是 `O`。讲义 p3 的原话是「This definition is now appropriate.」

### 2.3 两条原则

| 原则 | 讲义表述 | 数学后果 |
|---|---|---|
| **实用性**（practically useful） | 只关心大输入的行为 | 引入 `n0`，忽略小输入 |
| **持久性**（enduring） | 分析结果不因机器变快而改变 | 忽略常数因子 `c` |

### 2.4 三条基本事实

**事实一：多项式只看最高次项**

```
O(5n^2 + 3n + 83) = O(n^2)
```

要严格证明，可以取 `c = 9`、`n0 = 9`：对 `n >= 9`，

```
5n^2 + 3n + 83 <= 5n^2 + 3n^2 + n^2 = 9n^2   ✓
```

> 讲义只给结论不给 `c`、`n0`。但考试若要求「证明」，**必须给出具体的 `c` 与 `n0` 并验证不等式**。

**事实二：对数的底数不影响**

```
O(log2 n) = O(log_b n)     对任意常数 b > 1
```

理由：换底公式 `log_b n = log2 n / log2 b`，分母 `log2 b` 是常数，被 `c` 吸收。

**事实三：`O` 是包含关系，不是相等关系**

```
O(log n) 是 O(n) 的真子集
```

### 2.5 `O` 是上界，不是精确界（p4）

讲义特别强调这一点：

> As a side note, it is mathematically correct to say the worst-case running time of binary search is O(n), because log n ∈ O(n). It is, however, a looser characterization than saying ... O(log n).

所以：

| 说法 | 是否正确 | 说明 |
|---|---|---|
| 二分搜索最坏 `O(log n)` | 正确 | 紧界 |
| 二分搜索最坏 `O(n)` | 也正确 | 松界，但没有信息量 |
| 二分搜索最坏 `O(1)` | 错误 | `log n` 不在 `O(1)` 里 |

> **约定**：题目问「复杂度」时，**要的是最紧的 `O` 界**。写松界虽然数学上没错，但不给分。

### 2.6 多变量情形（p4）

```
2w + 2h^2 + 4 ∈ O(w + h^2)
```

形式化时说：存在**一个**常数 `c`，但对**每个变量**各取一个起点 `w0`、`h0`。图算法里 `O(v + e)` 就是这种形式。

## 三、从代码推复杂度：三个模板

### 3.1 单层循环

```c
for (int i = 0; i < n; i++) { ... O(1) 的操作 ... }
```

复杂度 = 迭代次数 × 每轮代价 = `n * O(1)` = **`O(n)`**。

**关键**：先确定迭代次数，再确定每轮代价，最后相乘。**不要一看到嵌套就乘，先看内层是否真的跑满。**

### 3.2 嵌套循环

```c
for (int i = 0; i < n; i++)
  for (int j = 0; j < n; j++) { ... O(1) ... }
```

`O(n^2)`。

但下面这个是 `O(n)` 而不是 `O(n^2)`：

```c
for (int i = 0; i < n; i++)
  for (int j = i; j < n; j++) { ... O(1) ... }
```

因为内层跑 `n - i` 次，总数是：

```
n + (n-1) + (n-2) + ... + 1 = n(n+1)/2 ∈ O(n^2)
```

等一下——这个**确实**是 `O(n^2)`。要得到 `O(n)`，内层必须是**常数次**，例如：

```c
for (int i = 0; i < n; i++)
  for (int j = i; j < i + 3 && j < n; j++) { ... O(1) ... }
```

> **易错点**：`n(n+1)/2` 是 `O(n^2)`，不是 `O(n)`。常数 `1/2` 被 `O` 丢掉，但 `n^2` 保留。

### 3.3 每轮规模减半（对数复杂度）

```c
while (n > 1) { n = n / 2; }
```

迭代次数：`log2 n` 次（因为 `n / 2^k = 1` 时 `k = log2 n`）。复杂度 **`O(log n)`**。

L06 p3 的推导：设 `n = 2^k`，每轮减半，`k` 轮后规模变成 1，所以至多 `k + 1` 轮。若 `n` 不是 2 的幂，**向上取整到下一个 2 的幂**，界仍然成立（实际步数只会更少）。

**「翻倍输入只增加常数代价」**（L06 p3）：

```
c * log(2n) = c * (log 2 + log n) = c + c * log n
```

输入翻倍，代价只增加常数 `c`。这是对数复杂度的标志性特征。

**具体数字**（L06 p3）：32 位补码最大正数是 `2^31 - 1`（约 20 亿），二分搜索最多循环 **31 次**。

## 四、复杂度对比表

### 4.1 五种增长速率

| 复杂度 | 名称 | n=10 | n=100 | n=1000 | n=10^6 | 典型算法 |
|---|---|---|---|---|---|---|
| `O(1)` | 常数 | 1 | 1 | 1 | 1 | 数组下标访问、哈希查找（期望） |
| `O(log n)` | 对数 | 3.3 | 6.6 | 10 | 20 | 二分搜索 |
| `O(n)` | 线性 | 10 | 100 | 1000 | 10^6 | 线性搜索、选择排序的一轮 |
| `O(n log n)` | 线性对数 | 33 | 664 | 9966 | 2×10^7 | 归并排序、快排（期望）、heapsort |
| `O(n^2)` | 平方 | 100 | 10^4 | 10^6 | 10^12 | 选择排序、插入排序、快排（最坏） |

**读表方法**：看 `n = 10^6` 那一列。`O(n^2)` 是 `10^12` 次操作——按每秒 10^9 次算要 **1000 秒**；`O(n log n)` 是 `2×10^7`，**0.02 秒**。**这就是「能不能用」的分界线。**

### 4.2 搜索算法对比

| 算法 | 前提 | 最坏 | 平均 | 备注 |
|---|---|---|---|---|
| 线性搜索 | 无 | `O(n)` | `O(n)` | L04 |
| 二分搜索 | **数组已排序** | `O(log n)` | `O(log n)` | L06；前提不能忘 |
| 哈希查找 | 好的哈希函数 | `O(n)`（全部冲突） | **`O(1)`** | L12；最坏与平均差极大 |
| BST 查找 | 树平衡 | `O(h)`，最坏 `O(n)` | `O(log n)` | L15 |
| AVL 查找 | 无（自平衡） | **`O(log n)`** | `O(log n)` | L16 |

> **关键区别**：二分搜索的 `O(log n)` 是**最坏**；哈希的 `O(1)` 是**期望**；AVL 的 `O(log n)` 是**最坏且确定**。三者不能混着说。

### 4.3 排序算法对比

| 算法 | 最好 | 最坏 | 平均/期望 | 额外空间 | 稳定 |
|---|---|---|---|---|---|
| 选择排序（L05） | `O(n^2)` | `O(n^2)` | `O(n^2)` | `O(1)` | 否 |
| 插入排序 | `O(n)`（已排序） | `O(n^2)` | `O(n^2)` | `O(1)` | 是 |
| 快速排序（L07） | `O(n log n)` | **`O(n^2)`** | **`O(n log n)`** | `O(log n)` 栈 | 否 |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` | 是 |
| 堆排序（L26） | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)`（原地） | 否 |

**选择排序的复杂度来源**（L05 p5–p7）：外层 `n` 轮，每轮在内层找最小值扫一遍剩余部分，总计 `n + (n-1) + ... + 1 = n(n+1)/2`，即 `O(n^2)`。**无论输入是否已排序，都是 `O(n^2)`**——这是它和插入排序的关键区别。

**快排的三重复杂度**（L07 p3–p4）：

| 情形 | 枢轴选择 | 递归深度 | 总代价 |
|---|---|---|---|
| 最好 | 恰好是中位数 | `log n` | `O(n log n)` |
| 最坏 | 每次都是最小或最大元素 | `n` | `O(n^2)` |
| 期望（随机枢轴） | 随机 | `O(log n)` | `O(n log n)` |

讲义 p4 的关键警告：

> With any fixed-pick strategy, there will be sample inputs on which the algorithm takes O(n^2) steps. For example, if we ... always pick the first element ... and the array is already sorted, quicksort will take O(n^2) steps.

**所以「取首元素作枢轴」是有缺陷的策略**：已排序数组（最常见的实际输入之一）会让它退化。随机选枢轴后，期望时间与输入无关，恒为 `O(n log n)`。

### 4.4 数据结构操作对比

| 结构 | 查找 | 插入 | 删除 | 空间 |
|---|---|---|---|---|
| 无序数组 | `O(n)` | `O(1)` | `O(n)` | `O(n)` |
| 有序数组 | `O(log n)` | `O(n)` | `O(n)` | `O(n)` |
| 无界数组（L11） | `O(n)` | **`O(1)` 摊还** | `O(n)` | `O(n)` |
| 哈希表（L12） | `O(1)` 期望 | `O(1)` 期望 | `O(1)` 期望 | `O(n)` |
| BST（L15） | `O(h)` | `O(h)` | `O(h)` | `O(n)` |
| AVL（L16） | `O(log n)` | `O(log n)` | `O(log n)` | `O(n)` |
| 堆（L25） | `O(n)`（找任意） / `O(1)`（找最小） | `O(log n)` | `O(log n)` | `O(n)` |

## 五、摊还分析：无界数组（L11 p10–p12）

这是全课最容易被误解的复杂度分析。

### 5.1 问题

无界数组（unbounded array，uba）的 `uba_add` 在数组满时要扩容：分配新数组、复制全部元素。**单次 `uba_add` 的最坏代价是 `O(n)`**。

那么 `n` 次 `uba_add` 是 `O(n^2)` 吗？**不是，是 `O(n)`。**

### 5.2 为什么不是 `O(n^2)`

关键在于**扩容不是每次都发生**。若每次容量翻倍：

| 第几次 add | 容量 | 是否扩容 | 本次代价 |
|---|---|---|---|
| 1 | 1 | 是（0→1） | 1 |
| 2 | 2 | 是（1→2） | 2 |
| 3 | 4 | 是（2→4） | 3 |
| 4 | 4 | 否 | 1 |
| 5 | 8 | 是（4→8） | 5 |
| 6–8 | 8 | 否 | 1 each |
| 9 | 16 | 是（8→16） | 9 |
| ... | ... | ... | ... |

总代价 = `n` 次普通写入（每次 1）+ 各次扩容的复制量：

```
1 + 2 + 4 + 8 + ... + 2^k  <  2^(k+1)  <=  2n
```

其中 `2^k <= n`。所以总代价 `< 3n`，**平均每次 3 次数组写入**。

### 5.3 讲义的「代币法」（token method）

讲义 p10 给了一个更精细的论证，用「代币」记账：

**不变式**：数组中每个**已用**的格子都关联代币，规则是——

- 后半段的每个已用格子（下标 `i ∈ [limit/2, size)`）：1 枚**金色**代币
- 前半段对应的格子（下标 `i - limit/2`）：1 枚**蓝色**代币

**每次 `uba_add` 花 3 枚代币**：

1. 1 枚支付本次写入；
2. 1 枚金色，存在新元素上，供**将来扩容时复制它自己**；
3. 1 枚蓝色，存在前半段对应位置，供**将来扩容时复制那个元素**。

**扩容时**：老数组的每个格子都恰好有 1 枚代币（后半段是金色、前半段是蓝色），正好支付「复制每个元素一次」。扩容后数组恰好半满，按不变式**不需要任何储备代币**。

**代币总数**：`2 * size - limit`。

**结论**：`uba_add` 的摊还代价是 **3 次数组写入**，即 `O(1)` 摊还。

### 5.4 摊还 vs 最坏：两个都要说

| 说法 | 是否正确 |
|---|---|
| `uba_add` 最坏 `O(n)` | 正确 |
| `uba_add` 摊还 `O(1)` | 正确 |
| `uba_add` 最坏 `O(1)` | **错误** |
| `n` 次 `uba_add` 总共 `O(n^2)` | **错误** |

> **摊还分析的含义**（L11 p13 附近）：它说的是「一串操作的总代价」，不是「每次操作都快」。讲义强调：
>
> > There's no uncertainty with amortized analysis: we know that, if we calculate ... the total cost of k increments is in O(k), even though the worst case cost of a single increment operation is O(n).

**摊还不是平均**：平均需要概率假设，摊还是**确定性的**——对任意操作序列，总代价都有界。

### 5.5 缩容的陷阱（p11–p12）

如果数组**半满时就缩容**，摊还会失效。理由：半满时按不变式**没有储备代币**，付不起这次复制。

正确做法：**降到四分之一以下才缩容**。这样缩容后数组是「半满」的，仍有代币储备，可以承受下一次扩容。

**这是「抖动」（thrashing）问题的经典案例**：如果在边界附近反复增删，半满缩容会导致每次操作都触发复制，摊还代价退化到 `O(n)`。

## 六、哈希表的复杂度（L12）

### 6.1 期望 `O(1)` 的三个前提

哈希表查找是 `O(1)`——**但这是期望值，且有前提**：

1. **哈希函数均匀**：把键均匀映射到 `[0, m)`。讲义用伪随机数生成器（PRNG）构造哈希函数，因为「可预测（确定性）但看起来随机」正是需要的性质。
2. **负载因子有界**：`n/m` 不超过常数（讲义提到 `1.0` 左右）。超过就扩容（再哈希）。
3. **冲突处理得当**：讲义用分离链（separate chaining）。

去掉任何一条，`O(1)` 就不成立。

### 6.2 最坏情况

**最坏 `O(n)`**：所有键冲突到同一条链，退化成链表。讲义 p9 明确说：

> We know that, in this setup, implementing buckets using linked lists yields an O(n) cost for both looking up a key and inserting an entry.

### 6.3 生日悖论（L12 Ex2）

这是哈希表最反直觉的一点：**即使键的数量远小于表长，冲突也几乎必然发生**。

讲义 Ex2 的设定：676 个可能的双字母串（`26 * 26`），只用了 79 个，表长取 100。看起来 79 < 100 应该没冲突，但实际上：

- **鸽笼原理**：表长 < 79 时必然冲突。
- **生日悖论**：表长 100 时，79 个键中至少两个冲突的概率**很高**。类比：23 个人就有 50% 概率生日相同，70 人就有 90%。

**结论**：要**保证**无冲突，表长必须 ≥ 可能的键总数（676），而不只是 ≥ 实际键数（79）。

> 这个结论对工程实践有直接影响：**不要指望「表比元素多就无冲突」**，负载因子 0.79 已经很容易撞。

### 6.4 桶用别的数据结构（L12 Ex1）

讲义比较了用不同结构做桶的最坏复杂度（假设表不自扩容、哈希函数可能很差）：

| 桶实现 | 查找 | 插入 | 结论 |
|---|---|---|---|
| 链表 | `O(n)` | `O(n)` | 最简单，推荐 |
| 定长数组 | — | — | 不可行（大小固定） |
| 无界数组 | `O(n)`（线性搜索） | `O(1)` 摊还（尾部追加） | 查找没改善 |
| 有序无界数组 | `O(log n)` | `O(n)`（插入要挪位） | 查找改善，插入退化 |
| 另一个哈希表 | `O(1)` 期望 | `O(1)` 期望 | 理论最优但实现复杂 |

讲义的结论是：**在有好的哈希函数和扩容策略时，链表已经足够**，没必要用更复杂的结构做桶。

## 七、易错点清单

| 易错点 | 错误说法 | 正确说法 |
|---|---|---|
| 混淆上界与紧界 | 「二分是 `O(n)`」 | 数学上对，但答非所问；应说 `O(log n)` |
| 丢掉对数 | 「`n log n` 就是 `O(n)`」 | 不对，`log n` 无界增长 |
| 以为 `O(n^2)` 里的 `1/2` 能救 | 「`n(n+1)/2` 是 `O(n)`」 | 是 `O(n^2)`，常数因子才可丢 |
| 把摊还当最坏 | 「`uba_add` 是 `O(1)`」 | 摊还 `O(1)`，**最坏 `O(n)`** |
| 把摊还当平均 | 「摊还需要概率假设」 | 不需要，摊还是确定性的 |
| 忘掉二分的前提 | 「二分比线性快」 | 前提是**数组已排序**；排序本身要 `O(n log n)` |
| 以为快排总是 `O(n log n)` | 「快排是最快的排序」 | 最坏 `O(n^2)`；固定枢轴策略必有坏输入 |
| 以为哈希总是 `O(1)` | 「哈希查找是常数时间」 | **期望** `O(1)`；最坏 `O(n)` |
| 忽略多变量 | 「图算法是 `O(n^2)`」 | 应写 `O(v + e)` 或 `O(v^2)`，`v`、`e` 是两个独立量 |
| 只看一层循环 | 「双重循环一定 `O(n^2)`」 | 内层若只跑常数次，总体仍是 `O(n)` |

---

## 八、选型速查：看到什么信号选什么方案

| 需求信号 | 推荐方案 | 复杂度 | 出处 |
|---|---|---|---|
| 静态数据，只查不改 | 排序 + 二分 | 预处理 `O(n log n)`，查询 `O(log n)` | L06 |
| 频繁插入删除 + 查找 | 哈希表 | `O(1)` 期望 | L12 |
| 需要有序遍历 | BST / AVL | `O(log n)` | L15 / L16 |
| 只需要最小/最大 | 堆 | 取 `O(1)`，增删 `O(log n)` | L25 |
| 需要「是否连通」 | 并查集 | 近 `O(1)` 摊还 | L24 |
| 元素个数未知，需要动态增长 | 无界数组 | `O(1)` 摊还追加 | L11 |
| 内存紧张 | 原地排序（堆排序） | `O(n log n)`，`O(1)` 额外空间 | L26 |
| 需要稳定排序 | 归并排序 / 插入排序 | `O(n log n)` / `O(n^2)` | L05 |

## 九、自测

### 题 1

证明 `3n^2 + 5n + 2 ∈ O(n^2)`，给出具体的 `c` 和 `n0`。

<details><summary>参考答案</summary>

取 `c = 10`、`n0 = 1`。对任意 `n >= 1`：

```
3n^2 + 5n + 2 <= 3n^2 + 5n^2 + 2n^2 = 10n^2   ✓
```

（用了 `n <= n^2` 和 `1 <= n^2`，两者对 `n >= 1` 都成立。）

更紧的取法：`c = 4`、`n0 = 6`：

```
n >= 6 时，5n + 2 <= 5n + n/3 <= 6n <= n^2
所以 3n^2 + 5n + 2 <= 3n^2 + n^2 = 4n^2   ✓
```

**两种都对**。Big-O 证明不要求最优的 `c`、`n0`，只要求存在。

</details>

### 题 2

下面这段代码的复杂度是多少？

```c
int f(int n) {
  int s = 0;
  for (int i = 0; i < n; i++) {
    for (int j = 1; j < n; j = j * 2) {
      s += j;
    }
  }
  return s;
}
```

<details><summary>参考答案</summary>

**`O(n log n)`**。

- 外层循环 `n` 次。
- 内层 `j` 从 1 开始每次翻倍，直到 `>= n`，所以跑 `log2 n` 次。
- 每轮 `O(1)`。

总计 `n * log2 n = O(n log n)`。

**易错点**：看到双重循环就写 `O(n^2)` 是错的。**内层的迭代次数必须单独算**。

</details>

### 题 3

一个无界数组初始容量为 1，每次满时容量**增加 1**（而不是翻倍）。`n` 次 `add` 的总代价是多少？摊还每次多少？

<details><summary>参考答案</summary>

**总代价 `O(n^2)`，摊还每次 `O(n)`。**

第 `k` 次 add 时容量为 `k`，数组已满，需要复制 `k` 个元素。所以总复制量：

```
1 + 2 + 3 + ... + n = n(n+1)/2 ∈ O(n^2)
```

摊还每次：`O(n^2) / n = O(n)`。

**对比翻倍策略**：翻倍时总复制量 `< 2n`，摊还 `O(1)`。

**这就是为什么扩容必须「按倍数」而不是「按增量」**——按增量扩容会让 `add` 的摊还代价退化到线性，无界数组就失去了意义。

</details>

### 题 4

快排取首元素作枢轴，对下面哪个输入会退化到 `O(n^2)`？

- (A) 完全随机排列的数组
- (B) 已升序排列的数组
- (C) 已降序排列的数组
- (D) 所有元素都相等的数组

<details><summary>参考答案</summary>

**B、C、D 都会退化。**

- **B（已升序）**：首元素是最小值，划分后左段空、右段 `n-1` 个，递归深度 `n`，总代价 `O(n^2)`。
- **C（已降序）**：首元素是最大值，右段空、左段 `n-1` 个，同样 `O(n^2)`。
- **D（全相等）**：取决于划分的具体实现。若划分把「等于枢轴」的都放一边，则每次划分都是 `0 : n-1`，`O(n^2)`。讲义 p4 提到「almost sorted with a few exceptions」也会退化。

- **A（随机）**：期望 `O(n log n)`。

**讲义的原话**（p4）：

> With any fixed-pick strategy, there will be sample inputs on which the algorithm takes O(n^2) steps. ... If we pick the pivot randomly each time, the kind of array we get does not matter: the expected running time is always the same, namely O(n log n).

**教训**：「已排序输入」是最常见的实际输入，所以「取首元素」是最糟的固定策略之一。

</details>

### 题 5

哈希表有 1000 个桶，插入 1000 个键。查找的复杂度是 `O(1)` 吗？

<details><summary>参考答案</summary>

**不一定。要看负载因子和哈希函数。**

- 负载因子 `n/m = 1000/1000 = 1.0`。讲义说负载因子到 `1.0` 左右就该扩容，此时**平均链长约 1**，期望查找 `O(1)`。
- 但**最坏仍是 `O(n)`**：如果 1000 个键全部冲突到同一个桶，退化成 1000 个元素的链表。
- 而且根据生日悖论，即使哈希函数均匀，1000 个键散到 1000 个桶里，**必然有大量冲突**（期望空桶数约 `1000/e ≈ 368`，即有 632 个桶被占，其中不少桶有 2 个以上元素）。最长链的期望长度约 `log n / log log n`。

**准确说法**：期望 `O(1)`（在均匀哈希 + 负载因子有界的假设下），最坏 `O(n)`。

**如果要「保证」`O(1)`**，需要**完美哈希**（perfect hashing）：表长 ≥ 键的全集大小，且哈希函数无冲突。这在实际中很少可行。

</details>
