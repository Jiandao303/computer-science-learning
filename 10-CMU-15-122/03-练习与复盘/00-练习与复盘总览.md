## 一、这门课的练习从哪来

15-122 的练习来源有四层，**难度和可获得性差别很大**，下面按「本库能提供什么」逐一说明。

**两处异常**（撰写本表时逐讲核对页码发现）：

- **L23 Spanning Trees 与 L24 Union-Find 没有 `Sample Solutions` 小节**。这两讲的习题（L23 的「随机排列数组」「证明 cycle property 蕴含 Kruskal 正确性」、L24 的三道并查集证明/改写题）**只给题目不给答案**。L24 的三道题在讲义正文里有充分的铺垫（高度引理的完整证明在 p8，路径压缩在 p9），但最终答案要自己写。
- **L10 Linked Lists 有 14 道习题**，是全课最多的一讲（30 页讲义里 p18–21 全是题目）。这一讲的习题以「改写/补全链表操作」为主，适合集中练手。

> **页码依据**：以上页码取自各讲 PDF 的 `Exercises` / `Sample Solutions` 标题页。L23、L24、L25 的习题页较少，是因为这三讲讲义本身短（9/11/13 页），习题直接接在正文后。

**使用方法**：先合上答案自己做，写完再对。**看懂答案和能写出来是两件完全不同的事**——尤其是 L01、L15、L16、L24、L26 这五讲的证明题，看懂 sample solution 只需要五分钟，自己写要半小时以上，但只有后者能让你在考试里写出来。

### 1.2 官方代码包（26 个 `.tgz`）

每个讲次配一个代码包，位于 `90-原始PDF/15-122/code/<id>.tgz`，例如 `15-bst.tgz`（22 KB）、`14-generic.tgz`（25.4 KB）。包内通常包含：

- `.c0` / `.c1` / `.c` 源文件（讲义中引用的实现）
- `.h` 接口头文件
- 测试驱动（`main` 函数 + 断言）
- 有时带一个 `Makefile` 或 `README`

**解压方式**：

```bash
cd /tmp && mkdir -p 15122 && cd 15122
tar -xzf "D:/work file/study/CMU-Computer-Science/90-原始PDF/15-122/code/15-bst.tgz"
ls
```

**代码包的正确用法**（比读一遍有用得多）：

1. **先跑通**：用 `cc0 -d` 或 `gcc -Wall -Wextra -Werror -std=c99 -g -DDEBUG` 编译，跑测试驱动，确认全绿。
2. **改坏它**：故意删掉一条 `//@loop_invariant`、或把 `<=` 改成 `<`，看哪个测试失败、报什么错。**这是理解不变式最有效的方式**——不变式写错时，测试往往抓不到，但 `-d` 下的契约检查会立刻报错。
3. **重写它**：合上讲义，从空文件开始重新实现一遍接口，再跑原测试驱动。这是唯一能检验「真的会了」的方法。

> **注意**：L17 起的代码包是标准 C，`//@` 契约**不会被自动检查**。要让契约生效必须 `#include "lib/contracts.h"` 并用 `-DDEBUG` 编译（见 L17 讲义 p6–7）。

### 1.3 gts 入门指南（15 份）

`90-原始PDF/15-122/gts/` 下有 15 份短指南，**不是习题集，而是工具说明书**。它们解决的问题是「我知道该做什么，但不知道怎么做」。最该先读的四份：

| 文件 | 页数 | 什么时候读 |
|---|---|---|
| `gts/style.pdf` | 14 | **写第一份作业之前**。C0 与 C 的代码风格规范，命名、缩进、注释、禁止的写法 |
| `gts/valgrind.pdf` | 12 | L17 之后每次跑程序之前。怎么读泄漏报告、怎么定位第一个错误 |
| `gts/contracts.pdf` | 3 | L01 之后。契约写法速查（`@requires` / `@ensures` / `@loop_invariant` / `@assert`） |
| `gts/cdebugging.pdf` | 4 | L17 之后。gdb 基本操作 |

其余 11 份（`autolab`、`c0debugging`、`clib`、`cprint`、`laptop`、`print`、`questions`、`terminal`、`testing`、`vim`、`vscode`）按需查阅。

### 1.4 Autolab 在线评测（本库无法提供）

CMU 的作业提交与自动评分系统是 **Autolab**（`https://autolab.andrew.cmu.edu/`）。它提供：

- 官方作业（Programming Assignment，PG）的自动评分
- 隐藏测试用例

**限制说明**：

- 因此本库**不提供 Autolab 作业的完整复现**。想练手的话，用代码包里的测试驱动 + 讲义习题替代。

| 文件 | 覆盖内容 | 对应讲次 |

| [[10-CMU-15-122/03-练习与复盘/01-契约与循环不变式复盘\|01 契约与循环不变式复盘]] | L01 讲义 p33–35 的四道习题，逐题写出思路与答案要点；把「INIT / PRES / EXIT / TERM」四步证明固化成模板 | L01，回扣 L04、L06 |
| [[10-CMU-15-122/03-练习与复盘/02-复杂度与算法复盘\|02 复杂度与算法复盘]] | Big-O、二分、快排、哈希的复杂度对比表与易错点；一张「看到什么信号选什么复杂度」的对照表 | L05、L06、L07、L11、L12 |
| 本文件 | 练习来源、使用方法、资源限制 | 全课 |

**为什么只做这两个主题的复盘？**

因为它们分别是整门课的**两条主线**：

- **正确性主线**：契约 → 循环不变式 → 数据结构不变式 → 部分不变式（L01 → L15/L16 → L26）。这条线的能力是「证明代码对」，从第一讲贯穿到最后一讲。
- **效率主线**：Big-O → 摊还分析 → 数据结构选型 → 图算法复杂度（L05 → L11 → L21–L25）。这条线的能力是「判断代码够不够快」。

其余讲次的习题在各自笔记的第 11 节已经给出（每篇 3–5 题，答案折叠）。这两个复盘文件做的是**跨讲次的横向对照**，是笔记第 11 节做不到的事。

## 三、练习节奏建议

### 3.1 每讲的三轮练习

| 轮次 | 时机 | 做什么 | 时长 |
|---|---|---|---|
| **第一轮：理解** | 读完讲义当天 | 讲义习题里最简单的那道（通常是「找出反例」或「补全代码」） | 20 min |
| **第二轮：证明** | 读完讲义 2–3 天后 | 需要写证明的题（INIT/PRES/EXIT/TERM） | 40 min |
| **第三轮：重写** | 一周后 | 合上讲义，从空文件重写该讲的核心函数，跑原测试驱动 | 60 min |

**第三轮最关键也最容易被跳过。** 「读懂」和「写出来」之间的差距，在 L15（`is_ordered` 的正确版本）、L24（按高度合并）、L26（`grandparent_check`）这三处体现得最明显——这三处的代码都只有十几行，但第一遍几乎不可能写对。

### 3.2 每五讲一次的横向复盘

学完 L04、L08、L13、L16、L20、L26 之后各做一次：

1. 把这五讲的不变式列成一张表（结构 | 不变式 | 破坏方式 | 修复操作 | 复杂度）。
2. 找出这五讲里**重复出现**的模式。你会发现：
   - 「用一个 header 结构包装指针」出现了三次（L15 `dict_header`、L21 `neighbor_header`、L26 `heap_header`），根因都是 **C 的值传递**。
   - 「先破坏、再局部修复」出现了四次（L11 扩容、L16 旋转、L24 合并、L26 sift）。
   - 「契约只写在接口上」出现了两次（L08 库设计、L14 泛型字典）。
3. 把找不到模式的那一讲重读一遍——通常说明你还没抓住它的核心。

### 3.3 考试前的最后检查

15-122 的笔试（Written Exam）重点在**证明**而非编码。考前应该能做到：

- [ ] 给定一段带循环的代码，**在 15 分钟内**写出 INIT / PRES / EXIT / TERM 四步证明。
- [ ] 给定一个数据结构，写出它的不变式谓词（C0 或伪代码），并指出「如果去掉某一条会出什么错」。
- [ ] 给定两段算法，比较复杂度并说明**差在哪一项**（不是笼统地说「更快」）。
- [ ] 手算：AVL 插入后的旋转序列、并查集的数组状态、堆的 sift 过程、字节码的栈变化。
- [ ] 说出 C0 与标准 C 的至少五处差异，并各举一个会因此出错的例子。

## 四、常见误区

| 误区 | 表现 | 纠正 |
|---|---|---|
| 把 sample solution 当阅读理解 | 「看懂了」但自己写不出来 | 合上答案重写，写完逐行对照 |
| 只跑测试不写契约 | 测试全绿就以为对了 | 测试只覆盖有限输入；契约覆盖任意输入。用 `-d` 跑 |
| 跳过「找反例」类习题 | 觉得不如写代码有用 | 找反例是理解「为什么需要这条前置条件」的唯一途径 |
| 把 Big-O 当性能测试 | 说「这个更快」但说不出为什么 | Big-O 描述的是增长速率，不是绝对时间；要说清是哪一项主导 |
| 认为 L17 之后还能靠 `coin` | 用 C0 的思维写 C | L17 起契约不再被检查，内存要手动管理，必须用 valgrind |
| 只做讲义习题不看代码包 | 缺少「完整程序」的经验 | 代码包里有接口、实现、测试三层结构，这是讲义给不了的 |
