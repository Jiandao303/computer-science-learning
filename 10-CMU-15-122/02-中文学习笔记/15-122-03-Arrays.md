# 第 3 讲：数组（Arrays）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 写出 `t[]` 类型、用 `alloc_array(t, n)` 分配数组，并解释为什么一个 10 元素的数组变量里存的是「地址」而不是元素本身。
2. 说明 C0 中数组访问越界的后果，并对比标准 C 的「未定义行为」与缓冲区溢出攻击的关系。
3. 用 `\length(A)` 在契约中描述数组长度，为返回数组的函数写出有意义的后置条件。
4. 对遍历数组的 `for` 循环写出**能证明下标安全**的循环不变式（上界由守卫给出、下界由不变式给出），并完成 INIT / PRES / EXIT / TERM 四段证明。
5. 解释 Aliasing（别名）的语义：`B = A` 复制的是地址；并写出正确的数组拷贝函数。
6. 说明 C0 为什么在运行时保存数组长度却不让程序读取它，以及垃圾回收（Garbage Collection）在这里的作用。

## 3. 核心概念

**Array（数组）**：存放**固定数量**、**同一类型**元素的聚合数据结构。类型写作 `t[]`，例如 `int[]`、`bool[]`、`char[][]`。

**alloc_array（分配数组）**：C0 中创建数组的唯一方式，`alloc_array(t, n)` 分配 n 个类型为 t 的元素，返回该数组的**地址**。n 为负会失败。

**Zero-based（零基）**：元素编号从 0 开始，长度为 n 的数组合法下标是 `0, 1, ..., n-1`。

**Safe（安全）**：讲义的定义——「程序执行不会因异常条件而中止」。到目前为止，除法/取模（除零、`int_min() / -1`）与数组越界是仅有的两类潜在不安全操作。**安全是需要证明的**，不是祈祷出来的。

**`\length(A)`**：契约语言中的特殊函数，返回数组 A 的元素个数。它**只能在契约与断言中使用**，不能出现在 C0 程序代码里。

**Aliasing（别名）**：两个数组变量持有同一个地址。此时通过一个变量修改元素，另一个变量看到的内容也会改变。

**Garbage Collection（垃圾回收）**：C0 不提供显式释放内存的操作。运行时自动回收「从当前程序已无法访问」的内存，供后续 `alloc_array` 使用。

**Buffer Overflow（缓冲区溢出）**：标准 C 中越界访问会写到不该写的内存位置，可被利用来劫持程序控制流。C0 用边界检查消除这一类攻击面。

## 4. 通俗理解

**数组 = 一排带编号的储物柜**。`alloc_array(int, 10)` 是向管理员租下 10 个连续柜子；变量 `A` 里存的不是柜子里的东西，而是**第一排柜子的位置编号**（讲义里是 `0xECE2FFF0` 这样的十六进制地址）。所以 `A[3]` 的含义是「从 A 指的那一排起，数到第 3 号柜」。

这解释了两件事：

- 为什么 `B = A` 之后改 `B[0]` 会连带改掉 `A[0]`：两个变量记的是**同一个位置编号**，就像两个人拿了同一把钥匙。
- 为什么必须传长度：C0 不让你从数组里问出「这一排有几个柜子」。管理员知道，但不告诉你——因为标准 C 也不知道，C0 故意模拟这种「必须自己记住长度」的现实。

**循环不变式在这里的作用**是「下标安全带」：`i < n` 这个上界由循环守卫直接给出，而 `0 <= i` 必须由不变式提供，两者合起来才保证 `A[i]` 不越界。

## 5. 原理与推导

### 5.1 为什么数组变量存的是地址

C0 的变量只能存放**机器字长**（32 位）的值。一个 10 元素的 `int` 数组需要 10 个机器字，装不进一个变量。于是语言设计为：变量里放**首元素的内存地址**，元素按顺序连续排列。

推论：

1. 数组是**引用语义**：赋值复制地址，不复制内容。
2. `A[i]` 的地址可以算作「首地址 + i × 元素大小」，这也是数组能 O(1) 随机访问的根本原因。
3. 地址的具体数值是实现细节。讲义明确说：下次运行 `coin` 可能得到完全不同的地址，而且**你永远不需要、也无法把它当数字用**。

### 5.2 边界检查与安全性证明

`alloc_array(int, 10)` 之后，合法访问是 `A[0]` 到 `A[9]`。讲义实测：

```
--> A[10];
Error: accessing element 10 in 10-element array
--> A[-1];
Error: accessing negative element in 10-element array
```

**为什么这是「安全」问题而不是「方便」问题**：在标准 C 中没有这种检查。越界写会落到某个未分配的内存位置，可能是另一个变量的存储、可能是返回地址——这正是缓冲区溢出攻击的原理。C0 选择在运行时检查，把「未定义行为」变成「明确报错」。

但检查只保证**运行时**不会越界；本课程要求的是**静态地证明**不会越界，这样程序在**任何**输入下都安全，而不是靠碰运气没触发。

### 5.3 数组的默认初始化

分配后所有元素为 0（`int` 的默认值；其他类型有各自默认值）。这是实现保证的，但讲义建议：**不要依赖隐式初始化**——对读代码的人来说，分不清「这里靠默认值」还是「这里忘了赋值」。

### 5.4 遍历数组的标准模式与不变式

```c0
for (int i = 0; i < n; i++)
//@loop_invariant 0 <= i;
{
  A[i] = i * i * i;
}
```

**安全性证明（这是本讲的核心技能）**，要证每次执行 `A[i]` 时 `0 <= i < \length(A)`：

- **上界**：循环守卫给出 `i < n`；由分配语句 `A = alloc_array(int, n)` 且 `n` 在循环中未被修改，得 `\length(A) == n`；故 `i < \length(A)`。
- **下界**：守卫 `i < n` 不提供任何下界信息（`i` 完全可能是负数），所以必须由不变式 `0 <= i` 提供。

**为什么不能用「i 从 0 开始只增不减，所以不会负」这种说法**：这是操作性推理（operational reasoning），本课程明确禁止。而且它在有溢出时是错的——若 `i` 已经接近 `int_max()`，`i++` 会回绕成负数。把结论写成不变式后，PRES 步骤里必须显式论证 `i' = i + 1` 不会溢出成负数，这个漏洞才被堵上。

**INIT**：`i = 0`，故 `0 <= 0` 成立。
**PRES**：设 `0 <= i` 且守卫 `i < n` 成立。`i' = i + 1`。由 `i >= 0` 得 `i' >= 1 > 0`。又由 `i < n <= int_max()` 知 `i + 1` 不溢出，故 `0 <= i'`。
**TERM**：`n - i` 每轮严格减 1，下界 0。

### 5.5 完整示例：`cubes` 的规格演化

**第一版（无规格）**：

```c0
int[] cubes(int n) {
  int[] A = alloc_array(int, n);
  for (int i = 0; i < n; i++) {
    A[i] = i * i * i;
  }
  return A;
}
```

看起来没问题，但有两个隐藏前提：

1. `alloc_array(int, n)` 在 `n < 0` 时会失败 → 需要前置条件 `n >= 0`。
2. 返回值是一个数组，后置条件该说什么？→ 需要 `\length(\result) == n`。

**第二版（加契约）**：

```c0
int[] cubes(int n)
//@requires n >= 0;
//@ensures \length(\result) == n;
```

**为什么后置条件只写长度不够**：`\length(\result) == n` 只说明尺寸对，没说明内容对。要说明内容，需要引入**规格函数**（specification function），即一个只用于描述的纯函数——这正是 5.6 节 `same_segs` 的作用。

### 5.6 用规格函数描述「内容」

习题 1 的答案给出 `same_segs`：判断两段等长区间是否逐元素相同。

```c0
bool same_segs(int[] A, int loA, int hiA,
               int[] B, int loB, int hiB)
//@requires 0 <= loA && loA <= hiA && hiA <= \length(A);
//@requires 0 <= loB && loB <= hiB && hiB <= \length(B);
//@requires hiA - loA == hiB - loB;
```

三条前置条件缺一不可：
- 前两条保证两段下标都合法（否则函数自己就不安全）；
- 第三条保证两段**等长**（否则「逐元素比较」没有意义，也保证不了循环能同时走完）。

它的循环用**两个下标 i、j 同步推进**，因此需要三条不变式：

```c0
//@loop_invariant loA <= i && i <= hiA;
//@loop_invariant loB <= j && j <= hiB;
//@loop_invariant hiA - i == hiB - j;
```

第三条是「同步性」不变式：它保证只要 `i` 没走到 `hiA`，`j` 就一定没走到 `hiB`，所以在循环体内 `B[j]` 一定安全。讲义用一条 `//@assert j < hiB;` 把这个推理显式标出来：

```
To Show: j < hiB
a. i < hiA            由循环守卫（第 9 行）
b. hiA - i > 0        由 (a) 与数学
c. hiA - i == hiB - j 由不变式（第 12 行）
d. hiB - j > 0        由 (b)(c)
e. j < hiB            由 (d)
```

**这正是数组安全证明的范式**：从一个下标的安全，经一条等式不变式，推出另一个下标的安全。

### 5.7 `array_part`：带偏移的复制

```c0
int[] array_part(int[] A, int lo, int hi)
//@requires 0 <= lo && lo <= hi && hi <= \length(A);
//@ensures same_segs(A, lo, hi, \result, 0, hi-lo);
{
  int[] res = alloc_array(int, hi-lo);
  for (int i = lo; i < hi; i++)
  //@loop_invariant lo <= i && i <= hi;
  //@loop_invariant same_segs(A, lo, i, res, 0, i-lo);
  {
    res[i-lo] = A[i];
  }
  return res;
}
```

要点：

- **分配长度** `hi - lo`：因为 `lo <= hi`（前置条件），这个值非负，分配安全。
- **写位置** `res[i-lo]`：`i` 从 `lo` 走到 `hi-1`，所以 `i-lo` 从 0 走到 `hi-lo-1`，正好覆盖 `res` 的全部下标。**偏移量是这套写法的关键**，写错成 `res[i]` 就会越界。
- **不变式 `lo <= i && i <= hi`** 同时提供上下界：上界 `i <= hi` 配合守卫 `i < hi` 证明读安全；`i >= lo` 配合 `i <= hi` 证明 `i-lo` 落在 `[0, hi-lo]`，证明写安全。
- **内容不变式 `same_segs(A, lo, i, res, 0, i-lo)`** 说的是「已经复制完的那部分两段相同」。这里用了「前缀」式表述：区间右端点是 `i`，随着循环推进而增长。

**EXIT 的推导**：由守卫取反 `i >= hi` 与不变式 `i <= hi` 得 `i == hi`，代入内容不变式即得后置条件 `same_segs(A, lo, hi, res, 0, hi-lo)`。**注意 `i >= hi` 单独不够，必须靠不变式补上 `i <= hi`**——这与第 1 讲 `e >= 0` 的故事是同一个模式。

### 5.8 别名（Aliasing）的语义

讲义用 `coin` 演示：

```
--> int[] A = alloc_array(int, 5);   A is 0xE8176FF0 (int[] with 5 elements)
--> int[] B = A;                     B is 0xE8176FF0 (int[] with 5 elements)
--> A[0] = 42;                       A[0] is 42 (int)
--> B[0];                            42 (int)
```

`B = A` 只复制了地址，所以 `A` 与 `B` 是**别名**。反之：

```
--> F = cubes(15);   F is 0xF6969A80 (int[] with 15 elements)
--> G = F;           G is 0xF6969A80
--> G = cubes(10);   G is 0xF6969A30 (int[] with 10 elements)
```

第二次赋值给 `G` 换了一个**新地址**，于是 `G` 与 `F` 不再别名，`F` 的 15 元素数组原封不动。

**未初始化变量的错误**：`int[] G;` 只声明不赋值，随后 `G[2]` 会报 `Error: uninitialized value used`。这说明「声明」与「赋值」是两件事，与 Java 的「数组变量自动为 null」不同。

### 5.9 正确的数组拷贝

C0 没有内建拷贝。要真拷贝必须新建数组并逐元素复制：

```c0
int[] array_copy(int[] A, int n)
//@requires n == \length(A);
//@ensures \length(\result) == n;
{
  int[] B = alloc_array(int, n);
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i;
  {
    B[i] = A[i];
  }
  return B;
}
```

前置条件 `n == \length(A)` 是**必须的**：若 `n > \length(A)`，读 `A[i]` 会越界；若 `n < \length(A)`，只复制前缀（语义上也许可接受，但必须写清楚）。

验证效果（`-d` 模式）：拷贝后改 `A[9] = 17`，`B[9]` 仍是 81，证明二者不别名。

**为什么后置条件还应该更强**：真正完整的拷贝契约应写成 `same_segs(A, 0, n, \result, 0, n)`，否则「返回一个长度正确但内容全 0 的数组」也满足契约。这是第 1 讲「契约要恰好表达意图」的再次体现。

### 5.10 运行时的长度与 `\length` 的分工

为了让边界检查可行，C0 运行时必须在数组旁边保存长度。但**程序代码无法读取它**——这是刻意模拟 C 的实践：C 的数组不带长度，所以函数必须额外传长度参数。

于是形成分工：

| 场景 | 能否得到长度 | 做法 |
|---|---|---|
| 普通 C0 代码（循环、函数体） | 不能 | 额外传 `n` 参数，并在契约里约束 `n == \length(A)` |
| 契约（`@requires`、`@ensures`、`@loop_invariant`、`@assert`） | 能 | 直接用 `\length(A)` |

`\length` 与 `\result` 一样，属于**契约语言**，不是 C0 语言的一部分。

### 5.11 `int f(int[] A);` 为什么不可能有用

习题 3 问：能不能写出一个有意义的 `int f(int[] A)`？

答案是不能。因为**没有长度参数**，你无法证明任何 `A[i]` 访问是安全的，于是你连一个元素都读不到；读不到任何元素，就没有任何信息可以返回。唯一的合法实现是 `return 0;` 这类不接触数组的退化函数——它有用吗？显然没有。

这个练习说明了一个深刻的设计后果：**C0 里「数组」与「长度」必须成对传递，否则函数根本无法访问数组内容。**

### 5.12 内存图与垃圾回收

习题 4 的程序逐步构造出三种内存状态：

- **第 7 行**：`A` 与 `B` 指向同一个 3 元素数组（别名）。
- **第 13 行**：`C` 指向一个新分配的 3 元素数组，内容从 `A` 逐元素复制；此时有 4 个变量/数组对象参与。
- **第 19 行**：`A = C` 后 `A` 指向 C 的数组；`B = alloc_array(int, 2)` 后 `B` 指向新的 2 元素数组。**第 2 行分配的那个 3 元素数组已经没有任何变量指向它**——它被标记为可回收（garbage collected）。

**为什么需要垃圾回收**：C0 没有 `free`，若不可达的内存永远不回收，长时间运行的程序会耗尽内存。GC 的判据是「可达性」：从当前活跃的变量出发能否走到。走不到就是垃圾。

**（3）规格函数 `same_segs`，第 12 页：**

```c0
bool same_segs(int[] A, int loA, int hiA,
               int[] B, int loB, int hiB)
//@requires 0 <= loA && loA <= hiA && hiA <= \length(A);
//@requires 0 <= loB && loB <= hiB && hiB <= \length(B);
//@requires hiA - loA == hiB - loB;
{
  int i = loA;
  int j = loB;
  while (i < hiA)
  //@loop_invariant loA <= i && i <= hiA;
  //@loop_invariant loB <= j && j <= hiB;
  //@loop_invariant hiA - i == hiB - j;
  {
    //@assert j < hiB;
    if (A[i] != B[j])
      return false;
    i++;
    j++;
  }
  return true;
}
```

**（5）跨数组复制 `copy_into`，第 16 页：**

```c0
int copy_into(int[] source, int i, int n, int[] target, int j)
//@requires n >= 0;
//@requires 0 <= i && i+n <= \length(source);
//@requires 0 <= j && j+n <= \length(target);
//@ensures same_segs(source, i, i+n, target, j, j+n);
//@ensures (n == 0 && \result == -1) || (n > 0 && \result == j+n-1);
{
  for (int x = 0; x < n; x++)
  //@loop_invariant 0 <= x && x <= n;
  //@loop_invariant same_segs(source, i, i+x, target, j, j+x);
  {
    target[j+x] = source[i+x];
  }

  if (n == 0)
    return -1;
  return j + n - 1;
}
```

注意前置条件 `i+n <= \length(source)` 的写法：它比 `i+n-1 < \length(source)` 更简洁，且当 `n == 0` 时也自然成立（此时 `i <= \length(source)`）。这类「用加法代替减法避免下溢」的写法在边界推理中非常常见。

**示例 A：原位反转数组（练习「双下标 + 交叉不变式」）。**

```c0
void reverse(int[] A, int n)
//@requires n == \length(A);
//@ensures same_segs(A, 0, n, \old(A), 0, n);   /* 概念示意，\old 在 C0 中不可用 */
{
  int i = 0;
  int j = n - 1;
  while (i < j)
  //@loop_invariant 0 <= i && i <= j + 1;
  //@loop_invariant j < n;
  {
    int tmp = A[i];
    A[i] = A[j];
    A[j] = tmp;
    i = i + 1;
    j = j - 1;
  }
}
```

（后置条件里的 `\old(A)` 是概念性写法，C0 的契约语言没有这个操作符，实际要描述「反转」需另定义规格函数。此处标 `> 待核实`：C0 是否提供 `\old` 需查官方文档。）

**示例 B：线性查找，返回下标或 −1（本讲与下一讲的衔接）。**

```c0
int find(int[] A, int n, int x)
//@requires n == \length(A);
//@ensures \result == -1 || (0 <= \result && \result < n);
{
  int i = 0;
  while (i < n)
  //@loop_invariant 0 <= i && i <= n;
  //@loop_invariant \forall(int k; 0 <= k && k < i; A[k] != x);
  {
    if (A[i] == x) return i;
    i = i + 1;
  }
  return -1;
}
```

第二条不变式表达「已经看过的部分都不等于 x」。它既是正确性论证的核心，也是下一讲 [[15-122-04-Searching-Arrays]] 讨论「循环不变式与查找正确性」的起点。`\forall` 的量词写法见 C0 契约语言文档，`> 待核实`：具体语法以官方 `cc0` 文档为准。

**示例 C：故意写错的不变式，观察 `-d` 报错。**

```c0
int sum_array(int[] A, int n)
//@requires n == \length(A);
{
  int s = 0;
  for (int i = 0; i <= n; i++)   /* 故意的 off-by-one */
  //@loop_invariant 0 <= i && i <= n;
  {
    s = s + A[i];                 /* i == n 时越界 */
  }
  return s;
}
```

守卫写成 `i <= n` 时，最后一轮 `i == n`，`A[n]` 越界。加上 `-d` 后 `coin` 会在该行报 `Error: accessing element n in n-element array`。**这个例子说明：不变式写对了也不够，循环守卫本身必须与不变式的边界一致。**

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| `B = A`（数组赋值） | `B[i] = A[i]`（元素赋值） | 前者复制**地址**（产生别名）；后者复制**值** | 赋值左边是变量还是元素 |
| 数组的「长度」 | 数组的「内容」 | `\length(\result) == n` 只说尺寸；内容需 `same_segs` | 尺寸 ≠ 内容 |
| `\length(A)`（契约语言） | 程序里的长度参数 `n` | 前者只能写在契约/断言里；后者是普通 `int` 参数 | 一个在注解里，一个在代码里 |
| 越界检查（C0） | 未定义行为（标准 C） | C0 报错并中止；C 可能静默破坏其他内存 | C0 安全，C 不安全 |
| 操作性推理「i 只增所以不负」 | 不变式 `0 <= i` | 前者被本课程禁止，且在溢出时错误；后者可被 INIT/PRES 证明 | 写下来才算证明 |
| 别名（aliasing） | 拷贝（copy） | 别名共享数据，改一处影响两处；拷贝各自独立 | 一把钥匙 vs 两把钥匙 |
| `A[i]` 中 i 的上界来源 | i 的下界来源 | 上界来自**循环守卫** `i < n`；下界必须来自**不变式** | 守卫只给一半 |
| 垃圾（garbage） | 泄漏（leak） | 前者是「不可达但会被回收」；后者是「不可达且永不回收」 | C0 有 GC，无泄漏概念 |

## 10. 本节复习

1. `t[]` 是数组类型；`alloc_array(t, n)` 分配 n 个元素并返回地址；长度为 n 的合法下标是 `0..n-1`。
2. 数组变量存的是地址，所以赋值是引用语义，`B = A` 产生别名。
3. C0 越界会报错；标准 C 是未定义行为，可被用于缓冲区溢出攻击。
4. `\length(A)` 只在契约与断言中可用；程序代码里必须额外传长度参数。
5. 数组访问的安全性证明：**上界来自循环守卫 `i < n` 与 `\length(A) == n`；下界来自不变式 `0 <= i`**。
6. 不变式必须能覆盖「偏移」：`res[i-lo]` 的安全依赖 `lo <= i && i <= hi`。
7. 内容正确性要用规格函数（如 `same_segs`）写进后置条件，只写长度不够。
8. `same_segs` 的多下标循环需要「同步不变式」`hiA - i == hiB - j` 才能证明第二个下标安全。
9. 完整的循环验证有四项：INIT、PRES、EXIT、TERM。
10. C0 有垃圾回收，没有显式 `free`；不可达的数组会被回收。
11. `int f(int[] A)` 无法写出有意义的实现，因为没有长度就无法安全访问任何元素。

## 11. 自我检查

**题 1.** 对下面这个循环，写出证明 `A[i]` 安全所需的全部事实，并指出哪一条来自循环守卫、哪一条必须写成不变式。
```c0
for (int i = 0; i < n; i++)
//@loop_invariant ???;
{
  A[i] = A[i] * 2;
}
```
（假设函数有 `//@requires n == \length(A);`）

**题 2.** 说明为什么 `array_part` 里必须写 `res[i-lo]` 而不能写 `res[i]`，并给出一个具体的越界输入。

**题 3.** 下面这段代码「看起来」完成了拷贝，请指出它的契约缺陷：
```c0
int[] bad_copy(int[] A, int n)
//@requires n == \length(A);
//@ensures \length(\result) == n;
{
  int[] B = alloc_array(int, n);
  return B;
}
```

**题 4.** 判断正误并说明理由：「因为 `i` 从 0 开始每轮加 1，所以 `A[i]` 永远不会用负下标访问。」

**题 5.** 在 `same_segs` 中，如果删掉不变式 `hiA - i == hiB - j`，`//@assert j < hiB;` 还能被证明吗？为什么？

<details>
<summary>参考答案</summary>

**答 1.** 需要三条事实：
- `i < n`：来自**循环守卫**。
- `\length(A) == n`：来自**前置条件**（且 `n` 未被修改）。
- `0 <= i`：必须写成**循环不变式**（守卫不提供任何下界）。

三者合起来给出 `0 <= i < \length(A)`，即 `A[i]` 合法。不变式应写 `//@loop_invariant 0 <= i;`。

**答 2.** `i` 的取值范围是 `[lo, hi)`，而 `res` 的长度是 `hi - lo`，合法下标是 `[0, hi-lo)`。若写 `res[i]`，当 `lo > 0` 时下标就整体偏移了。具体反例：`A` 长度 10，调用 `array_part(A, 3, 5)`，则 `res` 长度 2，循环中 `i` 依次取 3、4，`res[3]`、`res[4]` 都越界（合法只有 `res[0]`、`res[1]`）。正确写法 `res[i-lo]` 得到 `res[0]`、`res[1]`。

**答 3.** 后置条件太弱。它只保证返回数组长度为 n，而函数体只是分配了数组、从未写入，返回的是全 0 数组。这个实现满足契约，却完全不是「拷贝」。正确写法是加一条内容条件，例如 `//@ensures same_segs(A, 0, n, \result, 0, n);`。这也说明：**契约检查器不会替你判断契约是否表达了真实意图**。

**答 4.** 错误，两个层面都错。
（a）方法论上：这是操作性推理，本课程禁止用它代替不变式证明。
（b）事实上：若 `n` 接近 `int_max()`，`i` 递增到 `int_max()` 后再加 1 会回绕成 `int_min()`（负数），此时 `i < n` 仍可能成立（因为 `int_min() < n`），循环继续，`A[i]` 就会用负下标访问。所以「只增所以不负」在溢出面前是错的。正确做法是把 `0 <= i` 写成不变式，并在 PRES 中显式论证 `i+1` 不溢出。

**答 5.** 不能。`//@assert j < hiB;` 需要 `hiB - j > 0`。已知的是守卫 `i < hiA`，即 `hiA - i > 0`；要把这个正数「转移」到 `hiB - j` 上，唯一的桥梁就是等式 `hiA - i == hiB - j`。删掉它之后，`j` 与 `i` 之间再无联系，`j` 完全可能已经等于 `hiB`（甚至更大），断言无法证明，`B[j]` 的访问也就失去了安全保障。

</details>
