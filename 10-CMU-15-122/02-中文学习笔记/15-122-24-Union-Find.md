# 第 24 讲：并查集（Union-Find）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 说明**等价关系**（equivalence relation）的三个性质（自反、对称、传递），并解释为什么「生成树中的连通性」是一个等价关系。
2. 说明并查集（Union-Find / Disjoint Set）的抽象接口：`find` 与 `union`，以及它维护的**划分**（partition）不变式。
3. 用「每个等价类选一个规范代表（canonical representative）」的思路实现并查集，并分析基本版 `find` O(v)、`union` O(1) 的代价。
4. 实现**按高度合并**（union by height / rank）：用「根位置存 `−h`」的技巧同时编码「是否根」与「高度」。
5. 完整证明关键引理：**高度为 `h` 的树至少有 `2^(h−1)` 个节点**，并由此推出 `h ≤ log v`。
6. 推导 Kruskal 配并查集后的复杂度 **O(e log e)**，说明瓶颈从「判环」转移到「排序」。
7. 说明**路径压缩**（path compression）的原理，并知道它的摊还复杂度是 O(1 + A⁻¹(v))，其中 A 是 Ackermann 函数。

## 3. 核心概念

**Equivalence Relation（等价关系）**：满足三条性质的二元关系 `~`：自反 `a ~ a`、对称 `a ~ b ⇒ b ~ a`、传递 `a ~ b ∧ b ~ c ⇒ a ~ c`。

**Equivalence Class（等价类）**：`[a] = {x : x ~ a}`。等价关系把集合**划分**成互不相交的等价类。

**Partition（划分）**：把集合分成若干非空、互不相交、并集为全集的子集。

**Canonical Representative（规范代表）**：每个等价类选一个元素作为「代表」。`find(a)` 返回 `a` 所属类的代表。`a ~ b ⟺ find(a) == find(b)`。

**Union-Find / Disjoint Set（并查集）**：维护一个动态划分的数据结构，支持 `find`（查代表）与 `union`（合并两类）。

**Union by Height / Rank（按高度/秩合并）**：合并时把矮树挂到高树下，保证树高只在对等高度时增加 1。

**Path Compression（路径压缩）**：`find` 时把路径上所有节点直接指向根，压平树。

**Amortized Analysis（摊还分析）**：把「偶尔很贵」的操作成本分摊到「大量便宜」的操作上，得到「平均每次」的界。

## 4. 通俗理解

**并查集 = 「谁和谁是一伙的」查询系统**。每个人报出一个「老大」的名字，同一个老大的人就是一伙。`find(x)` 问「你的老大是谁」，`union(x,y)` 说「你们两伙合并，选一个当老大」。

**「根存 `−h`」的技巧 = 用一张表格同时记两件事**。数组 `A[i]`：

- 若 `A[i] = i`：`i` 自己是根（老大）。
- 若 `A[i] < 0`：`i` 是根，且这棵树的高度是 `−A[i]`。
- 若 `A[i] ≥ 0`：`i` 不是根，`A[i]` 是它的父节点。

**一个格子，三种含义**。这是「用符号位当标记」的经典技巧——省掉一个 `bool is_root[]` 数组。

**按高度合并 = 「小公司并入大公司」**。两家公司合并，通常保留大公司的名字。这样「从员工找到老板」的层级不会越来越深。

**路径压缩 = 「扁平化管理」**。每次有人问「我的老大是谁」，就顺手把沿途所有人的直接上级都改成老大本人。下次再问就一步到位。

**为什么 Kruskal 需要并查集**：Kruskal 的核心问题是「这条边的两端是否已经连通」。用 DFS 每次 O(v+e)，太慢。并查集把这个查询降到近 O(1)——**这就是为什么 Kruskal 能成为实用算法**。

## 5. 原理与推导

### 5.1 等价关系与划分

**定义**：集合 `S` 上的关系 `~` 是等价关系，当且仅当：

1. **自反**：`∀a ∈ S, a ~ a`。
2. **对称**：`∀a,b ∈ S, a ~ b ⇒ b ~ a`。
3. **传递**：`∀a,b,c ∈ S, a ~ b ∧ b ~ c ⇒ a ~ c`。

**等价类**：`[a] = {x ∈ S : x ~ a}`。

**基本定理**：等价关系的等价类构成 `S` 的一个**划分**——互不相交，并集为 `S`。

*证明*：

- **非空**：由自反，`a ∈ [a]`。
- **覆盖**：每个 `a` 都在 `[a]` 里，所以并集是 `S`。
- **互不相交**：设 `[a] ∩ [b] ≠ ∅`，取 `c` 在其中，则 `c ~ a` 且 `c ~ b`。由对称 `a ~ c`，由传递 `a ~ b`。于是对任意 `x ∈ [a]`，`x ~ a ~ b` ⇒ `x ∈ [b]`，所以 `[a] ⊆ [b]`；对称地 `[b] ⊆ [a]`。因此 `[a] = [b]`。∎

**为什么「连通性」是等价关系**：

- 自反：`u` 到 `u` 有长度 0 的路径（第 22 讲）。
- 对称：无向图的路径可反向走。
- 传递：路径可拼接（第 22 讲 5.1 节）。

**所以**：图的顶点被划分成**连通分量**。「`u` 与 `v` 连通吗」等价于「`find(u) == find(v)`」。

**注意**：如果是有向图，连通性**不是**等价关系（不对称）。所以并查集只适用于无向图。

### 5.2 并查集的接口与不变式

**接口**：

```c
typedef struct ufs_header *ufs;

ufs  ufs_new(unsigned int n);              /* 创建 n 个单元素类 */
void ufs_free(ufs eqs);
unsigned int ufs_find(ufs eqs, unsigned int a);   /* 返回 a 的代表 */
void ufs_union(ufs eqs, unsigned int a, unsigned int b);  /* 合并两类 */
```

**抽象不变式**：

1. `0 <= a < n` 对所有操作。
2. 内部维护一个划分：`n` 个元素被分成若干互不相交的类。
3. `ufs_find(eqs, a)` 返回 `a` 所在类的**规范代表**。
4. `a ~ b ⟺ ufs_find(eqs, a) == ufs_find(eqs, b)`。

**`ufs_union` 的后置条件**：合并后 `a` 与 `b` 在同一类，其他类不变。

**表示层不变式**（数组实现）：

```
A[i] == i          ⇒ i 是根（代表）
A[i] >= 0          ⇒ i 的父节点是 A[i]
A[i] <  0          ⇒ i 是根，树高为 -A[i]
```

**关键性质**：从任意 `i` 出发反复取父节点（`i = A[i]`）必然到达一个根。**这保证 `find` 终止。**

*为什么必然终止*：数组大小有限（`n` 个元素），若路径无限长必然重复访问某节点，形成环。但环上的节点都不是根（都有父节点），而根是唯一的「出口」——一个环无法从任何地方进入（因为每个节点只有一个父节点，环外的节点不可能指向环内而不形成更长链……严格说需要「每个节点最多一个父节点 + 根自指」的结构保证无环）。讲义用「高度」的归纳来保证这一点。

### 5.3 基本版：朴素 union

```c
struct ufs_header {
  unsigned int size;
  int *A;              /* 长度 size */
};

ufs ufs_new(unsigned int n) {
  ufs eqs = xmalloc(sizeof(struct ufs_header));
  eqs->size = n;
  eqs->A = xmalloc(n * sizeof(int));
  for (unsigned int i = 0; i < n; i++) eqs->A[i] = i;   /* 各自为根 */
  return eqs;
}

unsigned int ufs_find(ufs eqs, unsigned int a) {
  while (eqs->A[a] != (int)a)     /* 不是根就往上走 */
    a = eqs->A[a];
  return a;
}

void ufs_union(ufs eqs, unsigned int a, unsigned int b) {
  unsigned int ra = ufs_find(eqs, a);
  unsigned int rb = ufs_find(eqs, b);
  if (ra != rb) eqs->A[ra] = rb;   /* 把 ra 挂到 rb 下 */
}
```

**复杂度**：

- `ufs_new`：O(n)。
- `ufs_find`：O(h)，`h` 是树高。最坏 O(n)（退化成链）。
- `ufs_union`：两次 `find` + O(1) ⇒ O(h)。

**退化例子**：依次 `union(0,1), union(1,2), union(2,3), …, union(n−2,n−1)`。

- `union(0,1)`：`A[0] = 1`，树 `0 → 1`。
- `union(1,2)`：`find(1) = 1`，`find(2) = 2`，`A[1] = 2`，树 `0 → 1 → 2`。
- `union(2,3)`：`A[2] = 3`，树 `0 → 1 → 2 → 3`。
- ……

最终是一条长度 `n−1` 的链。`find(0)` 要 O(n) 步。

**Kruskal 配这个版本**：`e` 次 `find`，每次 O(v)，总计 **O(ev)**——**和边中心算法一样慢**。这就是为什么需要「按高度合并」。

### 5.4 按高度合并（union by height）

**规则**：合并两棵树时，把**矮的**挂到**高的**下面。

- `h₁ > h₂`：把 `T₂` 挂到 `T₁` 下，新高度 `h₁`。
- `h₁ < h₂`：把 `T₁` 挂到 `T₂` 下，新高度 `h₂`。
- `h₁ == h₂`：任选一个挂到另一个下，新高度 `h₁ + 1`。

**为什么这样能控制高度**：只有当两棵树**等高**时，高度才增加 1。而「高度增加」需要「节点数至少翻倍」（见 5.5 节的引理）。所以高度增长是**对数级**的。

**实现技巧：根位置存 `−h`**。

```c
unsigned int ufs_find(ufs eqs, unsigned int a) {
  while (eqs->A[a] >= 0)          /* 非根：A[a] 是父索引 */
    a = (unsigned int)eqs->A[a];
  return a;                        /* A[a] < 0：a 是根 */
}

void ufs_union(ufs eqs, unsigned int a, unsigned int b) {
  unsigned int ra = ufs_find(eqs, a);
  unsigned int rb = ufs_find(eqs, b);
  if (ra == rb) return;

  int ha = -eqs->A[ra];            /* ra 的高度 */
  int hb = -eqs->A[rb];            /* rb 的高度 */

  if (ha > hb) {
    eqs->A[rb] = (int)ra;          /* 矮的 rb 挂到高的 ra 下 */
  } else if (hb > ha) {
    eqs->A[ra] = (int)rb;
  } else {                          /* 等高：合并后高度 +1 */
    eqs->A[rb] = (int)ra;
    eqs->A[ra] = -(ha + 1);
  }
}
```

**初始化**：`A[i] = -1`（每个节点是根，高度 1）。

**为什么用 `−h` 而不是 `h`**：因为 `0` 已经被「指向索引 0」占用了。如果用 `A[i] = h` 表示根，`h = 0` 会与「父节点是 0 号」混淆。用负数就彻底分开了——**这是「用符号位当标记」的经典应用**。

**注意高度从 1 开始**（单节点树高度 1），所以 `A[i] = -1`。这与第 16 讲 AVL 的「空树高度 0」不同，需要注意。

### 5.5 关键引理：高度 `h` 的树至少有 `2^(h−1)` 个节点

**陈述**：在「按高度合并」的并查集中，任何高度为 `h` 的树至少有 `2^(h−1)` 个节点。

**证明（对 `h` 强归纳）**：

**基础 `h = 1`**：高度 1 的树只有根一个节点。`2^(1−1) = 2^0 = 1` ✓。

**归纳 `h > 1`**：设 `T` 是高度为 `h` 的树。它是通过某次 `union` 由 `T₁`、`T₂` 合并而成（并查集的树只能通过 union 长大）。

由「按高度合并」规则，合并后高度为 `h` 只可能是三种情形之一：

**情形 A：`h₁ = h`、`h₂ < h`，`T₂` 挂到 `T₁` 下。** 此时 `T = T₁`（`T₂` 成为 `T₁` 根的一个子树，但 `T₁` 的根仍是根）。**等等——合并后 `T₁` 的根的子节点多了一个，高度可能变吗？** 不会：`T₂` 的高度 `< h`，所以 `T₁` 的根到 `T₂` 最远叶子的距离是 `1 + h₂ ≤ h`（因为 `h₂ ≤ h−1`），不超过 `h₁ = h`。所以合并后高度仍是 `h`。

`T` 的节点数 = `|T₁| + |T₂| ≥ 2^(h−1) + 2^(h₂−1) ≥ 2^(h−1) + 1 > 2^(h−1)` ✓。

**情形 B：`h₂ = h`、`h₁ < h`。** 对称，同上。

**情形 C：`h₁ = h₂ = h − 1`（等高合并，高度从 `h−1` 变成 `h`）。**

由归纳假设：`|T₁| ≥ 2^(h−2)`、`|T₂| ≥ 2^(h−2)`。

合并后：`|T| = |T₁| + |T₂| ≥ 2^(h−2) + 2^(h−2) = 2 · 2^(h−2) = **2^(h−1)**` ✓。

**三种情形都满足 `|T| ≥ 2^(h−1)`。** ∎

**推论 1**：`n` 个节点的树高度 `h ≤ log₂(n) + 1`。

*推导*：`n ≥ 2^(h−1)` ⇒ `log₂ n ≥ h − 1` ⇒ `h ≤ log₂ n + 1`。**O(log n)**。

**推论 2**：如果森林里有 `e_T` 条 union 操作（即「合并边」数），最高树高 ≤ `log₂(min(e_T + 1, n))`。

*推导*：每次 `union` 成功合并（`ra ≠ rb`）会让「树的数量」减 1。初始 `n` 棵树，做 `e_T` 次成功合并后剩 `n − e_T` 棵。含最多节点的树至少有 `n / (n − e_T)` 个节点……更简单的界：一棵高度 `h` 的树至少有 `2^(h−1)` 个节点，而节点总数 ≤ `n`，所以 `h ≤ log₂ n + 1`。另一方面，高度 `h` 的树需要至少 `h − 1` 次「等高合并」，而每次等高合并需要前一次也等高……**总合并次数 `e_T ≥ 2^(h−1) − 1`**（构造高度 `h` 的树最少需要 `2^(h−1) − 1` 次合并，即不断把等高的树两两合并）。所以 `h ≤ log₂(e_T + 1) + 1`。

取两者较小：**`h ≤ log(min(e_T + 1, n)) + O(1)`**。∎

**这意味着**：`find` 是 **O(log(min(e+1, v)))**。

### 5.6 Kruskal 配按高度合并的并查集

**复杂度**：

- 排序：O(e log e)。
- `e` 次 `find`（每次 union 两次 find）：`O(e · log(min(e+1, v)))`。
- 总计：`O(e log e + e log(min(e+1,v)))`。

**化简**：因为 `min(e+1, v) ≤ e + 1`，所以 `log(min(e+1,v)) ≤ log(e+1)`。于是第二项 `≤ O(e log e)`。

**总计 = O(e log e)**。

**关键洞察**：**瓶颈从「判环」转移到了「排序」**。

- 朴素并查集：判环 O(ev)，排序 O(e log e) ⇒ 总 O(ev)，判环是瓶颈。
- 按高度合并：判环 O(e log v)，排序 O(e log e) ⇒ 总 O(e log e)，**两者同级**。
- 路径压缩：判环近 O(e)，排序 O(e log e) ⇒ 总 O(e log e)，**排序是唯一瓶颈**。

**排序是下界**：比较排序至少要 `Ω(e log e)` 次比较。所以 **Kruskal 已经最优**（在比较模型下）。

**能否绕过排序**？如果边权是**小整数**（例如 0…255），可以用计数排序 O(e + k)，此时 Kruskal 变成 **O(e + k)**——线性！这是「利用输入特殊性突破一般下界」的例子。

### 5.7 路径压缩

**思想**：`find(a)` 走了一条路径 `a → p₁ → p₂ → … → root`。既然已经走到了根，顺手把这条路径上所有节点都直接指向根：

```
压缩前：a → p₁ → p₂ → root
压缩后：a → root, p₁ → root, p₂ → root
```

**实现（两遍法）**：

```c
unsigned int ufs_find(ufs eqs, unsigned int a) {
  unsigned int root = a;
  while (eqs->A[root] >= 0) root = (unsigned int)eqs->A[root];   /* 第一遍：找根 */

  while (a != root) {                    /* 第二遍：路径上每个节点指向根 */
    unsigned int next = (unsigned int)eqs->A[a];
    eqs->A[a] = (int)root;
    a = next;
  }
  return root;
}
```

**注意**：路径压缩会破坏「`A[root] = −h` 是精确高度」这个不变式——压缩后子树变浅，但 `−h` 没更新。所以压缩后的 `−A[root]` 只是高度的**上界**，不再精确。

**这会影响正确性吗**：不会。按高度合并只需要「大致知道谁更高」，用上界也能保证「矮的挂到高的下」——只是可能偶尔挂错（把实际更高的挂到实际更矮的下面），导致高度略增。但**引理的界仍然成立**（因为 `−A[root]` 只会**高估**高度，所以合并规则更保守）。

**更严格的说法**：路径压缩后，把 `−A[root]` 重新解释为**秩**（rank）而不是高度——秩是「这棵树在没有任何压缩时的高度上界」。按秩合并 + 路径压缩是标准组合。

**摊还复杂度**：`O(1 + A⁻¹(n))`，其中 `A` 是 **Ackermann 函数**，`A⁻¹` 是它的反函数。

**Ackermann 函数**：

```
Ack(m, n) = n + 1                          若 m = 0
          = Ack(m − 1, 1)                  若 m > 0 且 n = 0
          = Ack(m − 1, Ack(m, n − 1))      若 m > 0 且 n > 0
```

**增长极快**：

| `Ack(m,m)` | 值 |
|---|---|
| `Ack(0,0)` | 1 |
| `Ack(1,1)` | 3 |
| `Ack(2,2)` | 7 |
| `Ack(3,3)` | 61 |
| `Ack(4,4)` | 约 `2^(2^(2^65536))`，**远超宇宙原子数（约 10⁸⁰）** |

**`A⁻¹(n)` 是反函数**：`A⁻¹(n)` = 最小的 `m` 使 `Ack(m,m) ≥ n`。

- `n ≤ 1`：`A⁻¹ = 0`
- `n ≤ 3`：`A⁻¹ = 1`
- `n ≤ 7`：`A⁻¹ = 2`
- `n ≤ 61`：`A⁻¹ = 3`
- `n ≤ Ack(4,4)`：`A⁻¹ = 4`

**实际意义**：对于任何现实中的 `n`（哪怕 `n = 10^80`），`A⁻¹(n) ≤ 4`。所以**摊还复杂度实际上是 O(1)**——常数不超过 4。

**这就是为什么路径压缩 + 按秩合并被称为「近乎常数时间」**。理论上是 `O(A⁻¹(n))`，实践中就是 O(1)。

### 5.8 三种版本的实现对比

讲义第 10 页提到两个文件：

**`unionfind-lin.c`（线性版）**：

- 不追踪高度，`union` 直接把 `ra` 挂到 `rb` 下。
- 但 `find` 里有**弱路径压缩**：把路径上每个节点指向其**祖父**（而不是根）。
- 后置条件写成 `eqs->A[i] == ufs_find(eqs, i)`——这个条件在「指向祖父」时不成立，所以讲义说这是「弱」压缩。

**`unionfind-log.c`（对数版）**：

- 用高度追踪（`A[root] = −h`）。
- `find` 不做压缩。
- 保证 O(log v)。

**习题的方向**：

- **Ex1**：证明 `n` 次 `union` 后链长 O(log n)（这就是 5.5 节的引理）。
- **Ex2**：给 `unionfind-lin.c` 加强路径压缩（改成指向根）。
- **Ex3**：给 `unionfind-log.c` 加路径压缩——需要**放松不变式**，因为 `−h` 不再精确。

**Ex3 的难点**：如果 `find` 压缩了路径，`A[root]` 的值就不对了。解决方案：

- 把 `−A[root]` 重新解释为「秩」而非高度（秩只会被高估，不影响正确性）。
- 或者压缩时只把节点指向根的**子节点**（保留高度信息）。

**标准做法**是第一种：**按秩合并**（union by rank）。秩的定义是「如果从未压缩，这棵树的高度」——压缩不改变秩。

### 5.9 完整算例

讲义第 2–6 页的例子。6 个顶点 `A–F` 编号 `0–5`，边序 `AE, ED, FB, CF, AD, EF, CB`。

**边到编号**：`AE = (0,4)`、`ED = (4,3)`、`FB = (5,1)`、`CF = (2,5)`、`AD = (0,3)`、`EF = (4,5)`、`CB = (2,1)`。

**初始**：`A = [−1, −1, −1, −1, −1, −1]`（6 棵单点树）。

**（1）`union(0,4)`（AE）**：`find(0) = 0`、`find(4) = 4`。等高（都 1），`A[4] = 0`、`A[0] = −2`。

```
A = [−2, −1, −1, −1, 0, −1]
树：4 → 0（高度 2）
```

**（2）`union(4,3)`（ED）**：`find(4)`：`A[4] = 0 ≥ 0`，走 `A[0] = −2 < 0`，根是 0。`find(3) = 3`。`h(0) = 2 > h(3) = 1`，`A[3] = 0`。

```
A = [−2, −1, −1, 0, 0, −1]
树：3 → 0, 4 → 0（高度 2，三个节点）
```

**（3）`union(5,1)`（FB）**：等高，`A[1] = 5`、`A[5] = −2`。

```
A = [−2, 5, −1, 0, 0, −2]
```

**（4）`union(2,5)`（CF）**：`find(2) = 2`、`find(5) = 5`。`h(2) = 1 < h(5) = 2`，`A[2] = 5`。

```
A = [−2, 5, 5, 0, 0, −2]
树：2 → 5 → 1，高度 2
```

**（5）`union(0,3)`（AD）**：`find(0) = 0`、`find(3)`：`A[3] = 0`，根是 0。**同一棵树**！跳过。

```
A 不变
```

**（6）`union(4,5)`（EF）**：`find(4)`：`4 → 0`，根 0。`find(5) = 5`。`h(0) = 2 = h(5) = 2`，等高！`A[5] = 0`、`A[0] = −3`。

```
A = [−3, 5, 5, 0, 0, 0]
树：5 → 0，2 → 5 → 0，1 → 5 → 0，3 → 0，4 → 0
高度 3，六个节点全部连通
```

**（7）`union(2,1)`（CB）**：`find(2)`：`2 → 5 → 0`，根 0。`find(1)`：`1 → 5 → 0`，根 0。**同一棵树**，跳过。

**最终**：一棵 6 节点、高度 3 的树。`2^3 = 8 ≥ 6` ✓（引理给出下界 `2^(3−1) = 4 ≤ 6` ✓）。

**对比朴素 union**：如果按同样顺序朴素合并（`A[ra] = rb`），可能得到更长的链。但注意这里前几步恰好也差不多——**按高度合并的优势在「刻意构造的坏序列」上才明显**（例如 5.3 节的递增 union）。

### 5.10 习题要点

### 6.2 Agent 自行编写的教学示例

> 非官方，仅用于说明概念

**示例一：完整可运行的并查集（按秩合并 + 路径压缩）。**

```c
#include <stdio.h>
#include <stdlib.h>
#include "lib/xalloc.h"

typedef struct ufs_header {
  unsigned int size;
  int *A;                    /* A[i] < 0: i 是根，秩 = -A[i]；A[i] >= 0: 父索引 */
} *ufs;

ufs ufs_new(unsigned int n) {
  ufs eqs = xmalloc(sizeof(struct ufs_header));
  eqs->size = n;
  eqs->A = xmalloc(n * sizeof(int));
  for (unsigned int i = 0; i < n; i++) eqs->A[i] = -1;   /* 各自为根，秩 1 */
  return eqs;
}

void ufs_free(ufs eqs) {
  if (eqs == NULL) return;
  free(eqs->A);
  free(eqs);
}

/* 两遍法：先找根，再压缩路径 */
unsigned int ufs_find(ufs eqs, unsigned int a) {
  unsigned int root = a;
  while (eqs->A[root] >= 0) root = (unsigned int)eqs->A[root];

  while (a != root) {
    unsigned int next = (unsigned int)eqs->A[a];
    eqs->A[a] = (int)root;
    a = next;
  }
  return root;
}

/* 按秩合并 */
void ufs_union(ufs eqs, unsigned int a, unsigned int b) {
  unsigned int ra = ufs_find(eqs, a);
  unsigned int rb = ufs_find(eqs, b);
  if (ra == rb) return;

  int rank_a = -eqs->A[ra];
  int rank_b = -eqs->A[rb];

  if (rank_a > rank_b) {
    eqs->A[rb] = (int)ra;
  } else if (rank_b > rank_a) {
    eqs->A[ra] = (int)rb;
  } else {
    eqs->A[rb] = (int)ra;
    eqs->A[ra] = -(rank_a + 1);
  }
}

/* 调试：打印数组与每个元素所属的类 */
void ufs_print(ufs eqs) {
  printf("A = [");
  for (unsigned int i = 0; i < eqs->size; i++)
    printf("%d%s", eqs->A[i], i + 1 < eqs->size ? ", " : "");
  printf("]\n");
  for (unsigned int i = 0; i < eqs->size; i++)
    printf("  find(%u) = %u\n", i, ufs_find(eqs, i));
}

int main(void) {
  ufs eqs = ufs_new(6);
  /* 讲义的边序：AE, ED, FB, CF, AD, EF, CB */
  unsigned int edges[][2] = {{0,4},{4,3},{5,1},{2,5},{0,3},{4,5},{2,1}};
  const char *names[] = {"AE","ED","FB","CF","AD","EF","CB"};

  for (int i = 0; i < 7; i++) {
    printf("union(%u,%u)  /* %s */\n", edges[i][0], edges[i][1], names[i]);
    ufs_union(eqs, edges[i][0], edges[i][1]);
    ufs_print(eqs);
  }
  ufs_free(eqs);
  return 0;
}
```

**注意 `ufs_find` 的副作用**：它会**修改**数组（路径压缩）。所以 `ufs_print` 里调用 `find` 会改变结构——这在调试时可能让人困惑。**这是路径压缩的固有特征：查询会改数据。**

**这也意味着 `find` 不是「只读」操作**，不能用在 `const` 语境下，也不能多线程并发调用（需要加锁）。

**示例二：用并查集数连通分量。**

```c
/* 返回图的连通分量个数。O(e·α(v))，α 是反 Ackermann 函数。 */
unsigned int count_components(unsigned int v, unsigned int e,
                              unsigned int edges[][2]) {
  ufs eqs = ufs_new(v);
  for (unsigned int i = 0; i < e; i++)
    ufs_union(eqs, edges[i][0], edges[i][1]);

  /* 数不同的根 */
  unsigned int count = 0;
  for (unsigned int i = 0; i < v; i++)
    if (ufs_find(eqs, i) == i) count++;    /* i 自己是根 */

  ufs_free(eqs);
  return count;
}
```

**这个函数比 DFS 更好吗**：

- **并查集**：O(e·α(v))，但**只回答连通性**，不给出具体路径。
- **DFS**：O(v + e)，能给出路径、能遍历。

**复杂度相当**（α(v) ≤ 4），但并查集的**常数因子更小**（没有递归、没有邻接表遍历）。而且并查集**支持增量**——可以一次加一条边、随时查询，不需要重建。

**这就是为什么 Kruskal 用并查集而不用 DFS**：Kruskal 是增量式的（一条边一条边地加），并查集天然匹配。

**示例三：观察路径压缩的效果。**

```c
#include <stdio.h>

int main(void) {
  /* 构造一条长链：union(0,1), union(1,2), ..., union(8,9)
   * 用朴素 union（不加高度控制）会得到 0→1→2→...→9
   */
  ufs eqs = ufs_new(10);
  for (unsigned int i = 0; i + 1 < 10; i++) {
    /* 强制朴素合并：直接把 i 挂到 i+1 下 */
    eqs->A[i] = (int)(i + 1);
  }
  eqs->A[9] = -1;

  printf("压缩前：\n");
  ufs_print(eqs);

  printf("\nfind(0) = %u（第一次，要走 9 步）\n", ufs_find(eqs, 0));
  printf("压缩后：\n");
  ufs_print(eqs);

  printf("\nfind(0) = %u（第二次，1 步）\n", ufs_find(eqs, 0));
  ufs_free(eqs);
  return 0;
}
```

输出（关键部分）：

```
压缩前：
A = [1, 2, 3, 4, 5, 6, 7, 8, 9, -1]
  find(0) = 9
  ...
find(0) = 9（第一次，要走 9 步）
压缩后：
A = [9, 9, 9, 9, 9, 9, 9, 9, 9, -1]
  find(0) = 9
  ...
find(0) = 9（第二次，1 步）
```

**第一次 `find(0)` 走了 9 步，顺手把 0…8 全部指向 9。第二次只需 1 步。**

**这就是摊还分析的直观来源**：单次 `find` 可能很贵（O(n)），但它**同时压平了整条路径**，让后续查询变便宜。一串操作的总代价被「压平」这个动作摊薄了。

**摊还界的推导思路**（不展开严格证明）：每个节点的「父指针」只会被改有限次（每次改动都让它离根更近），而「离根更近」的潜力最多 `log` 级……严格证明需要「秩」的分组论证，见 Tarjan 1975 的论文。**结论是 O(α(n)) 摊还**。

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| 等价关系 | 一般关系 | 前者要自反 + 对称 + 传递；后者无要求 | 三条缺一不可 |
| 等价类 | 连通分量 | 前者是抽象概念；后者是图上的等价类 | 同一概念的两个视角 |
| 按高度合并 | 按大小合并 | 前者看树高；后者看节点数。**两者都给出 O(log n)** | 高度更好实现 |
| 高度 `h` | 秩 `rank` | 前者是实际高度（压缩后失真）；后者是「未压缩时的高度上界」 | 压缩后用秩 |
| `A[i] = i` | `A[i] < 0` | 前者是「朴素版」的根标记；后者是「高度版」的根标记 | 两种约定不能混 |
| `find` 是只读的 | `find` 会改数据 | 路径压缩让 `find` 有副作用 | 别在 const 上下文调用 |
| 路径压缩 | 按秩合并 | 前者降低「查询成本」；后者降低「树高增长」 | 两者互补 |
| Kruskal 朴素版 | Kruskal + 并查集 | 前者 O(ev)；后者 O(e log e) | 差一个数量级 |

## 10. 本节复习

1. 等价关系三性质：自反、对称、传递。等价类构成划分。图的连通性是无向图上的等价关系。
2. 并查集接口：`ufs_new` / `ufs_find` / `ufs_union` / `ufs_free`。表示层不变式：`A[i] = i` 或 `A[i] < 0` 表示根，`A[i] ≥ 0` 表示父索引。
3. 朴素版：`find` O(h) 最坏 O(v)，`union` 两次 find。递增 union 会退化成链。
4. 按高度合并：矮的挂到高的下，等高时高度 +1。根存 `−h` 同时编码「是根」与「高度」。
5. 关键引理：高度 `h` 的树至少 `2^(h−1)` 个节点。归纳分三种合并情形，等高合并时 `2^(h−2) + 2^(h−2) = 2^(h−1)`。推论 `h ≤ log₂n + 1`。
6. Kruskal 配按高度合并：O(e log e + e log(min(e+1,v))) = **O(e log e)**。瓶颈转移到排序（比较排序下界 Ω(e log e)，所以最优）。
7. 路径压缩：`find` 时把路径上所有节点指向根。摊还 O(1 + A⁻¹(n))，实践中 ≤ 4，即近 O(1)。压缩后 `−A[root]` 只是秩（高度上界）。

**证明（对 `h` 强归纳）**：

**基础 `h = 1`**：高度 1 的树只有根一个节点（没有任何子节点，否则高度 ≥ 2）。`2^(1−1) = 2^0 = 1` ✓。

**归纳步 `h > 1`**：设 `T` 是高度 `h` 的树。并查集的树只能通过 `union` 长大，所以 `T` 是某次合并 `T₁ ∪ T₂` 的结果。设合并前高度为 `h₁`、`h₂`。

由按高度合并规则，合并后高度为 `h` 只有三种可能：

**情形 A：`h₁ = h`、`h₂ ≤ h − 1`，`T₂` 挂到 `T₁` 的根下。**

合并后 `T` 的根就是 `T₁` 的根。从根到 `T₂` 里最远叶子的距离是 `1 + h₂ ≤ 1 + (h−1) = h`。从根到 `T₁` 里最远叶子的距离是 `h₁ = h`。所以新高度 `max(h, 1+h₂) = h` ✓（与假设一致）。

节点数：`|T| = |T₁| + |T₂|`。由归纳假设 `|T₁| ≥ 2^(h−1)`（因为 `h₁ = h`）。所以 `|T| ≥ 2^(h−1) + |T₂| ≥ 2^(h−1) + 1 > 2^(h−1)` ✓。

**情形 B：`h₂ = h`、`h₁ ≤ h − 1`，`T₁` 挂到 `T₂` 的根下。**

与情形 A 对称。`|T| ≥ 2^(h−1)` ✓。

**情形 C：`h₁ = h₂ = h − 1`（等高合并，高度从 `h−1` 增到 `h`）。**

合并后新高度 = `h₁ + 1 = h` ✓。

由归纳假设：`|T₁| ≥ 2^(h₁−1) = 2^(h−2)`、`|T₂| ≥ 2^(h₂−1) = 2^(h−2)`。

`|T| = |T₁| + |T₂| ≥ 2^(h−2) + 2^(h−2) = 2 · 2^(h−2) = **2^(h−1)**` ✓。

**三种情形穷尽了所有可能**（合并后高度 `h` 必须来自「高树高 `h` + 矮树不增加」或「两棵高 `h−1` 合并」）。归纳完成。∎

**答 3.**
`v = 10⁶`、`e = 2×10⁶`。

**（a）朴素并查集**：每次 `find` 最坏 O(v) = 10⁶ 步。`e` 次 `union` = 2e 次 `find`。最坏 **O(e·v) = 2×10⁶ × 10⁶ = 2×10¹² 步**。这在实际中完全不可行（现代 CPU 每秒约 10⁹ 次操作，需要约 2000 秒）。

**（b）按高度合并**：`find` 是 O(log v) = O(log 10⁶) ≈ **20 步**。总 `2e × 20 = 8×10⁷ 步`。**约 0.1 秒**。可行。

**（c）加路径压缩**：摊还 `O(α(v))`，`α(10⁶) ≤ 4`（因为 `Ack(4,4)` 远超 10⁶）。总 `2e × 4 = 1.6×10⁷ 步`。**约 0.02 秒**。比 (b) 快约 5 倍。

**（d）瓶颈**：**排序**。`O(e log e) = 2×10⁶ × 21 ≈ 4×10⁷` 次比较。这与 (c) 的判环代价同级，但排序的每次比较更贵（要访问边的两个字段、可能缓存不命中）。

所以**总复杂度 O(e log e) ≈ 4×10⁷**，主要花在排序上。**并查集部分已经优化到几乎免费。**

**这就是「算法优化的边际收益递减」的典型例子**：从 (a) 到 (b) 是 25000 倍提升，从 (b) 到 (c) 只有 5 倍。**先优化最大的瓶颈。**

**答 4.**
**如果用 `A[i] = h` 表示根**：

问题在于 **`h` 可以是 0**（如果约定单节点树高度为 0，与第 16 讲 AVL 一致）。此时 `A[i] = 0` 有两种解释：

1. 「`i` 是根，高度 0」。
2. 「`i` 的父节点是 0 号」。

**无法区分。** 这会导致 `find` 死循环或返回错误结果。

**如果用 `A[i] = h` 且高度从 1 开始**（`h ≥ 1`）：`A[i] = 0` 就只表示「父节点是 0」，没有歧义。**但这个方案很脆弱**——一旦有人改了「高度从 0 开始」的约定，代码就悄悄出 bug，而且这种 bug 很难发现（因为大多数测试用例不会让某个节点的父恰好是 0 号）。

**用 `−h` 的优势**：

- `A[i] < 0` ⇔ `i` 是根（**符号位就是标记**）。
- `A[i] ≥ 0` ⇔ `A[i]` 是父索引（**非负就是索引**）。
- **两种情况彻底分开，不依赖任何数值约定。**

**代价**：`find` 里取高度要写 `-A[root]`，多一个负号。**这个代价可以忽略。**

**更广的模式**：用「符号」编码「类型标记」是 C 里的常见技巧（例如 `int` 里用最高位标记、指针里用最低位标记 tagged pointer）。**在类型系统不够强的地方，用数值范围编码信息。**

**答 5.**
**不影响正确性。**

**理由**：按高度合并只需要一个「谁更高」的**估计**。路径压缩后 `−A[root]` 可能**高估**真实高度（因为压缩让树变浅了，但 `−A[root]` 没变）。高估会导致：

- 有时把「实际更高」的树挂到「实际更矮」的树下面（因为记录值说反了）。
- 结果：树高可能比理论最优略大。

**但引理的界仍然成立**，因为：

- `−A[root]` 只会在**合并时**增加，增加的条件是「两棵树的记录值相等」。
- 记录值相等的两棵树，各自的**真实**节点数都 ≥ `2^(记录值−1)`（由归纳，压缩不减少节点数）。
- 所以合并后的节点数 ≥ `2^(记录值)`，记录值 +1 后仍是合法下界。

**结论**：用「记录值」代替「真实高度」不会破坏 `n ≥ 2^(rank−1)` 这个不变式。所以 `rank ≤ log n + 1`，`find` 的路径长度（在压缩前）≤ `rank`。

**「秩」（rank）的定义**：

> **秩**是「这棵树在**从未发生过路径压缩**的假设下会有的高度」。

形式化地，`rank` 在合并时按以下规则更新：

- 单节点树：`rank = 1`。
- `union(T₁, T₂)`：若 `rank(T₁) > rank(T₂)`，新树 `rank = rank(T₁)`；若相等，新树 `rank = rank(T₁) + 1`。

**关键性质**：路径压缩**不改变任何节点的秩**（压缩只改父指针，不改根的 `−A` 值）。所以秩是**单调不减**的，且满足 `rank ≤ log₂(节点数) + 1`。

**为什么叫「秩」而不叫「高度」**：因为它不再是几何意义上的高度（压缩后真实高度可能远小于秩）。它是「一个与高度同阶、但不会被压缩破坏的度量」。

**标准命名**：**Union by Rank + Path Compression**（按秩合并 + 路径压缩）——这是并查集的标准最优组合，摊还 `O(α(n))`。

**一个细节**：如果同时用「按大小合并」（union by size，记录节点数）与路径压缩，也能达到 `O(α(n))`——因为大小同样不会被压缩破坏。**按大小 vs 按秩，两者都可，按秩更省空间（一个 `int` 编码两个信息）。**
