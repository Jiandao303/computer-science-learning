# 第 5 讲：大 O 记号与选择排序（Big-O & Sorting）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 按「逐步放宽」的顺序复述大 O 定义的三次修改：全输入比较 → 只看大输入 → 忽略常数因子，并说明每一步对应哪条分析原则。
2. 写出 `f ∈ O(g)` 的严格定义，并用它证明具体结论（例如 `5n² + 3n + 83 ∈ O(n²)`、`max(x,y) ∈ O(x+y)`）。
3. 解释 `O(g)` 为什么被看成**函数集合**，以及 `O(log n) ⊊ O(n)` 的含义。
4. 说明「二分查找是 O(n)」为什么在数学上正确却不是好答案——**tightest bound（最紧界）** 的要求。
5. 写出选择排序（selection sort）的三条循环不变式，并逐条证明初始化与保持性。
6. 推导选择排序的比较次数 `n(n-1)/2`，并把它归约为 `O(n²)`。
7. 解释经验验证（empirical validation）的逻辑：若真是二次的，输入翻倍时间应约变 4 倍。

## 3. 核心概念

**Asymptotic Complexity（渐近复杂度）**：只关心输入趋于无穷时的增长阶、并忽略常数因子的复杂度度量。

**Big-O Notation（大 O 记号）**：`f ∈ O(g)` 表示「存在常数 `c > 0` 与起点 `n0`，使得所有 `n >= n0` 都有 `f(n) <= c * g(n)`」。等价地，`O(g)` 是所有「最终被 `c*g` 压住」的函数组成的**集合**。

**Worst-Case Analysis（最坏情况分析）**：在同样规模的输入中取最费时的那个。讲义明确选择最坏情况，因为平均情况依赖输入分布，而分布往往未知。

**Quadratic / Linear / Logarithmic Time（平方 / 线性 / 对数时间）**：分别为 `O(n²)`、`O(n)`、`O(log n)`；`O(1)` 称常数时间。

**Selection Sort（选择排序）**：每轮在未排序段 `A[i..n)` 中选出最小元素，与 `A[i]` 交换，使已排序前缀增长 1。

**Swap（交换）**：排序中只允许交换的理由是——交换是**排列（permutation）** 保持操作，天然保证输出是输入的重新排列。

**Auxiliary Function（辅助函数）**：与「规格函数」相对，是真正执行工作的函数，如 `swap`、`find_min`。

## 4. 通俗理解

**为什么忽略常数因子**：讲义给了两条原则。第一条是**实用**——输入小时算法之间的差别看不出来，只有输入大时才有意义；第二条是**持久**——二十年后机器快一百倍，`3n` 和 `5n` 谁快可能反转，但 `n²` 和 `n log n` 的胜负不会反转。**常数因子会被编译器、运行时、机器模型、内存状况共同决定，做「精确」分析既不合适也不可行。**

**为什么用集合而不是等号**：`f = O(g)` 是把一个函数和一个函数集合相比，这在数学上很可疑（讲义脚注明确说 questionable）。写成 `f ∈ O(g)` 就干净了：`O(g)` 是一个集合，`f` 是它的一个元素。

**选择排序 = 反复挑最小的放到队首**：像整理一手扑克牌，每次从剩下的牌里抽出最小的一张，插到已经排好的那一叠末尾。

**为什么必须交换而不是直接覆盖**：如果只是把最小值「写」到前面，被覆盖的那个元素就丢了，结果不再是原数组的排列。交换是**唯一同时满足「移动最小值」与「不丢失任何元素」的原子操作**。

## 5. 原理与推导

### 5.1 大 O 定义的三次放宽

设 `f`、`g` 是把输入规模映射到操作次数的函数。讲义的例子：`f(n) = 3 log n`（二分查找的比较次数）、`g(n) = 3n`（线性查找的比较次数）。

**第一版：逐点比较。**

```
f ≤0 g  当且仅当  对所有 n >= 0，f(n) <= g(n)
```

问题：违反原则 (1)。它要求我们在**所有**输入（包括小输入）上都成立，而小输入恰恰是我们不在意的。而且这个关系太脆弱：只要某个小 `n` 上反超，整个判断就失败。

**第二版：只看「最终」。**

```
f ≤1 g  当且仅当  存在自然数 n0，使得对所有 n >= n0 都有 f(n) <= g(n)
```

现在只看大输入了，符合原则 (1)。但常数因子还在起决定作用：`3n ≤1 5n` 成立，而 `5n ≤1 3n` 不成立。可这两个函数在渐近意义下应该「一样大」。

**第三版：允许乘上常数。**

```
f ≤2 g  当且仅当  存在实常数 c > 0 和自然数 n0，使得对所有 n >= n0 都有 f(n) <= c * g(n)
```

现在 `3n ≤2 5n`（取 `c = 1`）与 `5n ≤2 3n`（取 `c = 2`）同时成立，符合原则 (2)。

**正名。** `≤` 这个符号已经被重载太多次，于是改用：

```
f ∈ O(g)  当且仅当  存在实常数 c > 0 和自然数 n0，使得对所有 n >= n0 都有 f(n) <= c * g(n)
```

等价地，把 `O(g)` 写成集合：

```
O(g) = { f | 存在 c > 0 与 n0，使得对所有 n >= n0 有 f(n) <= c * g(n) }
```

由此立刻得到一条常用等式：**`O(g(n)) = O(c * g(n))`**（`c` 为正实常数）。因为常数因子可以被外层定义里的 `c` 吸收。

**变量名无关。** `n` 没有任何特殊性：`4x + log9 x + 2 ∈ O(x)`。**多变量**时，`2w + 2h² + 4 ∈ O(w + h²)`——注意定义要求**只有一个常数 `c`**，但**每个变量可以有自己的起点** `w0`、`h0`。这个细节是多变量大 O 的常见坑。

### 5.2 用定义做证明

**命题 1**：`5n² + 3n + 83 ∈ O(n²)`。

证明：取 `c = 6`、`n0 = 1`。对 `n >= 1`：

```
5n² + 3n + 83 <= 5n² + 3n² + 83n² = 91n²
```

`91` 太大不是问题，我们只需找到**某个** `c`。改用更精细的估计：对 `n >= 1`，`3n <= 3n²`；对 `n >= 10`，`83 <= 0.83n²`。于是对 `n >= 10`：

```
5n² + 3n + 83 <= 5n² + 3n² + 0.83n² = 8.83n² <= 9n²
```

所以取 `c = 9`、`n0 = 10` 即可。**这就是「多项式中只有最高次幂重要」的一般证明思路**：低次项在 `n` 足够大时总被最高次项吸收。

**命题 2**（习题 3）：对非负整数 `x, y`，`O(max(x,y)) = O(x+y)`。

证明分两个方向（要证集合相等，必须互相包含）：

- `max(x,y) ∈ O(x+y)`：因为 `max(x,y) <= x + y`（非负），取 `c = 1`、`n0 = 0`。
- `x + y ∈ O(max(x,y))`：因为 `x <= max(x,y)` 且 `y <= max(x,y)`，所以 `x + y <= 2*max(x,y)`，取 `c = 2`、`n0 = 0`。

合起来：`max(x,y) <= x + y <= 2*max(x,y)`，两个方向得证。**这个「双向夹逼」是证明 `O(f) = O(g)` 的标准套路**：每次都归结为找到 `c` 与 `n0`。

**命题 3**（习题 4，挑战题）：`O(log(n!)) = O(n log n)`。

左到右（容易）：

```
log(n!) = log(1*2*...*n) = log 1 + log 2 + ... + log n
        <= log n + log n + ... + log n      (n 项)
        = n log n
```

右到左（困难）：把 `n log n` 拆成 `n` 个 `log n`，再逐项配对成「`n` 除以某个数」的形式，使总和被 `log(n!)` 与另一份 `log(n!)` 夹住。讲义给出的最终不等式是 `n log n <= log(n!) + log(n!) = 2 log(n!)`，取 `c = 2`。

### 5.3 最紧界与常见误用

`O(log n) ⊆ O(n)`，但 `O(n) ⊄ O(log n)`，因此 `O(log n) ⊊ O(n)`（真子集）。

**对数换底**：`log_b n = log2 n / log2 b`，而 `1/log2 b` 是常数，故 `O(log2 n) = O(log_b n)`。**所以写大 O 时对数底数可以随便写**，这也是「忽略常数因子」的一个直接推论。

**「二分查找是 O(n)」对不对？** 对，因为 `log n ∈ O(n)`，所以它确实满足定义。但这是**更松**的刻画。同样正确的是 `O(log n)`，而 `O(1)` 就错了。讲义明确要求：**当被问到「最坏情况运行时间是多少」时，要给出大 O 意义下最紧的界。**

这条提醒的实际意义：大 O 只给上界，不说「不能再小」。**任何人写 `O(n²)` 都不会因为「其实只要 O(n log n)」而变成错误——只是没用。** 交流时必须给紧界。

**表：常见复杂度与其含义**

| 记号 | 名称 | 输入翻倍时的耗时变化 | 典型算法 |
|---|---|---|---|
| `O(1)` | 常数 | 不变 | 数组按下标取值、`swap` |
| `O(log n)` | 对数 | 加一个常数 | 二分查找 |
| `O(n)` | 线性 | 约 2 倍 | 线性查找、`is_sorted` |
| `O(n log n)` | 线性对数 | 约 2 倍多一点 | 归并排序、堆排序 |
| `O(n²)` | 平方 | 约 4 倍 | 选择排序、插入排序（最坏） |
| `O(n³)` | 立方 | 约 8 倍 | 朴素矩阵乘法 |

### 5.4 选择排序：算法与不变式

**记号**：`A[lo..hi)` 表示从 `lo` 到 `hi`（不含）的数组段。这一记号贯穿全讲。

**算法思想**：每轮在未排序段 `A[i..n)` 中找最小元素的位置 `min`，把 `A[i]` 与 `A[min]` 交换，然后 `i` 前进一格。未排序段缩小一格，已排序前缀增长一格。

**第一步：写出能推出后置条件的不变式。**

最朴素的两条：

```
0 <= i <= n
A[0..i) 已排序
```

**这两条能推出后置条件**（因为退出时 `i == n`，于是 `A[0..n)` 已排序），**但不足以证明保持性**。原因：交换会把一个**大**元素从 `A[i]` 挪到 `A[min]`，也就是挪进**未排序段**。如果不保证「已排序段的所有元素都 <= 未排序段的所有元素」，那么这次交换就可能把一个小元素搬回未排序区，使下一轮的前缀不再有序。

于是补第三条：

```
A[0..i) <= A[i..n)      (即所有左边元素 <= 所有右边元素)
```

这三条合起来才是完整的不变式组：

```
0 <= i <= n
A[0..i) sorted
A[0..i) <= A[i..n)
```

### 5.5 保持性证明（逐条）

设一轮开始时三条不变式成立，且守卫 `i < n` 成立。执行循环体：`min = find_min(A, i, hi)`，`swap(A, i, min)`，`i' = i + 1`。要证三条在 `i'` 处仍成立。

**(a) `0 <= i' <= n`。** 由 `i < n` 得 `i + 1 <= n`；由 `0 <= i` 得 `0 <= i + 1`。**注意这里用到守卫**——如果守卫是 `i <= n`，`i' = n+1` 就越界了。

**(b) `A[0..i')` 已排序，即 `A[0..i+1)` 已排序。**

需要 `A[0..i)` 有序 **且** `A[i-1] <= A[i]`（新增的最后一个元素不小于前一个）。

- `A[0..i)` 有序：直接来自第二条不变式（交换只动了 `A[i]` 与 `A[min]`，而 `min >= i`，所以前缀 `A[0..i)` **完全没有被触碰**）。
- `A[i-1] <= A[i]`：由第三条不变式，`A[i-1]`（属于左段）`<=` 任何右段元素；交换后 `A[i]` 位置上是**右段的最小值**，它当然 `<=` 原来的任意右段元素。更直接地：`A[i-1] <= A[min]`（`A[min]` 在右段），交换后 `A[min]` 位置放的是旧 `A[i]`——等等，这里要小心方向。**正确论证**：第三条不变式说 `A[i-1] <= A[i..n)` 中每个元素，因此 `A[i-1] <= min_value <= A[i]`（交换后的新 `A[i]` 就是 `min_value`）。所以 `A[i-1] <= A[i]` 成立。

**(c) `A[0..i+1) <= A[i+1..n)`。**

把左边拆成 `A[0..i)` 与 `A[i..i+1)`：

- `A[0..i) <= A[i+1..n)`：旧不变式给 `A[0..i) <= A[i..n)`，而 `A[i+1..n)` 是 `A[i..n)` 的子段，结论自然成立（**注意交换只影响位置 `i` 与 `min`，`A[i+1..n)` 内的元素集合可能变了——旧 `A[i]` 被放到了 `min` 处**。所以严格来说需要：旧 `A[i] <=` 旧 `A[i..n)` 中所有元素？不，我们只知道 `A[0..i) <=` 全部右段。交换后 `A[i+1..n)` 里多了一个旧 `A[i]`，少了 `min_value`。而 `A[0..i)` 的每个元素 `<= min_value`（旧不变式，因为 `min_value` 属于旧右段），且 `<=` 旧 `A[i]`（旧不变式）。**两条合起来覆盖了交换后右段的所有元素**——这正是讲义强调「交换把旧 `A[i]` 挪到新位置」时论证的微妙处。
- `A[i..i+1)` 即单个元素 `min_value <= A[i+1..n)` 中所有元素：这正是 `find_min` 的后置条件 `le_seg(A[\result], A, lo, hi)`——`min_value` 是 `A[i..n)` 的最小值，因此不大于右段任何元素（包括被搬进来的旧 `A[i]`，它本来就在 `A[i..n)` 里）。

**结论**：三条不变式保持。

**讲义的原话版本**（第 7 页）更简洁：`i' = i + 1` 只是为了让「旧 i」与「新 i」区分开——这是保持性证明的标准做法，与 [[15-122-01-Contracts]] 里 `x' = x*x, y' = y/2` 的处理完全一致。

### 5.6 初始化与退出

**INIT**：`i = lo`。

- `lo <= i && i <= hi`：由前置 `lo <= hi`。
- `A[lo..lo)` 有序：**空段恒有序**（右端开区间，段内没有元素）。
- `A[lo..lo) <= A[lo..hi)`：左段为空，**空段的「所有元素 <= ...」是空真（vacuously true）**。右段就是整个待排序部分。

**空段/空真**是本讲最重要的技巧之一：`i = lo` 时两条涉及 `A[0..i)` 的不变式都因为「段内无元素」而平凡成立。**写初始化证明时，「空段」和「空真」是最常用的两把钥匙。**

**EXIT**：守卫 `i < hi` 为假得 `i >= hi`；不变式给 `i <= hi`；故 `i == hi`。第二条不变式即 `A[lo..hi)` 已排序——**这正是 `@ensures`**。

### 5.7 辅助函数

**`swap`**：三条赋值用临时变量 `tmp` 中转。

```c0
void swap(int[] A, int i, int j)
//@requires 0 <= i && i < \length(A);
//@requires 0 <= j && j < \length(A);
{
  int tmp = A[i];
  A[i] = A[j];
  A[j] = tmp;
}
```

`i == j` 时数组不变（三次赋值变成自我覆盖），这对选择排序很重要：**当最小值就在 `A[i]` 时仍会调用 `swap(A,i,i)`**，习题 5 的「n 次交换」计数正是把这自交换也算了进去。

**`find_min`** 的契约是证明保持性的关键：

```c0
int find_min(int[] A, int lo, int hi)
//@requires 0 <= lo && lo < hi && hi <= \length(A);
//@ensures lo <= \result && \result < hi;
//@ensures le_seg(A[\result], A, lo, hi);
```

- 前置 `lo < hi` 是**严格**小于：段必须非空，否则「最小值」无定义。这比 `sort` 的前置更强，因为 `sort` 允许对空段排序（`lo == hi`），而 `sort` 只在 `i < hi` 时才调用 `find_min`，因此调用点的 `lo < hi` 恰好被满足——**这是「调用者前置由守卫保证」的范例**。
- 两条后置：一条管**下标合法**，一条管**值是最小**。二者缺一不可。

`find_min` 的不变式三件套与 `sort` 同构：

```
lo < i && i <= hi          -- i 的范围（注意下界是严格 <，因为 i 从 lo+1 开始）
lo <= min && min < hi      -- min 始终是合法下标
le_seg(A[min], A, lo, i)   -- min 指向 A[lo..i) 的最小值
```

**下界 `lo < i` 而非 `lo <= i`**：因为 `i` 初始化为 `lo + 1`，最小值候选 `min` 初始化为 `lo`。若把 `i` 写成可以等于 `lo`，就会出现「`A[lo..lo)` 是空段、`min` 却指向 `lo`」这种自相矛盾的状态。

### 5.8 复杂度推导

为记号简单设 `lo = 0`、`hi = n`。

**外层循环**：`i` 从 `0` 到 `n-1`，共 `n` 轮。（讲义指出其实可以少跑一轮——`i = n-1` 时右段只有一个元素，`find_min` 什么都不用做——但那只是常数级节省，不影响渐近复杂度。）

**内层循环**：第 `i` 轮里 `find_min(A, i, n)` 从 `i+1` 扫到 `n-1`，共 `n - i - 1` 次迭代。

**总迭代数**：

```
T(n) = (n-1) + (n-2) + (n-3) + ... + 0
     = n(n-1)/2
```

（高斯求和：首项 `n-1`、末项 `0`、共 `n` 项，和 = `n * (n-1) / 2`。）

**每轮只做常数次操作**（几次比较、赋值、自增），设这个常数为 `k`，总操作数 `<= k * n(n-1)/2`。于是：

```
O(n(n-1)/2) = O(n²/2 - n/2) = O(n²)
```

最后一步用「多项式中只有最高次幂重要」。所以**选择排序的最坏情况运行时间是平方级的（quadratic）**。

**为什么内层不能再快**：讲义明确说 `A[i+1..n)` 尚未排序，因此**无法**用二分之类的手段找最小值——找最小值本质上需要看每个元素。这解释了为什么选择排序绕不开 `n(n-1)/2`。

**平均情况与最坏情况几乎一样**：迭代次数**完全相同**，唯一差别是若数组已有序，`find_min` 循环体里的那两次赋值会少做一些。所以选择排序是「平均 = 最坏」的典型。

**交换次数的对比**（习题 5、习题 6 的结论）：

| 算法 | 比较次数 | 交换次数（最坏） |
|---|---|---|
| 选择排序 | `n(n-1)/2` | `n` |
| 插入排序 | `n(n-1)/2` | `n(n-1)/2` |

**选择排序的交换次数是线性的**，这是它在「写操作昂贵」的介质（如闪存）上的实际优势。而插入排序的最坏交换次数是平方的。

### 5.9 经验验证的逻辑

若运行时间真是 `O(n²)` 而**不是**渐近更快，则对大输入应有 `T(n) ≈ c*n²`。把输入从 `n` 加倍到 `2n`：

```
T(2n) ≈ c*(2n)² = 4*(c*n²) ≈ 4*T(n)
```

**所以「输入翻倍、时间约变 4 倍」是二次增长的判据。** 若是线性的，比值应约 2；若是 `n log n`，比值略大于 2。

实测（讲义第 12 页，`selectsort.c0` + `sort-time.c0`，`r = 100` 次重复）：

| n | 时间 (s) | 相邻比值 |
|---|---|---|
| 1000 | 0.700 | — |
| 2000 | 2.700 | 3.85 |
| 4000 | 10.790 | 4.00 |
| 8000 | 42.796 | 3.97 |

**比值几乎正好是 4**，猜想得到实验确认。注意 `n = 1000 → 2000` 的比值 3.85 略小，因为小规模时常数项与缓存效应还有影响；`n` 越大越接近 4——这正好演示了「渐近」的含义：**极限行为只在大输入时显现**。

**经验验证的地位**：它**不能证明**复杂度上界（只能反驳），但能有效发现「你以为 O(n log n) 其实是 O(n²)」这类错误。理论推导给保证，实验给信心，二者互补。

**（1）选择排序主函数，第 9 页：**

```c0
void sort(int[] A, int lo, int hi)
//@requires 0 <= lo && lo <= hi && hi <= \length(A);
//@ensures is_sorted(A, lo, hi);
{
  for (int i = lo; i < hi; i++)
  //@loop_invariant lo <= i && i <= hi;
  //@loop_invariant is_sorted(A, lo, i);
  //@loop_invariant le_segs(A, lo, i, A, i, hi);
  {
    int min = find_min(A, i, hi);
    swap(A, i, min);
  }
}
```

三条不变式与 5.4 节的三条一一对应：`lo <= i && i <= hi` ↔ `0 <= i <= n`；`is_sorted(A, lo, i)` ↔ `A[lo..i)` 有序；`le_segs(A, lo, i, A, i, hi)` ↔ `A[lo..i) <= A[i..hi)`。

**（2）`swap`，第 10 页：**

```c0
void swap(int[] A, int i, int j)
//@requires 0 <= i && i < \length(A);
//@requires 0 <= j && j < \length(A);
{
  int tmp = A[i];
  A[i] = A[j];
  A[j] = tmp;
}
```

**（3）`find_min`，第 10 页：**

```c0
int find_min(int[] A, int lo, int hi)
//@requires 0 <= lo && lo < hi && hi <= \length(A);
//@ensures lo <= \result && \result < hi;
//@ensures le_seg(A[\result], A, lo, hi);
{
  int min = lo;
  for (int i = lo+1; i < hi; i++)
  //@loop_invariant lo < i && i <= hi;
  //@loop_invariant lo <= min && min < hi;
  //@loop_invariant le_seg(A[min], A, lo, i);
  {
    if (A[i] < A[min]) {
      min = i;
    }
  }
  return min;
}
```

**（4）选择排序的规格（函数声明与契约），第 8 页：**

```c0
void sort(int[] A, int lo, int hi)
//@requires 0 <= lo && lo <= hi && hi <= \length(A);
//@ensures is_sorted(A, lo, hi);
;
```

讲义用这种「先写契约、再写实现」的顺序，并列出可用的五个辅助/规格函数：`is_sorted(A,lo,hi)`、`le_seg(x,A,lo,hi)`、`le_segs(A,lo1,hi1,B,lo2,hi2)`、`swap(A,i,j)`、`find_min(A,lo,hi)`。

**（5）插入排序（习题 6 答案），第 19 页：**

```c0
void inssort(int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@ensures is_sorted(A, 0, n);
{
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i && i <= n;
  //@loop_invariant is_sorted(A, 0, i);
  {
    int j = i;
    while (j > 0 && A[j-1] > A[j])
    //@loop_invariant 0 <= j && j <= i;
    //@loop_invariant is_sorted(A, 0, j);
    //@loop_invariant is_sorted(A, j, i+1);
    //@loop_invariant le_segs(A, 0, j, A, j+1, i+1);
    {
      swap(A, j-1, j);
      j--;
    }
  }
}
```

注意内层 `while` 的守卫 `j > 0 && A[j-1] > A[j]` 又一次使用了**短路求值**：`j == 0` 时不会去读 `A[-1]`。这与 [[15-122-04-Searching-Arrays]] 里 `i < n && A[i] <= x` 是同一个技巧。

**（6）习题 1 的两个函数，第 13 页：**

```c0
int function1(int[] A, int n)
//@requires n == \length(A);
{
  int count = 0;
  for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
      count = count + A[j] * (i-1);
    }
  }
  return count;
}
```

```c0
int function2(int[] A, int n)
//@requires (n == \length(A));
{
  int count = n;
  int k = 5;
  for (int i = 0; i < k; i++) {
    for (int j = 0; j < k; j++) {
      count = count + i * (j+1);
    }
  }
  return count;
}
```

`function1` 是 `O(n²)`（内外各 `n` 轮）；`function2` 是 `O(1)`（`k = 5` 是常数，内层总共执行 25 次，与 `n` 无关）。**注意 `function2` 的参数 `A` 和 `n` 完全没影响循环次数**——这是「循环变量与输入规模无关 ⇒ 常数时间」的判据。

### 6.2 Agent 自行编写的教学示例

> **非官方，仅用于说明概念。** 以下代码由本笔记自行编写，不是 CMU 官方代码，语言为 **C0**。

**示例 A：`O(n²)` 与 `O(n)` 的对比实验骨架。**

```c0
int count_pairs(int[] A, int n)
//@requires n == \length(A);
{
  int c = 0;
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i && i <= n;
  for (int j = i+1; j < n; j++)
  //@loop_invariant i < j && j <= n;
  if (A[i] == A[j]) c = c + 1;
  return c;
}
```

内层从 `i+1` 开始，总比较次数是 `(n-1) + (n-2) + ... + 1 = n(n-1)/2`——**和选择排序的 `find_min` 完全相同的求和式**。这个函数用来数「相等的无序对」。虽然只做了 `n(n-1)/2` 次（而不是 `n²` 次），仍是 `O(n²)`：常数因子 `1/2` 被忽略。

**示例 B：证明 `O(2n² + 100n) = O(n²)` 的两个方向。**

记 `f(n) = 2n² + 100n`、`g(n) = n²`。

- `f ∈ O(g)`：对 `n >= 1`，`100n <= 100n²`，故 `f(n) <= 102n²`，取 `c = 102`、`n0 = 1`。
- `g ∈ O(f)`：对 `n >= 0`，`n² <= 2n² + 100n`，取 `c = 1`、`n0 = 0`。

**两个方向都要给 `(c, n0)`**。这是 `O(f) = O(g)` 类题目的标准答案格式；只给一边只能证明包含关系，不能证明相等。（对应习题 3 的解法。）

**示例 C：为什么 `A[0..i) <= A[i..n)` 这条不变式不能省——反例追踪。**

假设只有前两条不变式，数组 `A = [1, 9, 2, 8]`：

| 轮次 | i | 未排序段 | 段内最小 | 交换后 | `A[0..i)` 有序？ |
|---|---|---|---|---|---|
| 1 | 0 | `[1,9,2,8]` | 1（在 0） | `[1,9,2,8]`（自交换） | 是（`[1]`） |
| 2 | 1 | `[9,2,8]` | 2（在 2） | `[1,2,9,8]` | 是（`[1,2]`） |
| 3 | 2 | `[9,8]` | 8（在 3） | `[1,2,8,9]` | 是（`[1,2,8]`） |

这里恰好顺利。但**若要证明第 3 轮的「是」**，必须知道 `A[1] = 2 <= A[2] = 8`（新加进前缀的元素不小于前一个），而这只能由 `A[0..i) <= A[i..n)` 提供。**没有第三条不变式，第二条在保持性证明里就断了链条。**

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| `f = O(g)` | `f ∈ O(g)` | 前者拿函数和集合比，数学上可疑；后者是集合成员关系 | 大 O 是一个**集合** |
| `f ∈ O(g)`（上界） | `f ∈ Θ(g)`（紧界） | 前者只要求最终被 `c*g` 压住；后者还要 `g` 也被 `f` 压住（差常数） | O 是 `<=`，Θ 是 `=` |
| `O(n²)`（正确但松） | `O(n log n)`（紧） | 二分查找两者都对，但课程要求**最紧界** | 答松界不算错，但算没答 |
| 忽略常数因子 | 忽略低次项 | 前者靠定义里的 `c`；后者靠「大 n 时高次项支配」 | 两条独立的简化 |
| `O(log2 n)` | `O(log_b n)` | 换底只差常数 `1/log2 b`，故相等 | 对数底随便写 |
| `0 <= i <= n` + `A[0..i)` 有序 | 再加 `A[0..i) <= A[i..n)` | 前两条能推后置条件但**证不出保持性** | 交换会把大元素搬进右段 |
| 选择排序交换 `n` 次 | 插入排序交换 `n(n-1)/2` 次 | 选择排序每轮只交换一次；插入排序逐个冒泡 | 选择排序写操作少 |
| `find_min` 前置 `lo < hi` | `sort` 前置 `lo <= hi` | 前者要求段非空；后者允许空段 | 调用点由守卫保证严格性 |
| 经验验证 | 数学证明 | 实验只能反驳不能证明；证明给保证 | 4 倍比值是二次的指纹 |

## 10. 本节复习

1. 三次放宽：`≤0`（所有 n）→ `≤1`（最终）→ `≤2`（允许常数倍 c）→ `∈ O(g)`。
2. `O(g)` 是函数集合；`O(g(n)) = O(c*g(n))`；`O(log2 n) = O(log_b n)`。
3. 大 O 只给上界，课程要求**最紧界**；`O(n)` 对二分查找正确但无用。
4. 多变量大 O：**一个常数 `c`，每个变量各自的起点**。
5. 选择排序三条不变式：`lo <= i <= hi`、`is_sorted(A,lo,i)`、`le_segs(A,lo,i,A,i,hi)`。第三条不可省，否则保持性证明断裂。
6. INIT 靠「空段」与「空真」：`A[lo..lo)` 有序，且「空段所有元素 <= ...」平凡成立。
7. EXIT 靠守卫取反：`i >= hi` 加不变式 `i <= hi` 得 `i == hi`，正好是 `@ensures`。
8. `find_min` 前置是 `lo < hi`（严格），由 `sort` 的守卫 `i < hi` 在调用点保证。
9. 复杂度：`(n-1)+...+0 = n(n-1)/2 = O(n²)`；内层无法用二分加速，因为右段未排序。
10. 选择排序比较 `n(n-1)/2` 次、交换 `n` 次；插入排序比较与交换最坏都是 `n(n-1)/2`。
11. 经验判据：输入翻倍、时间约 4 倍 ⇒ 二次；实测比值 3.85/4.00/3.97。

**题 1.** 用定义证明 `7n² + 20n + 5 ∈ O(n²)`，明确给出 `c` 与 `n0`。

**题 2.** 判断真假并说明理由：(a) `O(n) = O(2n+1)`；(b) `O(n²) ⊆ O(n³)`；(c) `n³ ∈ O(n²)`。

**题 3.** 求 `f(m,n) = 3m log n + n² + m` 的最紧大 O 界（用 `m`、`n` 表示）。如果只知道 `m <= n`，界能简化成什么？

**题 4.** 选择排序对 `A = [5, 3, 9, 1, 7]` 排序。写出每轮结束后的数组、`i` 的值，以及此时三条不变式是否成立。总比较次数与总交换次数各是多少？

**题 5.** 为什么 `sort` 的第二条不变式写成 `is_sorted(A, lo, i)` 而不是 `is_sorted(A, lo, i+1)`？后者在循环开头成立吗？

<details>
<summary>参考答案</summary>

**答 1.** 对 `n >= 1`：`7n² <= 7n²`，`20n <= 20n²`，`5 <= 5n²`，故 `7n² + 20n + 5 <= 32n²`。取 `c = 32`、`n0 = 1`。按定义即得 `7n² + 20n + 5 ∈ O(n²)`。
（更精细的取法也可，如 `c = 10`、`n0 = 5`，因为 `n >= 5` 时 `20n <= 4n²`、`5 <= 0.2n²`，总和 `<= 11.2n²`——注意仍要留余量。任意一组可行的 `(c, n0)` 都算对。）

**答 2.**
- (a) **真**。`O(n) = O(2n+1)` 是集合相等，需双向包含。`n ∈ O(2n+1)`：`n <= 1*(2n+1)`，取 `c=1, n0=0`。`2n+1 ∈ O(n)`：`2n+1 <= 3n` 对 `n >= 1`，取 `c=3, n0=1`。
- (b) **真**。`n² <= n³` 对 `n >= 1`，取 `c=1, n0=1`。
- (c) **假**。不存在 `c` 使 `n³ <= c*n²` 对所有大 `n` 成立，因为两边同除 `n²` 得 `n <= c`，而 `n` 无界。

**答 3.** 三项分别是 `O(m log n)`、`O(n²)`、`O(m)`。`O(m)` 被 `O(m log n)` 吸收（`log n >= 1` 当 `n >= 2`）。所以最紧界是 `O(m log n + n²)`。
若已知 `m <= n`，则 `m log n <= n log n <= n²`（`n >= 1` 时 `log n <= n`），于是 `O(m log n + n²) = O(n²)`。**注意「已知条件」能实质简化界——这是审题时必须留意的。**

**答 4.** 数组 `A = [5, 3, 9, 1, 7]`，`lo=0, hi=5`。

| 轮次 | 开始时 i | 未排序段 | 最小元素 | 最小位置 | 交换后数组 | `A[0..i)` 有序 | `A[0..i) <= A[i..n)` |
|---|---|---|---|---|---|---|---|
| 1 | 0 | `[5,3,9,1,7]` | 1 | 3 | `[1,3,9,5,7]` | `[1]` 是 | `1 <= 其余全部` 是 |
| 2 | 1 | `[3,9,5,7]` | 3 | 1 | `[1,3,9,5,7]`（自交换） | `[1,3]` 是 | `1,3 <= 9,5,7` 是 |
| 3 | 2 | `[9,5,7]` | 5 | 3 | `[1,3,5,9,7]` | `[1,3,5]` 是 | `1,3,5 <= 9,7` 是 |
| 4 | 3 | `[9,7]` | 7 | 4 | `[1,3,5,7,9]` | `[1,3,5,7]` 是 | `1,3,5,7 <= 9` 是 |
| 5 | 4 | `[9]` | 9 | 4 | `[1,3,5,7,9]`（自交换） | 全部有序 | 右段为空，空真 |

**比较次数**：第 1 轮 `find_min(A,0,5)` 从 `1` 扫到 `4`，4 次；第 2 轮 3 次；第 3 轮 2 次；第 4 轮 1 次；第 5 轮 0 次。总计 `4+3+2+1+0 = 10 = 5*4/2`。
**交换次数**：5 次（含第 2、5 轮的自交换 `swap(A,1,1)`、`swap(A,4,4)`）。与讲义「n 次交换」一致。

**答 5.** 循环开头 `i = lo`，此时 `A[lo..lo+1)` 只含 `A[lo]` 一个元素。**单元素段确实有序**，所以 `is_sorted(A, lo, i+1)` 在 `i = lo` 时成立。但**在后面的轮次就不成立**：进入第 `i` 轮时（`i > lo`），`A[i]` 还是未排序段的一部分，它与 `A[i-1]` 的大小关系尚未确定，`A[lo..i+1)` 可能无序。例如答 4 的第 3 轮开始：`A = [1,3,9,5,7]`，`i = 2`，而 `A[0..3) = [1,3,9]` 有序——这个例子碰巧成立，但若第 2 轮后是 `[1,9,3,...]` 就不成立了。
**更根本的理由**：不变式必须**在每次测试守卫前**成立，包括 `i` 已经推进之后的时刻。`is_sorted(A,lo,i)` 恰好描述「已完成的排序前缀」，而 `is_sorted(A,lo,i+1)` 描述的是「本轮还没做完就该成立的事」——**把结论提前写进不变式，是 INIT 或 PRES 失败的常见原因**（参见 [[15-122-04-Searching-Arrays]] 里 `i <= hi-1` 的反例）。

</details>
