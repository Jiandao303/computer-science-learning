# 第 6 讲：二分查找（Binary Search）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 说明二分查找（binary search）为什么需要「数组已排序」这个前置条件，并解释一次比较如何把搜索空间砍掉一半。
2. 推导 `n = 2^k` 时的迭代次数 `k + 1`，并推广到任意 `n` 得到 `c * log2 n`。
3. 写出二分查找的三条循环不变式，特别是用**析取（disjunction）** 处理边界的 `(lo == 0 || A[lo-1] < x)` 与 `(hi == n || A[hi] > x)`。
4. 解释为什么 `A[lo-1] < x` 单独作为不变式会**越界**，以及为什么「写不变式时也要检查数组访问的合法性」。
5. 分三种情形证明退出循环后 `!is_in(x, A, 0, n)` 成立。
6. 说明 `int mid = (lo + hi)/2` 的溢出缺陷，给出 `lo + (hi-lo)/2` 的修正并证明 `lo <= mid && mid < hi`。
7. 用实验数据说明「二分查找的计时看起来像线性」其实是**初始化数组的开销**掩盖了查找开销。

## 3. 核心概念

**Binary Search（二分查找）**：在**已排序**数组中查找目标 `x` 的算法。每次取当前区间的中点，与 `x` 比较，据结果丢弃一半区间。

**Divide and Conquer（分治）**：把问题空间一分为二、只递归（或迭代）处理其中一半的策略。讲义把它列为本讲的「计算思维」目标，并说二分查找是它的**前奏（prelude）**。

**Half-Open Interval（半开区间）**：`[lo, hi)` 表示含 `lo`、不含 `hi`。本讲的主版本采用这种约定。

**Inclusive Bounds（闭区间边界）**：`[lo, hi]` 两端都含。习题 1 要求改写为这种约定，代价是不变量与守卫都要调整。

**Disjunctive Invariant（析取式不变式）**：形如 `(lo == 0 || A[lo-1] < x)` 的不变式，用一个「哨兵情形」避开越界访问。

**Overflow-Safe Midpoint（防溢出中点）**：`lo + (hi - lo)/2`，先减后加，避免 `lo + hi` 溢出。

**Design by Invariant（按不变式设计）**：先写出足够强的循环不变式，再让循环体成为「保持它」的最自然实现。讲义反复强调这是本讲的方法论核心。

## 4. 通俗理解

**为什么排序能带来指数级加速**：在一堆无序的数字里找一个数，你只能一个个看；但如果它们按大小排好了，看一眼中间那个就能排除一半——因为它左边的全都更小、右边的全都更大。**有序性把「逐个检查」变成了「每次扔掉一半」。**

**Bentley 的警告**：讲义开头引用了 Jon Bentley 在《Programming Pearls》里的著名段落。他让上百位职业程序员用几小时写二分查找，结果**九成的人写出的程序有 bug**；而 Knuth 指出，第一个公开发表的二分查找出现在 1946 年，**第一个没有 bug 的公开发表版本要等到 1962 年**——中间隔了 16 年。

Bentley 的结论正是本讲的立论：这些人缺的不是聪明，而是**用循环不变式组织程序的能力**。讲义接着说：前置/后置条件、循环不变式与断言的「魔力」在于**它们把推理局部化（localize reasoning）**——你不需要盯着整个函数，只需要盯着几条语句加上不变式。

**为什么中点要用 `lo + (hi-lo)/2`**：直觉上 `(lo+hi)/2` 完全正确。但在 32 位机器上，若 `lo` 与 `hi` 都很大，`lo + hi` 会溢出成负数。**这是 Java 标准库真实存在过的 bug**（Joshua Bloch 报告过）。修正的办法是「先求差再折半」——差值 `hi - lo` 永远不超过数组长度，绝不会溢出。

**为什么实验数据看起来不对**：二分查找跑 `2^18`、`2^19`、`2^20` 个元素，时间是 0.020、0.039、0.077 秒——**几乎严格翻倍**，看起来是线性的！讲义解释：你测的其实不是查找，而是**用随机数初始化整个数组**的时间。把初始化代码注释掉后，`2^20` 的耗时从 0.077 降到 0.072——**查找本身只占 0.005 秒**。

## 5. 原理与推导

### 5.1 算法描述

在已排序数组 `A[0..n)` 中查找 `x`：

1. 取当前区间 `[lo, hi)` 的中点 `mid`。
2. 若 `A[mid] == x`，返回 `mid`。
3. 若 `A[mid] < x`，则 `x` 只可能在 `A[mid+1..hi)`（因为左边全 `<= A[mid] < x`），令 `lo = mid + 1`。
4. 若 `A[mid] > x`，则 `x` 只可能在 `A[lo..mid)`，令 `hi = mid`。
5. 区间空（`lo == hi`）时返回 `-1`。

### 5.2 运行时间推导

**情形一：`n = 2^k`。**

设第 `t` 次迭代开始时（即第 `t` 次测试守卫前）的区间长度为 `L_t`。初始 `L_0 = 2^k`。

每轮把区间切成 `[lo, mid)` 与 `[mid+1, hi)` 两段。由 `mid = lo + (hi-lo)/2`，两段长度分别是 `mid - lo = (hi-lo)/2` 与 `hi - (mid+1) = (hi-lo) - (hi-lo)/2 - 1`，都**不超过**原长度的一半。所以：

```
L_{t+1} <= L_t / 2
```

于是 `L_t <= 2^k / 2^t = 2^(k-t)`。当 `t = k` 时 `L_k <= 1`；再一轮（`t = k+1`）区间长度变成 0，守卫 `lo < hi` 为假，退出。

**总迭代次数至多 `k + 1`。** 每轮做常数次操作（算 `mid`、一两次比较、一次赋值），设常数为 `c`，则：

```
T(n) <= c * (k + 1) = c * (log2 n + 1) = O(log2 n)
```

**情形二：`n` 不是 2 的幂。** 把 `n` 向上取整到下一个 2 的幂。讲义举例：`n = 13` 取 `16 = 2^4`。真实步数只会**更小**，因为实际子区间可能比取整后的界更短。所以上界仍然成立。

**输入翻倍的效果**：

```
log2(2n) = log2 2 + log2 n = 1 + log2 n
```

所以 `T(2n) ≈ c*(1 + log2 n) = c + T(n)`——**只多了一个常数 `c`**，而不是像线性查找那样翻倍。

**具体数字**：32 位补码能表示的最大正整数是 `2^31 - 1 ≈ 21 亿`。即便数组真有这么大，二分查找**最多只循环 31 次**。这是讲义用来制造震撼感的那句话。

### 5.3 规格：与线性查找完全相同

```c0
int binsearch(int x, int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@requires is_sorted(A, 0, n);
/*@ensures (-1 == \result && !is_in(x, A, 0, n))
          || ((0 <= \result && \result < n) && A[\result] == x);
@*/
;
```

**注意**：二分查找只多了 `is_sorted(A, 0, n)` 这一条前置，后置条件与 [[15-122-04-Searching-Arrays]] 的线性查找**逐字相同**。这正是「规格与实现分离」的价值——换算法不改契约。

### 5.4 第一步：最简单的那条不变式

```c0
int lo = 0;
int hi = n;
while (lo < hi)
//@loop_invariant 0 <= lo && lo <= hi && hi <= n;
{
  // ...??...
}
return -1;
```

守卫是 `lo < hi`（区间非空），退出时 `lo == hi`。这条不变式保证 `lo`、`hi` 始终是合法边界，且区间不会反向。

### 5.5 第二步：表达「已排除的区域」

讲义先画图：把数组画成一排方格，用红框框住「仍在考虑中」的段 `A[lo..hi)`。**红框左边的一切都已被排除（它们严格小于 `x`），红框右边的一切也已被排除（严格大于 `x`），中间尚未探索。**

于是自然的表述是：

```
A[lo-1] < x
A[hi] > x
```

**为什么这两条够用**：由排序性质，`A[lo-1] < x` 意味着 `A[0..lo)` 中所有元素都 `< x`（它们都 `<= A[lo-1]`），所以 `x` 不可能在左段；同理 `A[hi] > x` 意味着 `A[hi..n)` 全 `> x`，`x` 不可能在右段。

### 5.6 第三步：发现越界 bug

讲义在这里踩了刹车：「**现在一个很强的编程直觉应该告诉你有点不对。** 你能在写循环体之前就看出新不变式的问题吗？」

问题：**`A[lo-1]` 和 `A[hi]` 可能越界。** 循环开始时 `lo = 0`，`lo - 1 = -1` 是非法下标；`hi = n`，`A[n]` 也是非法下标。**在图上它们位于数组中间，但在代码里它们一开始就在边界之外。**

讲义的原则：**每当访问数组元素，你必须有充分理由相信这次访问在界内。** 循环不变式在**每次**测试守卫前都必须成立，包括第一次。

### 5.7 修正：用析取引入「哨兵情形」

仿照线性查找的做法，给每条加一个「边界已到」的析取项：

```c0
//@loop_invariant 0 <= lo && lo <= hi && hi <= n;
//@loop_invariant (lo == 0 || A[lo-1] < x);
//@loop_invariant (hi == n || A[hi] > x);
```

**为什么这样安全**：C0（与 C 一样）的 `||` 是**短路求值（short-circuit evaluation）**。`lo == 0` 为真时，右半边 `A[lo-1] < x` **根本不会被求值**，所以不会发生 `A[-1]`。同理 `hi == n` 时不会读 `A[n]`。

**为什么这样仍然够强**：

- `lo == 0` 时，左段 `A[0..0)` 为空，「`x` 不在其中」平凡成立——**不需要 `A[-1]` 这个虚构元素来帮忙**。
- `hi == n` 时，右段 `A[n..n)` 为空，同理。

**这就是「用析取把空段情形编码进去」的通用手法**，与 [[15-122-04-Searching-Arrays]] 中 `i == 0 || A[i-1] < x` 完全同构。

### 5.8 第四步：先证后置条件（不写循环体也能证）

讲义强调了一个惊人的事实：**在写出循环体之前，就可以验证不变式足够强。** 这既是「按不变式设计」的威力，也是很好的中断阅读去做练习的时机。

**情形 A：在循环内 `return mid`。** 此时 `A[mid] == x` 且 `lo <= mid < hi <= n`，故 `0 <= mid < n` 且 `A[mid] == x`——后置条件的第二个析取项成立。

**情形 B：退出循环后 `return -1`。** 守卫为假得 `lo >= hi`，不变式给 `lo <= hi`，故 `lo == hi`。分三种子情形：

1. **`lo > 0` 且 `hi < n`**：由不变式 2 得 `A[lo-1] < x`，由不变式 3 得 `A[hi] > x`。因 `lo == hi`，有 `A[lo-1] < x < A[lo]`。数组有序，`x` 落在 `A[lo-1]` 与 `A[lo]` 之间却不在数组中——**`x` 不存在**。
2. **`lo == 0`**：则 `hi == 0`。由不变式 3，要么 `n == 0`（空数组，返回 `-1` 正确），要么 `A[hi] = A[0] > x`。数组有序且首元素已严格大于 `x`，故 `x` 不在数组中。
3. **`hi == n`**：则 `lo == n`。由不变式 2，要么 `n == 0`，要么 `A[n-1] = A[lo-1] < x`。数组有序且末元素已严格小于 `x`，故 `x` 不在数组中。

三种情形覆盖了 `lo == 0`、`hi == n`、以及两者都不成立的所有可能（因为 `lo <= hi <= n` 且 `0 <= lo`）。**每种情形都归结到「`x` 落在某个有序数组的缝隙里」这一直觉。**

### 5.9 第五步：从不变式反推循环体

现在让循环体成为「保持不变式」的最自然写法。

已测过 `A[mid] == x`，返回。否则只剩两种：

**若 `A[mid] < x`**：右端 `hi` 保持不动（不变式 3 自动保持，因为 `hi' = hi`），把 `lo` 推到 `mid + 1`。验证不变式 2：

```
A[lo' - 1] = A[(mid+1) - 1] = A[mid] < x
```

**若 `A[mid] > x`**：左端 `lo` 不动（不变式 2 自动保持），把 `hi` 拉到 `mid`。验证不变式 3：

```
A[hi'] = A[mid] > x
```

**不需要再测 `A[mid] > x`**：因为 `A[mid] == x` 与 `A[mid] < x` 都失败了，剩下只能是 `>`。讲义用断言把这个推理记下来：

```c0
else /*@assert(A[mid] > x);@*/
  hi = mid;
```

### 5.10 保持性证明（完整）

假设三条不变式成立且守卫 `lo < hi` 成立：

```
(Inv 1)  0 <= lo <= hi <= n
(Inv 2)  lo == 0 || A[lo-1] < x
(Inv 3)  hi == n || A[hi] > x
(Guard)  lo < hi
```

计算 `mid = lo + floor((hi-lo)/2)`。

**情形 `A[mid] == x`**：函数返回，无需证保持性（只需证后置条件，见 5.8）。

**情形 `A[mid] < x`**：`lo' = mid + 1`，`hi' = hi`。

- Inv 1：`0 <= lo'` 由 `0 <= lo <= mid` 得；`lo' <= hi'` 需 `mid + 1 <= hi`，而 `mid < hi`（见 5.11 的断言）故成立；`hi' <= n` 由 `hi <= n`。
- Inv 2：`A[lo' - 1] = A[mid] < x`（上面的计算）。
- Inv 3：`hi' = hi`，原样保持。

**情形 `A[mid] > x`**：`lo' = lo`，`hi' = mid`。

- Inv 1：`0 <= lo' = lo`；`lo' <= hi'` 需 `lo <= mid`（断言）；`hi' = mid < hi <= n`。
- Inv 2：`lo' = lo`，原样保持。
- Inv 3：`A[hi'] = A[mid] > x`。

**初始化（INIT）**：`lo = 0`、`hi = n`。

- Inv 1：`0 <= 0 <= n <= n`，由前置 `0 <= n`。
- Inv 2：`lo == 0` 使第一个析取项为真。
- Inv 3：`hi == n` 使第一个析取项为真。

**这正是「析取式不变式在 INIT 时靠哨兵项成立」的典型模式。**

### 5.11 中点的溢出陷阱

讲义先用一行「诱人」的写法：

```c0
int mid = (lo + hi)/2;
```

**为什么错**：若 `lo + hi > 2^31 - 1`，加法溢出成负数（在 C0 的模 2^32 语义下，`1 + int_max() = int_min()`）。此时 `mid` 是负数，`A[mid]` 就是负下标访问，程序中止。

**现实性**：`2^31 = 2G`，需要至少 10 亿个元素的数组才可能触发。**不是不可能**——Java 标准库里真有这个 bug（讲义脚注指向 Joshua Bloch 的 "Extra, Extra" 博文）。

**修正与证明**：

```c0
int mid = lo + (hi-lo)/2;
//@assert lo <= mid && mid < hi;
```

**下界**：`hi - lo > 0`（由守卫），故 `(hi-lo)/2 >= 0`（C0 除法向零截断，正数除以 2 不小于 0），于是 `mid = lo + (hi-lo)/2 >= lo + 0 = lo`。

**上界**：`(hi-lo)/2 < hi - lo`，因为**正数除以 2 严格变小**（`hi - lo >= 1` 时 `(hi-lo)/2 <= (hi-lo)/2 < hi-lo`；更严格地说 `hi-lo >= 1` 蕴含 `(hi-lo)/2 <= (hi-lo) - (hi-lo+1)/2 < hi-lo`）。于是：

```
mid = lo + (hi-lo)/2 < lo + (hi-lo) = hi
```

**「其他运算都不会溢出」**：二分查找里其余的算术都在 `n` 以下的范围里，而 `n <= \length(A)` 本身是 `int`。

### 5.12 为什么选正中间

讲义自问：为什么看中间元素而不是别的？答：**无论比较结果如何，看中间能最大化「一次比较学到的信息量」。**

- 相等：直接完成。
- 中点偏小：下半个数组整体变得无关。
- 中点偏大：上半个数组整体变得无关。

三者都是「学到一半」。讲义补一句：**别的选择（比如三分之一处）二分查找也基本能工作**，只是最坏情况不如取中间。

### 5.13 终止性

若循环体执行（`lo < hi`），则区间非空。由 `mid` 的两个不等式：

- `[lo, mid)` 的长度 `mid - lo < hi - lo`（严格更短）
- `[mid+1, hi)` 的长度 `hi - mid - 1 < hi - lo`（严格更短）

两个子区间都**严格短于**原区间。所以每轮 `hi - lo` 至少减少 1，非负整数不可能无限递减，最终 `hi - lo == 0` 退出（除非中途 `return`）。**这就是用「区间长度是严格递减的自然数」证终止。**

### 5.14 实测与「测量陷阱」

实验设置（讲义第 13 页）：

```
% cc0 find.c0 find-time.c0
% time ./a.out
```

**注意不用 `-d` 标志**：`-d` 会做动态契约检查，**完全打乱计时**（contract checking 的开销可能比算法本身大几个数量级）。

**线性查找**（2000 次查找，1000 次命中 + 1000 次随机未命中）：

| 数组规模 | 时间 (s) | 比值 |
|---|---|---|
| `2^18` | 4.602 | — |
| `2^19` | 9.027 | 1.96 |
| `2^20` | 19.239 | 2.13 |

比值接近 2，符合线性。讲义说更大的数组会因为内存局部性（memory locality）与其他开销而偏大。

**二分查找**：

| 数组规模 | 时间 (s) | 比值 |
|---|---|---|
| `2^18` | 0.020 | — |
| `2^19` | 0.039 | 1.95 |
| `2^20` | 0.077 | 1.97 |

**快得多，但「可疑地也是线性的」**。讲义指出原因：**初始化数组要用随机数填满整个数组，这一步是 `O(n)` 的**。把初始化之外的测试代码注释掉，`2^20` 测得 0.072 秒（对比 0.077）——**说明我们一直在测「建数组」而不是「查找」**。

**教训**：做经验复杂度验证时，必须确认被测的那部分确实是瓶颈。`O(log n)` 的算法配 `O(n)` 的准备步骤，整体仍是 `O(n)`——这不是算法错了，是测量对象错了。

## 6. 代码示例

### 6.1 官方课程代码

以下代码引自讲义 PDF `06-binsearch.pdf`，语言为 **C0**（不是标准 C/C++）。`//@` 形式的注解、`\length`、`\result` 都是 C0 特有的，标准 C 编译器不认识。

**（1）规格（与线性查找相同），第 3 页：**

```c0
int binsearch(int x, int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@requires is_sorted(A, 0, n);
/*@ensures (-1 == \result && !is_in(x, A, 0, n))
          || ((0 <= \result && \result < n) && A[\result] == x);
@*/
;
```

**（2）只有第一条不变式的骨架，第 4 页：**

```c0
int binsearch(int x, int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@requires is_sorted(A, 0, n);
/*@ensures (-1 == \result && !is_in(x, A, 0, n))
          || ((0 <= \result && \result < n) && A[\result] == x);
@*/
{
  int lo = 0;
  int hi = n;
  while (lo < hi)
  //@loop_invariant 0 <= lo && lo <= hi && hi <= n;
  {
    // ...??...
  }
  return -1;
}
```

**（3）加入越界的不变式（第 6 页，随后被判定为错误）：**

```c0
//@loop_invariant 0 <= lo && lo <= hi && hi <= n;
//@loop_invariant A[lo-1] < x;      // 错：lo == 0 时越界
//@loop_invariant A[hi] > x;        // 错：hi == n 时越界
```

**（4）修正后的完整实现，第 9 页：**

```c0
int binsearch(int x, int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@requires is_sorted(A, 0, n);
/*@ensures (-1 == \result && !is_in(x, A, 0, n))
          || ((0 <= \result && \result < n) && A[\result] == x);
@*/
{
  int lo = 0;
  int hi = n;
  while (lo < hi)
  //@loop_invariant 0 <= lo && lo <= hi && hi <= n;
  //@loop_invariant (lo == 0 || A[lo-1] < x);
  //@loop_invariant (hi == n || A[hi] > x);
  {
    int mid = lo + (hi-lo)/2;
    //@assert lo <= mid && mid < hi;
    if (A[mid] == x) return mid;
    else if (A[mid] < x) lo = mid+1;
    else /*@assert(A[mid] > x);@*/
      hi = mid;
  }
  return -1;
}
```

**（5）习题 1 答案：闭区间版本，第 17 页：**

```c0
int binsearch_inclusive(int x, int[] A, int n)
//@requires n == \length(A);
//@requires is_sorted(A, 0, n);
/*@ensures (-1 == \result && !is_in(x, A, 0, n))
          || ((0 <= \result && \result < n) && A[\result] == x); @*/
{
  int lo = 0;
  int hi = n-1;
  while (lo <= hi)
  //@loop_invariant 0 <= lo && lo <= hi+1 && hi < n;
  //@loop_invariant gt_seg(x, A, 0, lo);
  //@loop_invariant lt_seg(x, A, hi+1, n);
  {
    int mid = lo + (hi-lo)/2;
    //@assert lo <= mid && mid <= hi;
    if (A[mid] == x) return mid;
    else if (A[mid] < x)
      lo = mid+1;
    else /*@assert(A[mid] > x);@*/
      hi = mid-1;
  }
  //@assert lo == hi+1;
  return -1;
}
```

四处改动：`hi = n-1`；守卫 `lo <= hi`；`hi = mid-1`；不变式 `lo <= hi+1 && hi < n`。**边界约定的改变必须同步改变不变式与断言**——讲义特别提醒要检查 `n == 0` 时 `hi == -1` 的情形。

**（6）习题 2 答案：用 `!is_in` 重写不变式，第 21 页：**

```c0
int search(int x, int[] A, int n)
//@requires n == \length(A);
//@requires is_sorted(A, 0, n);
/*@ensures (\result == -1 && !is_in(x, A, 0, n))
          || (0 <= \result && \result < n && A[\result] == x); @*/
{
  int lo = 0;
  int hi = n;
  while (lo < hi)
  //@loop_invariant 0 <= lo && lo <= hi && hi <= n;
  //@loop_invariant !is_in(x, A,0,lo);
  //@loop_invariant !is_in(x, A,hi,n);
  {
    int mid = lo + (hi - lo)/2;
    //@assert lo <= mid && mid < hi;
    if (A[mid] == x) return mid;
    if (A[mid] < x) {
      //@assert mid + 1 <= hi;
      //@assert !is_in(x, A,0,mid+1);
      lo = mid+1;
    } else { //@assert A[mid] > x;
      //@assert !is_in(x, A,mid,n);
      hi = mid;
    }
  }
  //@assert lo == hi;
  //@assert !is_in(x,A,0,n);
  return -1;
}
```

**这版不变式不再需要析取**，因为 `!is_in(x, A, 0, 0)` 与 `!is_in(x, A, n, n)` 本身就是空段上的平凡真命题。代价是每条不变式都调用一个 `O(n)` 的规格函数——**只用于推理，不用于运行**。

### 6.2 Agent 自行编写的教学示例

> **非官方，仅用于说明概念。** 以下由本笔记自行编写，不是 CMU 官方代码，语言为 **C0**。

**示例 A：找最左出现位置（对应习题 3）。**

标准二分查找在有重复元素时**不保证**返回最左的那一个。反例：`A = [1, 2, 2, 2, 3]`、`x = 2`，`n = 5`。第一轮 `lo=0, hi=5, mid=2`，`A[2] == 2`，直接返回 `2`。但最左出现是下标 `1`。

修改思路：**相等时不返回，而是继续往左找**，同时记录当前最好的答案。

```c0
int binsearch_leftmost(int x, int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@requires is_sorted(A, 0, n);
/*@ensures (\result == -1 && !is_in(x, A, 0, n))
          || (0 <= \result && \result < n && A[\result] == x); @*/
{
  int lo = 0;
  int hi = n;
  int best = -1;
  while (lo < hi)
  //@loop_invariant 0 <= lo && lo <= hi && hi <= n;
  //@loop_invariant (best == -1 || (0 <= best && best < n && A[best] == x));
  //@loop_invariant (lo == 0 || A[lo-1] < x);
  //@loop_invariant (hi == n || A[hi] >= x);
  {
    int mid = lo + (hi-lo)/2;
    //@assert lo <= mid && mid < hi;
    if (A[mid] < x) lo = mid+1;
    else if (A[mid] > x) hi = mid;
    else { best = mid; hi = mid; }
  }
  return best;
}
```

**关键差别**：第三条不变式从 `A[hi] > x` 弱化成 `A[hi] >= x`，因为 `A[hi]` 现在**可能正好等于 `x`**（相等时我们把 `hi` 拉到 `mid`，右段里仍可能藏着更左的 `x`）。**不变式的强弱必须与算法的行为精确匹配**——这是「不变式即设计」的直接体现。

**示例 B：把 `mid` 的两种写法放在一起对比。**

```c0
int safe_mid(int lo, int hi)
//@requires 0 <= lo && lo < hi;
//@ensures lo <= \result && \result < hi;
{
  return lo + (hi-lo)/2;
}
```

契约 `//@ensures lo <= \result && \result < hi` 就是讲义第 9 页那条断言的**函数化版本**。若把它写成 `(lo+hi)/2`，在 `lo = 1`、`hi = int_max()` 时后置条件会失败——**契约自己会抓住这个 bug**（对应习题 4 的答案）。

**示例 C：三种 `mid` 写法的等价性检查（对应习题 5、6）。**

| 写法 | `lo=1, hi=1` | `lo=1, hi=3` | `lo=0, hi=1` | 是否总等价于 `(lo+hi)/2` |
|---|---|---|---|---|
| `(lo+hi)/2` | 1 | 2 | 0 | 基准 |
| `lo + (hi-lo)/2` | 1 | 2 | 0 | **总是等价**（习题 6） |
| `lo/2 + hi/2` | 0 | 1 | 0 | **不等价**（习题 5） |

`lo/2 + hi/2` 的失败条件是 **`lo` 与 `hi` 都是奇数**：此时两个除法各丢一个 `1/2`，合计丢掉 1。`lo + (hi-lo)/2` 安全的原因：`hi - lo` 的奇偶性与 `lo + hi` **相同**（差为 `2*lo`），所以折半时丢掉的量也一样。

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| `A[lo-1] < x` | `(lo == 0 \|\| A[lo-1] < x)` | 前者在 `lo == 0` 时越界；后者靠短路求值避开 | 空段用析取编码 |
| `while (lo < hi)`（半开） | `while (lo <= hi)`（闭） | 前者区间 `[lo,hi)`；后者 `[lo,hi]`，需 `hi = n-1` 与 `hi = mid-1` | 换约定要换全套 |
| `lo <= hi`（不变式） | `lo <= hi+1`（闭区间版） | 闭区间版允许 `lo == hi+1`（区间空） | 空区间的表示不同 |
| `A[hi] > x` | `A[hi] >= x`（找最左时） | 相等时不能排除右段，只能弱化成 `>=` | 不变式强弱要匹配算法 |
| `(lo+hi)/2` | `lo + (hi-lo)/2` | 前者溢出为负；后者差值不溢出 | 先减后加 |
| `(lo+hi)/2` | `lo/2 + hi/2` | 两者都是奇数时差 1（`1/2+1/2 = 0` vs `2/2 = 1`） | 两个半截各丢一次 |
| `is_sorted` 前置 | `is_in` 后置 | 二分查找**必须**有序；线性查找不需要 | 加速的代价是前置条件 |
| 算法 `O(log n)` | 端到端计时 `O(n)` | 初始化数组是 `O(n)`，掩盖了查找 | 测量对象要对 |
| 编译带 `-d` | 不带 `-d` | `-d` 做动态契约检查，彻底打乱计时 | 测性能一定不加 `-d` |
| 循环体 `lo=lo; hi=hi;` | 真正的二分 | 前者保持性平凡成立但**永不终止** | 不变量成立 ≠ 程序正确 |

## 10. 本节复习

1. 二分查找要求 `is_sorted(A, 0, n)`；规格的后置条件与线性查找**逐字相同**。
2. `n = 2^k` 时最多 `k+1` 轮；任意 `n` 取整到下一个 2 的幂；总代价 `O(log2 n)`。
3. 输入翻倍只多常数工作量：`log2(2n) = 1 + log2 n`。
4. 三条不变式：`0 <= lo <= hi <= n`；`(lo == 0 || A[lo-1] < x)`；`(hi == n || A[hi] > x)`。
5. 后两条的析取项是**为了避开越界访问**，靠 `||` 的短路求值生效；INIT 时正是靠析取项成立。
6. 退出时 `lo == hi`，分 `lo > 0 && hi < n`、`lo == 0`、`hi == n` 三种情形证 `!is_in`。
7. `A[mid] < x` 时 `lo = mid+1`（不变式 2 靠 `A[lo'-1] = A[mid] < x` 保持）；`A[mid] > x` 时 `hi = mid`（不变式 3 靠 `A[hi'] = A[mid] > x` 保持）。
8. 不必再测 `A[mid] > x`——前两个测试都失败就蕴含它，用 `//@assert` 记录这个推理。
9. `(lo+hi)/2` 会溢出（Java 库真有此 bug）；用 `lo + (hi-lo)/2` 并断言 `lo <= mid && mid < hi`。
10. 终止性：两个子区间的长度都**严格小于**原区间。
11. 闭区间版要同时改 `hi = n-1`、守卫 `lo <= hi`、`hi = mid-1`、不变式 `lo <= hi+1 && hi < n`。
12. 计时实验必须不带 `-d`，且必须确认被测部分不是 `O(n)` 的初始化。

**答 1.** `n = 10`，`lo = 0`，`hi = 10`。

| 迭代 | lo | hi | mid | A[mid] | 比较 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 10 | `0 + 10/2 = 5` | 23 | `== 23` | **返回 5** |

**只一轮就命中**——因为 23 恰好在正中间。这正好演示「最好情况」是 `O(1)`。
若改成 `x = 16`：第 1 轮 `mid = 5`、`A[5] = 23 > 16`，`hi = 5`；第 2 轮 `lo=0, hi=5, mid = 0 + 5/2 = 2`，`A[2] = 8 < 16`，`lo = 3`；第 3 轮 `lo=3, hi=5, mid = 3 + 2/2 = 4`，`A[4] = 16`，**返回 4**。三轮。
若 `x = 17`（不存在）：第 1 轮 `mid=5`、`23 > 17`，`hi=5`；第 2 轮 `mid=2`、`8 < 17`，`lo=3`；第 3 轮 `lo=3,hi=5,mid=4`、`16 < 17`，`lo=5`；此时 `lo == hi == 5` 退出，返回 `-1`。由不变式 2：`A[4] = 16 < 17`；不变式 3：`A[5] = 23 > 17`。`17` 夹在 `A[4]` 与 `A[5]` 之间而不在数组中——正确。

**答 2.** `A[lo-1]` 在 `lo == 0` 时是 `A[-1]`，**不是「值为假」，而是「非法内存访问」**。C0 运行时会直接中止并报「数组下标越界」错误，整个不变式检查失败，程序根本走不到判断真假那一步。**契约里的表达式也受数组边界检查约束**——这是本讲最反直觉的一点：写不变式时同样要考虑安全性（safety）。
`||` 在 C0 中是短路求值：先算左操作数，若为真则整个表达式为真，**右操作数完全不被求值**。所以 `lo == 0 || A[lo-1] < x` 在 `lo == 0` 时不会触碰 `A[-1]`。同理 `&&` 也是短路的（[[15-122-04-Searching-Arrays]] 里 `i < n && A[i] <= x` 用的是同一机制）。
**注意顺序不能颠倒**：写成 `A[lo-1] < x || lo == 0` 就失去保护了。

**答 3.** 闭区间版 `hi = n-1`，守卫 `lo <= hi`，退出条件是 `lo > hi`，即 `lo == hi + 1`（由不变式 `lo <= hi+1`）。

取 `n = 1`：`lo = 0`、`hi = 0`，区间是单元素 `A[0..0]`。
- 若 `A[0] == x`，第 1 轮 `mid = 0 + 0/2 = 0`，返回 0。
- 若 `A[0] != x`，第 1 轮后 `lo = 1` 或 `hi = -1`，守卫 `lo <= hi` 为假，退出。此时 `lo = 1 = hi + 1`（或 `hi = -1`、`lo = 0 = hi+1`）。

**关键**：退出时 `lo` 比 `hi` 大 1，而不是相等。若不变式只写 `lo <= hi`，退出时它**立刻为假**，EXIT 条件无法从「不变式 + 守卫取反」推出任何有用的东西。写成 `lo <= hi+1` 才能保证不变式在退出后仍然成立，从而支撑 `//@assert lo == hi+1;` 与后续的 `!is_in` 证明。
**`n == 0` 的边界**：此时 `hi = -1`、`lo = 0`，`lo = hi + 1` 恰好成立，守卫 `0 <= -1` 为假，直接返回 `-1`——正确。**这正是 `lo <= hi+1` 这个「奇怪的」形式存在的理由**：它必须同时覆盖 `hi = -1` 这个空区间情形。

**答 4.** 设 `d = hi - lo >= 0`。整数除法向零截断，对非负数即取下整。分 `d` 的奇偶：

- `d = 2m`：`(hi-lo)/2 = m`，故左边 `= lo + m`。右边 `(lo+hi)/2 = (2lo + 2m)/2 = lo + m`。**相等**。
- `d = 2m+1`：`(hi-lo)/2 = m`，左边 `= lo + m`。右边 `(lo + hi)/2 = (2lo + 2m + 1)/2 = lo + m`（`1/2` 被截掉）。**相等**。

所以两式恒等（在**无溢出**的整数运算下）。这也解释了为什么习题 5 的 `lo/2 + hi/2` 会失败：`lo = 2a+1`、`hi = 2b+1` 时

```
lo/2 + hi/2 = a + b
(lo+hi)/2 = (2a+2b+2)/2 = a + b + 1
```

**差 1**，因为 `lo + hi` 是偶数而两个半截各丢了一次 `1/2`，合起来丢了 1。`lo + (hi-lo)/2` 之所以没这个问题，是因为 `hi - lo` 与 `lo + hi` 的**奇偶性相同**（差 `2*lo`），折半时丢的量一致。

**答 5.** **三条不变式全部成立。** 因为 `lo`、`hi` 不变，保持性证明变成「结论 = 前提」，平凡成立（INIT 也照旧成立）。这就是习题 7 的结论。

**但程序不正确，因为不终止。** 若初始 `lo != hi`（即 `n != 0`），守卫 `lo < hi` 永远为真，循环永不退出，函数永远不返回——**后置条件（`return -1` 那条路径）永远无法达成**。

**教学价值**：这个反例说明「循环不变式成立」只是**部分正确性（partial correctness）**，必须**加上终止性**才是**完全正确性（total correctness）**。讲义在 [[15-122-01-Contracts]] 里已经区分过这两件事：不变式的三条证明义务（INIT/PRES/EXIT）只管「若退出则结论对」，终止性要单独证——而这里正是终止性单独失效的例子。

</details>
