## 3. 核心概念

**Tree（树）**：连通且无简单环的无向图。

**Forest（森林）**：无环的无向图（可以不连通）。森林的每个连通分量是一棵树。

**Spanning Tree（生成树）**：图 `G = (V,E)` 的生成树是满足以下两条的图 `T = (V, E')`：`E' ⊆ E`，且 `T` 是树。**顶点集完全相同**，边集是子集。

**Minimum Spanning Tree（最小生成树，MST）**：带权图 `G` 中，边权和最小的生成树。

**Cycle Property（环性质）**：设 `C` 是图中的一个简单环，`e` 是 `C` 中权重**最大**的边（严格最大），则存在某棵 MST 不含 `e`。

**Kruskal 算法**：按权重升序考虑每条边，若加入后不成环就加入，直到有 `v−1` 条边。

**Prim 算法**：从一个顶点开始，每次加入「连接树内与树外、权重最小」的边。

## 4. 通俗理解

**生成树 = 「用最少的边把所有点连起来」**。`v` 个点最少要 `v−1` 条边才能连通——少一条就有两个点断开，多一条就必然有环。生成树就是「刚好够用」的连通方案。

**MST = 「最便宜的连通方案」**。要在 `v` 个城市之间铺光纤，怎么铺最省钱？答案是一棵 MST。

**Cycle Property 的直觉**：一个环上如果有一条特别贵的边，你**永远不需要它**——因为环上其他边已经能把这圈连起来了。把贵边删掉，环上剩下的边仍然连通两端。**所以最贵的边可以安全丢弃。**

**Kruskal = 「从最便宜的边开始，能加就加」**。像拼图：先拿最便宜的碎片，只要不形成闭环就拼上。最后一定得到 MST。

**Prim = 「从一个点开始，不断吸收最近的邻居」**。像滚雪球：雪球（树）每次粘上一个离它最近的外部点。

**随机迷宫 = 随机生成树**。把网格的每个格子当顶点、相邻格子的墙当边，随机打乱边序后用 Kruskal 处理——得到的生成树就是「任意两点恰有一条通路、无环」的迷宫。**这就是为什么迷宫总是「一条路走到黑、没有环路」。**

## 5. 原理与推导

### 5.1 树的六种等价刻画

讲义第 2 页列出六条，它们对有限无向图**互相等价**：

1. `T` 连通且无环。
2. `T` 连通，且任意两个相邻顶点之间**没有其他通路**（即删掉这条边就不连通）。
3. `T` 是单点图，或者 `T` 由两棵树加一条连接它们的边构成。
4. `T` 是单点图，或者 `T` 由一个顶点加一条边连到一棵树构成。
5. `T` 连通且恰有 `v − 1` 条边。
6. `T` 中任意两个不同顶点之间**恰有一条**路径。

**证明思路（选证几组）**：

**（1）⇒（6）**：连通保证「至少一条路径」；无环保证「至多一条」——若有两條不同路径 `P₁`、`P₂`，它们必然在某处分叉又汇合，形成环，矛盾。

**（6）⇒（5）**：连通 ⇒ 至少 `v−1` 条边（连通的必要条件）；无环 ⇒ 至多 `v−1` 条边（`v` 个顶点的森林最多 `v−1` 条边）。两条合起来得恰 `v−1`。

**（5）⇒（1）**：连通已给。假设有环，删掉环上一条边仍连通，得 `v−2` 条边的连通图——但连通图至少 `v−1` 条边，矛盾。所以无环。

**（3）与（4）是结构归纳的定义**，用于证明「所有树都具有某性质」——对树的规模做归纳，把大树分解成小树。

**（5）的用处最大**：它给出一个**计数判据**。「`v` 个顶点、`v−1` 条边、连通」三个条件中任意两个推出第三个。Kruskal 算法就用「加满 `v−1` 条边就停」作为终止条件。

### 5.2 边中心算法

讲义第 3 页：

```
从 v 个单点树开始（每个顶点是一棵只有自己的树）
重复：
  取一条原图的边 {u,v}
  用 DFS/BFS 判断 u 和 v 是否已在同一棵树里
  若不在，加入这条边（合并两棵树）
直到只剩一棵树（或没有更多边）
```

**复杂度**：最多 `e` 轮，每轮做一次连通性判断（DFS 是 O(v+e)）。总计 **O(e·(v+e)) = O(ev)**（当 `e ≥ v` 时）。

**这个算法的两个问题**：

1. **判断连通性太慢**。每次 DFS 都是 O(v+e)。第 24 讲的**并查集**把它降到近 O(1)。
2. **边的顺序任意**。得到的是「某棵」生成树，不是 MST。要得到 MST 必须**按权重排序**——这就是 Kruskal。

### 5.3 顶点中心算法

讲义第 4–5 页：

```
任选一个起点，标记它（这是初始的树）
重复：
  取一条「一端在树内、一端在树外」的边
  加入这条边，标记树外那端
直到所有顶点都被标记
```

**复杂度**：每条边最多被检查一次（或两次），每个顶点被标记一次。总计 **O(v + e)**——**比边中心快得多**。

**为什么更快**：顶点中心算法不需要「判断两端是否已连通」——它只找「一端在内、一端在外」的边，这个条件在扫描边时 O(1) 就能判断（查两个 `mark` 值）。

**正确性**：每次加入的边连接「树内」与「树外」，所以：

- **不会成环**：新边的一端是新顶点，不构成回路。
- **保持连通**：新顶点通过新边接入已有的树。
- **终止时是生成树**：所有顶点都被标记，且加了 `v−1` 条边。

**边的顺序仍然任意**——所以顶点中心算法得到的也是「某棵」生成树，不是 MST。

**顶点中心 → Prim**：如果把「取一条边」改成「取**权重最小**的那条跨界边」，就得到 Prim 算法（见 5.7 节）。**所以 Prim = 顶点中心 + 贪心选最小边。**

### 5.4 随机迷宫生成

讲义第 5–6 页：

1. 把网格的每个格子看作顶点。
2. 相邻格子之间有一条边（代表「可以打通墙」）。
3. **随机打乱边的顺序**。
4. 用边中心算法（或 Kruskal，不排序而是用随机顺序）处理。

得到的生成树就是迷宫：任意两个格子之间**恰有一条**通路（性质 6），且**没有环**（性质 1）。

**为什么迷宫不能有环**：有环就意味着「有两条路可以到同一个地方」，玩家可以绕圈——这不符合迷宫的定义（迷宫应该是「树形」的，唯一解）。

**为什么随机顺序**：不同的边序产生不同的生成树，所以每次生成的迷宫都不同。**这是「随机化算法」的简单例子**——不需要真的随机选树，只需要随机化输入顺序。

### 5.5 Cycle Property 及其证明

**陈述**（讲义第 6 页）：设 `C` 是图 `G` 的一个简单环，`e` 是 `C` 中权重**严格最大**的边。则存在某棵 MST `T` 使得 `e ∉ T`。

**证明**（交换论证，exchange argument）：

设 `T` 是任意一棵 MST。

**情形 1：`e ∉ T`**。那么 `T` 本身就是所求。✓

**情形 2：`e ∈ T`**。从 `T` 中删掉 `e`，得到两棵子树 `T₁`、`T₂`（因为树删一条边就分成两个连通分量）。`e` 的两端分别在 `T₁` 和 `T₂`。

现在看环 `C`。`C` 是一条闭合回路，它从 `e` 的一端出发、经过环上其他边、回到 `e` 的另一端。因为 `e` 连接 `T₁` 与 `T₂`，环 `C` 上必然有**另一条边** `e'` 也连接 `T₁` 与 `T₂`——否则环无法从 `T₁` 回到 `T₂`。

（形式化：沿环 `C` 从 `e` 的一端走到另一端，起点在 `T₁`、终点在 `T₂`，所以路径上必有一步从 `T₁` 跨到 `T₂`，那一步就是 `e'`。）

构造 `T' = (T \ {e}) ∪ {e'}`。

- **`T'` 是生成树**：`e'` 连接 `T₁` 与 `T₂` 两个分量，加入后重新连通，且 `T'` 有 `v−1` 条边、连通 ⇒ 是树（性质 5）。
- **`T'` 的权重 ≤ `T`**：`weight(T') = weight(T) − w(e) + w(e')`。因为 `e` 是环上**严格最大**的，所以 `w(e') < w(e)`，于是 `weight(T') < weight(T)`。

**但 `T` 是 MST，不可能有更小的生成树**——矛盾！

所以情形 2 不成立，`e ∉ T`。∎

**这个证明的结构值得记住**：假设「最优解包含坏元素」→ 构造一个「换掉它但不更差」的解 → 与最优性矛盾。**这是贪心算法正确性证明的标准模板。**

**严格最大 vs 最大**：如果环上有两条并列最大的边，结论是「存在某棵 MST 不含 `e`」仍然成立（用 `≤` 代替 `<`，得到 `weight(T') ≤ weight(T)`，`T'` 仍是 MST）。但**不能断言「所有 MST 都不含 `e`」**——可能某棵 MST 必须含它。所以讲义说「存在某棵」。

### 5.6 Kruskal 算法

**算法**（讲义第 6–7 页）：

```
把边按权重升序排序
T = 空集
for each edge e in sorted order:
    if T ∪ {e} 不含环:
        T = T ∪ {e}
    if |T| == v - 1:
        break
return T
```

**正确性（由 Cycle Property 推出）**：

**断言**：Kruskal 加入的每条边都属于某棵 MST。

*证明（对加入的边数归纳）*：设当前已加入的边集为 `T`，且 `T ⊆ T*`（某棵 MST）。

考虑下一条被 Kruskal 选中的边 `e = {u,v}`（加入后不成环）。

在 `T*` 中，`u` 与 `v` 之间恰有一条路径 `P`（性质 6）。`P` 加上 `e` 构成一个环 `C`。

- **若 `e ∈ T*`**：直接有 `T ∪ {e} ⊆ T*`。✓
- **若 `e ∉ T*`**：则 `P` 上必有某条边 `e'` 不在 `T` 中（否则 `u`、`v` 在 `T` 中已连通，加入 `e` 会成环，与「Kruskal 选中 `e`」矛盾）。
  
  因为 Kruskal 按权重升序处理，而 `e'` 还没被处理（不在 `T` 中且排在 `e` 之后或被跳过），所以 `w(e) ≤ w(e')`。
  
  若 `w(e) < w(e')`：`e` 是环 `C` 上严格最大的边之一？不——`e` 是最小的。这里要用**反向**的论证：`e'` 是环上「未被选中的」边。
  
  由 Cycle Property 的对称版本：若 `e'` 是环 `C` 上权重最大的边，则可以把它换掉。但这里 `w(e) ≤ w(e')`，所以 `e'` 才是（或并列）最大的。
  
  构造 `T*' = (T* \ {e'}) ∪ {e}`。`T*'` 是生成树（`e'` 在 `T*` 的 `u-v` 路径上，删掉后 `u`、`v` 分属两个分量，加 `e` 重新连通）。权重 `weight(T*') = weight(T*) − w(e') + w(e) ≤ weight(T*)`。因为 `T*` 是 MST，所以 `T*'` 也是 MST。
  
  于是 `T ∪ {e} ⊆ T*'`。✓

**归纳完成**：Kruskal 结束时 `T` 有 `v−1` 条边（性质 5 保证这足够连通），且 `T ⊆ 某棵 MST`。两者合起来 ⇒ `T` 就是那棵 MST。∎

**复杂度**：

- **排序**：O(e log e)。
- **判环**：讲义这里用边中心的方法（DFS/BFS），每次 O(v+e)，共 `e` 次 ⇒ **O(e(v+e)) = O(ev)**。
- **总计**：**O(e log e + ev)**。

**瓶颈在判环**。第 24 讲的**并查集**把它降到近 O(1)，于是 Kruskal 变成 **O(e log e)**——排序成为瓶颈，这已经是最优的（比较排序的下界）。

### 5.7 Prim 算法

**算法**（讲义第 8 页）：顶点中心算法 + 优先队列。

```
任选起点 s，标记 s
把所有与 s 相邻的边放入优先队列（按权重）
while 队列非空 且 未标记顶点数 < v:
    取出权重最小的边 e = {u, w}，其中 u 已标记、w 未标记
    若 w 已标记，丢弃 e（过时的边），继续
    加入 e，标记 w
    把 w 的所有「另一端未标记」的边放入队列
```

**复杂度**：每个顶点入队一次、每条边最多入队两次。优先队列操作 O(log e)。总计 **O(v + e log e)**。

**Prim vs Kruskal**：

| | Kruskal | Prim |
|---|---|---|
| 视角 | 边中心（全局最小边） | 顶点中心（局部最小边） |
| 需要排序 | 是（O(e log e)） | 否（用堆） |
| 复杂度 | O(e log e)（配并查集） | O(e log e)（配二叉堆） |
| 适合 | 稀疏图 | 稠密图（配斐波那契堆可到 O(e + v log v)） |
| 实现难度 | 简单（排序 + 判环） | 中等（需要堆 + 过时边处理） |

**两者都正确**：由 Cycle Property 可以证明 Prim 也正确（每次选的边是「跨越当前割的最小边」，属于某棵 MST）。这个论证叫 **Cut Property（割性质）**，是 Cycle Property 的对偶。

### 5.8 完整算例

讲义第 6–7 页的例子。图有 5 个顶点 `{A,B,C,D,E}`、6 条边，权重：

| 边 | 权重 |
|---|---|
| AE | 2 |
| BE | 2 |
| CE | 2 |
| BC | 3 |
| CD | 3 |
| AB | 3 |

**Kruskal 执行过程**：

1. 排序：`AE(2), BE(2), CE(2), BC(3), CD(3), AB(3)`。
2. 加 `AE`：`T = {AE}`，2 个顶点连通。
3. 加 `BE`：`T = {AE, BE}`，`{A,B,E}` 连通。
4. 加 `CE`：`T = {AE, BE, CE}`，`{A,B,C,E}` 连通。
5. 考虑 `BC(3)`：`B` 与 `C` 已通过 `E` 连通（`B–E–C`），加入会成环 `BCE`。**跳过**。
6. 加 `CD(3)`：`T = {AE, BE, CE, CD}`，5 个顶点全连通，4 条边 = `v−1`。**停止**。

**MST 权重** = `2 + 2 + 2 + 3 = 9`。

**验证 Cycle Property**：环 `B–C–E–B` 的三条边是 `BC(3)`、`CE(2)`、`BE(2)`。最大的是 `BC(3)`。Cycle Property 说「存在 MST 不含 `BC`」——确实，我们的 MST 就不含它。✓

**如果边权有并列**：假设 `BC` 也是 2，那么环 `BCE` 上有三条权重 2 的边。「存在某棵 MST 不含 `BC`」仍成立（可以选 `BE` 和 `CE`），但也存在含 `BC` 的 MST（选 `BC` 和 `AE`、`CD`、再加一条连 `E` 的）。**MST 不唯一，但权重唯一。**

5 个顶点 `{A,B,C,D,E}`、6 条边 `{AB, BC, CD, AE, BE, CE}`。

**（2）树的六种等价刻画**（第 2 页）

连通无环 / 连通且相邻顶点间无其他通路 / 两棵树加一边 / 一顶点连到一棵树 / 连通且 `v−1` 条边 / 任意两点恰一条路径。

**（3）森林的定义**（第 2 页）

树的集合，每个连通分量是树。

**（4）边中心算法**（第 3 页）

从 `v` 个单点树开始，反复用 DFS/BFS 判断两端是否已连通。复杂度 O(ev)。

**（5）顶点中心算法**（第 4–5 页）

标记起点，反复取「一端在内一端在外」的边。复杂度 O(max(v,e))。

**（6）随机迷宫**（第 5–6 页）

随机排列边序 + 边中心算法。

**（7）Cycle Property 与证明**（第 6 页）

交换论证：删 `e` 分两子树，环上必有另一条跨界边 `e'`，用 `e'` 换 `e` 得权重不增的生成树。

**（8）Kruskal 算法**（第 6–7 页）

按权重升序，不成环就加，加满 `v−1` 条停。示例边权 `AE 2, BE 2, CE 2, BC 3, CD 3, AB 3` ⇒ 加 `AE, BE, CE`，跳过 `BC`（成环 `BCE`），加 `CD` ⇒ MST 权重 **9**。

### 6.2 Agent 自行编写的教学示例

> 非官方，仅用于说明概念

**示例一：用并查集的「朴素版」实现 Kruskal（完整可运行）。**

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include "lib/xalloc.h"

typedef struct edge {
  int u, v, w;
} edge;

/* 比较函数：按权重升序 */
int cmp_edge(const void *a, const void *b) {
  const edge *ea = a, *eb = b;
  if (ea->w < eb->w) return -1;
  if (ea->w > eb->w) return  1;
  return 0;
}

/* 朴素并查集：parent[i] = i 表示 i 是根 */
int uf_find(int *parent, int x) {
  while (parent[x] != x) x = parent[x];
  return x;
}

void uf_union(int *parent, int x, int y) {
  int rx = uf_find(parent, x);
  int ry = uf_find(parent, y);
  if (rx != ry) parent[rx] = ry;
}

/* 返回 MST 的总权重，选中的边写入 result（长度 *count） */
int kruskal(int v, edge *edges, int e, edge *result, int *count) {
  qsort(edges, e, sizeof(edge), cmp_edge);       /* O(e log e) */

  int *parent = xmalloc(v * sizeof(int));
  for (int i = 0; i < v; i++) parent[i] = i;     /* 每个顶点自成一棵树 */

  int total = 0;
  *count = 0;

  for (int i = 0; i < e && *count < v - 1; i++) {
    int ru = uf_find(parent, edges[i].u);
    int rv = uf_find(parent, edges[i].v);
    if (ru != rv) {                              /* 不成环 */
      parent[ru] = rv;                           /* 合并 */
      result[(*count)++] = edges[i];
      total += edges[i].w;
    }
    /* 成环则跳过 */
  }

  free(parent);
  return total;
}

int main(void) {
  /* 讲义的例子：A=0, B=1, C=2, D=3, E=4 */
  edge edges[] = {
    {0, 4, 2},   /* AE */
    {1, 4, 2},   /* BE */
    {2, 4, 2},   /* CE */
    {1, 2, 3},   /* BC */
    {2, 3, 3},   /* CD */
    {0, 1, 3},   /* AB */
  };
  int e = sizeof(edges) / sizeof(edges[0]);
  edge result[8];
  int count;

  int total = kruskal(5, edges, e, result, &count);
  printf("MST weight = %d, edges = %d\n", total, count);
  for (int i = 0; i < count; i++)
    printf("  {%d,%d} w=%d\n", result[i].u, result[i].v, result[i].w);
  return 0;
}
```

输出：

```
MST weight = 9, edges = 4
  {0,4} w=2
  {1,4} w=2
  {2,4} w=2
  {2,3} w=3
```

**注意 `qsort` 的稳定性**：`qsort` **不保证稳定**。当有多条权重相同的边时，不同运行可能得到不同的 MST——但**总权重相同**（MST 的权重唯一）。这是「解不唯一但最优值唯一」的典型例子。

**朴素并查集的复杂度**：`uf_find` 最坏 O(v)（退化成链），`e` 次 ⇒ O(ev)。这与讲义的「边中心算法」同级。第 24 讲的**按秩合并 + 路径压缩**把它降到近 O(1)。

**示例二：顶点中心算法（不带权重，构造任意生成树）。**

```c
#include <stdbool.h>
#include "graph.h"

/* 返回一棵生成树的边（以邻接表形式），假设 G 连通。
 * 调用者负责 free。这里只打印边。
 */
void spanning_tree_vertex_centric(graph_t G) {
  unsigned int v = graph_size(G);
  bool *mark = xcalloc(v, sizeof(bool));

  mark[0] = true;                  /* 任选起点 */
  int added = 0;

  while (added < (int)v - 1) {
    /* 扫描所有顶点，找一条「一端在内、一端在外」的边 */
    bool found = false;
    for (vertex u = 0; u < v && !found; u++) {
      if (!mark[u]) continue;      /* u 必须在树内 */
      neighbor_t nb = graph_get_neighbors(G, u);
      while (graph_hasmore_neighbors(nb)) {
        vertex w = graph_next_neighbor(nb);
        if (!mark[w]) {            /* w 在树外 */
          printf("add edge {%u, %u}\n", u, w);
          mark[w] = true;          /* 标记为树内 */
          added++;
          found = true;
          break;
        }
      }
      graph_free_neighbors(nb);
    }
    if (!found) {
      printf("graph is not connected!\n");
      break;
    }
  }

  free(mark);
}
```

**这个实现是 O(v·(v+e))**——每加一条边都重新扫描所有顶点。**讲义的版本是 O(v+e)**，做法是「维护一个待检查的边列表」，而不是每轮重扫。

**优化思路**：把「树内顶点的所有跨界边」放进一个队列/栈，每次取一条。这样每条边最多被检查两次（两端各一次），总 O(v+e)。**这正是 Prim 的结构**——只是 Prim 用优先队列（按权重取最小），这里用普通队列（任意取）。

**示例三：验证 Cycle Property 的小实验。**

```c
/* 给定图与一棵 MST，检查「每个简单环上权重最大的边都不在 MST 中」。
 * 这里只检查三角形环（3 个顶点的环），足以演示思路。
 */
void check_cycle_property(int v, edge *edges, int e, bool *in_mst) {
  int violations = 0;
  for (int i = 0; i < e; i++)
    for (int j = i + 1; j < e; j++)
      for (int k = j + 1; k < e; k++) {
        /* 检查这三条边是否构成三角形 */
        int a[3] = {edges[i].u, edges[j].u, edges[k].u};
        int b[3] = {edges[i].v, edges[j].v, edges[k].v};
        /* 三条边的六个端点恰好是 3 个不同顶点，每个出现两次 */
        int verts[6] = {a[0],b[0],a[1],b[1],a[2],b[2]};
        /* 简化：只检查是否两两共享端点 */
        bool triangle =
          (edges[i].u == edges[j].u || edges[i].u == edges[j].v ||
           edges[i].v == edges[j].u || edges[i].v == edges[j].v) &&
          (edges[j].u == edges[k].u || edges[j].u == edges[k].v ||
           edges[j].v == edges[k].u || edges[j].v == edges[k].v) &&
          (edges[i].u == edges[k].u || edges[i].u == edges[k].v ||
           edges[i].v == edges[k].u || edges[i].v == edges[k].v);
        if (!triangle) continue;

        /* 找权重最大的边 */
        int wi = edges[i].w, wj = edges[j].w, wk = edges[k].w;
        int maxw = wi > wj ? (wi > wk ? wi : wk) : (wj > wk ? wj : wk);
        /* 若最大边唯一且在 MST 中，报违规 */
        int cnt_max = (wi == maxw) + (wj == maxw) + (wk == maxw);
        if (cnt_max == 1) {
          int idx = (wi == maxw) ? i : (wj == maxw ? j : k);
          if (in_mst[idx]) {
            printf("VIOLATION: edge %d (w=%d) is max in a cycle but in MST\n",
                   idx, maxw);
            violations++;
          }
        }
      }
  printf("violations = %d\n", violations);
}
```

在讲义的例子上运行，`violations = 0`——因为 `BC(3)` 是环 `BCE` 的最大边，而它确实不在 MST 中。

**这个实验的意义**：Cycle Property 不是「算法的一个技巧」，而是**图的结构的必然性质**。任何 MST 都必须遵守它。Kruskal 之所以正确，就是因为它**系统性地利用了这条性质**。

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| 树 | 森林 | 前者连通；后者可以不连通（是树的集合） | 森林 = 多棵树 |
| 生成树 | 最小生成树 | 前者只要「是树且含全部顶点」；后者还要「权重最小」 | MST 是特殊的生成树 |
| 边中心算法 | 顶点中心算法 | 前者每次判连通性（O(ev)）；后者找跨界边（O(v+e)） | 顶点中心更快 |
| Cycle Property | Cut Property | 前者说「环上最大边不属于某 MST」；后者说「跨越割的最小边属于某 MST」 | 一个排除，一个纳入 |
| Kruskal | Prim | 前者边中心（排序 + 判环）；后者顶点中心（堆 + 跨界边） | 一个看边，一个看点 |
| MST 唯一 | MST 权重唯一 | 前者不一定（并列权重时多解）；后者一定 | 权重唯一，方案不唯一 |
| 生成树的边数 | 原图的边数 | 前者恒为 `v−1`；后者任意 | 生成树只用 `v−1` 条 |

## 10. 本节复习

1. 树 = 连通无环；森林 = 无环（可不连通）；生成树 = 顶点集相同、边集是子集的树；MST = 权重最小的生成树。
2. 树的六种等价刻画，最常用的是「连通 + `v−1` 条边」与「任意两点恰一条路径」。
3. 边中心算法 O(ev)（每次判连通）；顶点中心算法 O(v+e)（找跨界边）。
4. 随机迷宫 = 随机边序 + 生成树算法；保证「唯一通路、无环」。
5. Cycle Property：环上严格最大的边不属于某棵 MST。证明用交换论证：删 `e` 分两子树，环上必有另一条跨界边 `e'`，换掉后权重不增，与 MST 最优性矛盾。
6. Kruskal：按权重升序，不成环就加，加满 `v−1` 条停。复杂度 O(e log e + ev)（判环用 DFS），配并查集后 O(e log e)。
7. Prim：顶点中心 + 优先队列，O(v + e log e)。Kruskal 看边、Prim 看点。

## 11. 自我检查

**题 1.** 一个连通图有 8 个顶点。它的生成树有几条边？如果这个图有 12 条边，那么「不在生成树里」的边有几条？

**题 2.** 用 Kruskal 算法求下面图的 MST，写出加边的顺序与总权重。边与权重：`AB 1`、`BC 2`、`CD 3`、`DA 4`、`AC 5`（顶点 A、B、C、D）。

**题 3.** 陈述 Cycle Property，并说明证明中「环上必然存在另一条连接 `T₁` 与 `T₂` 的边」这一步为什么成立。

**题 4.** 顶点中心算法为什么比边中心算法快？请从「每轮做什么操作」的角度对比。

**题 5.** 判断正误并说明理由：
（a）所有 MST 的权重相同。
（b）所有 MST 的边集相同。
（c）若图中所有边权重互不相同，则 MST 唯一。

<details>
<summary>参考答案</summary>

**答 1.**
生成树的边数恒为 `v − 1 = 8 − 1 = **7**`（树的等价刻画 5）。

原图有 12 条边，生成树用 7 条，所以**不在生成树里的边有 12 − 7 = 5 条**。

**补充**：这 5 条边每一条都「制造了一个环」——如果它不成环，Kruskal 就会把它加入。所以「非树边数 = 图的环空间维数（cycle rank）= e − v + 1 = 12 − 8 + 1 = 5」✓。这个量在图论里叫**环秩**（cyclomatic number），等于「独立环的个数」。

**答 2.**
**排序**：`AB(1), BC(2), CD(3), DA(4), AC(5)`。

**执行**：

1. 加 `AB(1)`：`T = {AB}`，`{A,B}` 连通。
2. 加 `BC(2)`：`T = {AB, BC}`，`{A,B,C}` 连通。
3. 加 `CD(3)`：`T = {AB, BC, CD}`，`{A,B,C,D}` 全连通，3 条边 = `v−1 = 3`。**停止**。

**MST 权重** = `1 + 2 + 3 = **6**`。

**被跳过的边**：`DA(4)`、`AC(5)`——它们在 Kruskal 停止前根本没被考虑（已经加满 `v−1` 条）。

**验证 Cycle Property**：环 `A–B–C–D–A` 的四条边权重 `1, 2, 3, 4`，最大是 `DA(4)`。它不在 MST 中 ✓。环 `A–B–C–A` 的三条边 `AB(1), BC(2), AC(5)`，最大是 `AC(5)`，也不在 MST 中 ✓。

**补充**：如果先考虑 `DA(4)`（例如排序不稳定导致顺序变化），会得到 `{AB, BC, DA}`，权重也是 6——**MST 不唯一，权重唯一**。

**答 3.**
**陈述**：设 `C` 是图 `G` 的一个简单环，`e` 是 `C` 中权重严格最大的边。则存在某棵 MST 不含 `e`。

**「环上必然存在另一条连接 `T₁` 与 `T₂` 的边」的论证**：

设 `T` 是含 `e` 的 MST。删掉 `e` 后 `T` 分成两个连通分量 `T₁`、`T₂`，`e` 的两端 `u ∈ T₁`、`v ∈ T₂`。

环 `C` 是一条闭合路径，它包含 `e`（因为 `e ∈ C`）。从 `u` 出发，沿 `C` 走一圈回到 `u`。这条路的第一步是 `e`，走到 `v`；然后沿 `C` 上剩余的边走，最终回到 `u`。

考虑这条剩余路径 `v → … → u`。它的起点 `v` 在 `T₂`，终点 `u` 在 `T₁`。路径是一步步走的，每一步跨越一条边。**从 `T₂` 到 `T₁` 必然有某一步是「从 `T₂` 里的顶点走到 `T₁` 里的顶点」**——这一步对应的边就是 `e'`。

形式化：把路径的顶点序列记为 `v = p₀, p₁, …, pₖ = u`。定义 `f(i) = 1` 若 `pᵢ ∈ T₁`，`f(i) = 2` 若 `pᵢ ∈ T₂`。`f(0) = 2`、`f(k) = 1`，所以存在某个 `i` 使 `f(i) = 2` 且 `f(i+1) = 1`。边 `{pᵢ, pᵢ₊₁}` 就是 `e'`。

**为什么 `e' ≠ e`**：`e` 已经被排除在这条「剩余路径」之外（我们走的是 `C` 去掉 `e` 的部分）。所以 `e'` 是环上另一条边。✓

**为什么 `w(e') < w(e)`**：因为 `e` 是环上**严格最大**的，而 `e'` 是环上另一条边，所以严格更小。✓

**结论**：`T' = (T \ {e}) ∪ {e'}` 是生成树且权重严格更小，与 `T` 是 MST 矛盾。所以 `e ∉ T`。

**答 4.**
**边中心算法每轮做的事**：

1. 取一条原图的边 `{u,v}`。
2. **用 DFS 或 BFS 判断 `u` 与 `v` 是否已连通**——这是 O(v + e) 的操作。
3. 若未连通，加入这条边。

最多 `e` 轮，每轮 O(v+e)，总计 **O(e(v+e)) = O(ev)**。

**顶点中心算法每轮做的事**：

1. 取一条边 `{u,v}`。
2. **检查 `mark[u]` 与 `mark[v]`**——这是 O(1) 的操作。
3. 若恰好一个为真（一端在内一端在外），加入这条边并标记。

每条边最多被检查两次（两端各一次），总计 **O(v + e)**。

**关键差异**：边中心算法要回答「这两点连通吗」，这是个**全局**问题，需要遍历；顶点中心算法要回答「这条边是否跨越当前边界」，这是个**局部**问题，只看两个标记位。

**为什么顶点中心能只看局部**：因为它**维护了一棵不断长大的树**，而不是「一堆散落的树」。在边中心算法里，图被分成多棵树，「`u` 和 `v` 是否同树」需要搜索；在顶点中心算法里，只有「树内」与「树外」两种状态，用 `mark` 数组 O(1) 就能判断。

**代价**：顶点中心算法只能从**一个**起点长大，所以它要求图**连通**（否则长不到所有顶点）。边中心算法能自然处理不连通的图（得到生成森林）。

**答 5.**
**（a）正确。** 所有 MST 的权重相同。

*理由*：MST 的定义是「权重最小的生成树」。如果两棵 MST 权重不同，权重大的那棵就不是最小的，矛盾。**最优值唯一，即使最优解不唯一。**

**（b）错误。** 所有 MST 的边集不一定相同。

*反例*：三角形 `A–B–C`，三条边权重都是 1。任意两条边都构成一棵 MST（3 条边选 2 条 = 3 种方案），权重都是 2。三棵 MST 的边集互不相同。

**（c）正确。** 若所有边权重互不相同，则 MST 唯一。

*证明*：假设有两棵不同的 MST `T₁ ≠ T₂`，权重都是 `W`。取 `T₁` 中不在 `T₂` 的边 `e`（存在，因为 `T₁ ≠ T₂` 且边数相同）。在 `T₂` 中，`e` 的两端之间有唯一路径 `P`。`P` 上必有某条边 `e'` 不在 `T₁` 中（否则 `T₁` 里 `e` 的两端已连通，`e` 会成环）。

构造 `T₁' = (T₁ \ {e}) ∪ {e'}`，是生成树，权重 `W − w(e) + w(e')`。因为权重互不相同，`w(e) ≠ w(e')`。若 `w(e') < w(e)`，则 `T₁'` 权重小于 `W`，与 `T₁` 是 MST 矛盾；若 `w(e') > w(e)`，则 `T₂' = (T₂ \ {e'}) ∪ {e}` 权重小于 `W`，与 `T₂` 是 MST 矛盾。两种情况都矛盾。

所以不可能有两棵不同的 MST。∎

**这个证明的结构**与 Cycle Property 的证明相同——**交换论证**。区别是这里用「权重互不相同」来保证严格不等，从而排除「并列最优」的可能。
