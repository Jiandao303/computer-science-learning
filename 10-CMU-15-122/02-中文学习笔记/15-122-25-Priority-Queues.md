# 第 25 讲：优先队列（Priority Queues）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 给出优先队列（priority queue）的抽象接口，说明它与队列（queue）的本质区别。
2. 说明为什么「优先级比较函数」必须是**严格**的（`has_higher_priority(e1, e2)` 只在 `e1` 严格高于 `e2` 时返回真），以及不严格会导致什么。
3. 列出优先队列的四种实现（无序数组、有序数组、AVL 树、堆），并对比 `add` / `rem` / `peek` 的复杂度。
4. 复述**最小堆有序不变式**（min-heap ordering invariant）的两种等价表述，并证明它们等价。
5. 复述**堆形状不变式**（heap shape invariant）：按层从左到右填满，形状完全由元素个数决定。
6. 手工模拟 `sift up`（加入）与 `sift down`（删除最小），并证明两者都是 O(log n)。
7. 说明为什么数组表示的下标从 1 开始（而不是 0），并写出父子下标的换算公式。

## 3. 核心概念

**Priority Queue（优先队列）**：一个容器，支持「加入元素」与「取出优先级最高的元素」。**不保证先进先出**——取出顺序由优先级决定。

**Priority（优先级）**：由用户提供的比较函数定义。本课程默认「数值越小优先级越高」（最小堆）。

**`has_higher_priority_fn`**：`typedef bool has_higher_priority_fn(elem e1, elem e2);`，返回 `true` 当且仅当 `e1` **严格**高于 `e2`。

**Min-Heap（最小堆）**：满足「父节点优先级不低于任一子节点」的完全二叉树。根是全局最小元。

**Ordering Invariant（有序不变式）**：每个节点的键 ≤ 其所有后代的键（等价地：≤ 其直接孩子的键）。

**Shape Invariant（形状不变式）**：完全二叉树——除最后一层外全满，最后一层从左到右连续填充。

**sift up（上滤）**：新元素放到末尾，与父比较，若优先级更高就交换，直到满足不变式。

**sift down（下滤）**：根被移除后，把末尾元素放到根，与**较小的孩子**比较并交换，直到满足不变式。

## 4. 通俗理解

**优先队列 = 医院急诊分诊台**。不是「先来先看」，而是「谁病得重谁先看」。新病人来了要插到合适的位置（`add`），医生每次叫「下一个」时取最重的（`rem`）。

**堆 = 一个「部分有序」的完全二叉树**。它不要求整棵树有序（那太贵），只要求「父 ≤ 子」。这个弱条件足够保证「根是最小元」，而且维护起来只要 O(log n)。

**为什么「父 ≤ 子」就够了**：因为根没有父，所以根 ≤ 它的孩子 ≤ 它的孙子 ≤ …… 由传递性，根 ≤ 所有节点。**所以根一定是全局最小。** 这个推理只需要「父子有序」+「传递性」，不需要「兄弟之间有序」。

**sift up 的直觉 = 新员工入职**。新人从最底层开始，如果比上级能力强就换位置，一路往上「冒泡」，直到遇到更强的上级。

**sift down 的直觉 = 空降的领导不称职**。把最后一个人提到根的位置（可能是能力最差的），然后让他和「更强的那个孩子」比较，不如就换下去，一路下沉到合适的位置。

**为什么和「较小的孩子」换而不是随便一个**：如果和较大的孩子换，较小的孩子就会变成「比父大」——违反不变式。**必须和更强的孩子换，才能保证换完之后父仍然 ≤ 两个孩子。**

## 5. 原理与推导

### 5.1 优先队列的抽象接口

讲义第 1–4 页：

```c
typedef bool has_higher_priority_fn(elem e1, elem e2);

pq_t pq_new(has_higher_priority_fn *prior);
void pq_free(pq_t P);
bool pq_empty(pq_t P);
void pq_add(pq_t P, elem e);
elem pq_rem(pq_t P);        /* 删除并返回优先级最高的 */
elem pq_peek(pq_t P);       /* 返回但不删除 */
```

**有界版本**（讲义第 3–4 页）：

```c
pq_t pq_new(int capacity, has_higher_priority_fn *prior);
bool pq_full(pq_t P);
void pq_add(pq_t P, elem e)
/*@requires !pq_full(P); @*/;
```

**为什么要「有界」**：无界优先队列的 `add` 可能因为内存耗尽而失败。把「容量」写进构造参数，`pq_add` 的前置条件加 `!pq_full(P)`，就把「内存不足」这个失败模式**从运行时移到契约层**——调用者必须自己检查。

**讲义特别提到「防 denial-of-service」**：如果 `add` 不检查容量，攻击者可以不断 `add` 直到内存耗尽，让服务崩溃。**显式容量 + 前置条件**让这种攻击变成「调用者的 bug」而不是「系统的漏洞」。

**`has_higher_priority_fn` 必须严格**：

```c
bool int_prior(elem e1, elem e2) {
  return e1 < e2;         /* 严格小于 */
}
```

如果写成 `e1 <= e2`（非严格），那么 `has_higher_priority(e1, e1)` 返回 `true`——「`e1` 比自己优先级高」。这会让：

- `sift up` 在遇到相等元素时继续交换，可能死循环。
- `pq_rem` 的「取最小」在并列时行为不确定。

**「严格」保证**：`has_higher_priority(e1, e2)` 与 `has_higher_priority(e2, e1)` **不能同时为真**。这是一个**反对称性**要求，让堆的不变式有唯一解释。

### 5.2 四种实现的复杂度对比

讲义第 5 页：

| 实现 | `add` | `rem` | `peek` | 备注 |
|---|---|---|---|---|
| 无序数组 | O(1) | O(n) | O(n) | `add` 直接追加；`rem` 要扫全部找最小 |
| 有序数组 | O(n) | O(1) | O(1) | 插入要移动元素；`rem` 取末尾 |
| AVL 树 | O(log n) | O(log n) | O(log n) | 平衡保证高度 |
| **堆** | **O(log n)** | **O(log n)** | **O(1)** | 根就是最小元 |

**为什么堆比 AVL 好**：`peek` 是 O(1) 而非 O(log n)，因为根就是最小元。`add`/`rem` 同为 O(log n)，但堆的常数因子小得多（没有旋转、没有平衡因子维护、数组存储缓存友好）。

**为什么 AVL 仍然有用**：AVL 支持**完整的有序遍历**（中序），堆不支持。如果需要「按优先级顺序遍历所有元素」而不只是「取最小」，用 AVL。

**有序数组的隐藏优势**（习题 Ex1 的方向）：如果用**有序链表**，`add` O(n)、`rem` O(1)、`peek` O(1)，且**空间正比于元素个数**而不是容量。堆的数组实现必须预先分配 `capacity` 个位置，即使只存了 3 个元素。

**这个对比说明了「抽象数据类型」的价值**：同一个接口，四种实现，各有取舍。**接口不变，实现可换。**

### 5.3 最小堆有序不变式

讲义第 5–6 页给出**两种等价表述**：

**表述 1（父子式）**：对每个节点 `i`（非根），`key(parent(i)) ≤ key(i)`。

**表述 2（后代式）**：对每个节点 `i` 和它的**所有后代** `j`，`key(i) ≤ key(j)`。

**两者等价**：

**（1）⇒（2）**：设 `j` 是 `i` 的后代。从 `i` 到 `j` 的路径是 `i = p₀, p₁, …, pₖ = j`，每对相邻是父子关系。由（1），`key(p₀) ≤ key(p₁) ≤ … ≤ key(pₖ)`。由传递性 `key(i) ≤ key(j)` ✓。

**（2）⇒（1）**：父节点是孩子的（直接）后代，所以（2）的直接特例就是（1） ✓。

**为什么用表述 1 作为「实现要维护的不变式」**：它只涉及**局部**（每个节点只看自己的父），所以可以在 O(1) 内检查某个位置是否满足，也可以在 O(log n) 内修复（只需沿一条路径调整）。

**表述 2 是「表述 1 的推论」**，用于**证明正确性**（根是最小元）。

**推论：根是全局最小元。**

*证明*：对任意节点 `j`，`j` 是根的后代（根是所有节点的祖先）。由表述 2，`key(root) ≤ key(j)`。所以 `key(root)` 是全局最小 ✓。

**这就是 `pq_peek` 能做到 O(1) 的原因**——不需要搜索，根就是答案。

**注意：堆不保证「兄弟之间有序」**。左孩子可能比右孩子大，这不违反不变式。所以**堆不能用来做有序遍历**——只能保证「根最小」。

### 5.4 堆形状不变式

讲义第 6 页：

**形状不变式**：堆是一棵**完全二叉树**（complete binary tree）：

1. 除最后一层外，所有层都填满。
2. 最后一层的节点从左到右连续排列，中间没有空洞。

**关键性质：形状完全由元素个数 `n` 决定。**

- `n = 1`：只有根。
- `n = 2`：根 + 左孩子。
- `n = 3`：根 + 左孩子 + 右孩子。
- `n = 4`：再加一个「左孩子的左孩子」。
- ……

**没有「形状选择」的自由度**——给定 `n`，树的结构唯一确定。**这让数组表示成为可能**：第 `i` 个元素（按层序编号）就存在数组的第 `i` 格。

**为什么必须「完全」**：

1. **数组表示要求连续**。如果有空洞，数组就要浪费空间或引入复杂映射。
2. **高度是 ⌊log₂n⌋ + 1**。完全二叉树在给定 `n` 下高度最小，保证 O(log n)。
3. **「下一个空位」唯一确定**。`add` 时总是放在第 `n+1` 个位置，不需要搜索。

**高度推导**：`n` 个节点的完全二叉树，前 `h−1` 层有 `2^(h−1) − 1` 个节点，第 `h` 层有 `n − (2^(h−1) − 1)` 个。因为第 `h` 层最多 `2^(h−1)` 个，所以

```
2^(h−1) − 1 < n ≤ 2^h − 1
```

取对数：`h − 1 < log₂(n+1) ≤ h`，即 **`h = ⌈log₂(n+1)⌉ = ⌊log₂ n⌋ + 1`**。

**对于 `n ≥ 1`，层数 = `⌊log₂ n⌋ + 1`**。例如 `n = 1` 时 1 层、`n = 7` 时 3 层、`n = 8` 时 4 层。**这就是 O(log n) 的来源。**

### 5.5 sift up（加入）

**算法**（讲义第 7–8 页）：

```
把新元素放到「下一个空位」（第 n+1 个位置，按层序）
while 不是根 且 新元素优先级严格高于父节点:
    与父交换
    当前位置 = 父的位置
```

**为什么这样能恢复不变式**：

**循环不变式**：除「当前位置 `i` 与其父 `i/2`」这一对之外，所有父子对都满足不变式。

- **初始**：新元素放在末尾，它是叶子（没有孩子），所以「它作为父」的所有对都平凡满足（没有孩子）。唯一的可能违规是「它作为孩子」与它的父。
- **保持**：交换 `i` 与 `i/2` 后，原来 `i/2` 位置的元素（较大的那个）移到 `i`。它的两个孩子原来是 `i` 的兄弟，都比它小吗？**不一定**——但原来的不变式说「`i/2` ≤ 它的两个孩子」，而 `i` 是其中之一。交换后，`i/2` 位置的元素是原来的 `i`（新元素，更小），它 ≤ 两个孩子 ✓。而 `i` 位置的元素是原来的 `i/2`（较大），它 ≤ `i` 的两个孩子吗？原来的不变式说 `key(i/2) ≤ key(i)` 的孩子？**不，原来的不变式只说 `key(i/2) ≤ key(i)` 和 `key(i/2) ≤ key(i的兄弟)`**。交换后需要 `key(原i/2) ≤ key(i的孩子)`。因为 `key(i) ≤ key(i的孩子)`（不变式），且 `key(原i/2) ≤ key(i)`……**这给不出 `key(原i/2) ≤ key(i的孩子)`**。

**等等——这里有个微妙点。** 实际上，`sift up` 的正确性依赖于**交换前 `key(原i/2) ≤ key(i的孩子)`**。这个成立吗？

**成立**，因为原来的不变式保证 `key(原i/2) ≤ key(i)`，而 `i` 是 `原i/2` 的孩子。但 `i的孩子` 是 `原i/2` 的**孙子**。原来的不变式只保证 `key(原i/2) ≤ key(i)`，不保证 `≤ key(i的孩子)`。

**但由表述 2（后代式）**：`原i/2` 是 `i的孩子` 的祖先，所以 `key(原i/2) ≤ key(i的孩子)` ✓。

**所以 sift up 的正确性依赖于「后代式」不变式，而不只是「父子式」。** 这是一个重要的细节——**父子式不变式在交换后需要重新验证，而后代式自动保持**。

讲义第 7–8 页的论证方式是「追踪被移动元素的位置」，比较简洁。严格的证明需要说明「交换只影响 `i` 与 `i/2` 这一对」，而其他对的不变式不受影响（因为其他节点的父子关系没变，键也没变）。

**复杂度**：每次交换上升一层，最多从叶子到根，即 `h − 1 = ⌊log₂ n⌋` 次。每次 O(1)。**O(log n)**。

**终止条件**：`i == 1`（到根）或 `!has_higher_priority(新元素, 父)`（父的优先级不低于新元素）。

**为什么用「严格高于」**：如果新元素与父**相等**，不交换。这保证算法终止（否则相等元素会无限交换）。**这也是比较函数必须严格的原因。**

### 5.6 sift down（删除最小）

**算法**（讲义第 8–9 页）：

```
保存根元素（这是要返回的最小元）
把「最后一个元素」移到根的位置，删除末尾
while 当前位置有孩子:
    找出优先级更高的那个孩子
    if 当前位置的元素优先级不低于那个孩子:
        break
    与那个孩子交换
    当前位置 = 孩子的位置
```

**为什么是「较小的孩子」**：

假设当前节点 `i` 有两个孩子 `2i` 和 `2i+1`，`key(2i) < key(2i+1)`（左孩子更小）。

- **若与左孩子换**：新父是 `原key(2i)`。它 ≤ `原key(i)`（因为 `key(2i) < key(i)`，这是我们要修的不变式），且 ≤ `key(2i+1)`（因为 `key(2i) < key(2i+1)`）。✓ 两个孩子都满足。
- **若与右孩子换**：新父是 `原key(2i+1)`。它 ≤ `原key(i)` ✓，但它 ≤ `key(2i)` 吗？**不一定**——`key(2i) < key(2i+1)`，所以 `原key(2i+1) > 原key(2i)`。**违反不变式。**

**所以必须与较小的孩子换。** 这是 sift down 与 sift up 的**关键不对称**：sift up 只与唯一的父比较，sift down 要在两个孩子中选。

**复杂度**：每次下降一层，最多 `h − 1` 次。**O(log n)**。

**边界情形**：

- **只有一个孩子**（左孩子存在、右孩子不存在）：只与左孩子比较。
- **没有孩子**（叶子）：停止。

**这两个边界是 sift down 实现中最容易写错的地方**——必须检查 `2i < n`（有左孩子）和 `2i+1 < n`（有右孩子）。

### 5.7 数组表示

讲义第 10 页：

**根下标为 1**（不是 0）：

| 关系 | 公式 |
|---|---|
| 根 | `1` |
| 节点 `i` 的左孩子 | `2i` |
| 节点 `i` 的右孩子 | `2i + 1` |
| 节点 `i` 的父 | `i / 2`（整数除法，向下取整） |

**为什么不用 0**：

如果用 0 作根：

- 左孩子 = `2·0 + 1 = 1`、右孩子 = `2·0 + 2 = 2`。
- 节点 1 的父 = `(1−1)/2 = 0`。
- **节点 0 的左孩子是 1，节点 1 的父是 0** —— 这看起来对。

但问题在**「0 的左孩子」与「0 自己」的关系**：如果用 `2i` 和 `2i+1`，则 0 的左孩子是 0（`2·0 = 0`）——**根与左孩子同址**，灾难。

如果改成 `2i+1` 和 `2i+2`，公式能用，但：

- **父的公式变成 `(i−1)/2`**，多一次减法。
- **下标 0 的位置在「层序编号」里没有自然位置**——第 1 层是下标 0，第 2 层是 1、2，第 3 层是 3、4、5、6……编号与层数的对应关系变复杂。

**用 1 作根的好处**：

- 父子公式统一为 `2i`、`2i+1`、`i/2`，**没有任何偏移**。
- 「第 `k` 层」对应下标区间 `[2^(k−1), 2^k − 1]`——**干净的二进制结构**。
- 代价：浪费下标 0 一格（O(1) 空间）。

**这个「浪费一格换公式简洁」的取舍在系统编程里很常见**（例如「哨兵节点」）。**简洁的公式减少 bug，比省一个字节重要。**

**数组大小**：需要 `capacity + 1` 格（下标 0 不用）。讲义第 26 讲用 `int limit = capacity + 1`，`next` 指向「下一个空位」，`1 ≤ next ≤ limit`。

### 5.8 完整算例

假设依次加入 `5, 3, 8, 1, 9, 2`（数值越小优先级越高）。

**（1）`add(5)`**：放到位置 1。堆：`[_, 5]`。

**（2）`add(3)`**：放到位置 2。`3 < 5`，与父交换。堆：`[_, 3, 5]`。

```
    3
   /
  5
```

**（3）`add(8)`**：放到位置 3。`8 > 3`，不交换。堆：`[_, 3, 5, 8]`。

```
    3
   / \
  5   8
```

**（4）`add(1)`**：放到位置 4。`1 < 5`（父是位置 2 的 5），交换 → 位置 2。`1 < 3`（父是根），交换 → 位置 1。堆：`[_, 1, 3, 8, 5]`。

```
    1
   / \
  3   8
 /
5
```

**（5）`add(9)`**：放到位置 5。`9 > 3`，不交换。堆：`[_, 1, 3, 8, 5, 9]`。

```
    1
   / \
  3   8
 / \
5   9
```

**（6）`add(2)`**：放到位置 6。`2 < 8`（父是位置 3 的 8），交换 → 位置 3。`2 > 1`（父是根），停止。堆：`[_, 1, 3, 2, 5, 9, 8]`。

```
      1
    /   \
   3     2
  / \   /
 5   9 8
```

**（7）`rem()`（删除最小）**：返回 1。把最后一个元素 8 移到根，删末尾。堆：`[_, 8, 3, 2, 5, 9]`。

现在 sift down：

- 位置 1 的 8，孩子是 3（位置 2）和 2（位置 3）。**较小的是 2**。`8 > 2`，交换 → 位置 3。堆：`[_, 2, 3, 8, 5, 9]`。
- 位置 3 的 8，孩子是位置 6（不存在，因为 `n = 5`）。停止。

```
      2
    /   \
   3     8
  / \
 5   9
```

**验证不变式**：`2 ≤ 3`、`2 ≤ 8`、`3 ≤ 5`、`3 ≤ 9` ✓。根 2 是剩余元素 `{3,8,5,9}` 的最小 ✓。

### 5.9 习题要点

- **Ex1（第 11 页，解在第 12 页）**：用有序链表实现优先队列。`add` O(n)（找到插入位置）、`rem` O(1)（取头）、`peek` O(1)。**优点**：空间正比于元素个数，不需要预分配容量。**缺点**：`add` 慢。

### 6.2 Agent 自行编写的教学示例

> 非官方，仅用于说明概念

**示例一：一个完整可运行的整数最小堆（数组表示）。**

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include "lib/xalloc.h"

typedef struct heap_header {
  int capacity;      /* 最多存 capacity 个元素 */
  int next;          /* 下一个空位，1 <= next <= capacity+1 */
  int *data;         /* 长度 capacity+1，data[0] 不用 */
} *heap;

heap heap_new(int capacity) {
  heap H = xmalloc(sizeof(struct heap_header));
  H->capacity = capacity;
  H->next     = 1;
  H->data     = xmalloc((capacity + 1) * sizeof(int));
  return H;
}

void heap_free(heap H) {
  if (H == NULL) return;
  free(H->data);
  free(H);
}

bool heap_empty(heap H) { return H->next == 1; }
bool heap_full(heap H)  { return H->next == H->capacity + 1; }

/* 整数比较：小的优先级高（严格） */
static bool higher(int a, int b) { return a < b; }

static void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

/* sift up：把位置 i 的元素上滤到合适位置 */
static void sift_up(heap H, int i) {
  while (i > 1 && higher(H->data[i], H->data[i / 2])) {
    swap(&H->data[i], &H->data[i / 2]);
    i = i / 2;
  }
}

/* sift down：把位置 i 的元素下滤到合适位置 */
static void sift_down(heap H, int i) {
  while (2 * i < H->next) {                 /* 有左孩子 */
    int left  = 2 * i;
    int right = 2 * i + 1;
    int child = left;

    /* 若有右孩子且右孩子优先级更高，选右孩子 */
    if (right < H->next && higher(H->data[right], H->data[left]))
      child = right;

    if (!higher(H->data[child], H->data[i])) break;   /* 孩子不更高，停 */
    swap(&H->data[i], &H->data[child]);
    i = child;
  }
}

void heap_add(heap H, int x) {
  /* 前置：!heap_full(H) */
  H->data[H->next] = x;
  sift_up(H, H->next);
  H->next++;
}

int heap_rem(heap H) {
  /* 前置：!heap_empty(H) */
  int min = H->data[1];
  H->next--;
  if (H->next > 1) {
    H->data[1] = H->data[H->next];      /* 末尾元素移到根 */
    sift_down(H, 1);
  }
  return min;
}

int heap_peek(heap H) { return H->data[1]; }

/* 调试：按层打印 */
void heap_print(heap H) {
  int level = 1, count = 0;
  for (int i = 1; i < H->next; i++) {
    printf("%d ", H->data[i]);
    if (++count == level) {
      printf("\n");
      count = 0;
      level *= 2;
    }
  }
  if (count > 0) printf("\n");
}

int main(void) {
  heap H = heap_new(16);
  int vals[] = {5, 3, 8, 1, 9, 2};
  for (int i = 0; i < 6; i++) {
    heap_add(H, vals[i]);
    printf("after add(%d):\n", vals[i]);
    heap_print(H);
  }
  printf("peek = %d\n", heap_peek(H));
  while (!heap_empty(H)) {
    printf("rem -> %d\n", heap_rem(H));
    heap_print(H);
  }
  heap_free(H);
  return 0;
}
```

**三个易错点**：

1. **`heap_add` 里 `sift_up` 必须在 `H->next++` 之前调用**。因为 `sift_up` 的循环条件里用 `H->next` 判断边界吗？不——`sift_up` 只看 `i > 1`。但**新元素的位置是 `H->next`**，`sift_up(H, H->next)` 要在这个位置上操作，所以必须先把元素放进去。`H->next++` 放在最后，保证「`next` 始终指向下一个空位」。

2. **`sift_down` 的循环条件是 `2*i < H->next`**（有左孩子）。`H->next` 是「下一个空位」，所以有效元素下标是 `1 … H->next−1`。左孩子 `2i` 存在当且仅当 `2i ≤ H->next−1`，即 `2i < H->next` ✓。

3. **`heap_rem` 里 `if (H->next > 1)` 的判断**。删除后如果 `H->next == 1`（原本只有 1 个元素），堆空了，不需要 sift down。**漏掉这个判断会读到 `data[1]`（已被删除的旧值）并可能越界。**

**示例二：用函数指针做通用的优先队列（对照第 26 讲）。**

```c
typedef void* elem;
typedef bool has_higher_priority_fn(elem e1, elem e2);

typedef struct pq_header {
  int capacity;
  int next;
  has_higher_priority_fn *prior;
  elem *data;                     /* 长度 capacity+1 */
} *pq_t;

pq_t pq_new(int capacity, has_higher_priority_fn *prior) {
  pq_t P = xmalloc(sizeof(struct pq_header));
  P->capacity = capacity;
  P->next     = 1;
  P->prior    = prior;
  P->data     = xmalloc((capacity + 1) * sizeof(elem));
  return P;
}

static void pq_swap_up(pq_t P, int child)
/*@requires 2 <= child && child < P->next; @*/
{
  elem tmp = P->data[child];
  P->data[child] = P->data[child / 2];
  P->data[child / 2] = tmp;
}

void pq_add(pq_t P, elem e)
/*@requires !pq_full(P); @*/
{
  int i = P->next;
  P->data[i] = e;
  while (i > 1 && (*P->prior)(P->data[i], P->data[i / 2])) {
    pq_swap_up(P, i);
    i = i / 2;
  }
  P->next++;
}
```

**注意 `(*P->prior)(...)` 的写法**：`P->prior` 是函数指针，`*P->prior` 是函数本身，`(*P->prior)(a, b)` 是调用。**括号不能省**——`*P->prior(a,b)` 会被解析成 `*(P->prior(a,b))`（先调用再解引用，类型错误）。

**这是第 14 讲「函数指针三步法」的实际应用**：

1. 原型 `bool int_prior(elem e1, elem e2);`
2. `typedef bool has_higher_priority_fn(elem e1, elem e2);`
3. `has_higher_priority_fn *F = &int_prior;`

**`elem` 是 `void*`**（第 14 讲），所以这个优先队列可以存任何类型——只要提供一个比较函数。**这就是「泛型」在 C0 里的实现方式。**

**示例三：用堆排序验证堆的正确性。**

```c
/* 堆排序：把所有元素加入堆，再逐个取出 */
void heap_sort(int *A, int n) {
  heap H = heap_new(n);
  for (int i = 0; i < n; i++) heap_add(H, A[i]);
  for (int i = 0; i < n; i++) A[i] = heap_rem(H);
  heap_free(H);
}
```

**复杂度**：`n` 次 `add`（每次 O(log n)）+ `n` 次 `rem`（每次 O(log n)）= **O(n log n)**。

**这与归并排序同级**，但：

- **空间**：需要额外的 O(n) 堆数组。归并排序也需要 O(n) 辅助空间。
- **稳定性**：堆排序**不稳定**（相等元素的相对顺序可能改变）。归并排序稳定。
- **最坏情况**：堆排序最坏也是 O(n log n)；快排最坏 O(n²)。

**第 26 讲会给出「原地」堆排序**——直接在输入数组上建堆，不需要额外空间。**这是堆相对于其他数据结构的一个独特优势**：数组表示让「原地操作」成为可能。

**一个值得注意的细节**：上面这个 `heap_sort` 是 O(n log n)，但**建堆本身可以做到 O(n)**（而不是 O(n log n)）——从最后一个非叶节点开始，依次 `sift_down`。这叫 **Floyd 建堆法**。第 26 讲会提到。

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| 优先队列 | 普通队列 | 前者按优先级出队；后者先进先出 | 急诊 vs 排队 |
| 堆 | 二叉搜索树 | 前者只保证「父 ≤ 子」；后者保证「左 < 根 < 右」 | 堆不能有序遍历 |
| 有序不变式（父子式） | 有序不变式（后代式） | 前者是局部条件（实现用）；后者是全局推论（证明用） | 两者等价 |
| 有序不变式 | 形状不变式 | 前者管「键的大小关系」；后者管「树的结构」 | 一个管值，一个管形 |
| sift up | sift down | 前者只与父比较；后者要在两个孩子中选较小的 | 一个向上，一个向下 |
| 与「较小的孩子」换 | 与「任意孩子」换 | 后者会破坏不变式 | 必须选小的 |
| 数组下标从 1 | 从 0 | 前者公式干净（`2i`、`i/2`）；后者要偏移 | 浪费一格换简洁 |
| `has_higher_priority` 严格 | 非严格 | 后者会让相等元素无限交换 | 必须严格 |
| 堆排序 | 归并排序 | 前者不稳定、可原地；后者稳定、需辅助空间 | 各有取舍 |

检查：`2 ≤ 3` ✓、`2 ≤ 5` ✓、`3 ≤ 9` ✓。正确。

**为什么必须选较小的**：交换后，新父（原来的孩子）要 ≤ **两个孩子**。如果选较大的孩子 `c_big`，那么另一个孩子 `c_small < c_big` 就成了它的兄弟，而 `c_big > c_small`——违反「父 ≤ 兄弟」吗？不，兄弟之间不需要有序。**真正的问题是**：新父 `c_big` 的**另一个孩子**（原来 `i` 的另一个孩子）……等等，交换后 `c_big` 到了位置 `i`，它的孩子是原来 `i` 的两个孩子的**后代**。

**更准确的分析**：交换 `i` 与孩子 `c` 后，位置 `c` 上的元素是原来的 `data[i]`，它的孩子是 `c` 的两个孩子（原来的孙子）。需要 `data[i] ≤ 那些孙子`。由后代式不变式，`data[i] ≤ 所有后代`，包括孙子 ✓。

而位置 `i` 上的元素是 `data[c]`，它的孩子是 `2i` 和 `2i+1`（原来的两个孩子）。需要 `data[c] ≤ data[2i]` 和 `data[c] ≤ data[2i+1]`。

- 若 `c = 2i`（左孩子，较小）：需要 `data[2i] ≤ data[2i]`（平凡 ✓）和 `data[2i] ≤ data[2i+1]`（因为左孩子较小 ✓）。
- 若 `c = 2i+1`（右孩子，较大）：需要 `data[2i+1] ≤ data[2i]`——**但 `data[2i] < data[2i+1]`，违反！**

**所以必须选较小的孩子。** 上面的具体反例（`5 ≤ 2` 失败）正是这个论证的实例。

**答 4.**
`n = 1000`。

**堆的高度**：`⌊log₂ 1000⌋ + 1 = 9 + 1 = **10**`（因为 `2^9 = 512 ≤ 1000 < 1024 = 2^10`）。

**`add` 最坏比较次数**：新元素从叶子（第 10 层）上滤到根（第 1 层），需要 `10 − 1 = **9**` 次比较（每次与父比较）。

**`rem` 最坏比较次数**：sift down 从根到叶子，每层要做 **2 次**比较（一次比较两个孩子选较小的，一次比较当前元素与选中的孩子）。共 `9` 层，所以 `9 × 2 = **18**` 次比较。

**AVL 的 `peek`**：AVL 的 `peek` 需要走到最左节点（最小值）。最坏深度 `O(log n) = O(log 1000) ≈ 10`，实际约 `1.44 × log₂ 1000 ≈ 14` 次比较（AVL 的高度上界是 `1.44 log₂ n`）。

**对比**：堆的 `peek` 是 **1 次**（`data[1]`），AVL 是 **约 14 次**。**这就是堆的优势**——「取最小」是 O(1) 而非 O(log n)。

**答 5.**
**用下标 0 作根 + `2i` / `2i+1` 公式的问题**：

```
根 = 0
左孩子(0) = 2 × 0 = 0      ← 根与左孩子同址！
右孩子(0) = 2 × 0 + 1 = 1
父(1) = 1 / 2 = 0
```

**`左孩子(0) = 0`**——根是自己的左孩子。这会让 sift down 陷入无限循环（不断「下降到自己的孩子」，而孩子就是自己）。

**用下标 0 作根的正确公式**：

```
根 = 0
左孩子(i) = 2i + 1
右孩子(i) = 2i + 2
父(i) = (i − 1) / 2
```

验证：`左孩子(0) = 1`、`右孩子(0) = 2`、`父(1) = 0`、`父(2) = 0`、`左孩子(1) = 3`、`右孩子(1) = 4`、`父(3) = 1`、`父(4) = 1` ✓。

**这个公式是对的，但有两个缺点**：

1. **父的公式多一次减法** `(i−1)/2`。虽然编译器能优化，但在「每层都要算父」的 sift up 里，这是可测量的开销。
2. **「第 k 层」的下标区间不再是干净的二进制形式**。用 1 作根时，第 `k` 层是 `[2^(k−1), 2^k − 1]`；用 0 作根时，第 `k` 层是 `[2^(k−1) − 1, 2^k − 2]`——**每个边界都偏移 1**，容易在「层序遍历」「按层打印」等操作里出错。

**用 1 作根的代价**：浪费下标 0 一格。对 `capacity = 10⁶` 的堆，浪费 4 字节——**完全可以忽略**。

**结论**：**用 1 作根，公式更简洁，bug 更少。** 这是「用一点空间换代码清晰度」的典型取舍。讲义的实现（第 26 讲）用 `int limit = capacity + 1` 与 `next` 从 1 开始，正是这个选择。
