# 第 4 讲：数组查找（Searching Arrays）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 写出无序数组上的线性查找 `is_in`，并解释为什么它的前置条件要写成 `0 <= lo && lo <= hi && hi <= \length(A)` 而不是简单的 `0 <= n`。
2. 用规格函数 `is_sorted` 描述「有序」，并说明它的不变式为什么**不能**写成 `i <= hi-1`。
3. 识别循环守卫里数组访问的越界风险，并用短路求值（short-circuiting）修正求值顺序。
4. 为有序数组的查找写出关键不变式 `i == 0 || A[i-1] < x`，并从它推出「返回 −1 时 x 不在数组中」这一后置条件。
5. 估算线性查找的最坏比较次数（约 `3n`），并解释「线性时间」意味着输入翻倍、时间翻倍。
6. 区分「规格函数」与「可执行实现」：为什么 `!is_in(x,A,lo,i)` 可以出现在断言里，却不宜出现在循环不变式里。

## 2. 前置知识

- [[15-122-03-Arrays]]：数组下标、`\length`、别名、循环守卫提供上界 / 不变式提供下界的范式。
- [[15-122-01-Contracts]]：INIT / PRES / EXIT / TERM 四段证明。
- 逻辑：合取 `&&`、析取 `||`、否定 `!`，以及它们的**短路求值**语义。

## 3. 核心概念

**Linear Search（线性查找）**：从头到尾逐元素比较，找到即返回，找不到返回「不存在」的标记。时间与元素个数成正比。

**Specification Function（规格函数）**：只用于描述、不追求效率的纯函数，如 `is_in`、`is_sorted`。它们常常本身就是递归或带循环的，因此**不适合再被别的规格引用**（会造成「用未验证的东西证明别的东西」的循环）。

**Sortedness（有序性）**：对升序数组，要求每对相邻元素满足 `A[i] <= A[i+1]`。注意用 `<=` 而非 `<`，允许重复元素。

**Short-Circuiting Evaluation（短路求值）**：`e1 && e2` 在 `e1` 为假时不求值 `e2`；`e1 || e2` 在 `e1` 为真时不求值 `e2`。这既是效率优化，更是**安全性工具**——把边界检查放在前面，就能保护后面的数组访问。

**Prefix Invariant（前缀不变式）**：形如「已检查过的前缀都满足某性质」的不变式，是查找类算法的核心。数学记号 `x ∉ A[lo, i)`，代码里写作 `!is_in(x, A, lo, i)`。

**`ge_seg(x,A,lo,hi)`**：讲义预告的规格函数，表示「x 大于等于区间内所有元素」。用它才能写出「返回值确实是最大值」的后置条件。

## 4. 通俗理解

**无序查找 = 在一堆没编号的抽屉里翻找钥匙**：只能一个个拉开看，最坏要拉完所有抽屉。

**有序查找 = 在按字母排好的书架上找一本书**：一旦看到某本书排在目标之后，就可以立刻停下——后面的一定更靠后，不可能有目标。这正是「顺序（order）作为解题工具」的含义：**排序的代价换来提前终止的权利**。

**短路求值 = 先看有没有门，再决定要不要伸手**。写成 `A[i] <= x && i < n` 就像「先伸手摸柜子，再检查柜子是否存在」；写成 `i < n && A[i] <= x` 才是「先确认柜子存在，再伸手」。**顺序本身就是安全性论证的一部分。**

## 5. 原理与推导

### 5.1 无序查找：`is_in`

```c0
bool is_in(int x, int[] A, int lo, int hi)
//@requires 0 <= lo && lo <= hi && hi <= \length(A);
{
  for (int i = lo; i < hi; i++)
  //@loop_invariant lo <= i && i <= hi;
  {
    if (A[i] == x) return true;
  }
  return false;
}
```

**前置条件逐项解释**：

| 条件 | 作用 |
|---|---|
| `0 <= lo` | 保证起点不是负下标 |
| `lo <= hi` | 保证区间非空或至少合法（允许空区间 `lo == hi`） |
| `hi <= \length(A)` | 保证终点不越界 |

**为什么用 `lo/hi` 而不是 `n`**：这样函数可以只搜前 n 个元素，也可以表达「x 不在 A 的前 k 个元素中」这种**局部性质**——后者正是后面写不变式时需要的表达力。

**不变式 `lo <= i && i <= hi` 的上下界分工**：
- 下界 `lo <= i` 来自不变式（守卫 `i < hi` 不提供下界）；
- 上界 `i <= hi` 也来自不变式，而读 `A[i]` 需要的上界是 `i < hi`，这由守卫提供。**注意不变式必须允许 `i == hi`**，因为循环最后一次测试守卫时 `i` 已经等于 `hi`。这就是为什么写 `i <= hi` 而不是 `i < hi`。

### 5.2 为什么不宜写 `!is_in(x, A, lo, i)` 当不变式

直觉上，`is_in` 循环的「真正含义」是「到 i 为止都没找到 x」，于是想写：

```c0
//@loop_invariant !is_in(x, A, lo, i);
```

讲义明确建议避免。原因有两点：

1. **循环论证**：`is_in` 本身是一个需要被验证的函数，用它的结论去证明它自己的循环，逻辑上是循环的。只有「基本规格」（basic specification）才允许这样用——即那些被当作公理接受、不再进一步验证的规格函数。
2. **效率**：`is_in` 是 O(n) 的，把它放进每轮都检查的不变式里，会让验证代价变成 O(n²)。

于是本讲的策略是：**规格函数只在后置条件里使用**（那时它被调用一次，且是对「整体结果」的描述），循环不变式里只用**初等的、可 O(1) 检查的**算术与比较式。

### 5.3 有序性规格 `is_sorted`

```c0
bool is_sorted(int[] A, int lo, int hi)
//@requires 0 <= lo && lo <= hi && hi <= \length(A);
{
  for (int i = lo; i < hi-1; i++)
  //@loop_invariant lo <= i;
  if (!(A[i] <= A[i+1])) return false;
  return true;
}
```

**为什么守卫是 `i < hi-1`**：循环体访问 `A[i]` 与 `A[i+1]`，需要 `i+1 < hi`，即 `i < hi-1`。

**为什么不变式只有下界 `lo <= i`、没有上界**：

- 需要 `0 <= i`：来自 `0 <= lo`（前置）与 `lo <= i`（不变式）。
- 需要 `i+1 < \length(A)`：由守卫 `i < hi-1` 得 `i+1 < hi`，再由前置 `hi <= \length(A)` 得 `i+1 < \length(A)`。

上界完全由守卫提供，不需要写进不变式。

**为什么不能写 `i <= hi-1` 当不变式**（讲义特意点出的教学点）：

INIT 步骤立刻失败。取 `lo = hi = 0`（前置条件允许），则循环初始化 `i = lo = 0`，要证 `0 <= hi - 1 = -1`，**假**。所以这条「看起来更紧」的不变式其实是错的。

这个例子的教训：**不变式必须在「循环守卫还没被测试」的时刻也成立**，此时 `i` 可能已经等于上界，甚至上界本身是退化的。写不变式时永远要检查 `hi == lo`（空区间）这个边界情形。

讲义还提到可以写 `i <= hi`，但那对证明数组安全毫无帮助——因为 `hi <= \length(A)` 已经由前置条件给出。

### 5.4 有序数组查找：第一版（没用上「有序」）

```c0
int search(int x, int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@requires is_sorted(A,0,n);
/*@ensures (\result == -1 && !is_in(x, A, 0, n))
        || ((0 <= \result && \result < n) && A[\result] == x);
@*/
{
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i && i <= n;
  if (A[i] == x) return i;
  return -1;
}
```

后置条件是一个析取，两种情况：

1. 返回 −1 **且** x 确实不在 `A[0,n)` 中；
2. 返回一个合法下标 **且** 该位置的值等于 x。

**为什么后置条件必须这么复杂**：如果只写 `\result == -1 || A[\result] == x`，那么「返回 −1 但其实 x 在数组里」也能通过——这是错误的实现。**后置条件要同时约束「找不到」的诚实性。**

第一版正确但没有利用 `is_sorted`，因此最坏仍要看完全部 n 个元素。

### 5.5 想提前终止，却写出了越界 bug

改进思路：既然有序，一旦 `A[i] > x` 就可以立刻返回 −1。于是有人写成：

```c0
for (int i = 0; A[i] <= x && i < n; i++)   /* 有 bug */
//@loop_invariant 0 <= i && i <= n;
```

**问题**：守卫的求值顺序是先算 `A[i] <= x`，后算 `i < n`。当 `i == n` 时（循环刚跑完 n 轮，准备测试守卫），`A[n]` 已经越界。

**为什么会走到 `i == n`**：不变式只保证「测试守卫之前 `0 <= i <= n`」，`i == n` 完全合法。n 个元素的下标是 `0..n-1`，所以 `A[n]` 非法。

**修正：交换合取项。**

```c0
for (int i = 0; i < n && A[i] <= x; i++)
```

现在 `A[i] <= x` 只在 `i < n` 为真时才求值，安全。**这就是短路求值作为安全工具的确切用法**：把「边界检查」放在「解引用」之前。

**为什么这个修正「刚好够」**：守卫里 `i < n` 保证上界；下界 `0 <= i` 由不变式保证。两条合起来给出 `0 <= i < n <= \length(A)`。

### 5.6 更易读的写法：把判断移进循环体

```c0
for (int i = 0; i < n; i++)
//@loop_invariant 0 <= i && i <= n;
{
  if (A[i] == x) return i;
  else if (A[i] > x) return -1;
}
return -1;
```

守卫回到最朴素的 `i < n`，安全性一目了然。但讲义指出：**这个版本的不变式不足以证明后置条件**。

具体来说：
- 循环体内 `return i` 的分支：能证 `A[\result] == x`，没问题。
- 循环外 `return -1` 的分支：需要证 `!is_in(x, A, 0, n)`，**证不出来**。因为不变式只说 `0 <= i <= n`，完全没说「前面的元素与 x 有什么关系」。

### 5.7 关键不变式：`i == 0 || A[i-1] < x`

要证「返回 −1 时 x 不在数组中」，必须把「有序 + 已扫描前缀」这两个事实编码进不变式。候选写法：

```c0
//@loop_invariant i == 0 || A[i-1] < x;
```

**为什么不能直接写 `A[i-1] < x`**：第一次测试守卫前 `i == 0`，`A[-1]` 越界。用析取 `i == 0 || ...` 借助**短路求值**规避：`i == 0` 为真时不会去算 `A[i-1]`。

**PRES 证明**（这是本讲最漂亮的一段）：

设一轮开始时不变式成立、守卫 `i < n` 成立，且**这一轮没有从循环体内返回**。要证 `i' = 0 || A[i'-1] < x`，即 `i+1 == 0 || A[i] < x`。

1. 因为没返回，`A[i] == x` 为假（否则走 `return i`），故 `A[i] != x`。
2. 因为没返回，`A[i] > x` 为假（否则走 `return -1`），故 `A[i] <= x`。
3. 由 (1)(2)：`A[i] < x`。
4. 于是 `i+1 == 0 || A[i+1-1] < x` 成立。

讲义为此在循环体末尾加了一条显式断言，把第 3 步「钉」在代码里：

```c0
//@assert A[i] < x;
```

**这条断言的作用**：它是 PRES 证明的「枢纽事实」。写出来以后，读者（和验证器）都能看到「不返回」等价于「`A[i] < x`」这个关键推理。

### 5.8 从不变式推出后置条件（EXIT）

**情形一：从循环体内 `return i`。** 立即得 `A[\result] == x` 且 `0 <= \result = i < n`（守卫 + 不变式下界）。满足后置条件第二支。

**情形二：从循环体内 `return -1`。** 此时 `A[i] > x`。由不变式，`A[i-1] < x`（若 `i > 0`）。数组有序且升序，故 `A[0] <= ... <= A[i-1] < x`，且 `x < A[i] <= ... <= A[n-1]`，所以 x 不在任何位置。满足第一支。

**情形三：正常退出循环，执行 `return -1`。** 守卫为假得 `i >= n`，不变式给 `i <= n`，故 `i == n`。由不变式（`i > 0` 时）`A[n-1] < x`。有序性给出 `A[0] <= ... <= A[n-1] < x`，故 x 不在数组中。

**三种情形都必须覆盖**——这是「一个函数有多个 return 点」时的标准做法：**每个 return 点单独验证后置条件**。习题 2 的答案里，讲义也正是用「We distinguish cases based on where the function returns」来处理。

**注意情形二、三都强依赖「数组有序」**。如果数组无序，`A[i] > x` 完全不能说明后面没有 x。这就是讲义那句提醒的含义：**如果你的不变式没用到「有序」，那它多半太弱了，因为这个函数在无序数组上根本就是错的。**

### 5.9 操作次数分析

最坏情况：循环跑 n 轮。每轮（除最后一轮外）做三次比较：

1. `i < n`（守卫）
2. `A[i] == x`
3. `A[i] > x`

所以比较次数约 `3n`。**这就是「线性时间」的朴素含义**：时间与输入规模成正比。

**可预测性的实际价值**：若实测 n 的耗时是 T，则输入 `2n` 的耗时约为 `2T`。这种「翻倍关系」让性能预测变得可靠——这正是下一讲 [[15-122-05-Big-O]] 要把这种观察抽象成 `O(n)` 记号的动机。

**提前终止的收益**：有序版本在「x 很小」或「x 不存在且小于多数元素」时远快于 `3n`，但**最坏情况仍是 O(n)**（例如 x 大于所有元素）。要突破线性下界，必须利用「随机访问 + 有序」做二分——那是 [[15-122-06-Binary-Search]]。

### 5.10 规格与实现的分离（本讲的元层次主题）

讲义把「区分 specification 与 implementation」列为学习目标之一。本讲给了两个层次：

- **规格函数**（`is_in`、`is_sorted`、`ge_seg`）：描述「是什么」，写得越直白越好，效率无所谓。
- **实现**（`search`）：追求效率，用不变式把「为什么这样快还对」说清楚。

二者的桥梁就是**契约**：实现只需满足规格函数写成的后置条件，读者无需阅读实现就能使用它。

`is_sorted` 本身也是「规格函数」，但它带循环，所以在被用于契约时其实已经在「执行」了。讲义的取舍是：**允许规格函数有循环（否则无法描述数组性质），但不要把复杂的规格函数塞进每轮都检查的不变式。**

{

  //@loop_invariant lo <= i;

**（3）有 bug 的版本（守卫顺序错误），第 5 页：**

```c0
for (int i = 0; A[i] <= x && i < n; i++)   /* 错误：i == n 时 A[i] 越界 */
//@loop_invariant 0 <= i && i <= n;
```

**（4）修正版：交换合取项，第 6 页：**

```c0
for (int i = 0; i < n && A[i] <= x; i++)
//@loop_invariant 0 <= i && i <= n;
```

**（5）最终版：把判断移入循环体并补强不变式，第 8 页：**

```c0
int search(int x, int[] A, int n)
//@requires 0 <= n && n <= \length(A);
//@requires is_sorted(A,0,n);
/*@ensures (-1 == \result && !is_in(x, A, 0, n))
        || ((0 <= \result && \result < n) && A[\result] == x);
@*/
{
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i && i <= n;
  //@loop_invariant i == 0 || A[i-1] < x;
  {
    if (A[i] == x) return i;
    else if (A[i] > x) return -1;
    //@assert A[i] < x;
  }
  return -1;
}
```

注意多行契约的写法用 `/*@ ... @*/` 包裹，这样跨行的 `@ensures` 才能被解析。

**（6）习题 1 的 `find_max`，第 10 页：**

```c0
int find_max(int[] A, int n)
//@requires n == \length(A) && n > 0;
{
  int max_index = 0;
  int max_num = A[0];

  for (int i = 1; i < n; i++)
  //@loop_invariant 1 <= i && i <= n;
  {
    if (A[i] > max_num) {
      max_index = i;
      max_num = A[i];
    }
  }
  return max_index;
}
```

**（7）习题 2 的 `doubling`，第 10 页：**

```c0
void doubling(int[] A, int[] B, int n)
//@requires n <= int_max() / 2;
//@requires \length(A) == n && \length(B) == 2*n;
{
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i && i <= n;
  {
    B[2*i] = A[i];
    B[2*i + 1] = A[i];
  }
}
```

（上面已把原题中**无效的前置条件** `n*2 <= int_max()` 换成答案给出的正确版本 `n <= int_max() / 2`，原因见 7 节对比表。）

**（8）习题 3 的区间查找，第 11 页：**

```c0
int search(int x, int[] A, int lo, int hi)
//@requires 0 <= lo && lo <= hi && hi <= \length(A);
/*@ensures (\result == -1 && !is_in(x, A, lo, hi))
        || (lo <= \result && \result < hi && A[\result] == x);
@*/
{
  for (int i = lo; i < hi; i++)
  //@loop_invariant lo <= i && i <= hi;
  //@loop_invariant !is_in(x, A, lo, i);
  {
    if (A[i] == x)
    return i;
  }
  //@assert !is_in(x, A, lo, hi);
  return -1;
}
```

这一题特意示范了在**无序**区间上使用 `!is_in` 作为不变式——因为这里 `is_in` 是明确的「基本规格」，且该函数本身就是要实现 `is_in` 的语义。注意这种情况下没有「提前终止」，所以不变式虽然 O(n) 但逻辑上必须。

**示例 A：找最后一个等于 x 的下标（练习「不变式描述已扫描部分」）。**

```c0
int last_index(int x, int[] A, int n)
//@requires n == \length(A);
//@ensures \result == -1 || (0 <= \result && \result < n && A[\result] == x);
{
  int res = -1;
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i && i <= n;
  //@loop_invariant res == -1 || (0 <= res && res < i && A[res] == x);
  {
    if (A[i] == x) res = i;
  }
  return res;
}
```

第二条不变式说的是「`res` 要么是 −1，要么是一个**已扫描过的**合法下标且其值为 x」。`res < i` 是关键部分：它保证 `res` 指向的是**过去**找到的位置，而不是未来。

**示例 B：有序数组上统计 x 出现次数（正确使用「提前终止」）。**

```c0
int count(int x, int[] A, int n)
//@requires n == \length(A);
//@requires is_sorted(A, 0, n);
{
  int c = 0;
  for (int i = 0; i < n && A[i] <= x; i++)
  //@loop_invariant 0 <= i && i <= n;
  //@loop_invariant c >= 0 && c <= i;
  {
    if (A[i] == x) c = c + 1;
  }
  return c;
}
```

守卫 `i < n && A[i] <= x` 用短路求值保证安全，同时利用有序性提前退出。不变式 `c <= i` 表达「计数不超过已扫描个数」，是一条弱的但极有用的合理性约束。

**示例 C：把「有序」用错的后果（反例）。**

```c0
int search_bug(int x, int[] A, int n)
//@requires n == \length(A);
{
  for (int i = 0; i < n; i++)
  //@loop_invariant 0 <= i && i <= n;
  //@loop_invariant i == 0 || A[i-1] < x;   /* 少了 is_sorted 前置！ */
  {
    if (A[i] == x) return i;
    else if (A[i] > x) return -1;
  }
  return -1;
}
```

对 `A = [3, 1, 2]`、`x = 2` 调用，第一轮 `A[0] = 3 > 2` 立刻返回 −1，但 2 确实在数组中。**错误不在不变式，而在缺少前置条件 `//@requires is_sorted(A,0,n);`**。这个例子说明：**不变式的证明力依赖前置条件；同一个循环在更弱的假设下可能不成立。**

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| `A[i] <= x && i < n` | `i < n && A[i] <= x` | 前者先解引用后检查边界，越界；后者靠短路求值保护 | 边界检查必须在前 |
| `i <= hi-1`（当不变式） | `i <= hi`（当不变式） | 前者在 `lo == hi == 0` 时 INIT 失败；后者恒真但无用 | 空区间是杀手 |
| `lo <= i && i <= hi` | `lo <= i` | 前者用于「读 `A[i]`」（需上界允许 `i == hi`）；后者用于「读 `A[i]` 与 `A[i+1]`」（上界由守卫 `i < hi-1` 给） | 上界常常由守卫给 |
| `n*2 <= int_max()` | `n <= int_max() / 2` | 前者对任何 `int` 都成立（因为 `n*2` 已经溢出回绕），是空条件；后者才真正限制 n | 溢出让「显然的」条件失效 |
| 规格函数 `is_in` | 实现 `search` | 前者描述语义、可以低效；后者追求效率、要靠不变式论证 | 「是什么」vs「怎么做」 |
| `!is_in(x,A,lo,i)` 当不变式 | `i == 0 \|\| A[i-1] < x` 当不变式 | 前者循环论证且 O(n)；后者 O(1) 且能推出后置条件（配合有序性） | 不变式要便宜且够强 |
| 返回 −1 的后置条件 | 只写 `\result == -1 \|\| A[\result] == x` | 前者还要求 `!is_in`，排除「有却不报」；后者允许错误实现 | 找不到也要诚实 |
| 最坏 `3n` 比较 | 平均更快 | 提前终止只改善平均，不改变最坏阶 | 最坏情况仍是 O(n) |

## 10. 本节复习

1. 数组类函数的标准前置条件：`0 <= lo && lo <= hi && hi <= \length(A)`。
2. 循环不变式必须允许「守卫即将为假」的时刻，因此上界常写成 `i <= hi` 而非 `i < hi`。
3. `is_sorted` 的守卫是 `i < hi-1`（因为要访问 `A[i+1]`）；不变式只写 `lo <= i`，上界由守卫提供。
4. `i <= hi-1` 不能当不变式：当 `lo == hi == 0` 时初始化为 `0 <= -1`，假。
5. 短路求值 `&&`、`||` 是安全性工具：边界检查必须写在数组访问之前。
6. 有序查找的关键不变式是 `i == 0 || A[i-1] < x`，析取的第一支专门用于规避 `A[-1]`。
7. 「不返回」等价于「`A[i] != x` 且 `A[i] <= x`」，即 `A[i] < x`——这是 PRES 的枢纽，讲义用 `//@assert` 显式写出。
8. 后置条件必须同时约束「找到」和「找不到」两种结果；多 return 点要逐个验证。
9. 线性查找最坏约 `3n` 次比较，是线性时间；提前终止不改变最坏阶。
10. `n*2 <= int_max()` 是永不失败的空条件，因为 `n*2` 本身会溢出；正确写法是 `n <= int_max()/2`。
11. 规格函数用于描述，实现用于执行；二者通过契约连接。

## 11. 自我检查

**题 1.** 解释为什么 `is_sorted` 的循环不变式只写 `//@loop_invariant lo <= i;` 就够了，而 `is_in` 必须写 `//@loop_invariant lo <= i && i <= hi;`。

**题 2.** 下面这个守卫有 bug 吗？若有，给出触发越界的具体输入。
```c0
for (int i = 0; i < n && A[i] <= x; i++)
```
（假设不变式为 `0 <= i && i <= n`，前置为 `0 <= n && n <= \length(A)`。）

**题 3.** 对 `A = [1, 3, 5, 7]`、`x = 4`，追踪最终版 `search` 的每一轮：写出 `i`、`A[i]`、守卫、走哪个分支、以及每轮结束时不变式 `i == 0 || A[i-1] < x` 的值。

**题 4.** 说明为什么最终版 `search` 若去掉前置条件 `//@requires is_sorted(A,0,n);` 就是错的，并给出一个反例数组。

**题 5.** 习题 2 中，`//@requires n*2 <= int_max();` 为什么「总是成立」？请用第 2 讲的模运算解释。

<details>
<summary>参考答案</summary>

**答 1.** 两者的数组访问模式不同。
- `is_sorted` 访问 `A[i]` 与 `A[i+1]`，需要 `i+1 < hi`，即 `i < hi-1`。这正是**循环守卫**。所以上界由守卫提供，不变式只需补下界 `lo <= i`（配合前置 `0 <= lo` 得 `0 <= i`）。
- `is_in` 只访问 `A[i]`，需要 `i < hi`，也就是守卫本身。但 `is_in` 的不变式还必须保证「循环结束时 `i` 不会超过 `hi`」，因为退出后要用 `i == hi` 之类的推理；而且更重要的是要在**每次测试守卫前**给出 `i` 的完整范围，使 `i <= hi` 这条信息在循环外也可用。写全 `lo <= i && i <= hi` 是更稳妥的通用范式。

**答 2.** 没有 bug。顺序正确：先 `i < n`，短路保证 `i >= n` 时不会求值 `A[i] <= x`。配合不变式 `0 <= i` 与前置 `n <= \length(A)`，访问安全。**如果顺序反过来**（`A[i] <= x && i < n`）才有 bug：当 `i == n` 时先访问 `A[n]`，越界。（这正是讲义第 5 页的反例。）

**答 3.** 追踪表：

| 轮次 | 测试前 i | 守卫 `i<n && A[i]<=x` | 分支 | 轮末不变式 `i==0 \|\| A[i-1]<x` |
|---|---|---|---|---|
| 1 | 0 | `0<4 && A[0]=1<=4` 真 | `A[0]==4`? 否；`A[0]>4`? 否 → 继续，断言 `A[0]<4` 成立 | `i` 变 1，检查 `A[0]=1<4` 真 |
| 2 | 1 | `1<4 && A[1]=3<=4` 真 | `3==4`? 否；`3>4`? 否 → 继续，断言 `3<4` 成立 | `i` 变 2，`A[1]=3<4` 真 |
| 3 | 2 | `2<4 && A[2]=5<=4` 假 | 退出循环 | — |

退出后 `i = 2 < n = 4`，执行 `return -1`。**注意这里是从「守卫为假」退出，不是从 `A[i] > x` 分支退出**——因为守卫先检查 `A[i] <= x`，一旦为假就退出循环，根本进不到体内的 `else if`。此时由不变式得 `A[1] = 3 < 4`，再由有序性得 `A[0..1] < 4` 且 `A[2..3] >= 5 > 4`，故 4 不在数组中，返回 −1 正确。

**答 4.** 去掉 `is_sorted` 后，`A[i] > x → return -1` 这一步失去依据：后面的元素不一定更大。反例：`A = [5, 1, 9]`，`x = 1`。第一轮 `A[0] = 5 > 1`，函数立刻返回 −1，但 `A[1] = 1 == x`，x 明明在数组中。同理，退出循环后由 `A[n-1] < x` 推「所有元素 < x」也依赖有序性。

**答 5.** 在 C0 中 `n` 是 32 位 `int`，所以 `n <= int_max() = 2^31 - 1` 恒成立。计算 `n*2` 时若数学结果超过 `2^31-1`，会按模 2^32 回绕成**负数**（例如 `n = 2^30` 时 `n*2 = 2^31 ≡ -2^31`）。而负数当然 `<= int_max()`。所以 `n*2 <= int_max()` 对任何 `int` n 都为真，是一条**空条件**，完全没有约束力。正确写法是把约束加在未溢出的量上：`n <= int_max()/2`，它等价于「`2n` 不发生溢出」。

</details>
