# 第 1 讲：契约（Contracts）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 用自己的话解释 Contract（契约）、Precondition（前置条件）、Postcondition（后置条件）、Loop Invariant（循环不变量）、Assertion（断言）五个概念的区别与联系。
2. 在 C0 代码中正确写出 `//@requires`、`//@ensures`、`//@loop_invariant`、`//@assert` 四类注解，并说明它们各自在什么时刻被检查。
3. 对一个带 `while` 循环的函数，完成「初始化（Initialization）+ 保持性（Preservation）+ 退出（Exit）」三段式证明，并给出 Termination（终止性）论证。
4. 用 Point-to Reasoning（指向式推理）判断一段推理是否合法，能指出「偷看循环体」「偷看被调函数体」这两类常见错误。
5. 能复现讲义中快速幂函数 `f` 的调试过程：从「猜它算 x 的 y 次方」到「发现 y=0 时出错」再到「修改循环条件并补强不变式」。

## 2. 前置知识

  - 指数律：`(a^b)^c = a^(b*c)`、`a^(b+c) = a^b * a^c`。
  - 对「对所有 n 成立」的命题有直观感受即可，本讲不要求严格的数学归纳法书写。
- 需要具备的编程基础：变量、赋值、`while` 循环、`if` 分支、函数调用。

## 3. 核心概念

**Contract（契约）**：写在代码里的「使用说明书 + 保证书」。它同时约束调用者（你必须给我什么样的输入）和被调函数（我保证给你什么样的输出）。在 15-122 中，契约是 function contract（函数契约）、loop invariant（循环不变量）与 assertion（断言）的统称。

**Precondition（前置条件）**：调用者必须先满足的条件，写作 `//@requires e;`，放在函数体之前。函数体内可以无条件假定前置条件成立；如果调用时违反它，函数不做任何承诺，C0 在 `-d` 模式下会直接报 `@requires annotation failed`。

**Postcondition（后置条件）**：函数返回时必须保证成立的条件，写作 `//@ensures e;`，放在前置条件之后。可以用特殊变量 `\result` 指代返回值。调用者读完契约就可以使用函数，无需看函数体。

**Specification Function（规格函数）**：只用于描述、不被真正高效执行的数学函数。本讲的 `POW(x,y)` 就是典型：它用最直白的递归定义表达「x 的 y 次方」，本身效率很低，但作为契约里的「标准答案」非常合适。

**Loop Invariant（循环不变量）**：在循环每次测试退出条件之前都成立的性质，写作 `//@loop_invariant e;`，紧贴在循环体 `{` 之前。它是把「循环跑了多少圈」这种操作性直觉，转成可证明的逻辑命题的唯一桥梁。

**Assertion（断言）**：程序执行到该行时必须为真的命题，写作 `//@assert e;`。它既是调试工具，也是写给人看的「此处我依赖什么」的说明。

**Termination（终止性）**：证明循环或递归在有限步内结束。标准做法是找一个表达式，它在每轮循环中严格变小（或严格变大），且永远不会越过某个使循环守卫为假的下界（或上界）。

**Point-to Reasoning（指向式推理）**：本课程唯一接受的证明风格。每一步推理都必须能「指」到某一行代码、某条契约或某条数学定律作为依据。除终止性证明外，所有证明都只用指向式推理。

**Operational Reasoning（操作式推理）** 与 **Logical Reasoning（逻辑推理）**：前者是「追踪程序怎么跑」得出结论，后者是「用已知为真的事实推出新事实」。两者都可靠，但操作式推理在大段代码上极易出错；本课只允许其中一种极简形式——「刚给变量赋值，就立刻使用这个值」。

**C0**：CMU 自研的 C 安全子集，带垃圾回收和 `//@` 契约注解。**这是 C0，不是标准 C，也不是 C++。** 讲义中所有代码都在 C0 下运行，解释器叫 `coin`。

## 4. 通俗理解

把函数想成一台自动售货机：

- **前置条件**是「投入的必须是 1 元、5 元或 10 元硬币，且商品编号必须在 1–20 之间」。你违反了这个条件，机器卡住或者吐错东西，厂家不负责任。
- **后置条件**是「只要按规矩投币并选号，机器保证吐出你选的那件商品，且找零正确」。
- **循环不变量**是机器内部传送带每一圈都会回到的「基准位置」：不管这一圈抓取了几件商品，回到基准位置时，账目必须仍然对得上。
- **断言**是机器上贴的「此处电压应为 220V」标签，用来中途自检。

具体数字例子：讲义里的 `f(2, 7)` 应该返回 `2^7 = 128`。程序用「平方求幂」：每轮把底数平方、把指数减半，指数是奇数时额外把当前底数乘进结果。三轮之后 `b=16, e=1, r=8`，返回 `r*b = 128`。整个过程中 `r * b^e` 始终等于 128——这就是那个「不会变的量」。

## 5. 原理与推导

### 5.1 起点：一个来路不明的程序

讲义第 2 页给出待调试的函数（原文 PDF 页码，下同）：

```c0
int f(int x, int y) {
  int r = 1;
  while (y > 1) {
    if (y % 2 == 1) {
      r = x * r;
    }
    x = x * x;
    y = y / 2;
  }
  return r * x;
}
```

先做实验（第 3–4 页）：`f(2,3)=8`、`f(2,4)=16`、`f(3,2)=9`、`f(-2,3)=-8`、`f(2,10)=1024`。于是形成猜想：

> 对 `y >= 0`，`f(x, y) = x^y`。

但第 11 页立刻给出反例：`f(2,0)` 返回 2（应为 1），`f(2,-1)` 也返回 2。这说明「猜想」需要被精化成一份**带前置条件的契约**。

### 5.2 数学定义如何变成契约

整数幂的归纳定义是：

- `x^0 = 1`
- `x^(y+1) = x * x^y`，对 `y >= 0`

这个定义在 `y < 0` 时根本没有定义。于是在程序里把它写成**前置条件**：

```c0
//@requires y >= 0;
```

再用规格函数把「标准答案」写出来：

```c0
int POW(int x, int y)
//@requires y >= 0;
{
  if (y == 0) return 1;
  else return x * POW(x, y-1);
}
```

最后写**后置条件**：

```c0
//@ensures \result == POW(x,y);
```

到这里，契约就完整了：**调用者保证 `y >= 0`，函数保证返回值等于 `POW(x,y)`**。

### 5.3 为什么不能直接改参数 x、y

讲义第 15 页展示了一个真实的编译错误：

```
mystery2b.c0:20.5-20.6:error:cannot assign to variable 'x'
used in @ensures annotation
```

原因：后置条件 `\result == POW(x,y)` 里的 `x`、`y` 指的是**调用时传入的实参**。如果函数体里改了 `x`，后置条件的含义就跟着变了，违反「只看契约就能用函数」的原则。解决办法是引入辅助变量 `b`（base）与 `e`（exponent），原参数保持不变：

```c0
int b = x;   /* base */
int e = y;   /* exponent */
```

之后循环只改 `b`、`e`、`r`。

### 5.4 找不变式：从特殊情况到一般情况

**特殊情况（y 是 2 的幂）**：若 `y = 2^k`，则每轮 `e` 都是偶数，`if` 分支永不进入，`r` 恒为 1。此时不变量是 `x^y` 本身。第 7 页的追踪表（`x=2, y=8`）：

| iteration | x | y | r | x^y |
|---|---|---|---|---|
| 0 | 2 | 8 | 1 | 256 |
| 1 | 4 | 4 | 1 | 256 |
| 2 | 16 | 2 | 1 | 256 |
| 3 | 256 | 1 | 1 | 256 |

**一般情况（y 任意）**：第 18 页对 `f(2,7)` 的追踪表显示 `b^e` 不是不变量，但 `r * b^e` 是：

| iteration | b | e | r | b^e | r * b^e |
|---|---|---|---|---|---|
| 0 | 2 | 7 | 1 | 128 | 128 |
| 1 | 4 | 3 | 2 | 64 | 128 |
| 2 | 16 | 1 | 8 | 16 | 128 |

原因：当 `e = 2n+1` 为奇数时，`b^e = b * (b*b)^n`，那个多出来的因子 `b` 恰好被 `r = b * r` 吸收。于是不变式写成 C0 布尔表达式：

```c0
//@loop_invariant r * POW(b,e) == POW(x,y);
```

注意：C0 的循环不变量必须是布尔表达式，不能写「表达式 `r*POW(b,e)` 不变」这种非布尔形式，所以必须写成等式。

### 5.5 三段式证明之一：Initialization（初始化）

要证：第一次测试循环守卫之前，`r * POW(b,e) == POW(x,y)` 成立。

| 步骤 | 依据 |
|---|---|
| `r = 1` | 第 5 行赋值 |
| `b = x` | 第 6 行赋值 |
| `e = y` | 第 7 行赋值 |
| `r * POW(b,e) = 1 * POW(x,y) = POW(x,y)` | 数学（代入与 1 乘律） |

同理，`e >= 0` 的初始化：`e = y`（第 7 行）且 `y >= 0`（前置条件），由数学得 `e >= 0`。

### 5.6 三段式证明之二：Preservation（保持性）

设循环体执行前的值为 `r, b, e`，执行一轮后的值为 `r', b', e'`（加撇号表示「一轮之后」）。假设 `r * b^e = x^y`，要证 `r' * b'^e' = x^y`。

**情形 A：e 为偶数**，设 `e = 2n`（n > 0）。

- `r' = r`（`e % 2 == 1` 为假，不进入 if）
- `b' = b * b`（第 15 行）
- `e' = e / 2 = n`

推导：
```
r' * b'^e' = r * (b*b)^n
           = r * b^(2n)
           = r * b^e
           = x^y        （由归纳假设）
```

**情形 B：e 为奇数**，设 `e = 2n + 1`（n >= 0）。

- `r' = b * r`（第 13 行）
- `b' = b * b`
- `e' = e / 2 = n`（整数除法，(2n+1)/2 = n）

推导：
```
r' * b'^e' = (b * r) * (b*b)^n
           = (b * r) * b^(2n)
           = r * b^(2n+1)
           = r * b^e
           = x^y
```

两种情形都成立，故保持性得证。**注意这里用了「分类讨论」——这是处理 `if` 的标准手法，也是 point-to reasoning 允许的：每一类都能指到具体代码行。**

### 5.7 三段式证明之三：Exit（退出）

循环结束时，循环守卫 `e > 0` 为假，只能推出 `e <= 0`。但仅凭 `r * b^e = x^y` 和 `e <= 0`，推不出 `r = x^y`——因为 `b^e` 在 `e = 0` 时是 1，在 `e < 0` 时根本没有定义。

所以必须**补强**第二个不变量：

```c0
//@loop_invariant e >= 0;
```

有了它，退出时 `e >= 0` 与 `e <= 0` 合起来给出 `e == 0`，于是 `b^e = b^0 = 1`，得 `r = r * 1 = r * b^e = x^y`。讲义第 21 页还额外加了一条冗余断言帮助读者：

```c0
//@assert e == 0;
```

这就是「不变式太弱」的典型案例：**证明失败不一定是代码错，可能是不变式写得不够强。**

### 5.8 终止性（Termination）

取表达式 `e`，下界 0，要证对任意一轮：

> 若 `e > 0`，则 `e' < e` 且 `e' >= 0`。

- `e' = e / 2`（第 16 行）；
- 对正整数 `e`，整数除法满足 `e/2 < e`；
- 同样由整数除法定义，`e/2 >= 0`。

所以 `e` 严格递减且有下界 0，循环只能执行有限轮。注意这一步允许使用「每一轮都」这种表述——**终止性是本课程唯一允许非指向式操作推理的地方**。

### 5.9 发现 bug 并修复

到第 19 页为止的函数仍是：

```c0
while (e > 1) { ... }
return r * b;
```

当 `y = 0` 时，`e = 0`，循环一次都不执行，直接返回 `r * b = 1 * x = x`，而正确答案是 `x^0 = 1`。

修复方法（第 20 页）：把循环条件从 `e > 1` 改成 `e > 0`，返回值从 `r * b` 改成 `r`。这样 `e = 0` 时直接返回 `r = 1`；`e = 1` 时最后一轮会进入 `if` 分支执行 `r = b * r`，把最后一份底数乘进去，然后 `e` 变成 0 退出。

### 5.10 一个「证明对了却算错」的惊讶

第 25 页：

```
--> f(2,30);   1073741824
--> f(2,31);   -2147483648
--> f(2,32);   0
```

`2^31` 是负数、`2^32` 是 0，看起来与「已证明正确」矛盾。真正的原因是：**C0 的 `int` 是 32 位定长整数，运算按模 2^32 进行**。`2^31` 溢出到符号位，`2^32` 回绕为 0。数学意义上的 `x^y` 与机器意义上的 `int` 乘法并不是同一个函数——契约证明的是「机器整数模运算下」的性质，这一点在下一讲 [[15-122-02-Ints]] 详述。

### 5.11 契约的两种用途与证明义务

**用途一：测试。** 契约是「对任意输入的通用测试」。但只有真正用会触发失败的输入跑过，契约才有价值——`f(2,0)` 就是这样的输入。

**用途二：推理。** 契约给出规格，并把推理局部化：从大程序降到每个函数的契约，从大函数降到每个循环不变量。

| 注解 | 检查时机 | 你要证明什么 | 你能假定什么 |
|---|---|---|---|
| `@requires` | 函数体执行前 | 每个调用点上实参满足前置条件 | 函数体内可假定它成立 |
| `@ensures` | 函数体执行后 | 每个 return 点上返回值满足后置条件 | 调用点可假定它成立 |
| `@loop_invariant` | 每次测试循环守卫前 | 初始化 + 保持性 | 循环之后可假定「不变式 ∧ 守卫取反」 |
| `@assert` | 执行到该行时 | 该行处命题为真 | 之后的语句可假定它成立 |

### 5.12 Point-to Reasoning 的两条红线

讲义第 28–32 页用一个大例子列出合法与非法推理。核心结论：

**合法（指向式）：**
- `if` 的 then 分支里可假定条件为真；else 分支里可假定条件为假。
- 循环体内可假定循环守卫为真；循环之后可假定守卫为假。
- 函数体内可假定前置条件；调用点可假定后置条件。
- 循环体内可假定循环不变量；循环之后可假定循环不变量。
- 刚赋值后可使用该变量的新值。
- 数学定律（逻辑律、模运算律、补码律）。

**非法（非指向式）：**
- 在循环外谈论「循环体里发生过什么」——除非它被写进了某个循环不变量。
- 谈论被调函数「内部怎么算的」——除非它写在后置条件里，或者是规格函数。
- 变量被修改后，继续使用修改前的旧结论。

一个便于记忆的判据：**如果你发现自己的论证里出现了「总是」「从不」「所有轮」「每一圈」，那多半不是指向式推理**（终止性证明除外）。

### 6.2 Agent 自行编写的教学示例

> **非官方，仅用于说明概念。** 以下代码由本笔记自行编写，不是 CMU 官方代码，语言为 C0。

一个「求和」版本，用来练习三段式证明：

```c0
int sum_to(int n)
//@requires n >= 0;
//@ensures \result == n * (n+1) / 2;
{
  int s = 0;
  int i = 0;
  while (i < n)
  //@loop_invariant 0 <= i && i <= n;
  //@loop_invariant s == i * (i+1) / 2;
  {
    i = i + 1;
    s = s + i;
  }
  //@assert i == n;
  return s;
}
```

三处要点：

1. `0 <= i && i <= n` 是「范围不变量」，用来保证退出时能推出 `i == n`，同时保证 `i*(i+1)/2` 不会因负数而出问题。
2. `s == i*(i+1)/2` 是「功能不变量」，初始化时 `0 == 0*1/2` 成立；保持性上，一轮后 `i' = i+1`、`s' = s + i' = i(i+1)/2 + (i+1) = (i+1)(i+2)/2 = i'(i'+1)/2`。
3. 终止性取 `n - i`，每轮严格减 1，下界 0。

再给一个「故意写弱不变式导致证明失败」的反例：

```c0
int bad_sum(int n)
//@requires n >= 0;
//@ensures \result == n * (n+1) / 2;
{
  int s = 0;
  int i = 0;
  while (i < n)
  //@loop_invariant s >= 0;      /* 太弱，推不出后置条件 */
  {
    i = i + 1;
    s = s + i;
  }
  return s;
}
```

`-d` 模式下会在返回处报 `@ensures annotation failed`。这正说明：**契约检查器能告诉你「证明链断了」，但不能替你补上正确的不变式。**

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| Precondition（前置条件） | Postcondition（后置条件） | 前者是调用者的义务、函数体的权利；后者是函数的义务、调用者的权利 | 「进门要票，出门交货」 |
| Loop Invariant（循环不变量） | Assertion（断言） | 不变式在**每次**测试守卫前都成立，需要证初始化与保持性；断言只在**执行到该行**时检查一次 | 不变式是「每圈都查」，断言是「路过查一次」 |
| `@requires`（契约） | `@assert`（自检） | `@requires` 的证明义务在**调用点**；`@assert` 的义务在**当前行** | 责任方不同 |
| Specification Function（规格函数） | 普通函数 | 规格函数只用于描述、可以极低效甚至不可执行；普通函数要真的跑 | `POW` 是规格，`f` 是实现 |
| Operational Reasoning（操作式推理） | Logical Reasoning（逻辑推理） | 前者追踪「怎么变」，后者依据「已知为真」；本课只允许前者中「赋值后立即使用」一种 | 「跟着跑」vs「拿已知推」 |
| C0（本讲语言） | 标准 C | C0 有 `//@` 契约注解、有垃圾回收、由 `coin` 解释执行；标准 C 没有这些 | **本讲全部代码是 C0，不是 C** |

## 10. 本节复习

1. 契约的四种形式：`@requires`（前置）、`@ensures`（后置）、`@loop_invariant`（循环不变式）、`@assert`（断言）。
2. 只有加 `-d` 参数时契约才被动态检查；不加时注解被忽略。
3. 循环不变式必须写成**布尔表达式**，不能写「某量不变」这种非布尔说法。
4. 三段式：Initialization（进入循环前成立）、Preservation（一轮后仍成立）、Exit（不变式 + 守卫取反 推出后置条件）。
5. 不变式太弱会导致 Exit 推不出来；此时应补强不变式，而不是改代码。
6. 终止性：找一个严格递减且有下界的量；这是本课唯一允许非指向式推理的地方。
7. 指向式推理的两条红线：不偷看循环体、不偷看被调函数体（规格函数除外）。
8. 证明的是「机器整数」而非「数学整数」：`int` 是 32 位、按模 2^32 运算，`2^32` 会变成 0。

## 11. 自我检查

**题 1.** 对 `f(2, 7)`，手工填出每一轮循环开始时的 `b, e, r` 与 `r * POW(b,e)`，并说明为什么 `POW(b,e)` 单独不是不变量。

**题 2.** 若把 `//@loop_invariant e >= 0;` 删掉，只保留 `r * POW(b,e) == POW(x,y)`，Exit 步骤会卡在哪里？请写出你能得到的全部结论。

**题 3.** 下面这段推理是否属于 point-to reasoning？为什么？
> 「循环跑了 5 圈之后，`k` 一定等于 `4*y`，因为每圈 `k` 减 4、`y` 减 1，初始时 `k = 4*42`、`y = 42`。」

**题 4.** 对 6.2 节的 `sum_to`，写出 Preservation 的完整代数推导，并指出哪一步用到了 `i <= n` 这个范围不变量。

**题 5.** 讲义说 `f(2,31)` 返回 `-2147483648`。请用模运算解释这个结果，并说明这是否意味着「第 21 页的正确性证明错了」。

<details>
<summary>参考答案</summary>

**答 1.** 追踪表：

| iteration | b | e | r | POW(b,e) | r * POW(b,e) |
|---|---|---|---|---|---|
| 0 | 2 | 7 | 1 | 128 | 128 |
| 1 | 4 | 3 | 2 | 64 | 128 |
| 2 | 16 | 1 | 8 | 16 | 128 |

`POW(b,e)` 从 128 降到 64 再降到 16，明显在变；但 `r` 恰好按同样比例增大，二者乘积恒定。物理直觉：把 `b^e` 中「多出来的底数因子」搬到 `r` 里存着，账目始终平。

**答 2.** 退出时由 `e > 0` 为假得 `e <= 0`。由 `r * POW(b,e) == POW(x,y)`，若 `e = 0` 则 `POW(b,0) = 1`，得 `r = POW(x,y)`；但若 `e < 0`，`POW(b,e)` 的前置条件 `y >= 0` 被违反，表达式无定义，无法继续。因此只能得到「`e = 0` 时后置条件成立」这个条件性结论，无法排除 `e < 0`。补上 `e >= 0` 后，`e <= 0` 与 `e >= 0` 合并才给出 `e == 0`。

**答 3.** 不是。它谈论「循环跑了 5 圈之后」以及「每圈」发生的事，属于对循环体的操作性推理，无法指向某一行代码。合法做法是把结论写成循环不变量 `k == 4*y`，然后用初始化与保持性两段证明来验证它。例句中的「初始时 `k = 4*42`」可以指向赋值行，但「每圈减 4、减 1」之后直接跳到「5 圈后」是不允许的。

**答 4.** 设一轮前 `s = i(i+1)/2`、`0 <= i <= n`、`i < n`（循环守卫）。执行 `i = i+1` 得 `i' = i+1`；执行 `s = s+i'` 得 `s' = i(i+1)/2 + (i+1) = (i+1)(i+2)/2 = i'(i'+1)/2`，功能不变量保持。范围不变量：由 `i < n` 得 `i' = i+1 <= n`，又 `i >= 0` 得 `i' >= 1 > 0`。**`i <= n` 这一步用到了守卫 `i < n` 与整数的离散性**；若没有范围不变量，`i' <= n` 无法从功能不变量单独推出。

**答 5.** C0 的 `int` 是 32 位补码。`2^31 = 2147483648` 在模 2^32 下等于 `-2147483648`（最高位为 1，被解释为符号位）。这不是证明错了：第 21 页的证明针对的是「C0 的 int 乘法」，而 C0 的乘法本身就是模 2^32 的；契约 `\result == POW(x,y)` 中的 `POW` 也按机器整数语义求值。数学上的 `2^31` 与机器上的 `2^31` 是两个不同的对象。真正的教训是：**写契约时必须清楚自己描述的是数学整数还是机器整数。**

</details>
