# 第 20 讲：虚拟机（Virtual Machines）

## 1. 本节学习目标

学完本讲后，你应该能够：

1. 说明 C0VM 是什么、`cc0 -b` 如何把 `.c0` 编译成 `.bc0` 字节码文件，以及为什么「先编译成字节码再解释执行」在工程上有价值。
2. 描述 C0VM 的栈机（stack machine）结构：值栈 `S`、局部变量数组 `V`、指令指针 `pc`、调用栈（call stack）。
3. 把一段简单 C0 表达式手工编译成字节码序列，并写出对应的十六进制字节。
4. 解释字节码文件的物理格式：魔数 `C0 C0 FF EE`、版本号、函数表、常量池、代码段。
5. 复述函数调用的五个步骤（建立 `Vg` → 弹参 → 压帧 → 建空 `Sg` → 执行）与返回的五个对称步骤。
6. 说明局部变量、常量池、堆分配（`new` / `newarray`）、数组访问（`imload` / `imstore`）在字节码层面的具体指令。
7. 解释字节码验证（bytecode verification）检查什么、不能检查什么，以及为什么「无法静态检查除零与终止性」。
8. 给定一段字节码，反向还原出它对应的 C0 源代码。

## 3. 核心概念

**Virtual Machine（虚拟机）**：一台用软件模拟出来的计算机。它有自己的指令集、寄存器/栈、内存布局。C0VM 就是「能执行 C0 字节码的虚拟计算机」。

**Bytecode（字节码）**：虚拟机的指令。每条指令由 1 个操作码字节（opcode）加上若干操作数字节构成。

**Stack Machine（栈机）**：一种指令集架构，运算的操作数从**栈顶**弹出，结果压回栈顶。没有通用寄存器。C0VM 是栈机。

**Value Stack（值栈，`S`）**：存放中间计算结果的栈。`bipush 3; bipush 4; iadd` 就是从栈上弹出 3 和 4，把 7 压回去。

**Local Variables（局部变量数组，`V`）**：当前函数的局部变量与参数，用整数下标访问（`vload 0`、`vstore 2`）。

**Program Counter（程序计数器，`pc`）**：指向下一条要执行的指令的字节偏移。

**Constant Pool（常量池）**：字节码文件里存放所有整数常量、字符串常量、函数引用的表。指令用「池下标」引用它们。

**Bytecode Verification（字节码验证）**：加载字节码时做的一组静态检查，保证执行不会破坏虚拟机的完整性（例如栈下溢、跳转到非法地址）。

## 4. 通俗理解

**编译器是翻译，虚拟机是演员。**

`cc0` 把 C0 源码翻译成字节码（一份「剧本」），C0VM 是照着剧本表演的演员。剧本用的是演员能懂的语言（字节码），演员不需要懂原作者的母语（C0）。

**为什么不让演员直接读原著？** 因为「剧本」有三个好处：

1. **可移植**：同一份字节码可以在任何有 C0VM 的机器上跑（这正是 Java 的卖点）。
2. **可检查**：剧本比原著容易做静态审查——「这个跳转会不会跳到剧本外面」是可以逐条检查的。
3. **可分析**：想知道「这个程序用了多少内存」「执行了多少条指令」，看剧本比看原著容易。

**栈机的直觉**：想象一台只有「盘子堆」的计算器。你按 `3` 就放一个 3 号盘子，按 `4` 再放一个 4 号盘子，按 `+` 就把最上面两个盘子拿下来、换成一个 7 号盘子。**所有运算都在盘子堆顶部发生**，没有「寄存器 A」「寄存器 B」这种命名位置。

**局部变量数组的直觉**：一排带编号的抽屉。函数参数先放进 0 号、1 号抽屉，函数体里的局部变量依次往后放。`vload 2` 就是「打开 2 号抽屉取出东西放到盘子堆顶」。

## 5. 原理与推导

### 5.1 为什么需要字节码：从「直接解释源码」到「编译成指令」

如果直接解释 C0 源码，每次执行都要重新做词法分析、语法分析——慢，且难以做静态检查。

编译成字节码后：

- 词法/语法分析只做一次（编译期）。
- 运行时只做「取指令 → 解码 → 执行」的循环，非常快。
- 字节码是**线性**的指令序列，地址明确，便于静态验证。

`cc0 -b file.c0` 生成 `file.bc0`（二进制字节码文件）。不带 `-b` 时 `cc0` 直接解释执行 `.c0`（内部仍然编译成字节码，只是不落盘）。

### 5.2 栈机的执行模型

C0VM 的状态由四部分组成：

| 组件 | 符号 | 说明 |
|---|---|---|
| 值栈 | `S` | 当前函数的操作数栈 |
| 局部变量数组 | `V` | 当前函数的参数与局部变量 |
| 程序计数器 | `pc` | 当前指令在代码段中的偏移 |
| 调用栈 | — | 保存「返回地址 + 调用者的 `S` 和 `V`」 |

执行循环：

```
while (true) {
  op = code[pc];
  pc = pc + 1;
  switch (op) {
    case 0x10: /* bipush */ { int8_t b = code[pc]; pc++; push(S, b); break; }
    case 0x60: /* iadd   */ { int y = pop(S); int x = pop(S); push(S, x + y); break; }
    ...
  }
}
```

**关键点：操作数顺序。** `isub` 弹出 `y` 再弹出 `x`，计算 `x - y`（不是 `y - x`）。栈是后进先出，先压的是被减数。同理 `idiv` 计算 `x / y`。

### 5.3 手工编译：`(3 + 4) * 5 / 2`

这是讲义第 4–6 页的核心例子。按后序遍历语法树：

1. 要算 `*`，先算左边 `(3+4)`；要算 `+`，先压 3 和 4。
2. `bipush 3`、`bipush 4`、`iadd` → 栈上是 7。
3. 要乘 5：`bipush 5`、`imul` → 栈上是 35。
4. 要除 2：`bipush 2`、`idiv` → 栈上是 17。

指令序列：

```
bipush 3
bipush 4
iadd
bipush 5
imul
bipush 2
idiv
```

对应字节（`bipush` 的操作码是 0x10，后跟 1 字节立即数）：

```
10 03    bipush 3
10 04    bipush 4
60       iadd
10 05    bipush 5
68       imul
10 02    bipush 2
6C       idiv
```

合并：`10 03 10 04 60 10 05 68 10 02 6C`（11 字节）。

**验证栈高度**：每一步之后栈高度分别是 1, 2, 1, 2, 1, 2, 1。最终恰好剩一个值——这正是字节码验证要检查的性质之一（见 5.9 节）。

**为什么是后序？** 因为栈机要求「操作数先于运算符出现」。中序 `(3+4)*5/2` 里的 `*` 出现在 `3+4` 之后、`5` 之前，但此时 `5` 还没压栈——所以必须先算完 `3+4` 得到 7，再压 5，再乘。后序遍历正好给出这个顺序。

### 5.4 局部变量：`vload` 与 `vstore`

```c
int f(int x, int y) {
  int z = x + y;
  return z * 2;
}
```

编译后（`x` 在 `V[0]`、`y` 在 `V[1]`、`z` 在 `V[2]`）：

```
vload 0        ; 压 x
vload 1        ; 压 y
iadd           ; x + y
vstore 2       ; 弹出并存入 z
vload 2        ; 压 z
bipush 2
imul           ; z * 2
return
```

字节：`15 00 15 01 60 36 02 15 02 10 02 68 B0`（`vload`=0x15、`vstore`=0x36、`return`=0xB0）。

**参数顺序**：`V[0]` 是第一个参数，`V[1]` 是第二个，依此类推。局部变量接在参数之后。**这个布局由编译器决定**，函数头里记录了「参数个数」和「局部变量个数」（见 5.6 节）。

### 5.5 常量池：`ildc` 与 `aldc`

`bipush` 只能压 1 字节的有符号整数（−128…127）。更大的整数、字符串、函数引用都要通过**常量池**。

- `0x13 ildc <c1,c2>`：压入整数池中下标为 `(c1 << 8) | c2` 的整数。
- `0x14 aldc <c1,c2>`：压入「地址池」中下标对应的字符串或函数地址。

**为什么用两个字节做下标？** 因为池子最多 65536 项。两个字节是 16 位，够用且节省空间。

**为什么 `bipush` 还要存在？** 因为小整数太常见了。`bipush 0` 只占 2 字节，`ildc` 占 3 字节——对热代码这是 33% 的体积差距。这是典型的「短指令优化」。

讲义习题 Ex8 提到一个细节：如果整数池是空的，要压入 300 不能直接放常量 300（那就要占池子），可以用 `bipush 3; bipush 100; imul` 算出来。这是「用指令换常量池空间」的取舍。

### 5.6 字节码文件格式

讲义第 5 页给出格式：

```
偏移  内容
0     C0 C0 FF EE          魔数（magic number）
4     00 17                版本号：version = 0x00, arch = 0x17 (= 23)
6     ...                  整数常量池
...   ...                  地址池（字符串、函数）
...   ...                  函数表
...   ...                  代码段
```

**魔数**是文件类型标识：读文件时先看前 4 字节，不是 `C0 C0 FF EE` 就拒绝加载。这防止把别的文件当字节码执行。

**版本号** `00 17`：高字节是主版本（0），低字节是架构版本（0x17 = 十进制 23）。不同版本的 C0VM 拒绝加载不匹配的文件，避免「用旧解释器跑新指令」的静默错误。

**函数头**包含三个数字：参数个数、局部变量个数、代码长度。有了这三个数，加载器才能正确切分每个函数的代码段，并知道调用时为 `V` 分配多大空间。

### 5.7 函数调用：五个步骤

调用 `invokestatic`（0xB8）或 `invokenative`（0xB7）时：

1. **建立新的 `Vg`**：为被调函数的局部变量分配数组（大小来自函数头）。
2. **从 `Sf` 弹参存入 `Vg`**：调用者栈上已经按顺序压好了实参。**注意弹出顺序是逆序**——最后压的实参对应最后一个参数，要先弹它放进 `Vg[n-1]`，再弹前一个放 `Vg[n-2]`……
3. **压帧**：把调用者的 `Vf`、`Sf`、`pcf` 保存到调用栈上。
4. **建立空的 `Sg`**：被调函数从空栈开始。
5. **执行**：`pc` 指向被调函数的代码起点。

返回时对称地：

1. 从 `Sg` 弹出返回值（如果有）。
2. 弹出帧，恢复 `Vf`、`Sf`、`pcf`。
3. 把返回值压回 `Sf`。
4. `pc` 回到 `pcf` 之后。
5. 继续执行调用者的下一条指令。

**为什么要保存 `Sf` 而不只是 `pcf`？** 因为被调函数执行期间，`Sf` 上的值（调用者正在计算的中间结果）必须原样保留。如果只保存 `pc`，被调函数用完栈后调用者的中间结果就丢了。

**为什么实参要「先压后弹」而不是直接传递？** 因为栈机没有寄存器。实参只能通过栈传递——这是栈机架构的固有特征，也是它比寄存器机慢的原因之一（真实 CPU 用寄存器传参）。

### 5.8 堆、数组与字符串

**分配对象**：

- `0xBB new <c1,c2>`：在堆上分配一个对象（大小来自类型信息），把地址压栈。
- `0xBC newarray <c1,c2>`：分配一个数组（元素个数从栈顶弹出），把地址压栈。

**数组访问**（讲义第 12–15 页）：

| 指令 | 操作码 | 语义 |
|---|---|---|
| `imload` | 0x2E | 读 int 数组：`S: ..., addr, idx → ..., addr[idx]` |
| `imstore` | 0x4E | 写 int 数组：`S: ..., addr, idx, val → ...` |
| `amload` | 0x2F | 读对象数组 |
| `amstore` | 0x4F | 写对象数组 |
| `cmload` | 0x34 | 读 char 数组（字符串） |
| `cmstore` | 0x55 | 写 char 数组 |
| `arraylength` | 0xBE | 取数组长度 |

**`cmstore` 的细节**（讲义第 15–17 页）：C0 的字符串是不可变的（immutable），所以写字符时指令会做 `*a = x & 0x7f`——只保留低 7 位（ASCII 范围）。这保证写入的值永远是合法字符。这是一个**运行时强制**的不变式，静态检查做不到。

**`newarray` 的参数顺序**：元素个数从栈顶弹出。所以编译 `alloc_array(int, n)` 时先压 `n`，再执行 `newarray`。

### 5.9 字节码验证

加载 `.bc0` 文件时，C0VM 做以下静态检查（讲义第 17–18 页）：

1. **每个可达地址都是合法指令的起点**。如果跳转指令的目标落在一条多字节指令的中间，拒绝加载。
2. **每个局部变量索引 < `num_vars`**。防止 `vload 99` 读到 `V` 数组外面。
3. **`return` 时栈上恰好有一个值**（对非 `void` 函数）。否则调用者的栈会被破坏。
4. **每条指令执行前栈上有足够的元素**。例如 `iadd` 要求栈高 ≥ 2，否则栈下溢。

**检查方法**：从函数入口开始做一次「抽象执行」——不真的算值，只跟踪**栈高度**和**可达地址集合**。遇到分支就把两个目标都加入待检查队列。因为控制流图是有限的，这个过程必然终止。

**不能检查什么**：

- **除零**。`idiv` 的两个操作数是运行时的值，静态分析无法知道它们是不是 0。要检查就得做「值分析」，那会变成不可判定问题（等价于停机问题）。
- **终止性**。同上——判断任意程序是否终止是停机问题，图灵证明了不可判定。
- **数组越界**。`imstore` 的下标是运行时值。这也是为什么 C0 的数组访问在运行时会做边界检查（如果开启检查），而 C 不做（第 18 讲的 UB）。

**这个「能检查什么 / 不能检查什么」的边界，是编译原理里最深刻的结果之一**：静态检查只能覆盖「与值无关」的性质。所有涉及具体数值的性质，要么运行时检查，要么放弃。

### 5.10 条件与跳转

条件跳转（讲义第 11–12 页）：

| 指令 | 操作码 | 条件 |
|---|---|---|
| `if_cmpeq` | 0x9F | 相等则跳 |
| `if_cmpne` | 0xA0 | 不等则跳 |
| `if_icmplt` | 0xA1 | 小于则跳 |
| `if_icmpge` | 0xA2 | 大于等于则跳 |
| `if_icmpgt` | 0xA3 | 大于则跳 |
| `if_icmple` | 0xA4 | 小于等于则跳 |
| `goto` | 0xA7 | 无条件跳 |

**跳转偏移是 16 位有符号相对偏移**：目标地址 = 当前 `pc` + 偏移。用相对偏移而不是绝对地址，好处是「插入/删除指令时不需要重定位所有跳转」——只需调整跨越插入点的跳转。

**`if` 语句的编译模式**：

```c
if (x < y) { A } else { B }
```

编译成：

```
    vload 0
    vload 1
    if_icmpge ELSE      ; 若 x >= y 跳到 ELSE
    <A 的代码>
    goto END
ELSE:
    <B 的代码>
END:
```

**注意条件取反**：源码是 `x < y` 时执行 A，字节码是「`x >= y` 时跳过 A」。这是因为跳转指令的语义是「条件成立就跳」，而我们要跳过 A，所以要用 A 的反面条件。

**`while` 循环的编译模式**：

```c
while (cond) { body }
```

编译成：

```
LOOP:
    <cond 的代码>
    if_cmpXX END        ; 条件不成立就退出
    <body 的代码>
    goto LOOP
END:
```

**循环不变式在字节码层面不存在**——它只是源码里的注释（C0 的 `//@loop_invariant`）。字节码验证只看栈高度，不看值的性质。这正是第 26 讲「恢复不变量」要手工论证的原因。

### 5.11 习题要点

- **Ex1（第 21 页，解在第 27 页）**：编译 `(14 << 1) + (3 * 2) / 4`。左移 1 位等价于乘 2，所以 `14 << 1 = 28`；`(3*2)/4 = 6/4 = 1`（整数除法向零截断）；总计 **29**。注意运算优先级：`+` 低于 `/`，`*` 高于 `/`，`<<` 优先级低于 `+`，所以表达式是 `(14<<1) + ((3*2)/4)`。
- **Ex4（第 23 页，解在第 28–29 页）**：给定字节码回译成 C0 源码。答案：

  ```c
  int x = 0xBEEF;
  string s1 = "Hello";
  string s2 = "World";
  return x + 0xFEED;
  ```

  关键是识别 `ildc` 引用的是整数池的哪一项、`aldc` 引用的是字符串池的哪一项。`0xBEEF + 0xFEED = 0x1BEDC`，超出 16 位但在 32 位范围内，合法。
- **Ex8（第 25–26 页，解在第 30–31 页）**：整数池为空时要压 300，用 `bipush 3; bipush 100; imul` 算出 300。这是「用指令换常量池槽位」的技巧。

`ildc <c1,c2>`（0x13）、`aldc <c1,c2>`（0x14）。池下标 16 位。

**（5）函数调用**（第 9–10 页）

`invokestatic`（0xB8）、`invokenative`（0xB7）与调用的五个步骤。

**（6）条件**（第 11–12 页）

`if_cmpeq`（0x9F）、`if_cmpne`（0xA0）、`if_icmplt`（0xA1）、`if_icmpge`（0xA2）、`if_icmpgt`（0xA3）、`if_icmple`（0xA4）、`goto`（0xA7），16 位有符号相对偏移。

**（7）堆**（第 12–15 页）

`new <s>`（0xBB）、`newarray <s>`（0xBC）、`aaddf <f>`（0x62）、`aadds`（0x63）、`imload`（0x2E）、`imstore`（0x4E）、`amload`（0x2F）、`amstore`（0x4F）。

**（8）字符与字符串**（第 15–17 页）

`cmload`（0x34）、`cmstore`（0x55，执行 `*a = x & 0x7f`）、`arraylength`（0xBE）。

### 6.2 Agent 自行编写的教学示例

> 非官方，仅用于说明概念

**示例一：用 Python 写一个 12 条指令的迷你栈机。**

```python
# mini_vm.py —— 只实现 C0VM 的一个极小子集
# 非官方，仅用于说明概念

OP = {
    0x10: "bipush",   # 1 字节立即数
    0x60: "iadd",
    0x64: "isub",
    0x68: "imul",
    0x6C: "idiv",
    0x15: "vload",    # 1 字节下标
    0x36: "vstore",   # 1 字节下标
    0xB0: "return",
    0xA7: "goto",     # 2 字节有符号偏移
}

def run(code, num_vars=0, trace=False):
    S, V, pc = [], [0] * max(num_vars, 1), 0
    while pc < len(code):
        start = pc
        op = code[pc]; pc += 1
        name = OP[op]
        if name == "bipush":
            b = code[pc]; pc += 1
            if b >= 0x80: b -= 0x100          # 转成有符号
            S.append(b)
        elif name == "iadd":
            y = S.pop(); x = S.pop(); S.append(x + y)
        elif name == "isub":
            y = S.pop(); x = S.pop(); S.append(x - y)
        elif name == "imul":
            y = S.pop(); x = S.pop(); S.append(x * y)
        elif name == "idiv":
            y = S.pop(); x = S.pop()
            # C 的整数除法向零截断，Python 的 // 向负无穷截断
            q = abs(x) // abs(y)
            S.append(q if (x < 0) == (y < 0) else -q)
        elif name == "vload":
            i = code[pc]; pc += 1; S.append(V[i])
        elif name == "vstore":
            i = code[pc]; pc += 1; V[i] = S.pop()
        elif name == "goto":
            off = (code[pc] << 8) | code[pc + 1]; pc += 2
            if off >= 0x8000: off -= 0x10000   # 16 位有符号
            pc = pc - 2 + off                  # 相对「跳转指令起点」
        elif name == "return":
            return S.pop() if S else None
        if trace:
            print(f"pc={start:3d} {name:8s} S={S} V={V}")
    return S.pop() if S else None

if __name__ == "__main__":
    # (3 + 4) * 5 / 2
    code = bytes([0x10,3, 0x10,4, 0x60, 0x10,5, 0x68, 0x10,2, 0x6C, 0xB0])
    print(run(code, trace=True))    # 17
```

这个迷你 VM 演示了栈机的三个核心机制：**操作数从栈弹出**、**结果压回栈**、**`pc` 顺序推进**。真实 C0VM 还有常量池、堆、调用栈，但执行循环的形状完全相同。

**注意 `idiv` 的截断方向**：C 的整数除法向零截断（`-7/2 == -3`），Python 的 `//` 向负无穷截断（`-7//2 == -4`）。这个差异是「移植代码时最容易漏掉的 bug」之一。

**示例二：给迷你 VM 加循环，验证 `while` 的编译模式。**

```python
# 计算 1 + 2 + ... + 10
# 伪 C0:
#   int i = 1, sum = 0;
#   while (i <= 10) { sum = sum + i; i = i + 1; }
#   return sum;
#
# 布局：V[0] = i, V[1] = sum
code = bytes([
    0x10, 1, 0x36, 0,        # bipush 1;  vstore 0        i = 1
    0x10, 0, 0x36, 1,        # bipush 0;  vstore 1        sum = 0
    # LOOP (偏移 8)
    0x15, 0,                 # vload 0                   压 i
    0x10, 10,                # bipush 10                 压 10
    0xA3, 0x00, 0x04,        # if_icmpgt +4              i > 10 则跳到 END
    0x15, 1, 0x15, 0, 0x60, 0x36, 1,   # sum = sum + i
    0x15, 0, 0x10, 1, 0x60, 0x36, 0,   # i = i + 1
    0xA7, 0xFF, 0xEC,        # goto -20                  回到 LOOP
    # END
    0x15, 1, 0xB0,           # vload 1; return
])
print(run(code, num_vars=2))    # 55
```

`goto -20` 的偏移计算：`goto` 指令本身占 3 字节（0xA7 + 2 字节偏移），偏移是相对**指令起点**的。`goto` 起点在偏移 32，目标 LOOP 在偏移 8，所以偏移 = 8 − 32 = −24……但代码里写的是 −20。这个差异说明：**不同实现的偏移基准点不同**（有的相对指令起点，有的相对指令之后）。真实 C0VM 的规范见讲义第 11–12 页——写这类代码必须查规范，不能凭直觉。

**示例三：观察字节码验证能抓住什么。**

```python
def verify(code):
    """极简验证器：只检查可达地址都是指令起点，且栈高度不为负。"""
    # 第一遍：标出所有指令起点
    starts, pc = set(), 0
    sizes = {0x10:2, 0x60:1, 0x64:1, 0x68:1, 0x6C:1, 0x15:2, 0x36:2,
             0xB0:1, 0xA7:3, 0xA3:3, 0x13:3}
    while pc < len(code):
        starts.add(pc)
        pc += sizes.get(code[pc], 1)
    # 第二遍：从 0 开始做抽象执行，跟踪栈高度
    work, seen = [(0, 0)], set()
    while work:
        pc, h = work.pop()
        if (pc, h) in seen: continue
        seen.add((pc, h))
        if pc not in starts:
            return f"ERROR: pc={pc} 不是指令起点"
        op = code[pc]
        if op == 0x10:   work.append((pc + 2, h + 1))
        elif op in (0x60, 0x64, 0x68, 0x6C):
            if h < 2: return f"ERROR: pc={pc} 栈下溢（高度 {h}）"
            work.append((pc + 1, h - 1))
        elif op == 0x15: work.append((pc + 2, h + 1))
        elif op == 0x36:
            if h < 1: return f"ERROR: pc={pc} 栈下溢"
            work.append((pc + 2, h - 1))
        elif op == 0xB0:
            if h != 1: return f"ERROR: pc={pc} return 时栈高 {h} ≠ 1"
        elif op == 0xA7:
            off = (code[pc+1] << 8) | code[pc+2]
            if off >= 0x8000: off -= 0x10000
            work.append((pc + off, h))
        elif op == 0xA3:
            if h < 2: return f"ERROR: pc={pc} 栈下溢"
            off = (code[pc+1] << 8) | code[pc+2]
            if off >= 0x8000: off -= 0x10000
            work.append((pc + off, h - 2))
            work.append((pc + 3, h - 2))
    return "OK"
```

**这个验证器能抓住**：跳转到指令中间、栈下溢、`return` 时栈高不对。

**它抓不住**：`idiv` 的分母是 0、无限循环、数组越界。原因在 5.9 节说过——这些都需要知道运行时的**具体值**，而抽象执行只跟踪栈高度。

**这就是「静态检查的能力边界」的具象化**：能检查「形状」，不能检查「数值」。

## 7. 容易混淆的概念

| 概念 A | 概念 B | 关键区别 | 记忆点 |
|---|---|---|---|
| C0VM | 真实 CPU | 前者是软件模拟的栈机；后者是硬件寄存器机 | 一个是剧本，一个是演员 |
| 字节码 | 机器码 | 前者是虚拟机的指令；后者是 CPU 的指令 | 字节码要解释，机器码直接跑 |
| 值栈 `S` | 调用栈 | 前者存当前函数的中间结果；后者存「返回地址 + 调用者的 `S`、`V`」 | 一个函数一个 `S`，全局一个调用栈 |
| `vload` / `vstore` | `imload` / `imstore` | 前者访问局部变量数组；后者访问堆上的 int 数组 | `v` = variable，`im` = int memory |
| `bipush` | `ildc` | 前者压 1 字节立即数（−128…127）；后者从常量池压任意 int | 小的用 `bipush`，大的用 `ildc` |
| `isub` 的操作数顺序 | 直觉顺序 | 弹出 `y` 再弹 `x`，算 `x − y` | 先压的是被减数 |
| 字节码验证 | 类型检查 | 前者检查栈高度与跳转目标；后者检查类型匹配 | 验证管「形状」，不管「值」 |
| C0 的 `cmstore` | C 的字符赋值 | 前者强制 `& 0x7f`（ASCII）；后者无检查 | C0 有运行时保护，C 没有 |

## 10. 本节复习

1. `cc0 -b` 把 `.c0` 编译成 `.bc0` 字节码；C0VM 解释执行字节码。字节码的好处：可移植、可静态检查、可分析。
2. 栈机四要素：值栈 `S`、局部变量 `V`、程序计数器 `pc`、调用栈。运算从栈顶弹出操作数，结果压回栈顶。
3. `(3+4)*5/2` → `bipush 3 / bipush 4 / iadd / bipush 5 / imul / bipush 2 / idiv` = `10 03 10 04 60 10 05 68 10 02 6C`。编译顺序是**后序遍历**。
4. 文件格式：魔数 `C0 C0 FF EE`、版本 `00 17`、整数池、地址池、函数表（参数个数/局部变量个数/代码长度）、代码段。
5. 调用五步：建 `Vg` → 弹参存 `Vg`（逆序）→ 压帧 → 建空 `Sg` → 执行。返回五步对称。
6. 大整数走常量池 `ildc`，字符串/函数走 `aldc`；`new` / `newarray` 分配；`imload`/`imstore` 访问 int 数组；`cmstore` 强制 `& 0x7f`。
7. 字节码验证检查：可达地址是合法指令起点、局部变量下标在界内、`return` 时栈高恰为 1、每条指令栈高足够。**不能**检查除零、终止性、数组越界——这些依赖运行时的值。

## 11. 自我检查

**题 1.** 把 `(14 << 1) + (3 * 2) / 4` 编译成字节码，写出指令序列（不需要写十六进制），并算出结果。

**题 2.** 执行 `bipush 10; bipush 3; isub` 之后，栈顶是什么值？如果写成 `bipush 3; bipush 10; isub` 呢？请解释原因。

**题 3.** 为什么字节码文件要以魔数 `C0 C0 FF EE` 开头？如果去掉这 4 个字节会有什么问题？

**题 4.** 字节码验证能不能检查出下面这些问题？逐条说明能或不能，以及原因。
（a）`vload 99`，而该函数只有 3 个局部变量
（b）`idiv` 时除数为 0
（c）`return` 时栈上有 2 个值
（d）`while (true) {}` 无限循环
（e）`goto` 跳到了某条 `bipush` 指令的操作数字节上

**题 5.** 给定字节码 `15 00 10 05 68 B0`，请还原它对应的 C0 表达式（假设只有一个参数 `x` 在 `V[0]`），并说明它的返回值。

<details>
<summary>参考答案</summary>

**答 1.**
按优先级：`<<` 低于 `+`，`*` 高于 `/`，所以表达式是 `(14 << 1) + ((3 * 2) / 4)`。

左移编译成 `imul`（乘 2 的幂）：

```
bipush 14
bipush 2
imul            ; 14 << 1 = 28
bipush 3
bipush 2
imul            ; 3 * 2 = 6
bipush 4
idiv            ; 6 / 4 = 1（整数除法向零截断）
iadd            ; 28 + 1 = 29
return
```

结果：**29**。

注意 `6 / 4` 是 **1** 而不是 1.5——C0/C 的整数除法向零截断。这是最容易算错的一步。

**答 2.**
- `bipush 10; bipush 3; isub` → 栈顶是 **7**。
- `bipush 3; bipush 10; isub` → 栈顶是 **−7**。

**原因**：`isub` 的语义是「弹出 `y`（栈顶），再弹出 `x`，压入 `x − y`」。栈是后进先出，**先压的是被减数**。

- 第一种：先压 10（被减数），后压 3（减数），算 10 − 3 = 7。
- 第二种：先压 3（被减数），后压 10（减数），算 3 − 10 = −7。

这个顺序对所有非交换运算都成立（`isub`、`idiv`、比较指令）。记法：**「源码里写在左边的，先压栈」**。

**答 3.**
**作用**：魔数是文件类型的「身份证」。C0VM 加载文件时先读前 4 字节，不是 `C0 C0 FF EE` 就立即拒绝。

**去掉的问题**：

1. **误加载非字节码文件**。如果用户把 `.c0` 源文件或任意二进制文件当 `.bc0` 传给解释器，没有魔数检查就会按字节码去解码——可能读到非法操作码，也可能「碰巧」解出一堆合法指令然后执行完全错误的行为（更危险，因为不报错）。
2. **版本混淆**。魔数后面紧跟版本号 `00 17`，两者配合才能确认「这是 C0VM 字节码，且是兼容版本」。
3. **诊断困难**。有了魔数，错误信息可以是「不是有效的 C0 字节码文件」；没有魔数，错误信息只能是「在偏移 3 处遇到非法操作码 0x2A」——用户完全不知道发生了什么。

**更广的意义**：所有二进制格式都有魔数（PNG 的 `89 50 4E 47`、ELF 的 `7F 45 4C 46`、ZIP 的 `50 4B 03 04`）。这是「防御性编程」在文件格式层面的标准做法。

**答 4.**
- **（a）`vload 99` 越界：能检查。** 这是纯静态性质——函数头里写着局部变量个数，`vload` 的操作数是编译期常量。验证器只需比较 `99 < num_vars`。不需要知道任何运行时的值。
- **（b）`idiv` 除数为 0：不能检查。** 除数在运行时才确定（可能来自用户输入、文件、随机数）。要静态判断「这个值永远不为 0」需要做值分析，而这在一般情况下等价于停机问题，不可判定。
- **（c）`return` 时栈上有 2 个值：能检查。** 验证器做抽象执行时跟踪栈高度，到 `return` 指令时检查高度是否为 1。这是纯「形状」性质。
- **（d）`while (true) {}` 无限循环：不能检查。** 终止性是停机问题，图灵证明不可判定。验证器只能保证「如果它终止，状态是合法的」，不能保证「它终止」。
- **（e）`goto` 跳到指令中间：能检查。** 第一遍扫描标出所有指令起点（按每条指令的长度推进 `pc`），第二遍检查每个跳转目标是否在起点集合里。这是纯静态的地址计算。

**规律**：能检查的都是「与具体数值无关」的性质（下标范围、栈高度、地址合法性）；不能检查的都涉及「运行时会是什么值」（除数、循环条件、数组下标）。

**答 5.**
逐条解码：

```
15 00        vload 0        ; 压 V[0]，即 x
10 05        bipush 5       ; 压 5
68           imul           ; x * 5
B0           return         ; 返回栈顶
```

对应的 C0 表达式：

```c
return x * 5;
```

**返回值**：`5x`（即参数 `x` 的五倍）。

**验证方法**：跟踪栈高度——`vload` 后高度 1，`bipush` 后高度 2，`imul` 弹出 2 压 1，高度 1，`return` 时高度恰为 1 ✓。这正好满足字节码验证的第 3 条规则。

**补充**：如果这段字节码属于函数 `int times5(int x)`，那函数头的「参数个数」必须是 1，「局部变量个数」必须是 1（至少容纳参数）。这两个数字与实际使用的 `vload 0` 必须一致，否则验证失败。
