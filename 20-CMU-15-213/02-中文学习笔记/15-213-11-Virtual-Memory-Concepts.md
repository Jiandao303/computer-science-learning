# 虚拟内存：概念（Virtual Memory: Concepts）

## 1. 本节学习目标

- 说清为什么需要虚拟内存：让多个进程共享一台物理内存而不互相踩踏。
- 能把虚拟地址拆成 VPN 与 VPO，并用页表（page table）完成一次地址翻译。
- 能区分 page hit 与 page fault，并按 7 个步骤描述缺页处理流程。
- 能解释为什么 VM 的参数选择（大页、全相联、write-back、软件替换）与 L1/L2 缓存完全相反。
- 能说明 TLB 的作用与 TLB 命中/缺失的路径差异。
- 能推导单级页表在 32 位与 48 位地址下的空间开销，并解释多级页表如何省内存。

## 2. 前置知识

- [[15-213-10-Cache-Memories]]：缓存的组织、命中/缺失、写回、替换策略——虚拟内存本质上是“以 DRAM 为缓存、以磁盘为后备”的一层缓存，所有概念可以平移。
- [[15-213-03-Machine-Programming-I-Basics]]：地址、指针、栈指针 `%rsp`。
- [[15-213-04-Machine-Programming-II-Control]]：数组与指针运算，理解“地址”在机器级只是一个整数。
- 操作系统常识：进程（process）、内核（kernel）、异常（exception）。

## 3. 核心概念

- **Virtual Memory（虚拟内存）**：给每个进程一个私有的、连续的地址空间假象，由硬件（MMU）与操作系统协作，把虚拟地址翻译成物理地址。
- **Virtual Address Space（虚拟地址空间）**：N = 2^n 个虚拟地址的集合 {0, 1, …, N−1}，是进程看到的“内存”。
- **Physical Address Space（物理地址空间）**：M = 2^m 个物理地址的集合，真实 DRAM 的容量。
- **MMU（Memory Management Unit，内存管理单元）**：CPU 芯片上负责地址翻译的硬件。
- **Page（页）**：虚拟内存与磁盘之间传输的固定大小块，P = 2^p 字节，典型 4KB。
- **VPN / VPO（Virtual Page Number / Offset）**：虚拟地址的高位（页号）与低 p 位（页内偏移）。
- **PPN / PPO（Physical Page Number / Offset）**：物理地址的页号与页内偏移，PPO 与 VPO 完全相同。
- **Page Table（页表）**：由 PTE 组成的数组，把虚拟页映射到物理页；每个进程一份，放在 DRAM 中，由内核维护。
- **PTE（Page Table Entry，页表项）**：含 valid bit、权限位、物理页号或磁盘地址。
- **PTBR（Page Table Base Register）**：保存当前进程页表基址的寄存器，x86 上叫 CR3。
- **Page Hit（页命中）**：目标虚拟页已在物理内存中，valid = 1。
- **Page Fault（缺页）**：目标虚拟页不在物理内存中，valid = 0，触发异常，由内核处理。
- **Demand Paging（按需调页）**：等到真正访问才把页从磁盘调入，而不是提前全部装入。
- **Working Set（工作集）**：某一时刻程序活跃访问的那组虚拟页。
- **Thrashing（抖动）**：所有进程工作集之和超过物理内存，页面被反复换入换出，性能崩塌。
- **TLB（Translation Lookaside Buffer，翻译后备缓冲器）**：MMU 内的小型组相联硬件缓存，缓存 VPN → PPN 的映射。
- **Multi-Level Page Table（多级页表）**：把页表本身分页，用树形结构避免为未使用的地址区间分配页表项。

## 4. 通俗理解

### 4.1 为什么需要它

讲义第 3 页先戳破一个谎言：前面几讲一直说“内存就是一块 RAM，地址 0 到 M−1”，但你的电脑同时开着浏览器、编辑器、音乐播放器。如果每个程序都直接使用物理地址，它们会互相覆盖对方的数据，一个野指针就能把别的程序写坏。虚拟内存就是解决方案。

比喻：物理内存是一栋楼里的真实房间，虚拟地址是每个租户手里的房间号。每个租户都以为自己的房间从 101 开始连续排到 999，物业（MMU + 页表）在门口做一次换算，把“你家的 101”指到“真实的 507”。租户之间看不到彼此的房间，也无法闯进配电室（内核空间）。

### 4.2 三个作用（讲义第 12 页）

1. **把主存当缓存用**：DRAM 缓存磁盘上的虚拟地址空间，只有活跃的页才在内存里。
2. **简化内存管理**：每个进程都拥有同样的线性地址空间布局，链接器不必关心物理内存在哪。
3. **隔离地址空间**：进程之间互不可见；用户程序无法访问内核的特权代码与数据。

### 4.3 一个数字感受代价差异

讲义第 29 页：DRAM 比 SRAM 慢约 10 倍，磁盘比 DRAM 慢约 10,000 倍。所以虚拟内存的“缺失代价”（缺页）是几百万个周期级别，而 L1 缺失只有几十个周期。代价差了五个数量级，直接决定了后面所有设计选择都必须与 CPU 缓存相反。

## 5. 原理与推导

### 5.1 地址翻译的定义

讲义第 13 页给出映射函数：

```
MAP: V → P ∪ {∅}
MAP(a) = a'   若虚拟地址 a 的数据在物理地址 a'
MAP(a) = ∅    若该数据不在物理内存中（无效，或在磁盘上）
```

关键约束（第 14 页）：

- 映射的粒度是 **page**，大小由 ISA 规定，不是软件随意决定。
- 映射函数必须**简单且高效**，因为它由硬件实现，在每个 load/store 上都要跑一次。
- 实际实现是 **K 叉树（K-nary tree），即页表**，树的每个节点恰好是一页大小。

### 5.2 页表与地址拆分

页表是 PTE 的数组（第 15 页），每个进程一份，常驻 DRAM，由内核管理。虚拟地址与物理地址的拆分（第 16 页）：

```
虚拟地址：| VPN (n-p 位) | VPO (p 位) |
物理地址：| PPN (m-p 位) | PPO (p 位) |
```

- **VPO = PPO**：页内偏移在翻译前后不变，这是“页”作为映射粒度的直接结果。
- 用 VPN 作为下标查页表，取出 PTE：
  - valid = 1 → PTE 中存 PPN，拼上 VPO 得到物理地址。
  - valid = 0 → 该页不在内存（在磁盘上或从未分配），触发缺页异常。
- 页表基址来自 **PTBR**（x86 是 CR3），每次进程切换时内核更新它——这就是“每个进程有独立地址空间”的实现方式。

### 5.3 Page Hit 的 5 个步骤

讲义第 18 页：

1. 处理器把虚拟地址 VA 发给 MMU。
2. MMU 用 VPN 拼出 PTE 地址 PTEA，向缓存/内存请求 PTE。
3. 缓存/内存返回 PTE。
4. MMU 构造物理地址 PA，发给缓存/内存。
5. 缓存/内存把数据字返回处理器。

注意第 2–3 步本身是一次内存访问：如果不做优化，每个 load 都要变成两次内存访问。TLB 就是为消除这次额外访问而存在的（见 5.6）。

### 5.4 Page Fault 的 7 个步骤

讲义第 20 页：

1. 处理器把 VA 发给 MMU。
2. MMU 取 PTE。
3. PTE 返回。
4. valid = 0，MMU 触发**缺页异常**（page fault exception）。
5. 缺页处理程序（内核）选一个 victim 页；若该页 dirty，先把它写回磁盘（page out）。
6. 处理程序把目标页从磁盘读入（page in），更新内存中的 PTE（valid = 1，填入新 PPN）。
7. 处理程序返回原进程，**重新执行**引发缺页的那条指令——这次是 page hit。

第 24 页的要点：等到缺失发生才把页复制进 DRAM，称为 **demand paging**。它不是缺陷而是设计——程序往往只用到自己地址空间的一小部分，提前装入纯属浪费。

第 25 页补充：分配一个新页（如 `malloc` 触发 `brk`）时，内核在页表里新增一个 PTE，但此时页可能还没有实际物理页（或指向一个全零页），第一次写入才真正分配。

### 5.5 为什么 VM 的参数与 CPU 缓存完全相反

讲义第 29 页把因果关系讲得很清楚：**缺失代价决定一切**。

| 参数 | L1/L2 缓存 | 虚拟内存（DRAM 缓存） | 原因 |
|---|---|---|---|
| 块/页大小 | 64 字节 | 4KB，有时 4MB | 磁盘寻道极慢，必须一次搬大块摊薄 |
| 相联度 | 1/2/4/8/16 路 | 全相联 | 缺页代价太高，不能容忍冲突缺失 |
| 映射函数 | 简单位拆分 | 复杂（页表，多级树） | 全相联需要查表，无法用位运算 |
| 替换策略 | 硬件 LRU / 伪 LRU | 复杂软件算法（如 clock、LRU 近似） | 太复杂、太开放，硬件做不了 |
| 写策略 | write-back 或 through | 一律 write-back | 写磁盘太慢，必须攒着 |

这张表是本节最值得背下来的内容：同样的缓存理论，参数被代价重新塑形。

### 5.6 TLB：消除额外的内存访问

问题（第 32 页）：PTE 本身也放在内存里，会被普通数据引用挤出 L1；即便 PTE 命中 L1，也要多花一点延迟。而每次 load/store 都要查页表，这个开销不可接受。

解决方案：**TLB**，MMU 内的小型、组相联硬件缓存，缓存完整的 PTE（VPN → PPN），条目数通常几十到几千。

TLB 的地址拆分（第 33 页）：用 VPN 而不是整个 VA 去索引。

```
VPN = | TLBT (t 位) | TLBI (t' 位) |
```

- **TLBI（TLB index）** 选组，T = 2^t 组。
- **TLBT（TLB tag）** 与组内各条目的 tag 比较，确认命中。
- 命中后直接得到 PPN，与 VPO 拼接成 PA。

两条路径的差异（第 34–35 页）：

- **TLB hit**：省掉一次内存访问，只剩“取数据”这一次。
- **TLB miss**：需要额外访问内存取 PTE（多级页表则要访问多次，每级一次）。

第 35 页留了一个问题：“TLB 缺失很罕见，为什么？”答案是局部性：一个 4KB 页里有 512 个 8 字节数据，一次 TLB 命中之后，对该页内所有数据的访问都命中；只要工作集包含的页数不超过 TLB 条目数，TLB 缺失率就极低。

第 42 页强调：无论页表有几级，**TLB 里存的永远是完整的 VPN → PPN 映射**，所以 TLB 命中时完全不需要走页表。

### 5.7 单级页表的内存开销

讲义第 38 页给出 32 位系统的账：

- 32 位地址、4KB（2^12）页 → VPN 有 20 位 → 2^20 个 PTE。
- 每个 PTE 4 字节 → 页表本身 4MB。
- 每个进程一份 → 100 个进程就是 400MB，只为存映射。

而实际布局极度稀疏：2K 个页给代码和数据、6K 个未分配页、1023 个未分配页的空洞、1 个栈页。绝大多数 PTE 是空的，却必须占着空间。

48 位地址更夸张（第 39 页）：4KB 页、8 字节 PTE，单级页表需要 2^48 × 2^-12 × 2^3 = 2^39 字节 = **512 GB**，完全不可行。

### 5.8 多级页表

思路（第 39–41 页）：把页表本身也分页，用树结构。

- **一级页表**：每个 PTE 指向一个二级页表，**总是常驻内存**。
- **二级页表**：每个 PTE 指向一个物理页，可以像普通数据一样被换入换出。
- 若某个一级 PTE 为 null，对应的整个二级页表根本不必存在——这就是省内存的来源。

翻译过程（第 41 页）：VPN 被切成 VPN1 | VPN2 | … | VPNk，依次索引各级页表：

1. PTBR 指向一级页表，用 VPN1 取 PTE，得到二级页表基址。
2. 用 VPN2 在二级页表中取 PTE，得到三级页表基址……
3. 最后一级的 PTE 给出 PPN，拼上 VPO 得到 PA。

代价是：一次 TLB 缺失要走 k 次内存访问。所以多级页表与 TLB 是配套设计——TLB 命中时零额外访问，TLB 缺失时才付出多级遍历的代价。x86-64 实际使用 4 级（近年为 5 级）页表，每级用 9 位索引，正好索引 512 个 8 字节 PTE = 4KB 一页。

### 5.9 保护

讲义第 26 页：PTE 除了 valid 和 PPN，还有权限位：

- **READ / WRITE / EXEC**：是否可读、可写、可执行。
- **SUP**：仅内核（supervisor）可访问。

MMU 在每次访问时检查这些位。于是“只读代码段”不是靠编译器保证，而是靠硬件强制；用户程序想写内核页会直接触发异常。这就是虚拟内存作为“保护插桩点（interpositioning point）”的价值（第 43 页）。

### 5.10 与缓存的关系

讲义第 30 页的图说明：地址翻译发生在 L1 之前，L1 用的是物理地址（PIPT 风格）。PTE 本身也走 L1，所以一次数据访问可能涉及两次 L1 查找（PTE + 数据），除非 TLB 命中。

> 待核实：讲义第 30 页只画出“PTE 经 L1 缓存”的整合结构，未讨论 VIPT（虚拟索引物理标记）等现代优化；若需细节请查阅 CSAPP 9.6.4 或体系结构教材。

Virtual address

**进程地址空间布局（11-vm-concepts.pdf 第 10 页）：** 从高到低依次是内核虚拟内存、共享库的内存映射区、运行时堆（`malloc` 创建，由 `brk` 上界）、用户栈（`%rsp` 向下增长）、未使用区；低端 0x400000 起是可执行文件装入的只读段（`.init`、`.text`、`.rodata`）与读写段（`.data`、`.bss`）。

### 6.2 Agent 自行编写的教学示例

> 非官方，仅用于说明概念。

用 C 打印当前进程若干地址的高位，直观看到“虚拟地址空间”是稀疏且高位相同的：

```c
#include <stdio.h>
#include <stdlib.h>

int g_init = 42;          /* .data */
int g_zero;               /* .bss  */
static const char *msg = "rodata";  /* .rodata */

int main(void) {
    int local = 7;                 /* 栈 */
    int *heap = malloc(64);        /* 堆 */
    printf("text   ~ %p\n", (void *)main);
    printf("rodata ~ %p\n", (void *)msg);
    printf("data   ~ %p\n", (void *)&g_init);
    printf("bss    ~ %p\n", (void *)&g_zero);
    printf("heap   ~ %p\n", (void *)heap);
    printf("stack  ~ %p\n", (void *)&local);
    free(heap);
    return 0;
}
```

在 x86-64 Linux 上会看到 text/rodata/data/bss 集中在 0x55… 或 0x0040… 附近，heap 紧随其后，stack 在 0x7ff… 的高位——它们之间隔着巨大的空洞，正是多级页表要避免为其分配页表项的区域。

下面用 Python 演示一次页表翻译（单级、4KB 页、32 位地址）：

```python
# 非官方示例：单级页表翻译，仅演示位运算
PAGE_BITS = 12                    # 4KB 页
VPN_BITS = 32 - PAGE_BITS         # 20 位

def translate(va, page_table):
    vpn = va >> PAGE_BITS
    vpo = va & ((1 << PAGE_BITS) - 1)
    pte = page_table.get(vpn)
    if pte is None or not pte[0]:
        return None               # page fault
    ppn = pte[1]
    return (ppn << PAGE_BITS) | vpo

pt = {0x1: (1, 0x0A), 0x2: (1, 0x0B)}   # VPN 1 -> PPN 0x0A, VPN 2 -> PPN 0x0B
print(hex(translate(0x1ABC, pt)))       # 0xAABC
print(translate(0x3ABC, pt))            # None -> 缺页
```

输出 0xAABC 说明 VPO（0xABC）在翻译前后保持不变，只有页号被替换。

## 7. 容易混淆的概念

| 概念 A | 概念 B | 区别 |
|---|---|---|
| Program（程序） | Process（进程） | 程序是磁盘上的静态可执行文件；进程是它的一次运行实例，拥有独立地址空间（讲义第 4 页明确强调二者不同，也不同于 processor） |
| VPN | VPO | VPN 是被翻译的部分，VPO 翻译前后不变 |
| PTE 的 valid = 0 | 页不存在 | valid = 0 只表示“不在物理内存”，页可能在磁盘上，也可能从未分配 |
| Page fault（缺页） | Segmentation fault（段错误） | 前者是正常的、可恢复的机制；后者是访问了无效地址或违反权限位，内核通常终止进程 |
| TLB | Page table | TLB 是页表的缓存，条目极少；页表是完整映射，在内存中 |
| 一级页表 | 二级页表 | 一级页表常驻内存；二级页表可被换出 |
| Working set（工作集） | 地址空间大小 | 工作集是当前活跃页的集合，通常远小于整个地址空间 |

## 10. 本节复习

- VM 三大作用：高效利用内存（DRAM 缓存磁盘）、简化内存管理、隔离与保护。
- 地址拆分：VA = VPN | VPO，PA = PPN | PPO，VPO = PPO。
- 页表 = PTE 数组，每进程一份，PTBR（CR3）指向它。
- page hit 5 步；page fault 7 步，最后重新执行出错指令；按需调页。
- VM 参数与 CPU 缓存相反：大页、全相联、复杂软件替换、write-back——一切由巨大缺失代价决定。
- TLB 缓存 VPN → PPN；命中省一次内存访问；多级页表下 TLB 命中免去 k 次遍历。
- 单级页表 32 位需 4MB，48 位需 512GB；多级页表用稀疏性省空间。
- 工作集之和超过物理内存 → thrashing。

## 11. 自我检查

1. 一个系统有 32 位虚拟地址、30 位物理地址、4KB 页、4 字节 PTE。求 VPN 位数、VPO 位数、PPN 位数，以及单级页表的大小。
2. 描述 TLB 命中与 TLB 缺失时，从 CPU 发出 VA 到拿到数据分别经历哪些步骤。
3. 为什么虚拟内存选择全相联而不是组相联？如果强行改成直接映射会发生什么？
4. 48 位地址、4KB 页、8 字节 PTE，为什么单级页表要 512GB？多级页表如何避免这个开销？
5. 什么是 thrashing？它与 L1 缓存的 capacity miss 在机制上有什么相似与不同？

<details>
<summary>参考答案</summary>

1. 页大小 4KB = 2^12 → VPO = 12 位，PPO = 12 位。VPN = 32 − 12 = 20 位；PPN = 30 − 12 = 18 位。PTE 数 = 2^20，每个 4 字节 → 页表 4MB。

2. TLB 命中：CPU 发 VA → MMU 用 VPN 的 TLBI 选组、TLBT 比对 → 命中得到 PPN → 拼 VPO 得 PA → 访问 L1/内存取数据 → 返回。全程只有一次数据访问。TLB 缺失：MMU 需用 VPN 走页表（多级则每级一次内存访问）取 PTE → 得到 PPN 并填入 TLB → 拼 PA → 取数据。多出至少一次内存访问。

3. 因为缺页代价是磁盘级别（比 DRAM 慢约一万倍），一次冲突缺失就足以毁掉性能，所以不能容忍任何冲突，必须全相联。若改成直接映射，两个热点页映射到同一组会反复互相驱逐，每次都是缺页，程序会慢几个数量级——这正是 thrashing 的一种表现。

4. 页数 = 2^48 / 2^12 = 2^36，每项 8 字节 → 2^36 × 2^3 = 2^39 字节 = 512GB。多级页表把 VPN 切成多段，只有被使用的区间才分配下级页表；大量未使用区间的一级 PTE 为 null，下级页表根本不存在，因此实际占用与已分配页数成正比而非与地址空间大小成正比。

5. Thrashing 指多个进程工作集之和超过物理内存，页被连续换入换出，CPU 大部分时间在等磁盘。与 capacity miss 相似之处是都源于“工作集大于容量”；不同之处是 VM 的容量是物理内存、后备是磁盘，缺失代价高五六个数量级，而且替换由操作系统软件在多个进程之间全局决策，不是单个缓存的局部策略。

</details>
