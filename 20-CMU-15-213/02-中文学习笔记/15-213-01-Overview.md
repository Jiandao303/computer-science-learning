# L01 Course Overview（课程总览）

> 开课日期：2026 年 8 月 25 日。本讲不涉及具体技术细节，而是回答三个问题：这门课讲什么、为什么要学、以及怎么学（含学术诚信与工具链）。

## 1. 本节学习目标

学完本讲后，你应当能够：

1. 用自己的话说明 **15-213 的研究对象是「程序在真实机器上的行为」**，而不是算法或语言本身。
2. 解释课程采用的六层抽象栈（Application / Libraries / Operating System / Networking / Memory & Storage / Processors），并指出每一层「泄漏」给程序员的关键事实。
3. 说明「整数不是数学整数、浮点数不是实数」这两句话的确切含义，并能举出溢出与结合律失效的具体数字。
4. 复述 `struct_t` 越界写实验的现象，理解为什么内存错误的表现与原因在时间、空间上相距很远。
5. 说明本课的评分构成、实验（Lab）序列与延迟提交政策。
6. 说明本课对 AI 工具与学术诚信的硬性要求。

## 2. 前置知识

- **C 语言**：指针、数组、`struct`、`malloc/free`、`printf` 格式化。讲义 p56 明确指出 Lab0 应当是「复习」而非「新学」，若 Lab0 需要 10 小时以上，应重新考虑是否选修本课。
- **二进制与十六进制**：能手工在 0b / 0x / 十进制之间转换（下一讲 L02 会系统展开）。
- **命令行基础**：`ssh`、`ls`、`cd`、编辑器、`gcc`、`make`、`git`。
- **数据结构基础**：链表、哈希表——后续 `malloclab`、`cachelab` 会用到。

## 3. 核心概念

- **Computer System（计算机系统）**：硬件（处理器、内存、存储、网络）与软件（操作系统、库、应用）协同工作的整体。
- **Abstraction（抽象）**：用简单模型隐藏下层复杂性。本课的核心立场是：抽象会泄漏（leaky abstraction），程序员必须知道泄漏点在哪里。
- **Programmer-Centric（以程序员为中心）**：本课不教如何造 CPU 或写操作系统，而教「写程序的人需要知道的机器事实」。
- **Integer Overflow（整数溢出）**：有限位宽下的算术结果按模 2^w 回绕。
- **Floating Point（浮点数）**：IEEE 754 表示，不满足结合律。
- **Memory Hierarchy（存储层次）**：寄存器 / L1 / L2 / L3 / 主存 / 磁盘，容量递增、速度递减。
- **Locality（局部性）**：时间局部性与空间局部性，是缓存有效的根本原因。
- **Academic Integrity Violation（AIV，学术诚信违规）**：本课对抄袭、以及在禁止范围内使用 AI 的统称。

## 4. 通俗理解

把计算机系统想成一座**冰山**。你写的 C 代码只是露出水面的一角；水面之下依次是编译器、汇编、链接器、操作系统、缓存、内存控制器、磁盘。多数时候你只需要看冰山一角——直到程序崩溃、变慢、或者被攻击。本课就是把水面下的部分逐层照亮。

另一个比喻来自讲义 p7 的「抽象 vs 现实」：抽象是地图，现实是地形。地图很好用，但地图上没画的那条沟，会让你掉进去。

第三个比喻是讲义 p11 的三句话，值得背下来：

- 内存不是无限的（memory is not unbounded）；
- 内存访问不是等价的（memory is not uniform，访问 L1 与访问磁盘差好几个数量级）；
- 内存错误的表现与原因在时间与空间上相距很远（bugs are distant in time and space）。

## 5. 原理与推导

### 5.1 为什么「整数不是整数」

数学整数是无限的，而机器整数是 w 位宽的有限集合。以 32 位有符号整型为例：

```
TMax = 2^31 - 1 = 2147483647
```

讲义 p8 给出两个具体反例：

```
40000 * 40000 = 1600000000      // 仍在范围内，结果正确
50000 * 50000 = 2500000000      // 超出 TMax，实际得到 -1794967296
```

推导：50000 × 50000 = 2 500 000 000，而 2 500 000 000 − 2^32 = 2 500 000 000 − 4 294 967 296 = −1 794 967 296。这就是 **模运算（Modular Arithmetic）** 的直接后果：结果取乘积的低 32 位。

### 5.2 为什么「浮点数不是实数」

IEEE 754 单/双精度只能表示有限个实数，因此加法**不满足结合律**。讲义 p8：

```
(1e20 + -1e20) + 3.14  =  3.14
1e20 + (-1e20 + 3.14)  =  0.0     // 3.14 被 1e20 的精度「吃掉」
```

原因：1e20 的有效位数远超 double 的 52 位尾数，`1e20 + 3.14` 舍入后仍等于 1e20，再减去 1e20 就得 0。

讲义 p9 的结论值得记住：**整数运算满足环（ring）公理**——交换律、结合律、分配律都成立（在模 2^w 意义下）；**浮点运算满足序（ordering）公理**——单调性成立，但结合律不成立。两类运算各自牺牲了对方的一条性质。

### 5.3 内存错误为什么难查

讲义 p12–p13 的实验是整门课的「动机演示」：

```c
typedef struct {
    int a[2];
    double d;
} struct_t;

double fun(int i) {
    volatile struct_t s;
    s.d = 3.14;
    s.a[i] = 1073741824;   /* 可能越界 */
    return s.d;
}
```

在 x86-64 上，`struct_t` 的布局是 `a[0]`、`a[1]`、4 字节填充、`d` 的低 4 字节、`d` 的高 4 字节。于是：

| i | 实际写到哪 | 返回值 |
|---|---|---|
| 0 | `a[0]` | 3.14 |
| 1 | `a[1]` | 3.14 |
| 2 | `a[1]` 之后的填充区 | 3.1399998664856 |
| 3 | `d` 的低 4 字节 | 2.00000061035156 |
| 4 | `d` 的高 4 字节 | 3.14 |
| 6 | 栈帧之外 | Segmentation fault |

关键观察：**写越界发生在 `s.a[i] = ...`，症状却出现在 `return s.d`**。这就是「错误的表现与原因在空间上相距很远」。如果 `fun` 被调用一百万次，崩溃点可能落在完全无关的代码里。

### 5.4 常数因子的重要性

讲义 p16 的矩阵拷贝实验：2048×2048 的 `int` 矩阵，`copyij`（外层 i、内层 j，按行遍历）耗时 **4.3 ms**，`copyji`（外层 j、内层 i，按列遍历）耗时 **81.8 ms**，机器是 2.0 GHz Intel Core i7 Haswell。两者算法复杂度完全相同（O(n²)），差距全部来自**空间局部性**：C 数组按行存储，按列访问会反复驱逐缓存行。这为 L09 的存储层次埋下伏笔。

### 5.5 本课在课程体系中的位置

讲义 p21 给出先修链：`15-122`（C 与命令式编程）→ **`15-213`** → `15-410`（操作系统）、`15-411`（编译器）、`15-418`（并行体系结构）、`15-441`（网络）、`15-445`（数据库）。15-213 是「从写程序到理解机器」的转折点。

### 6.2 Agent 自行编写的教学示例

> 非官方，仅用于说明概念。

演示 5.3 节的越界写在实际机器上如何「污染」相邻字段。注意 `volatile` 阻止编译器把 `s` 放在寄存器里，保证它真的在栈上。

```c
/* overflow_demo.c —— 非官方示例，仅用于说明概念 */
#include <stdio.h>
#include <stddef.h>

typedef struct {
    int a[2];
    double d;
} struct_t;

int main(void) {
    /* 先打印布局，验证 5.3 节的假设 */
    printf("sizeof(struct_t) = %zu\n", sizeof(struct_t));
    printf("offsetof(d)      = %zu\n", offsetof(struct_t, d));

    struct_t s;
    s.d = 3.14;
    /* a[2] 与 a[3] 已经越界，落到填充区与 d 上 */
    s.a[2] = 0x00000000;
    s.a[3] = 0x40091EB8;   /* 3.14 的低 32 位，写入后 d 会被破坏 */
    printf("d = %.17g\n", s.d);
    return 0;
}
```

在 x86-64 上 `sizeof(struct_t)` 为 16，`offsetof(d)` 为 8：`a` 占 0–7，`d` 占 8–15，中间没有填充（因为 `double` 要求 8 字节对齐而 `a` 恰好结束在 8）。这与讲义 p13 图示的「index 2 落在 a[1] 之后的填充区」在 32 位环境下的布局一致——**结构体布局依 ABI 而异**，这正是需要 `offsetof` 而不是靠记忆的原因。

对应的 GDB 检查命令：

```
(gdb) p sizeof(struct_t)
(gdb) p &s
(gdb) x/16xb &s          # 按字节 dump 整个结构体
(gdb) watch s.d          # 谁改了 d？
```

## 10. 本节复习

- 本课的研究对象是**程序在真实机器上的行为**，而不是算法、语言或硬件设计。
- 六层抽象栈：应用 → 库 → 操作系统 → 网络 → 存储 → 处理器。
- 三句「内存事实」：不是无限、不是等价、错误远离现场。
- 整数是模 2^w 的环，浮点是只有序没有结合律的集合。
- `struct_t` 实验说明越界写的症状与原因可以完全脱钩。
- 相同复杂度的代码可以差 19 倍（`copyij` 4.3 ms vs `copyji` 81.8 ms），原因在存储层次。
- 评分：Lab 50% / Written 6% / Quiz 4% / Midterm 15% / Final 25%，绝对分制。
- 8 个 Lab 顺序：Lab0 C 复习 → datalab → bomblab → attacklab → cachelab → malloclab → tshlab → proxylab（另有 sfslab）。
- AI 政策：不得用 AI 写代码、不得用 AI 调试；可以问工具用法与「非常高层次」的设计。

## 11. 自我检查

**题 1**（可计算）：32 位有符号整型下，`50000 * 50000` 的机器结果是多少？请写出推导过程。

<details><summary>参考答案</summary>

乘积 2 500 000 000 超过 TMax = 2 147 483 647，按模 2^32 回绕：

2 500 000 000 − 4 294 967 296 = **−1 794 967 296**

即结果为 −1794967296。用 C 验证：`printf("%d\n", 50000*50000);` 输出 `-1794967296`。

</details>

**题 2**（可计算）：`(1e20 + -1e20) + 3.14` 与 `1e20 + (-1e20 + 3.14)` 的结果分别是什么？为什么？

<details><summary>参考答案</summary>

前者为 **3.14**，后者为 **0.0**。

原因：double 的尾数只有 52 位，1e20 的量级约为 2^66，其 ulp 远大于 3.14。计算 `1e20 + 3.14` 时 3.14 被完全舍去，结果仍是 1e20；再减去 1e20 得 0。这直接证明浮点加法不满足结合律。

</details>

**题 3**：`struct_t` 实验中 `fun(6)` 触发 Segmentation fault，而 `fun(3)` 只是返回了一个奇怪的数。这两者的本质区别是什么？

<details><summary>参考答案</summary>

`fun(3)` 写到的是**栈帧内**的合法内存（`d` 的低 4 字节），属于「静默数据破坏」：程序继续运行，只是结果错了。`fun(6)` 写到了栈帧之外，可能落入未映射的页或只读页，MMU 触发保护异常，操作系统向进程发送 SIGSEGV，进程被终止。前者是逻辑错误，后者是硬件/OS 层面的访问违规。

</details>

**题 4**：为什么本课被称为 programmer-centric 而不是 builder-centric？

<details><summary>参考答案</summary>

因为它不要求学生实现处理器、编译器或操作系统，而是要求学生理解「写程序时必须知道的机器事实」：数据表示、汇编、链接、存储层次、异常控制流、虚拟内存、并发。目标是让程序员能诊断性能问题、内存错误与安全漏洞，而不是培养系统构建者。

</details>

**题 5**：讲义把 `git add .` 和 `git commit -a` 列为不推荐操作，理由是什么？

<details><summary>参考答案</summary>

这两个命令会把工作区中**所有**改动一次性提交，包括调试用的临时文件、编译产物、甚至从别处拷来的代码。本课用 GitHub Classroom 收集作业并做抄袭检测，误提交他人代码会构成 AIV。讲义建议显式列出文件：`git commit <files>`，并「早提交、勤提交」。

</details>
