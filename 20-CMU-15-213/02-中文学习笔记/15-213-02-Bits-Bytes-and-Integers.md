# L02 Bits, Bytes, and Integers（位、字节与整数）

> 开课日期：2026 年 8 月 27 日。本讲建立整门课的地基：所有数据最终都是一串位，所谓「类型」只是对这串位的**解释方式**。

## 1. 本节学习目标

1. 熟练在二进制、八进制、十六进制、十进制之间手工转换，并说明为什么十六进制是机器世界的通用书写法。
2. 掌握四种布尔运算与四种位级运算（`&`、`|`、`^`、`~`），能把位向量看作集合、把位运算看作集合运算。
3. 区分位级运算 `&`/`|` 与逻辑运算 `&&`/`||`，说明短路求值的用途与陷阱。
4. 说明左移、逻辑右移、算术右移的语义，以及 C 中移位运算的未定义行为边界。
5. 推导补码编码公式，证明 `-x = ~x + 1`，说明 TMin 的特殊性。
6. 解释有符号与无符号之间的转换规则，并预测 C 中混合比较的结果。
7. 说明符号扩展与截断的位级规则。
8. 说明无符号加法、补码加法的回绕行为与溢出判定。
9. 说明乘 2^k 与除 2^k 的移位实现，以及有符号除法为何需要偏置（bias）。
10. 说明大端序与小端序的差别，并能从反汇编字节序列还原立即数。

## 2. 前置知识

- **位（bit）**：0 或 1，最小的信息单位。
- **字节（byte）**：8 位，机器可寻址的最小单位。
- **字（word）**：本课默认 64 位（x86-64 的机器字长），讲数据表示时常用 w 表示位宽。
- **C 语言整型**：`char`(1B)、`short`(2B)、`int`(4B)、`long`(8B on x86-64)、`long long`(8B)。
- **上一讲 L01** 的结论：整数不是数学整数，浮点不是实数。

## 3. 核心概念

- **Bit（位）** / **Byte（字节）** / **Word（字）**：数据的基本计量单位。
- **Hexadecimal（十六进制）**：基 16，用 `0x` 前缀，1 位十六进制对应 4 位二进制。
- **Boolean Algebra（布尔代数）**：`&`（与）、`|`（或）、`^`（异或）、`~`（非）。
- **Logical Operators（逻辑运算符）**：`&&`、`||`、`!`，结果只有 0 或 1，且短路。
- **Shift（移位）**：`<<` 左移、`>>` 逻辑/算术右移。
- **Unsigned（无符号数）**：B2U 编码，范围 `[0, 2^w − 1]`。
- **Two's Complement（补码）**：B2T 编码，范围 `[-2^{w-1}, 2^{w-1} − 1]`。
- **Sign Extension（符号扩展）**：向更宽类型转换时复制最高位。
- **Truncation（截断）**：向更窄类型转换时丢弃高位。
- **Overflow（溢出）**：结果超出可表示范围，按模 2^w 回绕。
- **Endianness（字节序）**：多字节数据在内存中的排列顺序，分大端（Big Endian）与小端（Little Endian）。

## 4. 通俗理解

**类型不是数据，类型是眼镜。** 同一串 8 个比特 `11111111`，戴「无符号眼镜」看是 255，戴「补码眼镜」看是 −1，戴「ASCII 眼镜」看是一个字符。机器里存的永远是那 8 个比特，变的只是你怎么读它。这一讲的所有「奇怪现象」——溢出、类型转换、比较反直觉——都源于「同一串位被两副眼镜轮流看」。

**补码的直观来源**：把 3 位的所有组合排成一个圈 `000 → 001 → 010 → ... → 111 → 000`。加法就是在这个圈上顺时针走。走过头就绕回来，这就是模运算。补码只是规定「圈的后半段读作负数」：`100` 读作 −4、`111` 读作 −1。这样读的好处是：**加法和减法可以用同一个硬件电路完成**。

**十六进制的地位**：因为 4 位二进制恰好等于 1 位十六进制，十六进制是二进制的「压缩书写」，且不会像十进制那样丢失位对齐信息。看到 `0x3B6D` 就能立刻写出 `0011 1011 0110 1101`。

## 5. 原理与推导

### 5.1 进制转换

二进制按位权展开：`1011₂ = 1·8 + 0·4 + 1·2 + 1·1 = 11`。

十六进制同理，讲义 p8 的例子：

```
1A2B = 1·16³ + 10·16² + 2·16 + 11
     = 4096 + 2560 + 32 + 11
     = 6699
```

十进制转十六进制用「除 16 取余」：

```
15213 ÷ 16 = 950 余 13 (D)
   950 ÷ 16 =  59 余  6 (6)
    59 ÷ 16 =   3 余 11 (B)
     3 ÷ 16 =   0 余  3 (3)
```

自下而上读余数：**15213 = 0x3B6D**。对应的二进制是 `0011 1011 0110 1101`——注意 15213 这个数字在本课中反复出现（CMU 的邮编区号），是讲义的标准测试值。

### 5.2 布尔运算与集合视角

讲义 p11–p12 的核心洞察：**位向量就是集合**。把 w 位向量的第 i 位看作「元素 i 是否在集合中」：

```
01101001 = {0, 3, 5, 6}
01010101 = {0, 2, 4, 6}
```

于是：

| 位运算 | 集合含义 | 例子 |
|---|---|---|
| `&` | 交集 | `01101001 & 01010101 = 01000001 = {0,6}` |
| `\|` | 并集 | `01101001 \| 01010101 = 01111101 = {0,2,3,4,5,6}` |
| `^` | 对称差 | `01101001 ^ 01010101 = 00111100 = {2,3,4,5}` |
| `~` | 补集 | `~01010101 = 10101010` |

数值验证（讲义 p11）：`0x69 & 0x55 = 0x41`，`0x69 | 0x55 = 0x7D`，`0x69 ^ 0x55 = 0x3C`，`~0x55 = 0xAA`。

**常用技巧**（本讲未列出，但后续 Lab 必备）：

- `x & (x-1)`：清除最低位的 1。反复执行可数 1 的个数。
- `x & -x`：取出最低位的 1（lowbit）。
- `x | (1 << k)`：置位第 k 位；`x & ~(1 << k)`：清位；`x ^ (1 << k)`：翻转。
- `~0`：全 1 掩码（−1）。

### 5.3 逻辑运算与短路

`&&`、`||`、`!` 把任何非零值当「真」，结果严格为 0 或 1（讲义 p15）：

```
!0x41 → 0x00
!0x00 → 0x01
!!0x41 → 0x01
```

短路求值是 C 的重要语义：`p && *p` 在 `p` 为 NULL 时不会解引用。**陷阱**：把 `&` 写成 `&&` 会得到语义完全不同的代码，且常常「看起来能跑」——因为 `1 && 2` 是 1，而 `1 & 2` 是 0。

### 5.4 移位

- `x << y`：左移，低位补 0，高位丢弃。
- `x >> y`：右移。**无符号数**用逻辑右移（高位补 0）；**有符号数**在 C 中由实现定义，x86 的 `sar` 是算术右移（复制符号位）。
- **未定义行为**：移位量 `< 0` 或 `>=` 位宽。

讲义 p16 的例子（8 位）：

```
01100010 << 3 = 00010000      // 高位溢出被丢弃
01100010 >> 2 = 00011000      // 逻辑右移
10100010 >> 2 = 11101000      // 算术右移，高位补 1
```

### 5.5 补码编码与 `-x = ~x + 1`

**编码公式**（讲义 p30）：

```
B2U(X) = Σ_{i=0}^{w-1} x_i · 2^i
B2T(X) = -x_{w-1} · 2^{w-1} + Σ_{i=0}^{w-2} x_i · 2^i
```

唯一区别是最高位的权重取负。例如 `101` 在 3 位补码下 = `-4 + 0 + 1 = -3`。

**求负的推导**（讲义 p26–p27）：

1. 对任意 x，`x + ~x = 111...1`（全 1），因为每一位恰好一 0 一 1。
2. 全 1 的补码值等于 −1（`B2T(111...1) = -2^{w-1} + (2^{w-1} - 1) = -1`）。
3. 所以 `x + ~x = -1`，即 `~x = -1 - x`。
4. 两边加 1：`~x + 1 = -x`。证毕。

**TMin 的特殊性**（讲义 p29）：`x = TMin = 0x8000`（16 位），`~x = 0x7FFF = 32767`，`~x + 1 = 0x8000 = TMin`。也就是说 **TMin 的相反数还是自己**——因为 `+2^{w-1}` 无法表示。这是一个必须记住的边界。

**取值范围**（讲义 p31）：

| 量 | 公式 | 16 位值 |
|---|---|---|
| UMin | 0 | 0x0000 |
| UMax | 2^w − 1 | 0xFFFF = 65535 |
| TMin | −2^{w-1} | 0x8000 = −32768 |
| TMax | 2^{w-1} − 1 | 0x7FFF = 32767 |
| −1 | 全 1 | 0xFFFF |

注意 `|TMin| = TMax + 1`：补码是**不对称**的，负数比正数多一个。

### 5.6 有符号与无符号的转换

**位模式不变，只换解释**。转换关系是 `T2U(x) = x + 2^w`（当 x < 0）或 `x`（当 x ≥ 0）。

C 中的规则（讲义 p36–p37）：

1. 整型常量默认是**有符号**的，加 `U` 后缀变无符号。
2. 显式 `(int)` / `(unsigned)` 转换是**重新解释位**，不是改数值。
3. 混合有符号与无符号运算时，**有符号数被隐式转成无符号数**——这是无数 bug 的来源。

讲义 p37 的比较表（W=32）：

| 表达式 | 结果 | 原因 |
|---|---|---|
| `0 == 0U` | 1 | 都转无符号 |
| `-1 < 0` | 1 | 都签名 |
| `-1 < 0U` | **0** | −1 变成 4294967295 |
| `2147483647 > -2147483647-1` | 1 | 都签名 |
| `2147483647U < -2147483647-1` | **0** | 右边变成 2147483648 |
| `-1 > -2` | 1 | 都签名 |
| `(unsigned)-1 > -2` | 1 | 都无符号 |
| `2147483647 < 2147483648U` | 1 | 都无符号 |
| `2147483647 > (int)2147483648U` | **1** | `(int)2147483648U` = TMin |

最后一行最容易错：`(int)2147483648U` 把 `0x80000000` 重解释为 **TMin = −2147483648**，所以 `2147483647 > -2147483648` 为真。

### 5.7 扩展与截断

**扩展（w → w+k）**：

- 无符号：**零扩展**，高位补 0。
- 有符号：**符号扩展**，高位复制符号位（讲义 p40–p43）。`int8_t su = -1`（`0xff`）→ `int16_t` 得 `0xffff`，仍是 −1。

```
 10 = 01010 → 0001010     (符号位 0，补 0)
-10 = 10110 → 11110110    (符号位 1，补 1)
```

**截断（w → w-k）**：直接丢弃高 k 位（讲义 p44–p47）。

```
 10 (01010) → 1010 = -6      // 符号翻转！
-10 (10110) → 0110 =  6      // 符号翻转！
  2 (00010) → 0010 =  2      // 不变
 -6 (11010) → 1010 = -6      // 巧合不变
```

规律：截断后的值等于 `原值 mod 2^{w-k}` 再按补码解释。所以截断可能改变符号，且不可逆。

### 5.8 加法与溢出

**无符号加法**（讲义 p50）：`UAdd_w(u,v) = (u + v) mod 2^w`，即丢弃进位。

```
E9 + D5 = 1BE → BE      // 233 + 213 = 446, 446 - 256 = 190
```

**补码加法**（讲义 p51）：位级行为与无符号**完全相同**，只是解释不同。

```c
int s = (int)((unsigned)u + (unsigned)v);
int t = u + v;
/* 在 x86-64 上 s == t 恒成立 */
```

溢出判定（讲义 p52–p54）：

- **正溢出（PosOver）**：两正数相加得负数，条件 `sum >= 2^{w-1}`。
- **负溢出（NegOver）**：两负数相加得正数，条件 `sum < -2^{w-1}`。

C 中有符号溢出是**未定义行为（Undefined Behavior）**，编译器可以假设它不发生；无符号溢出是**良定义的**模运算。

### 5.9 乘法与除法

**乘法**（讲义 p55）：精确乘积需要 2w 位，机器只保留低 w 位。`x * y` 在补码下的结果与无符号乘法在位级上一致。

**乘 2^k**（讲义 p56）：`u << k == u * 2^k`。编译器会把常数乘法改写成移位加组合：

```
u * 24  →  (u << 5) - (u << 3)      // 32u - 8u
```

**除 2^k**（讲义 p57–p60）：

- 无符号：`u >> k` 即整除（向下取整恰好等于向零取整）。讲义 p73：`15213 >> 4 = 950`。
- 有符号：算术右移是**向下取整**（朝 −∞），而 C 的 `/` 是**向零取整**。二者在负数上不同。

```
-5 >> 1 = 1101₂→ ... 算术右移得 -3    (向下取整)
-5 / 2  = -2                          (向零取整)
```

修正方法：先加偏置再移位（讲义 p59–p60）：

```c
(x + (1 << k) - 1) >> k      // 对 x < 0 时把结果推向零
```

验证：`-5 (1011) + 1 = 1100`，`1100 >> 1 = 1110 = -2`。正确。

### 5.10 字节序

讲义 p62–p63：`int x = 0x01234567`，存放在地址 `0x100`：

| 地址 | 大端序 | 小端序 |
|---|---|---|
| 0x100 | 01 | 67 |
| 0x101 | 23 | 45 |
| 0x102 | 45 | 23 |
| 0x103 | 67 | 01 |

- **大端（Big Endian）**：最高有效字节在最低地址。Sun SPARC、PowerPC Mac、**网络协议字节序**。
- **小端（Little Endian）**：最低有效字节在最低地址。**x86-64**、ARM（Android/iOS/Linux 默认）。

注意：**字节序只影响字节顺序，不影响字节内部的位顺序**；`char` 数组不受影响。

反汇编中的体现（讲义 p64）：

```
8048365: 5b              pop %ebx
8048366: 81 c3 ab 12 00 00   add $0x12ab,%ebx
```

立即数 `0x12ab` 补零到 32 位是 `0x000012ab`，小端存储为 `ab 12 00 00`——正好是机器码里的字节序列。

### 6.2 Agent 自行编写的教学示例

> 非官方，仅用于说明概念。

**示例 A：用位运算打印一个整数的二进制，观察补码**

```c
/* bits_demo.c —— 非官方示例，仅用于说明概念 */
#include <stdio.h>
#include <stdint.h>

static void show(int32_t x) {
    printf("%11d = 0x%08X = ", x, (uint32_t)x);
    for (int i = 31; i >= 0; i--)
        putchar(((uint32_t)x >> i) & 1 ? '1' : '0');
    putchar('\n');
}

int main(void) {
    show(0);
    show(-1);            /* 全 1 */
    show(INT32_MIN);     /* 0x80000000，TMin */
    show(~5 + 1);        /* -5，验证 -x = ~x + 1 */
    show(-5 >> 1);       /* 算术右移 = -3，向下取整 */
    show(-5 / 2);        /* C 除法 = -2，向零取整 */
    return 0;
}
```

预期输出（节选）：

```
          0 = 0x00000000 = 00000000000000000000000000000000
         -1 = 0xFFFFFFFF = 11111111111111111111111111111111
-2147483648 = 0x80000000 = 10000000000000000000000000000000
         -5 = 0xFFFFFFFB = 11111111111111111111111111111011
         -3 = 0xFFFFFFFD = 11111111111111111111111111111101
         -2 = 0xFFFFFFFE = 11111111111111111111111111111110
```

**示例 B：字节序探测**

```c
/* endian.c —— 非官方示例，仅用于说明概念 */
#include <stdio.h>

int main(void) {
    unsigned int x = 0x01234567;
    unsigned char *p = (unsigned char *)&x;
    for (int i = 0; i < 4; i++)
        printf("byte[%d] = 0x%02X\n", i, p[i]);
    return 0;
}
```

x86-64 上输出 `67 45 23 01`，即小端。

**示例 C：无符号比较陷阱的 GDB 验证**

```
(gdb) p -1 < 0
$1 = 1
(gdb) p -1 < 0U
$2 = 0
(gdb) p /x (unsigned)-1
$3 = 0xffffffff
```

## 7. 容易混淆的概念

| 概念 A | 概念 B | 区别 |
|---|---|---|
| `&` 位与 | `&&` 逻辑与 | 前者按位、不短路、结果不限于 0/1；后者短路、结果严格 0/1 |
| `>>` 逻辑右移 | `>>` 算术右移 | 无符号必为逻辑；有符号由实现定义，x86 的 `sar` 补符号位 |
| 符号扩展 | 零扩展 | 有符号→宽类型复制符号位；无符号→宽类型补 0 |
| 截断 | 溢出 | 截断是类型变窄丢高位；溢出是运算结果超范围回绕 |
| `(int)` 转换 | 数值转换 | C 的整型转换是**重新解释位**，不是数学取整 |
| TMin | −TMax | TMin = −2^{w-1}，TMax = 2^{w-1}−1，`-TMin == TMin` |
| 大端序 | 小端序 | 大端最高字节在低地址（网络序）；小端最低字节在低地址（x86） |
| 有符号溢出 | 无符号溢出 | 前者是 UB，编译器可任意优化；后者良定义为模运算 |
| `x / 2` | `x >> 1` | 正数相同；负数前者向零取整、后者向下取整 |
| 十六进制 | 十进制 | 十六进制与二进制按 4 位对齐，不丢失位信息；十进制会 |

## 10. 本节复习

- 十六进制与二进制按 4 位对齐；`15213 = 0x3B6D = 0b0011 1011 0110 1101`。
- 位向量即集合：`&` 交、`|` 并、`^` 对称差、`~` 补。
- `x & (x-1)` 清最低位 1，`x & -x` 取最低位 1。
- `>>` 在有符号数上是算术右移（x86），移位量越界是 UB。
- `B2T` 与 `B2U` 只差最高位权重的符号。
- `-x = ~x + 1`，且 `-TMin == TMin`。
- 有符号与无符号混合运算：有符号转无符号，`-1 < 0U` 为假。
- 扩展看符号（零扩展 / 符号扩展），截断丢高位（可能变号）。
- 补码加法位级等价于无符号加法；有符号溢出是 UB。
- 乘 2^k 是左移；除 2^k 对负数是算术右移加偏置 `(x + (1<<k) - 1) >> k`。
- x86-64 是小端；网络字节序是大端。

## 11. 自我检查

**题 1**：把十进制 `−15213` 表示为 16 位补码的十六进制形式。

<details><summary>参考答案</summary>

`15213 = 0x3B6D = 0011 1011 0110 1101`

取反：`1100 0100 1001 0010 = 0xC492`

加 1：`0xC493`

所以 `−15213 = 0xC493`。验证：`0x3B6D + 0xC493 = 0x10000`，16 位下为 0，正确。

</details>

**题 2**：8 位补码下，`0xE9 + 0xD5` 的结果是多少？是否溢出？溢出方向？

<details><summary>参考答案</summary>

`0xE9 + 0xD5 = 0x1BE`，丢弃进位得 **`0xBE`**。

按补码解释：`0xE9 = −23`，`0xD5 = −43`，真和 `−66`。`0xBE = −66`，**未溢出**（−66 在 `[−128, 127]` 内）。

若按无符号解释：`233 + 213 = 446`，`446 − 256 = 190 = 0xBE`，无符号也「回绕」了但这是良定义行为。

</details>

**题 3**：C 表达式 `-1 < 0U` 的值是什么？为什么？

<details><summary>参考答案</summary>

值为 **0（假）**。

因为 `0U` 是无符号，`-1` 被隐式转换为 `unsigned int`，位模式 `0xFFFFFFFF`，数值为 `4294967295`。于是比较变成 `4294967295 < 0`，为假。

这是 C 中最经典的隐式转换陷阱，编译器通常给出 `-Wsign-compare` 警告。

</details>

**题 4**：`x` 是 `int`，`x = -5`。分别求 `x >> 1`、`x / 2`、`(x + 1) >> 1` 的值（假设算术右移）。

<details><summary>参考答案</summary>

`-5 = 0xFFFFFFFB = ...11111011`

- `x >> 1` = `...11111101` = **−3**（向下取整）
- `x / 2` = **−2**（C 语义向零取整）
- `(x + 1) >> 1` = `-4 >> 1` = **−2**（偏置修正，与 `/` 一致）

一般公式：`(x + (1 << k) - 1) >> k` 对负数等价于 `x / 2^k`。

</details>

**题 5**：某 x86-64 程序的反汇编显示 `c7 45 fc 6d 3b 00 00 movl $0x____,-0x4(%rbp)`。请补全立即数。

<details><summary>参考答案</summary>

机器码中立即数字节为 `6d 3b 00 00`，小端序还原为 `0x00003b6d`，即 **`$0x3b6d`**。

`0x3B6D = 15213`，正是讲义反复使用的测试值。

</details>
