## 一、资料收集阶段

### 1.1 优先级

不要按领域编号顺序做，按**你现在最想学什么**做。但每个领域最多同时开两门课。

| 优先级 | 领域 | 理由 |
| --- | --- | --- |
| P0 | 30 数据结构与算法、40 计算机组成、50 操作系统 | 所有方向的公共地基，且已有 CMU 笔记可复用 |
| P1 | 60 网络、70 数据库、80 编译原理 | 系统方向的支柱 |
| P2 | 100 前端、110 后端、120 安全 | 全栈方向的支柱 |
| P3 | 90 软件工程、130 DevOps、150 架构 | 需要先有代码量才有意义 |
| P4 | 10 数学、20 编程基础、140 分布式、160 高级选修 | 按需 |

### 1.2 单个领域的收集流程

```
① 打开 docs/<领域>/02-权威课程与资料.md，选一门主课
      ↓
② 到课程官网确认本学期的 syllabus / schedule 是否还在
      ↓
③ 建 local-materials/<领域>/<课程名-学期>/ 目录
      ↓
④ 下载讲义到该目录，同时写 SOURCE.txt（见 local-materials/README.md）
      ↓
⑤ 在 sources/02-来源登记表.md 补一行 S-00X
      ↓
⑥ 在 docs/<领域>/01-知识点目录.md 里按课程章节补全知识点
```

第 ④ 步的下载纪律：

- **一次只下一门课**。下完、读完、写完笔记，再开下一门。
- **不追求下全**。讲义、作业说明、实验框架够了；视频不下载，记播放列表链接。
- **单次下载不超过 200 MB**。超过说明你在囤积而不是学习。

### 1.3 明确不做

- ❌ 批量抓取「所有 CS 课程 PDF」
- ❌ 下载商业教材（CLRS、CSAPP 全书扫描件等）
- ❌ 镜像任何需要登录才能访问的内容
- ❌ 把下载数量当作进度指标

## 二、中文笔记生成阶段

### 2.1 一篇笔记的标准结构

```markdown
---
title: <讲次或主题名>
course: <课程全名 + 学期>
source: <原始 URL>
date: YYYY-MM-DD
---

# <标题>

## 一句话总结

（这一讲讲什么，用一句话说完。写不出来说明还没懂。）

## 核心概念

（3–7 个概念，每个 2–3 句。不要抄讲义定义，用自己的话。）

## 推导 / 例子

（能算的就算一遍，能跑的就跑一遍，把过程写下来。）

## 和已有知识的连接

（链接到本 Vault 里其他相关笔记。这是 Obsidian 的价值所在。）

## 没懂的地方

（诚实列出。下次复习从这里开始。）

## 自测

1. （不看笔记能回答的问题）
```

### 2.2 质量红线

- **不机翻**。讲义原句直译出来的中文，读者看不懂，你自己也不会回看。
- **不堆砌**。一段话超过 5 行，拆开或删掉。
- **不编造**。讲义没讲的、你没验证的，写「待确认」，不要写成结论。
- **必留来源**。frontmatter 的 `source` 字段不能空。

### 2.3 与已有 107 篇笔记的关系

已有笔记**不迁移、不改名**。新笔记写在 `docs/<领域>/` 下，用 WikiLink 指回旧笔记：

```markdown
延伸阅读：[[15-213-05-Machine-Level-Programming]]
```

等某个领域的旧笔记整理到可以公开的程度，再考虑搬迁——那时单独做一次，配一次链接修复。

## 三、网站构建阶段

### 3.1 前置条件

以下三件事都完成后才动：

- [ ] `docs/` 下至少 5 个领域有实质内容（不是空模板）
- [ ] `sources/02-来源登记表.md` 覆盖所有被引用的来源
- [ ] 所有 `docs/` 页面的外部链接都通过核验

### 3.2 技术选型

**VitePress**，理由：

- Markdown 原生，不需要 MDX
- 内置全文搜索、暗色模式、侧边栏自动生成
- 构建产物是纯静态，可直接放 GitHub Pages

### 3.3 构建步骤

```bash
# 1. 在 Vault 根目录初始化（不要放在 docs/ 里，docs/ 是内容）
npm init -y
npm install -D vitepress

# 2. 配置 docs/.vitepress/config.mts
#    srcDir 指向 docs/，排除私有目录

# 3. 本地预览
npx vitepress dev docs

# 4. 构建
npx vitepress build docs
```

### 3.4 必须注意

- **`srcDir` 只指向 `docs/`**，`local-materials/` 和 `personal-notes/` 不能进构建。
- **中文路径**：VitePress 对中文目录名支持良好，但 URL 会变成百分号编码。如果想要干净的 URL，需要给每个页面配 `rewrites`。这件事在页面少的时候做，页面多了成本高。
- **图片**：放在 `docs/public/`，用绝对路径 `/xxx.png` 引用。
- **不要开评论、不要加统计**，除非你确实会看。
